# 错误处理

本文档介绍 yux 语言中的错误处理：可失败函数声明 `#Fallible(E)`、抛出 `ret E::V`、传播后缀 `!`、捕获块 `try { } catch e E { }`，以及不可恢复的 `panic` / `#NoReturn`。

> 规范层条款见 [docs/spec/draft/DRAFT-错误.md](spec/draft/DRAFT-错误.md)；`#Fallible` / `#NoReturn` 注解登记见 [构建注解.md](构建注解.md)。

## 概览

yux **不引入异常机制**：错误是值返回（无 unwind / SEH personality / DWARF cleanup landingpad）。语法形态借鉴 Swift `throws` / Zig `!T`，**ABI** 是一个隐式合并的 `{ isErr: bool, T_ok, E }` 结构：

| 用途 | 形态 | 出现位置 |
|---|---|---|
| 失败声明 | `#Fallible(E) fn f(...) T { ... }` | 顶层 `fn` / `structImpl` 内方法 |
| 抛错 | `ret E::Variant` 或 `ret E::Variant(...)` | `#Fallible(E)` 函数体内 |
| 同类型传播 | `expr!` 后缀 | `#Fallible(E)` 函数内 / `try` 块内 |
| 跨类型捕获 / 转换 | `try { ... } catch e E { ... }` | 任意函数内 |
| 不可恢复 | `panic(msg)` / `#NoReturn fn ...` | 任意位置 |

**不引入**：`throw` / `raise` / `try?` / `try!` / `Result<T,E>` / `From<E>` / `errdefer` / `defer` / `finally` / `!!`（force-unwrap）。

## 声明可失败函数：`#Fallible(E)`

```yux
enum ParseErr {
  Empty
  Invalid(String)
}

#Fallible(ParseErr)
fn parse_int(s String) i32 {
  if s == "" {
    ret ParseErr::Empty
  }
  ; ...
  ret 0i32
}
```

要点：

- 注解 `#Fallible(E)` 只接受**单参数**，且必须是已声明的具体 `enum` 类型。
- 错误通道**不挤占**返回类型语法：`fn parse_int(...) i32` 中 `i32` 仍是成功值类型，错误通道由注解独立承载。
- 每个函数最多一个 `#Fallible`；多类错误聚合用嵌套 `enum` + `try-catch` 显式包装（见下文）。
- 成功值类型 `T` 与错误类型 `E` **不得相等**（否则 `ret` 无法分流，`E7008`）。
- 声明 `#Fallible(E)` 但函数体没有抛错路径**允许**（接口先行 / 未来兼容），不会因此报错。

非白名单形态：

| 形态 | v1 行为 |
|---|---|
| 顶层 `fn` | ✅ |
| `structImpl` 内方法 | ✅ |
| `extern` 块内 `fnHeader` | ❌（FFI 边界推后）|
| `#CompilerInner` / `#Test` / `#NoReturn` | ❌ 互斥 |
| `#Fallible()` / `#Fallible(E1, E2)` / `#Fallible(NonEnum)` | ❌ |

## 抛出错误：`ret E::Variant`

`#Fallible(E)` 函数体内用 `ret` 后跟错误 enum 值进入错误通道，编译器按表达式类型分流：

```yux
enum IoErr {
  NotFound
  Other(i32)
}

#Fallible(IoErr)
fn read_code(code i32) i32 {
  if code == 404 {
    ret IoErr::NotFound          ; 错误通道
  }
  if code < 0 {
    ret IoErr::Other(code)       ; 错误通道（带 payload）
  }
  ret code                       ; 成功通道
}
```

不引入新关键字：抛出复用 `ret`。表达式类型决定走哪条通道。

## 传播错误：后缀 `!`

后缀 `!` 表示"如果错误就立刻按当前函数的错误通道往外抛"。**仅在两种位置合法**：

1. 调用者本身是 `#Fallible(E)` 函数，且 callee 错误类型与 `E` 严格相等 —— 直接透传。
2. `try` 块内（见下节）。

```yux
#Fallible(ParseErr)
fn parse_double(s String) i32 {
  let v i32 = parse_int(s)!     ; 同类型透传：错误自动 ret 出去
  ret v * 2                      ; 成功路径继续
}
```

诊断（节选）：

| 错误 | 触发条件 | 修复方向 |
|---|---|---|
| `E7001` | `!` 出现在非 `#Fallible` 函数内、非 `try` 块内 | 包一层 `try-catch`，或给外层函数加 `#Fallible(E)` |
| `E7004` | `!` 处 callee 错误类型与 caller `#Fallible` E 不相等 | 用 `try { ... } catch e CalleeErr { ret OuterErr::... }` 显式包装 |
| `E7006` | 调用 `#Fallible` 函数但既无 `!` 也无 `try` 包裹 | 加 `!`、加 `try-catch`，或显式忽略错误（v1 不提供，需走 `try-catch`）|

## 捕获 / 跨类型转换：`try { } catch e E { }`

```yux
let n i32 = try {
  parse_int(line)
} catch e ParseErr {
  -1
}
```

要点：

- `try` 块体是普通块表达式：末表达式作为成功路径的值。
- 至少一个 `catch` 子句；每个 `catch` 写作 `catch e <ErrEnumType> { ... }`，`e` 是 binding 名，类型是 binding 跟随的 enum。
- 必须**穷尽**：`try` 块内所有可能抛出的错误类型都得有对应 `catch`（`E7002`），多余 `catch` 也会报警。
- catch arm body 末表达式类型必须与 `try` 块成功值类型一致（`E7010`），与 `if-else` / `match` 同档。
- 流终止 arm（以 `ret` / `panic(...)` / `#NoReturn` 调用结尾）**不参与**类型合并，与 `if-else` / `match` 同档。

`!` 与 `try-catch` 是同一机制的两种形态：`expr!` 在概念上等同于 `try { expr } catch e SameE { ret e }`。

### 多 catch arm 按类型路由

`try` 块内调用多个不同错误类型的 `#Fallible` 函数时，编译器按错误类型路由到对应 `catch` arm：

```yux
let tag i32 = try {
  let p i32 = parse_int(s)        ; 可能抛 ParseErr
  let r i32 = read_code(p)        ; 可能抛 IoErr
  r
} catch e ParseErr {
  -10
} catch e IoErr {
  -20
}
```

### 在 catch arm 内解构 payload

`catch e E` 把错误绑定为 `e`（类型为 `E`），arm 体内可以照常 `match e { ... }`：

```yux
let msg String = try {
  parse_int(s)
} catch e ParseErr {
  match e {
    ParseErr::Empty => "empty"
    ParseErr::Invalid(reason) => reason
  }
}
```

### 表达式合并 / 流终止

`try` 表达式的值由两条路径合并：成功路径（`try` 块末）与各 `catch` arm 末。任一 arm 以 `ret` 结尾时该路径不参与合并：

```yux
fn process(s String) i32 {
  let v i32 = try {
    parse_int(s)
  } catch e ParseErr {
    ret -1                  ; arm 流终止 → 不参与 try 表达式 phi
  }
  ret v
}
```

## 跨类型错误的标准写法：catch arm 包装

跨类型错误转换**不**自动发生。caller 与 callee 错误类型不一致时，必须用 `try-catch` 显式 wrap：

```yux
enum AppErr {
  Parse(ParseErr)
  Io(IoErr)
}

#Fallible(AppErr)
fn process(line String, code i32) i32 {
  let n i32 = try {
    parse_int(line)
  } catch e ParseErr {
    ret AppErr::Parse(e)        ; ParseErr → AppErr 显式包装
  }
  let r i32 = try {
    read_code(code)
  } catch e IoErr {
    ret AppErr::Io(e)           ; IoErr → AppErr 显式包装
  }
  ret n + r
}
```

`ret AppErr::Parse(e)` 出现在 catch arm 内：它从外层 `#Fallible(AppErr)` 函数 ret 出去，把内层错误重打包给上层。这是 v1 唯一的跨类型错误转换路径。

## main 函数的错误退出

`main` 可以标 `#Fallible(E)`：未在 main 内处理的错误会由编译器生成的退出 wrapper 接住，向 stderr 写一行：

```
error: <module>.<EnumName>::<VariantName>
```

之后以退出码 `1` 终止进程。带 payload 的 variant 当前显示为 `<module>.<EnumName>::<VariantName>(...)`（payload 的可读化 v1 暂不接入）。

```yux
enum AppErr {
  Forbidden
  Other(i32)
}

#Fallible(AppErr)
fn run(arg i32) i32 {
  if arg == 2 {
    ret AppErr::Forbidden
  }
  ret arg
}

#Fallible(AppErr)
fn main() {
  let v i32 = run(2)!         ; 错误透传到 main
  ; v 在错误路径不会被赋值；wrapper 会写 stderr 并 exit(1)
  ret;
}
```

## panic / `#NoReturn`：不可恢复路径

错误通道之外，yux 提供 `panic(msg String)` 表示"不可恢复"：

- 入口在 stdlib：`#NoReturn fn panic(msg String) { ... }`，向 stdout 写 `panic: <msg>\n` 后立即终止进程。
- panic **不进**错误通道，**不能**被 `try-catch` 捕获。
- `assert_eq` / `assert_true` 等测试断言失败也走类似 abort 路径（详见 [docs/spec/§11.3.5](spec/11-内置注解.md)）。

`#NoReturn` 是显式标注"调用后不会返回"的注解：

```yux
#NoReturn
fn die(reason String) {
  panic(reason)
}
```

要点：

- `#NoReturn` 函数**不写**返回类型（`E7012`）。
- `#NoReturn` 与 `#Fallible` **互斥**（`E7013`）。
- `#NoReturn` 函数体**不得**结构性 fall-through：必须以 `ret`、无 `break` 的 `loop`、所有分支均流终止的 `if-else` / `match`、或调用另一个 `#NoReturn` 函数收尾（`E7014`）。

调用 `#NoReturn` 函数等价于流终止：

```yux
fn lookup(id i32) i32 {
  if id < 0 {
    panic("invalid id")        ; 后续语句不可达，编译器视该路径流终止
  }
  ret id * 2
}
```

## v1 不支持

- 析构 / 构造函数参与错误传播：析构出错 → panic；构造失败需改写为返回错误 enum 的工厂函数。
- 自动错误包装（Rust `From<E>` / Java checked exception 链）。
- catch-all：`catch` 必须按具体 enum 类型写，**不**提供"捕获一切"。
- "错误 → null" 折叠（`try?` 之类）。
- `defer` / `errdefer` / `finally`：清理依赖 RC 析构 + `try-catch` 编排。
- `extern fn` 上 `#Fallible(E)`（FFI 边界推后）。
- `#Fallible(GenericParam)` / 泛型参数化的错误类型。
- 多错误聚合签名 `#Fallible(E1, E2)`：用嵌套 enum 表达。

## 完整示例

```yux
enum ParseErr {
  Empty
  Invalid(i32)
}

enum IoErr {
  NotFound
  Other(i32)
}

enum AppErr {
  Parse(ParseErr)
  Io(IoErr)
}

#Fallible(ParseErr)
fn parse_pos(n i32) i32 {
  if n == 0 {
    ret ParseErr::Empty
  }
  if n < 0 {
    ret ParseErr::Invalid(n)
  }
  ret n
}

#Fallible(IoErr)
fn read_code(code i32) i32 {
  if code == 404 {
    ret IoErr::NotFound
  }
  ret code
}

#Fallible(AppErr)
fn process(n i32, code i32) i32 {
  let p i32 = try {
    parse_pos(n)
  } catch e ParseErr {
    ret AppErr::Parse(e)
  }
  let r i32 = try {
    read_code(code)
  } catch e IoErr {
    ret AppErr::Io(e)
  }
  ret p + r
}

#Fallible(AppErr)
fn main() {
  let v i32 = process(3, 200)!
  println(v)
  ret;
}
```
