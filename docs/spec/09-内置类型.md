# §9 内置类型

本章规范 yux 的内置类型语义合约：基本标量、堆句柄、引用 / 指针类型。本章描述形态、方法、ABI 与不变量；其所有权、RC 协议与析构的规范文字由 §8 给出，本章只在必要处指向。

## §9.1 基本标量

### §9.1.1 整数

| 类型 | 位宽 | 符号 | LLVM 落地 |
|---|---|---|---|
| `i8` `i16` `i32` `i64` | 8 / 16 / 32 / 64 | 有符号 | `iN` |
| `u8` `u16` `u32` `u64` | 8 / 16 / 32 / 64 | 无符号 | `iN`（符号靠操作区分） |
| `isize` `usize` | 指针宽度 | 有符号 / 无符号 | `iN`（N = 目标指针位宽） |

§9.1.1.1 整数算术 / 比较 / 位运算的语义见 §4.4 / §4.5；位移**应当**对计数 ≥ 位宽的情形按目标 ABI 行为（v1 不强制定义）。

§9.1.1.2 有 / 无符号是名义区分；`i32` 与 `u32` 不等同（§3.4.1.2）。互转走 `to_i*` / `to_u*`（§3.5）。

§9.1.1.3 v1 **不**提供 `i128` / `u128`（§3.2.1.1）。`isize` / `usize` 已在 v0.18 落地。

### §9.1.2 浮点

| 类型 | 标准 | LLVM 落地 |
|---|---|---|
| `f32` | IEEE 754 单精度 | `float` |
| `f64` | IEEE 754 双精度 | `double` |

§9.1.2.1 浮点比较遵从 IEEE 754 ordered 语义；`NaN == NaN` 为 `false`（同 C / Rust）。

§9.1.2.2 v1 **不**提供 `f16` / `f128`（§3.2.1.1）。

### §9.1.3 `bool`

§9.1.3.1 `bool` 取值仅 `true` / `false`，落 LLVM `i1`（ABI 上视实现可能扩展为 `i8`）。

§9.1.3.2 `bool` 与整数**不**互转，需经 `to_bool()`（0 → `false`，非零 → `true`）/ `to_i*()`（`false` → 0，`true` → 1）显式转换。

### §9.1.4 标量上的内置方法

§9.1.4.1 所有数值类型与 `bool` 提供 `to_<type>()` 转换方法（§3.5.2）；这些方法由编译器内部实现并标记为 `#Builtin`，用户**不得**重新定义。

§9.1.4.2 所有数值类型与 `bool` 提供 `to_string() String`（`ToString` spec，§12.7.1），返回该值的十进制 / `"true"` / `"false"` 文本表示。返回值是堆上 `String`（`Rc<Array<u32>>` 句柄，§9.3.1）：**不是**栈缓冲、**不是** C 字符串 / FFI `Ptr`。SDK 实现走码点缓冲 + `String::_take_buf` 接管（§9.3.3.2）。`String.to_string()` 是句柄共享（§9.3.4.2），不新分配。

§9.1.4.3 数值类型上的运算符走 §4.4 / §4.5 的内置规则；**不**经过 §7.2.3 的运算符重载查找。

## §9.2 `Array<T>`

### §9.2.1 形态与不变量

§9.2.1.1 `Array<T>` 是动态长度的堆句柄；其句柄 layout 为三字段内联结构（B-3 布局，v0.17）：

```
Array<T> = { _data: Ptr, _len: usize, _cap: usize }
```

- `_data`：指向元素数组的堆分配指针；`_data == null` 表示空数组（无分配）。
- `_len`：当前元素数量。
- `_cap`：当前分配容量（元素数，非字节数）。

句柄总宽 24 字节（LP64）。不含 RC Block 间接层——`_data` 直接由 `HeapAlloc` 分配，扩容走 `HeapReAlloc`；RAII 析构先逐个释放元素再 `HeapFree(_data)`。

> 早期版本（< v0.17）的 Array layout 为 `{ _handle: *Block }` 单指针 + Block = `{ rc, len, cap, data }`。B-3 去 Block 重构消灭了间接层与 RC 兼容负担，Array 不再参与 RC 协议。

§9.2.1.2 `Array<T>` 是**不可空**类型；可空写 `Array<T>?`。

§9.2.1.3 多个 `Array<T>` 句柄间赋值走**按值复制**（三字段 memcpy），不共享底层缓冲——每个句柄拥有独立 copy（与旧 Block 共享语义不同）。此设计消除共享可变性，移入赋值 `a <- b` 可 O(1) 转移所有权（§8.7.7）。

§9.2.1.4 元素类型 `T` 不得为借用 `T'&`（容器内层用 `type` 而非 `typeWithRef`，§3.2.3.2）。

### §9.2.2 构造与字面量

§9.2.2.1 空数组：目标类型为 `Array<T>` 的空字面量 `[]` 构造 `_len == 0`、`_cap == 0`、`_data == null` 的句柄（与 §9.2.2.2 同一路径）。旧同名构造 `Array<T>()` 已删除。

§9.2.2.1a `Array:<T>::with_capacity(n usize) Array<T>`：`#Builtin #Static` 工厂。返回 `_len == 0`、`_cap == n` 的数组。`n == 0` 时与空数组相同（不分配）。`n > 0` 时一次 `HeapAlloc(n * sizeof(T))` 预留缓冲；元素未初始化，由后续 `push` 写入。调用须带 turbofish（`Array:<i32>::with_capacity(8)`）。

§9.2.2.2 字面量 `[e1, e2, ..., eN]`：构造长度为 N 的 `Array<T>`，元素类型由统一规则推断（§4.10）。空字面量 `[]` 在上下文有目标类型时构造对应空 `Array<T>`，否则报错。字面量实现走 `__yux_array_alloc(elemSize, count)` runtime 入口，一次 `HeapAlloc` + 逐元素 placement write。

§9.2.2.3 `Array<T>` 的"按值复制"是三字段 memcpy（作为 `#NoCopy` 类型，**禁**隐式复制——§7.6a / §8.7.7）。深拷贝唯一入口是 `arr.clone()`：新分配 `len * sizeof(T)` 字节缓冲 + 逐元素 memcpy + 元素 retain + 嵌套 Heap 字段深拷，返回 `cap == len` 的紧凑新数组。`copy_of:<Array<T>>` **拒绝**（E4031，与其它 `#NoCopy` 类型一致，§7.6a.5）。所有权转移走 `move:<Array<T>>(arr_ref)`（§8.7.7）。

§9.2.2.4 `Array<T>` 是 `#NoCopy` 类型：编译器对其隐式包含 `#NoCopy` 语义（§7.6a.2），**禁**按值传参 / `let b = a` 复制形态——必须走 `move` 或 `clone()`。

### §9.2.3 方法

| 方法 | 形参 | 返回 | 说明 |
|---|---|---|---|
| `len()` | — | `usize` | 当前元素数 |
| `cap()` | — | `usize` | 当前容量 |
| `is_empty()` | — | `bool` | `len() == 0` |
| `get(i usize)` | i | `T&` | 取索引 i 的元素**引用**；通过 `copy_of:<T>(a.get(i))` 显式获得值；越界**应当**调用 `_exit(1)` 终止 |
| `first()` | — | `T&` | 首元素引用；空时终止 |
| `last()` | — | `T&` | 末元素引用；空时终止 |
| `push(value T)` | value | — | 追加；必要时扩容 |
| `pop()` | — | `T` | 移除并返回末元素；空时终止 |
| `clone()` | — | `Array<T>` | 深拷贝（§9.2.2.3）；`copy_of` 不接受 `Array<T>` |
| `clear()` | — | — | 释放所有元素，`len = 0` |
| `set_len(len usize)` | len | — | 仅用于截断；新 len > 当前 len 视为非法（v1 行为：终止） |
| `with_capacity(n usize)` | n | `Array<T>` | `#Static` 工厂（§9.2.2.1a）；预留容量，`len == 0` |

§9.2.3.1 `arr[i]` 返回 `T&`，语义等价于 `arr.get(i)`；通过 `#Mut let w T& = arr[i]; w = expr` 可写穿元素，或通过 `copy_of:<T>(arr[i])` 显式拷贝获得 `T` 值。<br>
`arr[i] = expr` 等价于 `arr.set(i, expr)`（§4.7 / §5.2），`set` 走 §7.4.4 的 retain-then-release。<br>
Array / `[T * N]` 上的 `[]` 由编译器直接 lower 为 GEP，不经过方法派发；`.get()` 声明保留给 LSP / 反射。

§9.2.3.2 修改类方法（`push` / `pop` / `clear` / `set_len` / 索引赋值）要求接收者通过 `Array<T>&` 借用；通过浅不可变 `let` 绑定的 `Array<T>` 局部变量**应当**禁止这些方法（编译器层；规则与 §7.5.1.1 一致）。

§9.2.3.3 容量增长策略由实现决定；规范层只承诺均摊 O(1) 的 `push`。扩容走 runtime `__yux_array_grow(handle, elemSize, newCap)`，内部用 `HeapReAlloc` 原地扩 `_data`；`_data` 值可能变化，但句柄的 `_len` / `_cap` 在函数返回后由调用方更新。

§9.2.3.4 **`Array<Heap<T>>` 例外**：当元素类型为 `Heap<T>` / `Heap<T>?`（或递归含 Heap 子项的复合）时，整个 Array 按 §9.5a.1.4 生命传染规则改走 Heap 语义——按值复制禁，按值搬移须经 `Array<Heap<T>>?` 走复合 move（§7.4.6.6）；`push` / `pop` 等修改方法行为不变（仍要求 `Array<Heap<T>>&` 借用）。

### §9.2.4 比较

§9.2.4.1 `Array<T> == Array<T>`：长度相等且元素逐项 `==`（递归调用元素的 `eq`）。

§9.2.4.2 地址相等走 `same_ref:<Array<T>>(a, b)`（§9.7 / §8）。

## §9.3 `String`

### §9.3.1 形态与不变量

§9.3.1.1 `String` 是**不可变**的 UTF 字符串堆句柄；其内部表示为 `Rc<Array<u32>>`，每个元素是一个 Unicode 码点（§1.6.5）。

§9.3.1.2 句柄 layout 为单一字段嵌入结构体：

```
String = { _buf: Rc<Array<u32>> }
```

- `_buf` 是 `Rc<Array<u32>>` 句柄（8 字节指针），指向 RC Block。
- RC Block 内 payload 类型为 `Array<u32>` = `{ _data, _len, _cap }`（24 字节，B-3 布局，§9.2.1.1）。
- 不可变下 `Array<u32>` 的 `_data` 在构造后不再变更；`_cap == _len`（无预留容量）。

§9.3.1.3 `String` 是不可空类型；可空写 `String?`。

> 早期版本 String 有独立 Block layout `{ rc, len, data[] }`。去 Block 重构后 String 复用 `Rc<Array<u32>>` 通用 RC 协议，消除重复实现。

### §9.3.2 字面量

§9.3.2.1 `STR_LINE` / `STR_LINE_RAW` 字面量编译为指向 `.rodata` 段 RC Block 的 `Rc<Array<u32>>` 句柄；该 Block 的 `rc.strong` / `rc.weak` 为哨兵 `0xFFFFFFFF`（§8.2.3）。runtime 入口检查到哨兵跳过 retain / release（§8）。

§9.3.2.2 字面量 `String` 与构造的 `String` 语义等价；二者可互相比较与共享。

### §9.3.3 构造

同名 ctor 通道已删除（§7.10.6）；构造唯一通道走 `#Static` 工厂：

| 方法 | 形参 | 说明 |
|---|---|---|
| `String::empty()` | — | 空字符串 |
| `String::from(buf Array<u32>&)` | buf | 从码点缓冲**深拷贝**构造；调用后 buf 仍可用 |
| `String::_take_buf(buf Array<u32>)` | buf | SDK 私有；move-in 接管缓冲，调用后 buf 失效 |

§9.3.3.1 `String::from` 对 buf 做 `clone()` 再装箱为 `Rc<Array<u32>>`；调用方仍持有原 Array。这是公开安全入口。

§9.3.3.2 `String::_take_buf` 走 `move:<Array<u32>>(buf)` 把所有权交给内部 `Rc<Array<u32>>`——零拷贝热路径（`to_string` / `StringBuilder.build`）。`_` 前缀模块私有（§10.4）；用户代码写 `String::from`。

### §9.3.4 方法

| 方法 | 返回 | 说明 |
|---|---|---|
| `len()` | `usize` | 码点数 |
| `get(i usize)` | `u32` | 第 i 个码点；越界终止 |
| `starts_with(prefix String&)` | `bool` | 是否以 prefix 开头；空 prefix 为 true |
| `ends_with(suffix String&)` | `bool` | 是否以 suffix 结尾；空 suffix 为 true |
| `contains(needle String&)` | `bool` | 是否包含 needle；空 needle 为 true |
| `to_upper()` | `String` | ASCII `a-z` → `A-Z`；其余码点不变 |
| `to_lower()` | `String` | ASCII `A-Z` → `a-z`；其余码点不变 |
| `split(sep String&)` | `Array<String>` | 按 sep 切分；见 §9.3.4.4 |
| `to_bytes()` | `Array<u8>` | UTF-8 编码字节数组 |

§9.3.4.1 v1 **不**提供 `trim` / `substring` / `repeat`。短生命周期累积**应当**用 `StringBuilder`（§9.4）；自定义码点缓冲可直接 `Array<u32>` + `String::from` / SDK 内 `_take_buf` 构造。`+` 自 v0.6 起可用于字符串拼接（§4.4.1.4）：编译器把整条 `+` 链 lower 为一次 `StringBuilder` 累加，叶子可为 `String` 或任意实现 `ToString` 的类型。

§9.3.4.2 `to_string()` 在 `String` 上的语义是返回自身（句柄共享）。

§9.3.4.3 `to_upper` / `to_lower` 只转换 ASCII 拉丁字母（`a-z` ↔ `A-Z`）；其余码点（含 Latin-1 / CJK 等）原样拷贝。v1 **不**引入 Unicode case mapping 表。二者返回新 `String`，不修改接收者。

§9.3.4.4 `split(sep String&) Array<String>`：按 `sep` 的码点序列切分，顺序保留。空 `sep` 按单个码点切开。连续 / 首尾 `sep` 产生空段。空接收者 + 非空 `sep` 得 `[""]`；空接收者 + 空 `sep` 得 `[]`。

### §9.3.5 比较

§9.3.5.1 `String == String`：长度相等且码点逐位相等。`String == STR_LINE` 字面量同规则。

§9.3.5.2 地址相等走 `same_ref:<String>(a, b)`。

## §9.4 `StringBuilder`

### §9.4.1 形态

§9.4.1.1 `StringBuilder` 是可变的 Unicode 码点累积器；内部持有 `Array<u32>` 缓冲。

§9.4.1.2 `StringBuilder` 是堆句柄、不可空；句柄复制按 §8 的 retain 语义；可空写 `StringBuilder?`。

### §9.4.2 方法

| 方法 | 形参 | 返回 | 说明 |
|---|---|---|---|
| `StringBuilder::make()` | — | — | 空缓冲工厂 |
| `len()` | — | `usize` | 当前码点数 |
| `append(cp u32)` | cp | — | 追加码点 |
| `append(b u8)` | b | — | 追加 ASCII 字节（合法值范围 0–127；超出由实现决定） |
| `append(s String)` | s | — | 追加 `s` 的全部码点 |
| `clear()` | — | — | 重置为空 |
| `build()` | — | `String` | 取出当前缓冲构造不可变 `String`，自身重置为空 |

§9.4.2.1 `build()` 之后 `StringBuilder` 自身缓冲为空；之后继续 `append` **不**影响已返回的 `String`（`build` 走 `_take_buf` 移交，§9.3.3.2）。

§9.4.2.2 修改类方法（`append` / `clear` / `build`）走 §9.2.3.2 的可变性约束——浅不可变 `let` 绑定的 `StringBuilder` 不得调用。

## §9.5 `Rc<T>`

### §9.5.1 形态

§9.5.1.1 `Rc<T>` 是持有 RC 堆对象的强句柄；句柄 layout 为单一指针指向 Block：

```
Block = { rc, payload: T }
```

§9.5.1.2 `Rc<T>` 是不可空类型；可空写 `Rc<T>?`。

§9.5.1.3 类型形参 `T` 不得为借用 `T'&`（§3.2.3.2）。

### §9.5.2 构造

§9.5.2.1 `Rc<T>` 的构造形态：把 `T` 类型值赋给 `Rc<T>` 上下文，编译器**应当**自动堆分配并把 payload 写入 Block。例：`let p Rc<Point> = Point(1.0, 2.0)`。

§9.5.2.2 显式构造走编译器 baked 内置 `rc:<T>(v T) Rc<T>`：分配 RC Block（refcount 头 + payload），把 `v` store 到 payload 位，返回 `Rc<T>` 句柄。例：`let r = rc:<Point>(1.0, 2.0)`。与上下文驱动的隐式装箱（§9.5.2.1）等价。

### §9.5.3 自动解引用

§9.5.3.1 `Rc<T>` 自身**没有**用户可见方法；所有 `box.field` / `box.method(args)` 均自动解引用到 payload `T` 上分发（DRAFT §4.2）。

§9.5.3.2 `box.field = expr`：解引用后字段写，走 §7.4.4 retain-then-release。

§9.5.3.3 `&box`：见 §8.3，结果是 `Rc<T>&`（句柄借用）；`&box.field`：见 §8.3，结果是字段类型的借用。

### §9.5.4 复制与析构

详见 §8。

§9.5.4.1 `Rc<T>` 句柄复制 = retain；归零释放时先析构 payload（按 §7.4），再判断 weak 计数决定 free Block。

§9.5.4.2 `Rc<T>` 之间赋值走 retain-then-release（§8 / §7.4.4）。

### §9.5.5 比较

§9.5.5.1 `Rc<T> == Rc<T>`：解引用后比 payload 内容；payload 类型应当可比较。

§9.5.5.2 地址相等（即"是否同一 Block"）走 `same_ref:<Rc<T>>(a, b)`。

### §9.5.6 保留名

§9.5.6.1 名字 `Arc` 在 v0.X 期间作为内置类型名**保留**，禁止用户重新定义或作为类型名引入。`Arc<T>` 计划为原子 RC（v1.x 多线程主题）；正式引入前使用报错 `E1132`（"未知内置类型"）。`Heap<T>` 已正式落地，见 §9.5a。

## §9.5a `Heap<T>`

### §9.5a.1 形态

§9.5a.1.1 `Heap<T>` 是单 owner 的作用域绑定堆句柄；句柄 layout 为单一指针指向 payload：

```
heap_payload = T   // 无 RC 头，与 Rc 的 Block = { rc, payload: T } 对照
```

§9.5a.1.2 `Heap<T>` 是不可空类型；可空写 `Heap<T>?`（启用 B 档 nullable move + C 档局部 move，§8.3a.4）。

§9.5a.1.3 类型形参 `T` 不得为借用 `T'&`（§3.2.3.2）。**允许**：`Heap<Heap<T>>` 多级嵌套、`Array<Heap<T>>` 数组元素。**禁**：`Rc<Heap<T>>` / `Weak<Heap<T>>` / `Heap<T>` 作 `Rc<U>` 内层字段（共享语义与单 owner 互斥，§8.3a.5.1 / `Exxx3`）。

§9.5a.1.4 **生命传染**：含 `Heap` 子项的复合类型（结构体字段、Array 元素、多级 Heap payload）整体按 Heap 生命计：单 owner、按值禁 copy（按 §7.4.6.6 走可空复合 move）、作用域绑定 free。`Array<Heap<T>>` 因此**不参与** §9.2 普通 Array 的句柄复制 + retain 语义。

### §9.5a.2 构造

§9.5a.2.1 `Heap:<T>(args)` 表达式：runtime `__yux_heap_alloc<T>` 分配 + 调 T 的 ctor，返回 `Heap<T>`。turbofish 可由上下文反推省略。

§9.5a.2.2 `Heap:<T>(p Ptr) Heap<T>` baked FFI 接管形态：从裸指针接管所有权，仅 `extern` / `#FFI` 上下文允许（§8.3a.5.3 / §9.7.2.4）。

§9.5a.2.3 OOM 处理 / ZST / 对齐协议见 `DRAFT-heap-types.md` §9a，待 Phase 0 正式条款落地后回填。

### §9.5a.3 自动解引用

§9.5a.3.1 `Heap<T>` 自身无用户可见方法；`h.field` / `h.method(args)` 自动解引用到 payload `T` 上分发（同 §9.5.3）。

§9.5a.3.2 `h.field = expr`：解引用后字段写，按 T 字段规则（含 §7.4.6 Heap 字段路径）。

§9.5a.3.3 `&h` → `Heap<T>&`（句柄借用）；`&h.field` → 字段类型借用，根 = h；payload 整体借用走 `as_ref:<T>(h) T&`（§8.3.5.5）。

### §9.5a.4 复制与析构

详见 §8.3a。

§9.5a.4.1 `Heap<T>` 非空形态按值禁 move / 禁 copy（`Exxx2`）；作用域出口自动 `__yux_heap_free<T>`。

§9.5a.4.2 `Heap<T>?` 形态：
- **B 档 nullable move**：按值调用时调用点源 slot 写 null（§8.3a.4.2）；
- **C 档 局部 move**：`Heap<T>?` 左值赋值搬移源 slot 写 null（§8.3a.4.4）；
- **A 档 NRVO**：`ret heap_local` 折叠分配 + free 为接管（§8.3a.4.1）。

### §9.5a.5 比较

§9.5a.5.1 `Heap<T> == Heap<T>`：解引用后比 payload 内容；payload 类型应当可比较。

§9.5a.5.2 地址相等走 `same_ref:<Heap<T>>(a, b)`。

## §9.6 `Weak<T>`

### §9.6.1 形态

§9.6.1.1 `Weak<T>` 是指向某 Block 的弱引用；不阻止 payload 析构。v1 **仅配** `Rc<T>`（即 `Weak<Array<T>>` / `Weak<String>` v1 不支持，§3.7）。

§9.6.1.2 `Weak<T>` **原生可空**：自带"空 / 已失效"状态；`Weak<T>?` 在语义层禁（§3.6.5.3 / §3.7）。

### §9.6.2 构造

| 形态 | 说明 |
|---|---|
| `Weak(box Rc<T>?)` | 传 `null` 得空 weak；传活 box 绑定并 retain weak 计数 |
| `weak:<T>(box Rc<T>?) Weak<T>` | 编译器 baked，与构造函数等价 |

§9.6.2.1 含 `Weak<T>` 字段的结构体在构造时**应当**显式给定初值（如 `Weak(null)`），DAA 不为其提供豁免（§7.3.3.4）。

### §9.6.3 方法

| 方法 / 内置 | 形参 | 返回 | 说明 |
|---|---|---|---|
| `upgrade(w Weak<T>)` | w | `Rc<T>?` | 强引用还在则返回持值 `Rc<T>?`，已释放或空 weak 返回空 |

§9.6.3.1 `upgrade` 是编译器 baked 内置（也可被视为 `Weak<T>` 上的方法，§10）；其语义见 §8.5。

### §9.6.4 比较

§9.6.4.1 v1 **禁用** `Weak<T>` 上的 `==` / `!=`（§3.7、§8.9）。要比较改走 `same_ref:<Weak<T>>(a, b)`（地址相等）或先 `upgrade` 后比 payload。

## §9.7 `Ref<T>` 与 `Ptr`

### §9.7.1 `Ref<T>`

§9.7.1.1 `Ref<T>` 是不可空原始指针的内置泛型形态，主要用于 SDK / FFI 边界。在用户代码中**应当**优先使用 `T&` 借用（§8.3），而非 `Ref<T>`。

§9.7.1.2 `Ref<T>` 不参与 RC；其寿命由用户保证。

§9.7.1.3 v1 不强制 `Ref<T>` 与 `T&` 互转规则；典型实现把 `T&` 编译落地为同形态指针，但规范层视它们为不同类型。

### §9.7.2 `Ptr`

§9.7.2.1 `Ptr` 等价于 C 的 `void*`：**无泛型参数**，仅 FFI 边界使用。不引入 `Ptr<T>` 泛型形态（对齐等问题，统一当 `void*` 用）。

§9.7.2.2 `Ptr` 类型变量可赋 `null`，是 yux 中**唯一**接受 `null` 字面量的非 Nullable 上下文（其余 `null` 应当出现在 `T?` 上下文，§3.6.1.3）。v1 **不**将 `Ptr` 归入 `T?` 体系：`Ptr` 本身即 C `void*`（可空），写 `Ptr?` 无意义。

§9.7.2.3 `T&` / `Rc<T>` / `Array<T>` / `String` / `Weak<T>` 作 `extern fn` 实参传给 `Ptr` 形参时**自动转换**（§3.4.2.6）。这是规范层唯一的隐式跨档位转换。

§9.7.2.4 显式转 `Ptr` 走编译器 baked 内置 `ptr_of:<T>(obj)`（§8 / §10）：

| 源类型 T | 结果指向 | 备注 |
|---|---|---|
| `U&` | U | 短寿命；C 端不可保存超出本次调用 |
| `Rc<U>` | U payload | 跳过 RC 头 |
| `Heap<U>` | U payload | 偏移 0；**交出所有权**，源 slot 标 moved_out（§8.3a.5.3） |
| `Array<U>` | 元素首地址 | |
| `String` | 码点首地址 | 不带 NUL 终止 |
| 内置标量 | — | **不**允许 |

§9.7.2.5 `Ptr` 算术（偏移 / 加减）**仅 SDK 内**可用；普通用户代码出现 Ptr 算术**应当**编译报错。v1 以私有函数 `_ptr_offset` 替代注解 / 路径白名单（§8.7.4.5 / E6023）。

§9.7.2.6 `Ptr` 没有成员方法、不参与析构。

## §9.8 `Nullable<T>` / `T?`

§9.8.1 `T?` 是语法糖，由编译器解糖为 SDK 提供的 `Nullable<T>` 结构体（§3.6.1）。

§9.8.2 方法（§3.6.2）：

| 方法 | 返回 | 说明 |
|---|---|---|
| `has()` | `bool` | 是否持值 |
| `get()` | `T` | 取出内层值；为空时调用 `_exit(1)` 终止 |

§9.8.3 表达式 `??` / `?.` 见 §4.6。

§9.8.4 内层类型 `T` 可以是堆句柄；`Rc<T>?` / `Array<T>?` / `String?` 合法（§3.6.5）。`Weak<T>?` 在语义层禁（§3.6.5.3）。

## §9.9 固定大小数组 `[T * N]`

§9.9.1 `[T * N]` 是值类型的固定长度数组，`N` 是编译期常量整数；存储在栈上 / 嵌入结构体内。

§9.9.2 构造形态：

| 形态 | 说明 |
|---|---|
| `[e1, e2, ..., eN]` | 元素逐项给定，长度 / 类型须匹配 |
| `[v ...]` | 用 `v` 填充整个数组 |
| `[v ... T]` | 显式指定元素类型 |

§9.9.2.1 字面量类型应当与目标元素类型一致（§3.4.2.4 / §3.4.2.5）。

§9.9.3 `a[i]` 返回 `T&`（同 `Array<T>`，语义等价于 `a.get(i)`）；`a[i] = expr` 为索引赋值（等价于 `a.set(i, expr)`）；越界由实现决定（v1：终止）。

§9.9.4 `[T * N]` 是值类型，按值复制；与 `Array<T>` 在传参 / 字段位置语义不同（§3.2.2 末段）。

§9.9.5 元素类型 `T` 不得为借用 `T'&`。

## §9.10 内置类型方法表的查找

§9.10.1 内置类型上的方法（如 `i32.to_string`、`Array<T>.push`）由编译器内部表与 SDK 协同提供：编译器内部实现的标记为 `#Builtin`；SDK 提供的随 `core/base.yux` 一同编译。

§9.10.2 用户**不得**对内置类型新增方法或重载运算符（§7.2.3.5）。v1 **不**引入 `extension`；设计窗口见 §12（扩展实现块 / `extend`）。
