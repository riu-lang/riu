# §5 语句与控制流

本章规范 yux 的语句（`statement` 产生式）与控制流构造的语义，包括变量声明、赋值、`if` / `loop`、`ret` / `break`，以及作用域与析构序。语法形态见 §2 / [附录 B §B.7](附录B-语法汇总.md#b7-语句)；与所有权 / RC 相关的细节见 §8。

## §5.1 声明语句

### §5.1.1 局部变量声明

§5.1.1.1 三种声明关键字：

| 关键字 | 可变性 | 允许位置 | 须显式类型？ |
|---|---|---|---|
| `var` | 可重赋值 | 局部 | 仅当无初始化时 |
| `val` | 仅一次赋值 | 局部 / 参数（默认） | 仅当无初始化时 |
| `cval` | 编译期常量 | 顶层（§5.1.4）/ 局部（§5.1.5） | 须 |

§5.1.1.2 形态（产生式 `statementDeclare` / `statementDeclareAssign`）：

```
DeclKey ID type codeLineEnd                    # 无初始化
DeclKey ID typeWithRef? '=' expr codeLineEnd   # 带初始化（类型可省）
```

§5.1.1.3 无初始化声明**应当**显式标注类型；类型推断仅在带初始化形态启用。

§5.1.1.4 带初始化形态可省略类型，由 `expr` 推断（§3.4 / §3.5）。整数 / 浮点字面量缺省靶向类型分别为 `i32` / `f64`（§1.6.1.2 / §1.6.2.3）。

### §5.1.2 `var` 与 `val` 的差异

§5.1.2.1 `val` 声明的变量在其作用域内**至多赋值一次**，包括以下两种合法形态：
- 带初始化：`val x i32 = 1`，初始化即唯一赋值。
- 先声明后赋值：`val x i32` 后 `x = 1`；后续再 `x = 2` 属编译期错误。

§5.1.2.2 `var` 声明的变量可任意重赋值，受 §5.2 赋值规则约束。

§5.1.2.3 `val` 与 `var` 在所有权 / RC 行为上**没有**差异：堆句柄类型（`Rc<T>` 等）的复制 / 析构语义不因可变性变化（§8.5）。

### §5.1.3 借用类型变量 `T&`

§5.1.3.1 局部 `T&` 变量**应当**带初始化（产生式 `statementDeclareAssign`）：

```yux
var c i32 = 1
var d i32& = &c          ; ✅
var e i32&               ; ❌ 编译期错误：T& 应当初始化
```

§5.1.3.2 `T&` 变量声明后**不得**重指向：`d = 3` 改的是被引对象（`c` 变 3），不是 `d` 自己（详见 §8.3.3）。

§5.1.3.3 从已有 `T&` 复制绑定时**不**写 `&`：

```yux
var d2 i32& = d          ; ✅ d2 与 d 绑同一目标
var d3 i32& = &d         ; ❌ T& & 由 §2.6.1 拒绝
```

§5.1.3.4 `T&` 的源对象寿命约束见 §8.4。

### §5.1.4 `cval` 全局常量

§5.1.4.1 `cval` 在顶层声明（产生式 `globalConst`），形态 `cval NAME T = literal`。

§5.1.4.2 初始值**应当**为 `literal`（含 `literalObj` 引用其它已定义 `cval`），不接受任意表达式；这保证编译期确定值。

§5.1.4.3 `cval` 的可见性遵循 §10：以 `_` 起始者为模块私有。

§5.1.4.4 `cval` 的类型**不得**含 `T&`（§3.7）。

### §5.1.5 `cval` 局部常量

§5.1.5.1 局部 `cval` 经 `statementCvalDeclAssign` 引入（[附录 B §B.7](附录B-语法汇总.md#b7-语句)），形态：

```
'cval' ID typeWithRef '=' expr codeLineEnd
```

§5.1.5.2 局部 `cval` 与 `val` 在重赋约束上等同（§5.2.1：不可赋值），与顶层 `cval`（§5.1.4）在初值约束上等同；但允许出现在函数体 / 任意 `statementBlock` 内，作用域、析构序按 §5.7 计算。

§5.1.5.3 初值表达式**应当**为可在编译期求值的常量表达式。v1 接受集合：

- 数值 / `bool` / `null` / 字符串 / `codePoint` 字面量；
- 对已声明的 `cval`（局部或全局）的名字引用；
- 由上述操作数经一元 `-` `~` `!`、二元 `+` `-` `*` `/` `%`、位 `&` `|` `^` `<<` `>>`、比较 `==` `!=` `<` `<=` `>` `>=`、逻辑 `&&` `||`、括号包裹组成的复合表达式。

§5.1.5.4 v1 **不**接受堆构造（`Rc` / `Array` / `String` 等）、结构体构造、任何函数 / 方法调用、字段访问、数组下标、`if`/`match` 等控制流表达式作为 `cval` 初值。违反者编译期报 `E3104`（附录 D §D.3.3）。

§5.1.5.5 `cval` 局部声明**应当**显式带类型（产生式形态如此）；类型推断不在 v1 启用。

§5.1.5.6 `cval` 局部不参与 RC（v1 允许的初值集合不构成堆句柄）。

> *Informative*：`#Const fn` 的调用形态当前**不**纳入 `cval` 初值集合；该扩展属未来阶段（参考 [draft/DRAFT-const-mut.md](draft/DRAFT-const-mut.md) §3.3 P4 备注）。

## §5.2 赋值语句

### §5.2.1 `statementAssign`

§5.2.1.1 形态：

```
(ID | '$') ('.' ID)* opAssign expr codeLineEnd
```

即左值仅限：
- 局部 `var` 变量（`val` / `cval` / 形参 / `#Frozen` 形参均不可赋值，违反者报 `E3093`）；
- `$.field` / `$.f.g` 字段链；
- `id.f` 字段链（`id` 为局部 `var` 或形参中**包含**可变路径的变量）。字段写另受 §7.1.4（`#Val` / `#Frozen` 字段）与 §6.2.2a（`#Frozen` 形参）约束。

§5.2.1.2 `opAssign` 集合（参见 [附录 B §B.6](附录B-语法汇总.md#b6-表达式按-yuxg4-中-expr-的分支顺序决定优先级)）：`=` `+=` `-=` `*=` `/=` `%=` `<<=` `>>=`。

§5.2.1.3 复合赋值 `a OP= b` 等价于 `a = a OP b`，但 `a` 仅求值一次（保证副作用顺序）。

### §5.2.2 类型与 RC 协议

§5.2.2.1 RHS 类型须可赋值给 LHS 类型（§3.4.2）。

§5.2.2.2 当 LHS 类型含堆句柄字段时，赋值按 §8.5.4 的 **retain-then-release** 顺序执行：先 retain RHS 的句柄，再 release 旧 LHS 的句柄。这保证 `a = a` 或别名情形不会读到已释放对象。

§5.2.2.3 `T&` 形态的 LHS（`var d T& = ...; d = expr`）：`expr` 为同种类型的值，赋值修改的是**被引对象**，不重指向 `d`。

### §5.2.3 索引赋值 `statementSet`

§5.2.3.1 形态：

```
expr '[' expr (',' expr)* ']' '=' expr codeLineEnd
```

§5.2.3.2 `obj[args] = value` 是 `obj.set(args, value)` 的语法糖；语义按 §4.8（调用语义）。

§5.2.3.3 v1 不支持复合赋值索引（`arr[i] += 1` 不在产生式范围）；如需要则展开为 `arr[i] = arr[i] + 1`。

## §5.3 表达式语句

### §5.3.1 形态

```
expr SymbolSemicolon? codeLineEnd
```

§5.3.1.1 表达式语句即"求值并丢弃结果"。

§5.3.1.2 尾随 `;` 表示**显式按空类型丢弃**：

- 在普通函数体中等价于无 `;` 的形态。
- 在结构体方法 / 块形 `if` 表达式上下文中，尾随 `;` 表示**该块整体不产出值**（语句形 `if`），无 `;` 的最末表达式语句的值即为块的值（§4.9.3.2 / §5.4.4）。

### §5.3.2 表达式语句的临时值

§5.3.2.1 表达式语句结束（`codeLineEnd` 处）即触发临时值清单清算（§4.1.2 / §8.6）：所有未消费的堆句柄临时值在该语句末尾 release。

## §5.4 `if` / `elif` / `else`

### §5.4.1 形态总览

`yux.g4` 的 `if` 有三种产生式（均归类为表达式 `expr`，§4.9）；按是否取值与是否单行划分：

| 形态 | 产生式 | 用途 |
|---|---|---|
| `if c { a } else { b }` | `exprOneLineIfElse` | 单行表达式 |
| `a if c else b` | `exprIfElsePreValue` | Python 风三元 |
| `if c block (elif ... )* (else ...)?` | `exprIfElse` | 块形 |

§5.4.1.1 三种形态均可作为**表达式**使用；当作为**语句**使用时归入 `statementExpr`，由 `codeLineEnd` 终结。

### §5.4.2 条件类型

§5.4.2.1 `cond` 类型**应当**为 `bool`。`i32` / 指针 / `T?` 不会自动转 `bool`；如需"非空"判定写 `nx.has()`。

### §5.4.3 分支类型一致性

§5.4.3.1 当 `if` 整体作为表达式使用时（赋给变量、作为另一表达式的子项、作为 `ret` 实参）：

- 各分支的"值"类型应当一致（§4.9.1.2）。
- `else` 分支**应当**存在；否则在 `cond` 为 `false` 时整体无值，属编译期错误。

§5.4.3.2 当 `if` 整体作为语句使用时（独立成语句，结果被丢弃）：

- 各分支的"值"类型不必一致；可省 `else`。
- 各分支体内的语句执行后即终结，不向外回传值。

### §5.4.4 块的值

§5.4.4.1 `statementBlock` 作为 `exprIfElse` 子块时，其"值"为：

- 块末尾最后一条 `statementExpr`（**不**带尾随 `;`）的值；
- 若末尾 `statementExpr` 带尾随 `;`，或末尾是其它 statement（赋值、`ret` 等），则该块产出空类型。

§5.4.4.2 含 `ret` 的分支不参与"值类型一致性"检查，因为该路径不会到达汇合点。

## §5.5 `loop` 与 `break`

### §5.5.1 `loop`

§5.5.1.1 形态：`loop statementBlock`。`loop` 是**无限循环**；唯一退出方式为：
- 循环体执行 `break;`；
- 循环体执行 `ret expr` / `ret;`（直接返回外层函数）。

§5.5.1.2 v1 **不**支持 `while` / `for` / 计数循环；按需用 `loop` + `break` 编写。

§5.5.1.3 `loop` 不是表达式，不产生值；仅出现在语句位置。

### §5.5.2 `break`

§5.5.2.1 形态：`break ';' codeLineEnd`。**应当**尾随 `;`（产生式 `statementBreak` 强制）。

§5.5.2.2 `break` 终止**最近一层** `loop`；v1 不支持带标签 break、不支持 `break expr` 形态。

§5.5.2.3 `break` 在非 `loop` 内部使用属编译期错误。

§5.5.2.4 v1 **不**支持 `continue`：`yux.g4` 未定义 `Continue` 关键字（附录 A 当前文本与 g4 不一致，待 Phase 5 修订）。如需"跳到下次迭代"以 `if` 包住其余循环体即可。

### §5.5.3 析构与 `break` / `ret` 的交互

§5.5.3.1 当 `break` 或 `ret` 触发提前退出时，从当前点回溯到目标作用域之间的所有局部变量按**声明逆序**析构（§5.7）。

§5.5.3.2 局部变量持有的堆句柄在析构时按字段级 release（§8.5.5）。

## §5.6 `ret`

### §5.6.1 两种形态

| 产生式 | 形态 | 用途 |
|---|---|---|
| `statementRet` | `ret expr codeLineEnd` | 带值返回 |
| `statementRetVoid` | `ret ';' LineEnd` | 空返回 |

§5.6.1.1 `ret expr`：`expr` 类型须可赋值给函数声明的返回类型（§3.4.2 / §6.3）。

§5.6.1.2 `ret;`：函数返回类型**须**为空（即 `fnHeader` 未声明 `retType`）；尾随 `;` 强制以避免与 `ret expr` 解析歧义。

§5.6.1.3 `ret;` 后只能跟 `LineEnd`，**不**接受 `LineEndComment`（产生式如此）。

### §5.6.2 返回值与所有权

§5.6.2.1 当返回类型为堆句柄类型（`Rc<T>` / `Array<T>` / `String` / `Weak<T>`）时，`ret expr` 触发 **move-return**：编译器对 `expr` 一律生成 retain；所有分支汇聚后净效果为 `+1` 给调用方；callee 末尾的析构 release 自然抵消（详见 §8.5.3）。

§5.6.2.2 返回 `T&` 形态由 `fnHeader` 直接禁（§2.6.3）。

§5.6.2.3 函数体未到达 `ret` 即落到末尾时，若返回类型非空属编译期错误。

### §5.6.3 表达式体函数

§5.6.3.1 形态 `fn f(...) T = expr` 等价于 `fn f(...) T { ret expr }`，但语法上**不**写 `ret`（详见 §6.1）。

## §5.7 作用域与析构

### §5.7.1 作用域单元

§5.7.1.1 yux 中产生新作用域的语法构造：

- 函数体（`fnBlockBody` / `fnExprkBody`）；
- `statementBlock`（`if` / `elif` / `else` / `loop` 的体）；
- 单行 `if-else`、Python 风三元的真值 / 假值表达式（其中临时值寿命延伸至所在语句边界，不形成独立作用域）。

§5.7.1.2 同名遮蔽：内层作用域的 `var` / `val` 可以与外层同名，遮蔽期内访问内层；遮蔽不影响外层 `T&` 的寿命计算（§8.4）。

### §5.7.2 析构序

§5.7.2.1 作用域结束时，该作用域内**显式声明**的局部变量按**声明逆序**析构。

§5.7.2.2 函数形参视为函数体最外层作用域的局部变量；末尾析构序为：先函数体内局部（最深至最浅、声明逆序），再形参（声明逆序）。

§5.7.2.3 临时值在所在语句 / 表达式边界 release，不进入作用域析构序（§4.1.2 / §8.6）。

§5.7.2.4 析构对每个变量执行 §8.5.5 的字段级 release：平凡类型按位丢弃，非平凡类型按构造逆序逐字段 release。

### §5.7.3 控制流提前退出

§5.7.3.1 `break` / `ret` 触发的提前退出沿 §5.5.3.1 的逆序析构，跨越的作用域逐层执行析构序。

§5.7.3.2 异常退出（v1 不支持异常）—— 不在规范范围。
