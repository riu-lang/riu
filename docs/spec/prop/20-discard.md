## 提议

`_` 只表示「这里有一个槽，不要名字」。可重复、不绑定、不能当表达式读。只允许出现在**字段名**和**变量名**（含形参、局部 `let`、元组解构、for-in 循环变量、match 载荷绑定）。**不能**当类型名、函数名、以及其它声明名。

### 现状

今天写 `struct Foo { _ u32 }` 或 `fn f(_ i32)` 会得到一个叫 `_` 的私有字段 / 形参：可 `s._`、要唯一、进符号表。C 头里的 reserved / padding / 故意忽略的实参没法干净表达。未使用的 `let` / 形参也没有「明确丢掉」的写法（v1 也还没有未使用警告，但绑定仍占名）。

### 允许的位置

槽在布局 / ABI / 控制流上存在，名字 `_` **不**进符号表：

| 位置 | 作用 |
|---|---|
| 实例字段 | 占布局；可重复；字面量不必写，隐式零填 |
| `fn` / 方法 / `extern fn` / lambda 形参 | 占 ABI 槽；调用处仍须按位传实参，不能省略 |
| 局部 `let` / `#Mut let` 等 | 求值 RHS（及副作用）后丢掉 |
| 元组解构 `let (_, y) = pair` | 该元素丢掉 |
| `for _ in xs` | 只要遍历副作用 / 次数，不要元素 |
| match 载荷 `E::V(_)` / `E::V(_, y)` | 丢掉该载荷槽 |

同一列表里多个 `_` 互不冲突。`fnParamGroup` 可以 `fn f(_, _ i32)`。

```riu
struct Pad {
  a u32
  _ u32
  _ [u8 * 2]
  b u16
}

extern {
  fn WriteFile(hFile Ptr, lpBuffer Ptr, n u32, written Ptr, _ Ptr) i32
}

fn ignore(x i32, _ bool, _ Ptr) {
  let _ = x + 1
  let (_, keep) = (1, 2)
}
```

字段字面量：有名字段仍须全覆盖（§7.3.2.2）；所有 `_` 字段**不必**出现，隐式按类型零填（标量 0、`Ptr` `null`、嵌套 struct 递归零填、`[T*N]` 元素零填）。这是「字段无默认值」（§7.3.3.2）的**唯一**例外，且只针对丢弃字段。显式写出 `. _ = expr` **不准**（没有叫 `_` 的字段名）。

单字段简写 §7.3.2.4：只计**有名**实例字段。结构体若除 `_` 外恰好一个有名字段，仍可 `Type{ expr }`。全是 `_`、零个有名字段 → 仍 E3129（没有可填的名字段）。

### 禁止的位置

恰好 `_` **不得**作为下列声明的名字（新诊断）：

- `struct` / `enum` / `#Spec` / `type` 别名
- `fn`（顶层、方法、`#Static fn`、`extern` 声明名）
- 全局 `let` / `#Cval` / `#Mut` 全局
- 静态字段
- 类型形参 `struct Foo<_>` / `fn f<_>`
- `use` 别名（含 `as _`）
- 模块 / 包名（文件名、`pkg` 项）

`_` 不是标识符，不适用 §10.3.2 私有规则：它没有「当前模块可见」的符号。

表达式里写裸 `_`、`s._`、`$. _`、`._ =`、取地址 `&s._` → 诊断（没有这个名字）。反射 `T::fields` **不**收录 `_` 字段（布局里仍在，只是无名）；`Field.value` 改写不到它们。

`_` 字段若类型需要释放，字段级 drop（现行 §7.4 / 将来 [#18](18-drop-spec.md)）仍按声明逆序走到该槽。padding 一般都是标量，no-op。

### 与 match 兜底

穷尽 match 的兜底臂仍是 `else`（已有决议）。`_` **不是**通配模式、不能 `match x { _ => ... }` 代替 `else`。只允许在**已写出的变体载荷**里丢槽：`Color::Rgb(_, _, b)`。

### 改为

1. 恰好 `_` = 丢弃槽：字段 / 变量类绑定位合法；可重复；不进符号表。
2. 其它声明名一律非法。
3. 不能读、不能写名字、不能当表达式。
4. `_` 字段字面量可省略并零填；`extern` / 普通调用的 `_` 形参不能省实参。
5. `_foo` 仍是私有名。不改 bnf。match 通配不做。

## 评估

- 赞成：
  - 和 C 的 reserved 参数、padding 字段、Go/Rust 的 `_` 丢弃同类，但收在「字段 / 变量」两档，避免 `_` 变成第二种通配语法。
  - 不改词法：非法位置用语义诊断，比把 `_` 加成关键字干净。
  - 字面量省略 `_` 字段，生成的 packed 结构才写得动；有名字段仍全覆盖，不会变成「随便缺字段」。
- 反对：
  - 零填是默认值的口子，必须写死「仅 `_` 字段」。有名字段继续禁默认值。
  - 无未使用警告时，`let _ = expr` 看起来像多余语法；有警告之后才刚需。现在就做，是为 FFI pad / 忽略形参，不是为警告。
- 未决：无（match 通配明确不做；载荷 `_` 做。for-in / 元组做。）

## 规范要点

- `_` 仅字段名与变量名（形参、局部 let、元组槽、for-in、match 载荷）。可重复、不绑定。
- 禁止：类型 / 函数 / 全局 / 静态字段 / 类型形参 / use 别名 / 模块名；禁止表达式与 `s._`。

- `_` 形参：调用仍按位传值。
- `_foo` 仍 §10.3.2 私有。match 兜底仍 `else`。
- 不做：`_` 通配模式、`_` 作类型/函数名、把 `_` 改成关键字、改 bnf。
