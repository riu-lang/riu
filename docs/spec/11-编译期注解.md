# §11 编译期注解

本章规范 yux 的编译期构建注解（build annotation）：在声明前以 `#Name` 形式附加的编译期语义标签。v1 注解仅供编译器内部使用，**不**支持用户自定义。

## §11.1 语法

### §11.1.1 形态

```
buildAnno ::= '#' ID codeLineEnd
```

§11.1.1.1 每条注解单独一行，以 `#` 开头，后跟标识符 `name`，再跟换行（含可选行尾注释）。

§11.1.1.2 注解**应当**紧贴声明出现：声明前可有零或多条 `buildAnno`，相邻注解共享同一目标声明。

### §11.1.2 可附着位置

§11.1.2.1 由 `yux.g4` 在产生式层规定的可附着位置：

| 位置 | 产生式 |
|---|---|
| 顶层函数 | `fn` |
| 函数头（`extern` 块内） | `fnHeader` |
| 结构体声明 | `structDecl` |
| 结构体方法块 | `structImpl` |
| 全局常量 | `globalConst` |
| `extern` 块本身 | `externDecl` |

§11.1.2.2 在上述位置之外出现 `#Name` **应当**视为语法错误。

§11.1.2.3 结构体方法块内的方法（`fn`）也接受注解，规则与顶层 `fn` 一致。

### §11.1.3 未知注解

§11.1.3.1 注解名 `name` 不在 §11.2 / §11.3 列表中时，编译器**应当**编译报错。v1 不引入"宽容未知注解"模式。

§11.1.3.2 注解**没有**参数：`#Name(args)` / `#Name = value` 形态在 v1 不接受。

## §11.2 `#CompilerInner`

### §11.2.1 语义

§11.2.1.1 `#CompilerInner` 标记声明体由**编译器内部合成实现**，源代码层不提供函数体或结构体字段。

§11.2.1.2 用在 `struct` 上：

- 表示该结构体是编译器认识的内置类型（如 `i8 / u8 / .. / f64 / bool` 占位声明）；
- 编译器**不**为其生成 LLVM 结构体字段；其内存形态由编译器内部表给出。

§11.2.1.3 用在 `fn` / 方法上：

- 该函数 / 方法**应当**省略函数体；
- 编译器在调用点直接合成实现（典型：基础类型转换 `to_i32` / `to_f64` / `to_string`、`upgrade` / `weak` / `same_ref` / `ptr_of` / `rc_leak_count` 等内置）。

### §11.2.2 互锁规则

§11.2.2.1 带 `#CompilerInner` 的函数 / 方法**应当**省略函数体。

§11.2.2.2 函数 / 方法头省略函数体时**应当**带 `#CompilerInner`（除 `extern fn` 外）；否则编译器**应当**报错。

§11.2.2.3 用户代码**不得**使用 `#CompilerInner`：该注解仅 SDK `base.yux` 与编译器内部约定下使用。Open Issue：是否提供路径白名单显式限制。

### §11.2.3 与 SDK 的关系

§11.2.3.1 `base.yux` 中内置类型（`i8`–`u64`、`f32` / `f64`、`bool`）的占位 `struct` 声明与对应的 `to_<type>` 方法都标 `#CompilerInner`；编译器据此跳过源码编译并合成 LLVM IR 指令（整数扩展 / 截断、浮点转换、比零等）。

§11.2.3.2 内置 builtin 函数（`upgrade` / `weak` / `same_ref` / `ptr_of` / `rc_leak_count` / `_ptr_offset`）也**应当**通过 `#CompilerInner` 在 `base.yux` 中给出签名占位（§8 / §9.10）。

§11.2.3.3 §10.4 的 SDK / 编译器版本绑定也涵盖 `#CompilerInner` 声明：增减或改签名**应当**同步重 build SDK。

## §11.3 其他注解

### §11.3.1 v1 注解集合

v1 已落地的注解：

| 注解 | 适用位置 | 语义 | 章节 |
|---|---|---|---|
| `#CompilerInner` | `struct` / `fn` / 方法 | 编译器合成实现 | §11.2 |

§11.3.1.1 v1 仅有 `#CompilerInner` 一种正式注解；其它注解形态属预留（§11.3.2）。

### §11.3.2 预留注解（informative）

§11.3.2.1 `extern` 块的 `buildAnnos` 在语法层已预留，未来**可以**用于指定链接库（如 `#Link("kernel32")`）。v1 接受语法但**不**赋予语义；用户**不应**写出。

§11.3.2.2 全局常量 `cval` 的 `buildAnnos` 在语法层已预留；v1 不赋予语义。

§11.3.2.3 候选未来注解（Open Issue）：

- `@sdk_only`（限定 `Ptr` 算术等仅 SDK 可用，§8.7.4.5 当前以 `_` 前缀私有函数替代）；
- `#Inline` / `#NoInline`；
- `#DebugOnly` / `#TestOnly`。

## §11.4 用户自定义注解

§11.4.1 v1 **不**支持用户自定义注解：未在 §11.2 / §11.3 列表中的 `name` 一律编译报错（§11.1.3.1）。

§11.4.2 引入用户自定义注解需先解决：

- 注解可见性（跨模块识别）；
- 注解参数的字面量子集与求值时机；
- 注解作用域（声明级 vs 表达式级）；
- 与 `extern` 链接、SDK 标记的命名空间冲突。

§11.4.3 该方向 Open Issue 跟踪在本章末尾。

## Open Issues

- 用户自定义注解的引入路径（§11.4）。
- `#Link("...")` 等 `extern` 链接库注解（§11.3.2.1）。
- `Ptr` 算术 `@sdk_only` 标记机制（§8.7.4.5）。
- 注解参数语法（`#Name(arg1, arg2)`）的设计窗口。
- 表达式级注解（如 `#assume(cond)`）的可行性。
