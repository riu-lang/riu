# §11 编译期注解

本章规范 yux 的编译期构建注解（build annotation）：在声明前以 `#Name` 形式附加的编译期语义标签。v1 注解仅供编译器内部使用，**不**支持用户自定义。

## §11.1 语法

### §11.1.1 形态

```
buildAnno ::= '#' ID ( '(' annoArg ')' )? codeLineEnd
annoArg   ::= ID genericDef? | INT | FLOAT | STR | type
```

§11.1.1.1 每条注解单独一行，以 `#` 开头，后跟标识符 `name`，可选携带**单参数** `(annoArg)`，再跟换行（含可选行尾注释）。`annoArg` 与 `yuxParser.g4` 对齐：`ID`（含 turbofish `<T>`）、整数 / 浮点数字面量、无插值 `"..."` / `r"..."`、完整 `type`。`#Impl(D)` / `#CName(...)` 用此槽。多参数 `#Name(a, b)` 与命名参数 `#Name(k=v)` / `#Name = value` 在 v1 不接受。

§11.1.1.2 注解**应当**紧贴声明出现：声明前可有零或多条 `buildAnno`，相邻注解共享同一目标声明。

### §11.1.2 可附着位置

§11.1.2.1 由 `yux.g4` 在产生式层规定的可附着位置：

| 位置 | 产生式 | 形态 |
|---|---|---|
| 顶层函数 / struct body 内方法 | `fn` / `fnHeader` | `buildAnno` |
| 结构体声明 | `structDecl`（含 `#Spec struct`） | `buildAnno` |
| 结构体字段（含静态字段） | `filedDecl` | `buildAnno` |
| `extern` 块本身 | `externDecl` | `buildAnno` |
| 函数形参 | `fnParamStd` / `fnParamGroup` | `paramAnno`（零参槽，`LineEnd?`） |
| 全局 `let` | `letGlobal` | `letAnno`（零参槽） |
| 局部 `let` | `statementLet` / `statementLetTuple` | `letAnno`（零参槽，inline） |

§11.1.2.2 在上述位置之外出现 `#Name` **应当**视为语法错误。v1 **不**引入表达式级注解（如 `#assume(cond)`）。

§11.1.2.3 struct body 内的方法（`fn`）也接受 `buildAnno`，规则与顶层 `fn` 一致。

### §11.1.3 未知注解

§11.1.3.1 注解名 `name` 不在对应位置的白名单中时，编译器**应当**报错：`buildAnno` → [E2005]；`letAnno` → [E3112]；字段 → [E3108]；参数 → [E3105]。v1 不引入"宽容未知注解"模式，也不支持用户自定义注解（§11.15）。

§11.1.3.2 语法层 `annoArg` 形态见 §11.1.1.1。各注解是否允许带参由该注解条款规定：零参注解带括号、或缺参的单参注解，报 [E2005]。多参数与命名参数在 v1 不接受。

## §11.2 `#Builtin`

### §11.2.1 语义

§11.2.1.1 `#Builtin` 标记声明体由**编译器内部合成实现**，源代码层不提供函数体或结构体字段。

§11.2.1.2 用在 `struct` 上：

- 表示该结构体是编译器认识的内置类型（如 `i8 / u8 / .. / f64 / bool` 占位声明）；
- 编译器**不**为其生成 LLVM 结构体字段；其内存形态由编译器内部表给出。

§11.2.1.3 用在 `fn` / 方法上：

- 该函数 / 方法**应当**省略函数体；
- 编译器在调用点直接合成实现（典型：基础类型转换 `to_i32` / `to_f64` / `to_string`、`upgrade` / `weak` / `same_ref` / `ptr_of` / `rc_leak_count` 等内置）。

### §11.2.2 互锁规则

§11.2.2.1 带 `#Builtin` 的函数 / 方法**应当**省略函数体。

§11.2.2.2 函数 / 方法头省略函数体时**应当**带 `#Builtin`（除 `extern fn` 外）；否则编译器**应当**报错。

§11.2.2.3 用户代码**不得**使用 `#Builtin`：该注解仅 SDK `base.yux` 与编译器内部约定下使用。v1 **不**按源路径白名单强制，也**不**引入 `@sdk_only` 注解；SDK 私有入口走 `_` 前缀（§10.3.2 / `_ptr_offset`，§8.7.4.5）。

### §11.2.3 与 SDK 的关系

§11.2.3.1 `base.yux` 中内置类型（`i8`–`u64`、`f32` / `f64`、`bool`）的占位 `struct` 声明与对应的 `to_<type>` 方法都标 `#Builtin`；编译器据此跳过源码编译并合成 LLVM IR 指令（整数扩展 / 截断、浮点转换、比零等）。各内置类型的 `to_string` 方法亦由 `base.yux` 内 `Type : ToString { #Builtin fn to_string() String }` 给出（§12.7.1）。

§11.2.3.2 内置 builtin 函数（`upgrade` / `weak` / `same_ref` / `ptr_of` / `rc_leak_count` / `_ptr_offset` / `as_ref` / `copy_of`）也**应当**通过 `#Builtin` 在 `base.yux` 中给出签名占位（§8 / §9.10 / §12.7.3）。其中：

- `as_ref` 含 `Rc<T>` / `Heap<T>` 两形态重载（§8.3.5.5）；
- `ptr_of` 含 `T&` / `Rc<U>` / `Heap<U>` / `Array<U>` / `String` 等源类型重载（§9.7.2.4）；
- `copy_of` 含 `T&` / `Heap<T>&` / `Heap<T>?&` 形态扩展（§8 / `DRAFT-heap-types.md` §6.5）；
- `Heap:<T>(p Ptr) Heap<T>` FFI 接管形态走同一 `#Builtin` 占位机制（§9.5a.2.2）。

runtime 入口 `__yux_heap_alloc<T>` / `__yux_heap_free<T>` 由编译器直接生成调用，**不**走 `#Builtin` 用户签名层；它们与 `__yux_rc_*` 入口同级（§8.2）。

§11.2.3.3 §10.4 的 SDK / 编译器版本绑定也涵盖 `#Builtin` 声明：增减或改签名**应当**同步重 build SDK。

## §11.3 `#Test`

### §11.3.1 语义

§11.3.1.1 `#Test` 标记一个**单元测试函数**，仅在 `yux test` 子命令下被收集与执行；普通 `yux build` **应当**跳过其 codegen，不进入 `.exe` / `.lib` 产物。

§11.3.1.2 `#Test` 仅可附着于 `fn`（顶层函数或 struct body 内方法）。出现在其他位置（`struct` / `extern` / `cval` 等）**应当**编译报错。

### §11.3.2 函数约束

§11.3.2.1 `#Test` 函数的签名**应当**为：无参数列表（`()` 形参列表为空）、无返回类型标注（语义等价 void）。

§11.3.2.2 `#Test` 函数**应当**有函数体；省略函数体**应当**报错（与 §11.2 `#Builtin` 互斥）。

§11.3.2.3 同一函数上 `#Test` 与 `#Builtin` **不得**同时出现。

### §11.3.3 测试文件

§11.3.3.1 `#Test` 函数**应当**只出现在以 `.test.yux` 结尾的源文件中；普通 `.yux` 源文件中出现 `#Test` **应当**编译报错。

§11.3.3.2 `*.test.yux` 文件由 `yux test` 在项目 `src/` 目录下递归发现；普通 `yux build` **应当**完全忽略这些文件（不解析、不 codegen、不参与依赖图）。

§11.3.3.3 测试文件的模块名**应当**取 src 根下相对路径转点分形式，**保留** `.test` 段。例：`<projectRoot>/src/yux/core/arithmetic.test.yux` → 模块 `yux.core.arithmetic.test`。

### §11.3.4 `yux test` 行为（informative）

§11.3.4.1 `yux test` **仅**在项目模式（cwd 含 `yux.toml`）可用；不接受单文件入参。

§11.3.4.2 选择器（informative）：
- `yux test`：当前项目下全部 `#Test`
- `yux test <prefix>`：模块名前缀匹配（例：`yux test yux.core` 命中 `yux.core.*.test`）
- `yux test <module>#<fnName>`：精确匹配模块名 + 函数名

§11.3.4.3 测试编译为独立 DLL（每模块一个 `*.test.dll`）；`yux test` 为每个 DLL 启动一个 `yux-test-runner` 子进程加载并执行。子进程隔离确保一个模块的内存脏化 / 崩溃不影响其他模块的测试。

§11.3.4.4 在单个 DLL 进程内，各 `#Test` 函数顺序执行并由 SEH wrapper 包裹——除零 / AV / `ASSERT_FAILED` 等异常只标记该测试 `FAIL`，继续执行后续测试。严重 SEH（非断言失败的 ACCESS_VIOLATION 等）发生后跳过 `FreeLibrary`（进程状态可能已损坏），直接 `ExitProcess` 由 OS 回收资源。

§11.3.4.5 `yux test -v / --verbose`：默认仅在测试失败时回放该测试的 stdout / stderr；`-v` 时所有测试都回放。

### §11.3.5 测试断言 API

§11.3.5.1 SDK 在 `sdk/yux/src/yux/core/assert.yux`（与 `base.yux` / `math.yux` 同属 `yux.core` 模块的平铺文件）提供四个 `#Builtin` 断言函数；与 §11.2 一致，签名仅作占位，调用时由编译器在调用点合成 IR：

```yux
#Builtin
fn assert_eq<T>(actual T, expected T)

#Builtin
fn assert_true(actual bool)

#Builtin
fn assert_false(actual bool)

#Builtin
fn fail(msg String)
```

§11.3.5.2 `assert_eq` 在 v1 支持以下类型分派：

- 数值与 `bool`：`i8` / `u8` / `i16` / `u16` / `i32` / `u32` / `i64` / `u64` / `f32` / `f64` / `bool` —— 由 `#Builtin` 通过 `compileTestAssertEq` 在调用点合成 ICmp/FCmp + 失败分支。
- `String`：由 `base.yux` 末尾的 yux 实现非泛型重载 `fn assert_eq(actual String&, expected String&)` 提供，体内走 `actual != expected` 触发 `_yux_test_assert_failed()`。dispatcher（`compiler_call.cpp`）在参数严格匹配的非泛型重载存在时**应当**优先选择该重载，绕开 `#Builtin` 泛型路径。

其他类型仍在调用点报 E6030。后续版本**可以**接 `<T : Eq>`（§12.7.4）扩展到用户结构体；v1 不接。

§11.3.5.7 v1 同时提供两个 `String&` 形参的字符串子串断言，以 yux 实现（同 `String` 重载的 dispatcher 路径），位于 `base.yux`：

```yux
fn assert_contains(haystack String&, needle String&)
fn assert_starts_with(s String&, prefix String&)
```

`assert_contains` 调 `String.contains(needle String&)`，`assert_starts_with` 调 `String.starts_with(prefix String&)`，两者都在条件不成立时调 `_yux_test_assert_failed()`。`String.contains` 当 `needle` 为空字符串时**应当**返回 `true`（与 `assert_starts_with("", "")` 一致）。

§11.3.5.3 断言失败语义：

- `assert_eq` 当 `actual != expected`、`assert_true` 当 `actual == false`、`assert_false` 当 `actual == true`、`fail` 在被调用时即视为失败；
- 失败时编译器合成的 IR **应当**：
  1. 调用 SDK 侧普通函数 `_yux_test_assert_failed()`（在 `assert.yux` 中以 yux 实现），其体内调用 Win32 `RaiseException` 抛出自定义异常码 `0xE0FA17ED`；
  2. 该异常由 `yux test` 的 SEH wrapper 捕获并显示为 `FAIL <module>#<fn> (assertion failed)`；先行的 `RUN <module>#<fn>` 行已足以定位失败位置。
- v1 **不**额外打印断言种类（`assert_eq` vs `assert_true` 等）或 `fail(msg)` 的实参文本：fail 的 `msg` 在 v1 仅用作源码自文档，运行时不输出。后续版本（与 §11.3.5.4 的 stringify 扩展同期）**可以**加上 `assertion failed at <file>:<line>: <kind>` 行。

§11.3.5.4 失败信息**不**打印实参的具体值（v1 限制：泛型 `T` 不要求 `to_string`）。v1 **不**引入独立 `Stringify` spec（§12.7.4.3）。后续版本**可以**在已有 `ToString` 或新约束上追加 `actual = ... / expected = ...` 行。

§11.3.5.5 这些函数**应当**只在 `*.test.yux` 文件内调用；在普通 `.yux` 文件中调用属于"调用 SDK `#Builtin` 函数"——v1 不主动拦截（与现有 `rc_leak_count` / `same_ref` 一致），但 SEH wrapper 不在普通 `yux build` 产出的 `.exe` 内，调用结果是直接异常退出，无诊断输出。

§11.3.5.6 这些函数**应当**与 §11.3.2 中的 `#Test` 函数签名约束兼容：`#Test` 函数无返回值、无参数，但其函数体内调用 `assert_*` / `fail` 不破坏该约束。

## §11.4 `#Spec` / `#Impl`

spec-unify v1（2026-05-19）以 `#Spec` 顶行注解 + `#Impl(D)` 顶行注解替代旧 `draft` 关键字与 `Type : D { ... }` 外置实现块。本节给出注解层规则；语义详见 §12。

### §11.4.1 `#Spec`

§11.4.1.1 `#Spec` 把一个 `structDecl` 转为一个 **spec**（接口契约，§12.1）。

§11.4.1.2 `#Spec` 仅可附着于 `structDecl`；附着于 `fn` / `extern` / `let` / 字段 / 参数等其它位置**应当**报 `E1110`。

§11.4.1.3 `#Spec` **不接受参数**（形态 `#Spec`，无 `(arg)` 槽）。

§11.4.1.4 `#Spec` 与 `#Impl(D)` **不得**在同一声明上共存（spec 自身不实现别的 spec）；违反报 `E1110`。

§11.4.1.5 `#Spec struct` body 内：

- 方法**禁带函数体**（`= expr` / `{ ... }` 两形均拒）；违反报 `E1139`。
- 字段、静态工厂（`#Static fn` 返回 `Self`）、析构 `fn ~()` 均**禁止**；违反报 `E2011`（spec body 非签名形态）。
- 单个 `fn` 签名**禁带本地泛型**（与 §12.3.2 一致）；违反报 `E1104`。

§11.4.1.6 `#Spec struct` 自身可带 `genericDef`（§12.1.1.3）。

### §11.4.2 `#Impl(D)`

§11.4.2.1 `#Impl(D)` 顶行注解附着在 `struct` 声明上，宣告该 struct 实现 spec `D`（§12.2）。

§11.4.2.2 `#Impl(D)` 仅可附着于**非 spec** 的 `structDecl`；附着于 `fn` / `extern` / `let` / 字段 / 参数 / `#Spec struct` 等位置**应当**报 `E1110`。

§11.4.2.3 `#Impl(D)` **必须带单参数 `(D)`**，其中 D 由 `ID genericDef?` 形态表达（§11.1.1.1 单参数糖解禁覆盖 `#Impl(...)`）。缺参 / 多参 / 字面量参（非 ID）报 `E2010`。

§11.4.2.4 同一 struct 可重复出现多条 `#Impl(D1)` / `#Impl(D2)`，顺序不影响语义。同名 D 重复出现报 `E1103`。

§11.4.2.5 `D` 解析失败或解析到非 spec（普通 struct / enum / fn）报 `E1131`。

§11.4.2.6 struct body 内方法集**应当**穷尽覆盖所有所列 spec 的签名并集；缺失报 `E1137`。spec 与 struct 共享方法 namespace；同名签名不一致按 §12.3.1 判 `E1137`（无法同时满足）。

### §11.4.3 历史 `#DraftLike`（已废弃）

§11.4.3.1 早期 v0.x 的 `#DraftLike` 注解（开放结构化匹配开关）在 spec-unify v1 已废弃。统一形态下，所有满足关系一律走显式 `#Impl(D)` 宣告，不再存在"结构化匹配"档位。

§11.4.3.2 `#DraftLike` 仍在注解白名单（lexer / parser 接受）。附着于非 `#Spec` 声明已报 `E1110`；附着于 `#Spec struct` 时语义为 noop。源码 / 文档侧应迁删该注解。

## §11.6 `#Const`

### §11.6.1 语义

§11.6.1.1 `#Const` 标记函数声明为**编译期常量函数**：函数体内**不得**修改外部状态。语义与 §6.1.2a 一致。

§11.6.1.2 `#Const` 仅可附着于 `fn`（顶层函数或 struct body 内方法）。析构函数 `fn ~()` 与 const-mut 体系正交（§6.1.2 / [draft/DRAFT-const-mut.md](draft/DRAFT-const-mut.md) §[#1.L]），不接受 `#Const`。

### §11.6.2 检查清单

§11.6.2.1 `#Const fn` 函数体内禁止：

1. 写 `$.f`（成员函数情形）；
2. 写任何参数的字段：`p.f = ...`、`p[i] = ...`；
3. 写非 `cval` 的全局变量；
4. 调任何非 `#Const fn`（含 SDK / extern）。

违反 (1)–(3) 报 `E3110`，违反 (4) 报 `E3111`（[附录 D §D.3.3](附录D-诊断.md#d33-e3xxx--类型)）。

§11.6.2.2 允许：读 `$` / 参数 / 全局 `cval` / 全局 `val`；声明并写函数体内的局部 `var` / `val` / `cval`；调其它 `#Const fn`。

§11.6.2.3 v1 **不**做推断；必须显式标 `#Const`。callee 形态识别覆盖：(a) 自由函数（`LiteralObjNode`，按 file 自身 + `wildcardImports` 查表）；(b) 方法（`obj.method(...)`，receiver 是简单变量字面量含 `$`，按 receiver 类型剥 `Ref<T>` 后查 `Type.method`）。其它复杂 callee（编译器内置 / 间接调用）放行。

### §11.6.3 互锁规则

§11.6.3.1 `#Const` 与 `#Builtin` **可共存**：编译器内置的纯函数可同时标。

§11.6.3.2 `#Const` 不接受参数（语法形态 `#Const`，无 `(arg)` 槽）。

§11.6.3.3 v1 SDK 内化（`Array.size` / `String.size` 等纯方法补 `#Const`）属未做项；与 `#Builtin` 内置叠加 `#Const` 的形态待后续 commit 评估。

### §11.6.4 const-eval 通路（自由 / 静态成员位）

§11.6.4.1 `#Const` 注解在**自由函数**与 **`#Static fn`** 位上额外承载**编译期求值（const-eval）通路**（[DRAFT-const-eval](draft/DRAFT-const-eval.md) §4）：编译期在 sema 阶段对调用点递归求值整个 body，产出 IR 无关的 `ConstantValue`；codegen 翻为 LLVM Constant emit 全局，不走 IRBuilder runtime 路径。

§11.6.4.2 可用于 const-eval 的 `#Const fn` 要求 body 形态在白名单内：

| 形态 | 允许 | 备注 |
|---|---|---|
| `= expr` 单表达式体 | ✅ | 推荐形态 |
| 单 `ret` 块体（多行） | ✅ | |
| 顺序 `#Cval let` 块体（多行） | ✅ | 局部 `let` 初值必须 const |
| `exprOneLineIfElse`（两分支单 expr，多行块） | ✅ | 求 cond 后挑分支递归 |
| `if c { ... } else { ... }` statement 形态（两分支均以 `ret <const expr>` 结尾） | ✅ | |
| `for` / `while` / `match` / 普通 stmt 序列 | ❌ | E3141 |
| `try` / `catch` 错误处理形态 | ❌ | E3141 |

§11.6.4.3 形参 / 返回类型白名单（被 const-eval 调用站点检查，违反 → E3144）：
- ✅ 标量（`i32` / `u64` / `bool` / `f64` 等）
- ✅ const struct（全字段公开 + 字段类型递归满足约束）
- ✅ `#Builtin` rodata struct（如 `Type` / `Field`）
- ❌ `T&` / `Rc<T>` / `Heap<T>` / `Array<T>` / `String`（涉及 Block / 分配 / refcount）

§11.6.4.4 成员位 `#Const`（实例方法）语义不变：不改 `$` / 不改参数 / 不调非 `#Const`；暂不主动在 const-eval 中求值（receiver 多为 runtime 实例）。

## §11.7 `#Frozen`

### §11.7.1 语义

§11.7.1.1 `#Frozen` 是**深不可变**限定，附着于参数或字段：

- **参数位置**（`fnParamStd` / `fnParamGroup` 上 `paramAnno`）：标记形参在函数体内不可重赋、不可写字段 / 下标、不可传给可写受方位（§6.2.2a）；
- **字段位置**（`filedDecl` 上 `buildAnno`）：标记字段在构造期外不可重赋、子字段写传染禁止（§7.1.4）。

§11.7.1.2 `#Frozen` 不接受参数。

### §11.7.2 检查清单（参数位）

§11.7.2.1 详见 §6.2.2a；错误码 `E3105`（未知参数注解）/ `E3106`（写 `#Frozen` 形参字段）/ `E3107`（`#Frozen` 表达式传给非 `#Frozen` 受方）。

### §11.7.3 检查清单（字段位）

§11.7.3.1 详见 §7.1.4；错误码 `E3108`（重复或未知字段注解 / 带实参糖）/ `E3109`（构造期外写 `#Val` / `#Frozen` 字段，含 `#Frozen` 深传染）。

### §11.7.4 脱 const 出口

§11.7.4.1 v1 唯一脱 `#Frozen` 路径为 builtin `copy_of:<T>(x T&) T`（§11.2.3.2 / §12.7.3）。`copy_of` 接受 `#Frozen` 形态时按 `T&` 看待——返回值不再带 `#Frozen` 痕迹。

## §11.9 `#Mut`

### §11.9.1 语义

§11.9.1.1 `#Mut` 是**局部 `let` 声明的可变性修饰**（[DRAFT-let-unify](draft/DRAFT-let-unify.md) §3）：默认 `let x` 浅不可变（重赋报 `E3093`），`#Mut let x` 放宽允许任意重赋。

§11.9.1.2 `#Mut` 形态唯一允许的"`let x T` 无初值"形态：`#Mut let x T`（保留旧 `var x T` 延后赋值语义）。默认 / `#Frozen` / `#Cval` 形态强制 init，违反报 `E3114`。

§11.9.1.3 `#Mut` 不接受参数；与 `#Cval` / `#Frozen` 三者**互斥**，叠加报 `E3115`。

### §11.9.2 可附着位置

§11.9.2.1 `#Mut` 附着于以下位置：

- **局部 `let` 声明**（产生式 `statementLet` / `statementLetTuple`）：inline 形态，紧贴 `let` 之前。默认 / `#Frozen` / `#Cval` 形态强制 init，`#Mut` 例外允许无初值（延后赋值）。
- **全局 `let` 声明**（产生式 `letGlobal`）：顶行 + 换行形态，`#Mut` 独占一行、`let NAME T = expr` 紧随。全局 `#Mut` 为运行期初始化可变变量；v1 **必须** init（禁延后赋值，缺 → `E3154`）。详见 §5.1.4。
- **struct 静态字段**（产生式 `staticFieldDecl`）：与 `#Static` 组合（`#Mut` 顶行 + `#Static` 顶行 + `FIELD T = expr`），标记该静态字段可变、允许写入。详见 §7.11。

形参位**不**接受 `#Mut`（`paramAnno` 仅 `#Frozen`，其余 E3105；§6.2.1.3）。后续版本可以接 `#Mut` 形参。

§11.9.2.2 注解形态：
- 局部：inline，紧贴 `let`（如 `#Mut let x = 1`）；
- 全局 / 静态字段：顶行 + 换行（`#Mut` 独占一行，声明紧随）。

## §11.10 `#Cval`

### §11.10.1 语义

§11.10.1.1 `#Cval` 标记 `let` 声明为**编译期常量**（[DRAFT-let-unify](draft/DRAFT-let-unify.md) §3）：

- **局部位置**（`statementLet` 上）：等同旧 `cval` 局部声明（§5.1.5），初值须为常量表达式（含字面量、`#Cval` 引用、算术/位/比较/逻辑运算、`#Const fn` 调用、struct 字面量；§5.1.4.1.3），否则报 `E3104` / `E3140`。
- **全局位置**（`letGlobal` 上）：`#Cval let NAME T = expr`，初值须为常量表达式（同上）；与无注解全局 val 及 `#Mut` 全局 var 并列三档之一（§5.1.4）。

§11.10.1.2 `#Cval let` 不可重赋（与默认 `let` 共享 E3093 路径）；其引用语义同旧 `cval`，可作为其它 `#Cval` 初值表达式的操作数。

§11.10.1.3 `#Cval` 不接受参数；与 `#Mut` / `#Frozen` 三者**互斥**。

### §11.10.2 可附着位置

§11.10.2.1 `#Cval` 附着于 `let` 声明（局部 `statementLet` / 全局 `letGlobal`）。**不**附着于字段 / fn / struct / 参数；字段位的"静态常量字段"未来通过独立 draft 引入。

§11.10.2.2 注解形态：
- 局部：inline，紧贴 `let`（`#Cval let MAX i32 = 50`）；
- 全局：顶行 + 换行（`#Cval` 独占一行，`let NAME T = expr` 紧随，其中 `expr` 为常量表达式；§5.1.4.1.3）。

## §11.8 `#Val`

### §11.8.1 语义

§11.8.1.1 `#Val` 是**浅不可变**字段限定（仅字段位，不接受参数 / 函数 / 其它位置）。语义见 §7.1.4：构造期内可写、其它成员函数不可重赋字段自身（子字段仍可改）。

§11.8.1.2 与 `#Frozen` 字段互斥；同一字段同时标二者报 `E3108`。

§11.8.1.3 `#Val` 不接受参数。

## §11.11 `#Static`

### §11.11.1 语义

§11.11.1.1 `#Static` 标记 struct body 内的方法为**关联函数**（静态函数）：编译器**不**为其注入接收者参数 `$`，方法在 IR 层是顶层函数；调用语法 `Type::name(...)`（§7.10.2）。

§11.11.1.2 `#Static fn` 体内**禁写** `$` / `$.field` / `&$`（报 E3128）；可写 `Self` 类型字面量（§7.10.3）与 `Self { ... }` 字段字面量（§7.10.3.4，仅在 `#Static fn` 体内合法）。

§11.11.1.3 `#Static` 不接受参数。

### §11.11.2 可附着位置

§11.11.2.1 `#Static` 附着于 struct body 内的以下位置：

- **方法 `fn`**：标记为关联函数 / 静态函数，编译器不注入 `$` 接收者，调用语法 `Type::name(...)`（§7.10.2）。
- **字段 `staticFieldDecl`**：标记为静态字段（关联于类型而非实例），必须与类型声明 + `= expr` init 共存，可叠加 `#Mut`（可变静态字段）。读写语法 `Type::FIELD` / `Type::FIELD = v`（§7.11）。

`#Static` 附着于顶层 fn / 普通 `filedDecl`（无 init）/ spec body 内签名 / enum 上由 ast_builder / sema 拒收。

§11.11.2.2 v1 构造函数形态已删除（§7.3.1.1）；与结构体同名的 `#Static fn` 在语法层允许，但**不推荐**（与 turbofish 类型构造 `Type:<...>` 写法易混淆）。

§11.11.2.3 与同名实例方法**共存允许**（调用形态 `Type::name` / `obj.name` 天然区分），sema 不报错。

§11.11.2.4 与 `#Const` 组合**允许**，语义为"无副作用的工厂"。与 `#Frozen` **不**组合（`#Frozen` 是字段 / 形参 / 局部 `let` 专用，§11.7）。

### §11.11.3 检查清单

§11.11.3.1 静态调用 sema 分流（§7.10.2.1）：错误码 `E3120`（误调实例方法）/ `E3121`（未找到静态 fn）/ `E3122`（LHS 既非 enum 也非已知 struct）。

§11.11.3.2 `Self` / `Self { ... }` 使用错误：`E3123`（`Self` 出在 struct body 外）/ `E3124`（`Self { ... }` 出在 `#Static fn` 体外）/ `E3125`（字段未覆盖全）/ `E3126`（未知字段）/ `E3127`（重复字段）。

§11.11.3.3 `#Static fn` 体内 `$` 误用：`E3128`。

## §11.12 `#Reflect`

### §11.12.1 语义

§11.12.1.1 `#Reflect` 标记一个 struct 声明为**反射保留**：编译器在 emit 该类型的反射 rodata 全局时，将其加入 `llvm.compiler.used` 集合，防止链接期 `--gc-sections` 误删（即使源码层未直接引用该类型的反射字段）。

§11.12.1.2 `#Reflect` 仅可附着于 `structDecl`（非 spec）。附着于 `fn` / `extern` / `let` / 字段 / 参数等位置**应当**报 `E1110`。

§11.12.1.3 `#Reflect` v1 **零参**（形态 `#Reflect`，无 `(arg)` 槽）。命名参数扩展（`#Reflect(fields=false)` 等）待 anno-struct 落地，窗口见 §13。

### §11.12.2 使用形态

```yux
#Reflect
struct User {
  name String
  age i32
}
```

§11.12.2.1 反射元数据默认 emit（即使未标 `#Reflect`），链接期 `--gc-sections` 自动回收未被引用的数据。`#Reflect` 仅用于**强制保留**场景：反射数据预期在外部工具（序列化框架、ORM、CLI parser 等）中引用，源码层未直接访问 `User::type` / `User::fields`。

## §11.13 `#NoCopy`

### §11.13.1 语义

§11.13.1.1 `#NoCopy` 标记结构体为**不可隐式复制**：编译器在 `let a = b`（b 是 `#NoCopy` 类型值的左值）、按值传参、按值返回等复制形态下拒绝，报 E4031。需要转移所有权走 `move:<T>(x)` builtin；`copy_of` 对 `#NoCopy` 类型一律拒绝（含 `Array<T>` 与用户自定义 `#NoCopy`）。`Array<T>` 的深拷贝唯一入口是 `arr.clone()`（§9.2.2.3）。

§11.13.1.2 `#NoCopy` **不接受参数**（形态 `#NoCopy`，无 `(arg)` 槽）。

§11.13.1.3 `#NoCopy` 仅可附着于 `structDecl`（非 spec）。附着于 `fn` / `extern` / `enum` 等位置报 E2005。

### §11.13.2 传染规则

§11.13.2.1 **字段传染**：若 struct 含有 `#NoCopy` 类型的字段（含 `Array<T>`——编译器对其隐式视作 `#NoCopy`，§9.2.2.4），该 struct **自身也必须标注 `#NoCopy`**，否则报 E4032。

§11.13.2.2 **隐式 `#NoCopy`**：`Array<T>` 由编译器内部视为 `#NoCopy`（即使未显式标注——`Array<T>` 不含 RC 头、不参与 retain/release，隐式复制会导致 double-free）。用户 struct 含 `Array<T>` 字段时触发 E4032 传染规则。

§11.13.2.3 **泛型类型识别**：`#NoCopy` 查找按 struct 基名进行。字段类型为泛型实例（`MyNoCopy<i32>` / `MyNoCopy<T>`）时剥掉类型实参再查 decl；泛型 struct 模板含 `#NoCopy` 字段时同样触发 E4032，不因模板尚未实例化而跳过。字段类型为本 struct 的类型形参（`struct W<T> { item T }`）时，实例化前无法判定，不在此处报 E4032。

### §11.13.3 `move:<T>(x)` builtin

§11.13.3.1 `move:<T>(x T&)` 是编译器 baked builtin（§6.4.3.1），语义为**所有权转移**：返回 `x` 所引用变量的值（`T`），同时将源变量标记为"已移走"（moved-out）。移入赋值 `a <- b` 复用了同一套 move 语义。

§11.13.3.2 要求实参为左值（`T&`）：变量引用（`move:<i32>(a)`）或 `&expr`（`move:<T>(&x)`）。实参为右值（字面量 / 调用结果）报 E4034。类型参数自身为引用（`move:<i32&>(x)`）报 E4035。

§11.13.3.3 move 后源变量不可再使用——任何后续访问（读 / 写 / 传参）报 E4033（use-after-move）。该检查由 SemaPass 在 sema 期完成（0 LLVM 依赖）。

## §11.14 `#Inline`

### §11.14.1 语义

§11.14.1.1 `#Inline` 标记全局 `#Cval` 常量为**内联常量**：编译器**不**为其创建 LLVM `GlobalVariable` 符号，而是在每个使用处直接将常量值替换为 `llvm::Constant*`（无 `load` 指令）。效果类似 C 的 `#define XXX AAA`。

§11.14.1.2 `#Inline` 仅可附着于全局 `#Cval let` 声明（`letGlobal` 产生式，`letAnno` 形态）。附着于局部 `let`、`fn`、`struct`、字段、参数等位置**应当**编译报错。

§11.14.1.3 `#Inline` **不接受参数**（形态 `#Inline`，零参、无 `(arg)` 槽）。

### §11.14.2 互锁规则

§11.14.2.1 `#Inline` **必须与 `#Cval` 同时出现**。单独 `#Inline`（无 `#Cval`）报 E3117。

§11.14.2.2 `#Inline` 与 `#Mut` / `#Frozen` **互斥**（`letAnno` 档位约束，§11.9.1.3 / §11.10.1.3）；违反报 E3115。

§11.14.2.3 `#Inline` 仅作用于**全局** `#Cval`。局部 `#Cval let` 已在编译期求值，由 sema 期 `ConstEvaluator` 直接 substitute，无需也不接受 `#Inline`。

### §11.14.3 代码生成行为

§11.14.3.1 编译器在 `compileGlobalConsts()` 阶段对 `#Inline` 标注的 `#Cval`：

1. 仍通过 `ConstEvaluator` 求值得到 `ConstantValue`；
2. 将 `ConstantValue` 转换为 `llvm::Constant*`；
3. 存入 `Compiler::_inlineConstantValues` 表（key = mangled name）；
4. **跳过** `new llvm::GlobalVariable(...)` —— 不产生 LLVM 符号。

§11.14.3.2 在使用处（`compileLiteralExpr` 的 `LiteralObjNode` 路径），编译器在查 `_module->getGlobalVariable()` 之前先查 `_inlineConstantValues` 表；命中则直接返回 `llvm::Constant*`，不产生 `load` 指令。

§11.14.3.3 与普通 `#Cval` 的对比：

| 维度 | `#Cval` | `#Inline` `#Cval` |
|---|---|---|
| LLVM GlobalVariable | 是（`isConstant=true`，ExternalLinkage） | 否（无符号） |
| 使用处 IR | `load @global, align N` | 常量直接 inline（如 `i32 42`） |
| 跨模块可见 | 是（ExternalLinkage） | 否（仅在当前编译单元可用） |
| 二进制体积 | 一条 load per use + rodata 槽 | 零开销（常量嵌入指令） |

### §11.14.4 使用形态

```yux
#Inline
#Cval
let MAX_BUFFER i32 = 4096

#Inline
#Cval
let APP_TIMEOUT_MS i64 = 30000

; 私有内联常量（_ 前缀）
#Inline
#Cval
let _INTERNAL_SEED u64 = 0xDEADBEEF

fn main() {
  ; 每次使用直接替换为常量值，与 C #define 等效
  let size i32 = MAX_BUFFER + 256          ; → 4096 + 256
  let timeout i64 = APP_TIMEOUT_MS         ; → 30000
}
```

## §11.15 用户自定义注解

§11.15.1 v1 **不**支持用户自定义注解：未在对应位置白名单中的 `name` 一律编译报错（§11.1.3.1）。

§11.15.2 引入用户自定义注解需先解决：

- 注解可见性（跨模块识别）；
- 注解参数的字面量子集与求值时机；
- 注解作用域（声明级 vs 表达式级）；
- 与 `extern` 链接、SDK 标记的命名空间冲突。

§11.15.3 该方向随独立草案 `DRAFT-anno-struct.md`（尚未落地）转后续版本；与多参数 / 命名参数 / `#Reflect` 精细化同一前置。
