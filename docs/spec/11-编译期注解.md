# §11 编译期注解

本章规范 yux 的编译期构建注解（build annotation）：在声明前以 `#Name` 形式附加的编译期语义标签。v1 注解仅供编译器内部使用，**不**支持用户自定义。

## §11.1 语法

### §11.1.1 形态

```
buildAnno ::= '#' ID ( '(' ID ')' )? codeLineEnd
```

§11.1.1.1 每条注解单独一行，以 `#` 开头，后跟标识符 `name`，可选携带**单参数糖** `(ID)`（由 [DRAFT-错误.md](draft/DRAFT-错误.md) §3.5 解禁，`#Fallible(E)` 用），再跟换行（含可选行尾注释）。多参数 `#Name(a, b)` 与命名参数 `#Name = value` 在 v1 不接受。

§11.1.1.2 注解**应当**紧贴声明出现：声明前可有零或多条 `buildAnno`，相邻注解共享同一目标声明。

### §11.1.2 可附着位置

§11.1.2.1 由 `yux.g4` 在产生式层规定的可附着位置：

| 位置 | 产生式 |
|---|---|
| 顶层函数 | `fn` |
| 函数头（`extern` 块内） | `fnHeader` |
| 结构体声明 | `structDecl` |
| 结构体方法块 | `structImpl` |
| 结构体字段 | `filedDecl` |
| 全局常量 | `globalConst` |
| `extern` 块本身 | `externDecl` |
| 函数形参 | `fnParamStd` / `fnParamGroup`（经 `paramAnno`，形态略不同：行尾 `LineEnd?` 而非 `codeLineEnd`） |

§11.1.2.2 在上述位置之外出现 `#Name` **应当**视为语法错误。

§11.1.2.3 结构体方法块内的方法（`fn`）也接受注解，规则与顶层 `fn` 一致。

### §11.1.3 未知注解

§11.1.3.1 注解名 `name` 不在 §11.2 / §11.3 列表中时，编译器**应当**编译报错。v1 不引入"宽容未知注解"模式。

§11.1.3.2 注解参数形态：单参数糖 `#Name(ID)` 由 §11.1.1.1 解禁（仅 `#Fallible(E)` 用）；多参数 `#Name(a, b)` 与命名参数 `#Name = value` 在 v1 不接受。

## §11.2 `#CompilerInner`

### §11.2.1 语义

§11.2.1.1 `#CompilerInner` 标记声明体由**编译器内部合成实现**，源代码层不提供函数体或结构体字段。

§11.2.1.2 用在 `struct` 上：

- 表示该结构体是编译器认识的内置类型（如 `i8 / u8 / .. / f64 / bool` 占位声明）；
- 编译器**不**为其生成 LLVM 结构体字段；其内存形态由编译器内部表给出。

§11.2.1.3 用在 `fn` / 方法上：

- 该函数 / 方法**应当**省略函数体；
- 编译器在调用点直接合成实现（典型：基础类型转换 `to_i32` / `to_f64` / `to_string`、`upgrade` / `weak` / `same_ref` / `ptr_of` / `rc_leak_count` 等内置）。

### §11.2.2 互锁规则

§11.2.2.1 带 `#CompilerInner` 的函数 / 方法**应当**省略函数体。

§11.2.2.2 函数 / 方法头省略函数体时**应当**带 `#CompilerInner`（除 `extern fn` 外）；否则编译器**应当**报错。

§11.2.2.3 用户代码**不得**使用 `#CompilerInner`：该注解仅 SDK `base.yux` 与编译器内部约定下使用。Open Issue：是否提供路径白名单显式限制。

### §11.2.3 与 SDK 的关系

§11.2.3.1 `base.yux` 中内置类型（`i8`–`u64`、`f32` / `f64`、`bool`）的占位 `struct` 声明与对应的 `to_<type>` 方法都标 `#CompilerInner`；编译器据此跳过源码编译并合成 LLVM IR 指令（整数扩展 / 截断、浮点转换、比零等）。各内置类型的 `to_string` 方法亦由 `base.yux` 内 `Type : ToString { #CompilerInner fn to_string() String }` 给出（§12.7.1）。

§11.2.3.2 内置 builtin 函数（`upgrade` / `weak` / `same_ref` / `ptr_of` / `rc_leak_count` / `_ptr_offset` / `as_ref` / `copy_of`）也**应当**通过 `#CompilerInner` 在 `base.yux` 中给出签名占位（§8 / §9.10 / §12.7.3）。其中：

- `as_ref` 含 `Rc<T>` / `Heap<T>` 两形态重载（§8.3.5.5）；
- `ptr_of` 含 `T&` / `Rc<U>` / `Heap<U>` / `Array<U>` / `String` 等源类型重载（§9.7.2.4）；
- `copy_of` 含 `T&` / `Heap<T>&` / `Heap<T>?&` 形态扩展（§8 / `DRAFT-heap-types.md` §6.5）；
- `Heap:<T>(p Ptr) Heap<T>` FFI 接管形态走同一 `#CompilerInner` 占位机制（§9.5a.2.2）。

runtime 入口 `__yux_heap_alloc<T>` / `__yux_heap_free<T>` 由编译器直接生成调用，**不**走 `#CompilerInner` 用户签名层；它们与 `__yux_rc_*` 入口同级（§8.2）。

§11.2.3.3 §10.4 的 SDK / 编译器版本绑定也涵盖 `#CompilerInner` 声明：增减或改签名**应当**同步重 build SDK。

## §11.3 `#Test`

### §11.3.1 语义

§11.3.1.1 `#Test` 标记一个**单元测试函数**，仅在 `yux test` 子命令下被收集与执行；普通 `yux build` **应当**跳过其 codegen，不进入 `.exe` / `.lib` 产物。

§11.3.1.2 `#Test` 仅可附着于 `fn`（顶层函数或 `structImpl` 方法）。出现在其他位置（`struct` / `extern` / `cval` 等）**应当**编译报错。

### §11.3.2 函数约束

§11.3.2.1 `#Test` 函数的签名**应当**为：无参数列表（`()` 形参列表为空）、无返回类型标注（语义等价 void）。

§11.3.2.2 `#Test` 函数**应当**有函数体；省略函数体**应当**报错（与 §11.2 `#CompilerInner` 互斥）。

§11.3.2.3 同一函数上 `#Test` 与 `#CompilerInner` **不得**同时出现。

### §11.3.3 测试文件

§11.3.3.1 `#Test` 函数**应当**只出现在以 `.test.yux` 结尾的源文件中；普通 `.yux` 源文件中出现 `#Test` **应当**编译报错。

§11.3.3.2 `*.test.yux` 文件由 `yux test` 在项目 `src/` 目录下递归发现；普通 `yux build` **应当**完全忽略这些文件（不解析、不 codegen、不参与依赖图）。

§11.3.3.3 测试文件的模块名**应当**取 src 根下相对路径转点分形式，**保留** `.test` 段。例：`<projectRoot>/src/yux/core/arithmetic.test.yux` → 模块 `yux.core.arithmetic.test`。

### §11.3.4 `yux test` 行为（informative）

§11.3.4.1 `yux test` **仅**在项目模式（cwd 含 `yux.toml`）可用；不接受单文件入参。

§11.3.4.2 选择器（informative）：
- `yux test`：当前项目下全部 `#Test`
- `yux test <prefix>`：模块名前缀匹配（例：`yux test yux.core` 命中 `yux.core.*.test`）
- `yux test <module>#<fnName>`：精确匹配模块名 + 函数名

§11.3.4.3 v1 测试默认在同一进程内顺序执行；每个 `#Test` 函数由 SEH wrapper 包裹，单条 SEH 异常（除零 / AV / `ASSERT_FAILED` 等）只标记该测试 `FAIL` 并继续后续测试。

§11.3.4.4 `yux test --isolate=process`：每个 `#Test` 函数在独立子进程内执行，崩溃 / 内存脏化只影响该测试。代价是每个测试承担一次 LLJIT 启动开销（~2s），适用于借用 / RC 类用例。退出码语义与默认模式一致（全 pass = 0；任一失败 = 1）。`--isolate=none`（默认）保持同进程行为。

§11.3.4.5 `yux test -v / --verbose`：默认仅在测试失败时回放该测试的 stdout / stderr；`-v` 时所有测试都回放。

### §11.3.5 测试断言 API

§11.3.5.1 SDK 在 `sdk/yux/src/yux/core/assert.yux`（与 `base.yux` / `math.yux` 同属 `yux.core` 模块的平铺文件）提供四个 `#CompilerInner` 断言函数；与 §11.2 一致，签名仅作占位，调用时由编译器在调用点合成 IR：

```yux
#CompilerInner
fn assert_eq<T>(actual T, expected T)

#CompilerInner
fn assert_true(actual bool)

#CompilerInner
fn assert_false(actual bool)

#CompilerInner
fn fail(msg String)
```

§11.3.5.2 `assert_eq` 在 v1 支持以下类型分派：

- 数值与 `bool`：`i8` / `u8` / `i16` / `u16` / `i32` / `u32` / `i64` / `u64` / `f32` / `f64` / `bool` —— 由 `#CompilerInner` 通过 `compileTestAssertEq` 在调用点合成 ICmp/FCmp + 失败分支。
- `String`：由 `base.yux` 末尾的 yux 实现非泛型重载 `fn assert_eq(actual String&, expected String&)` 提供，体内走 `actual != expected` 触发 `_yux_test_assert_failed()`。dispatcher（`compiler_call.cpp`）在参数严格匹配的非泛型重载存在时**应当**优先选择该重载，绕开 `#CompilerInner` 泛型路径。

其他类型仍在调用点报 E6030。后续版本**可以**扩展到用户结构体（参见 Open Issues 末尾的"用户结构体相等约束"）。

§11.3.5.7 v1 同时提供两个 `String&` 形参的字符串子串断言，以 yux 实现（同 `String` 重载的 dispatcher 路径），位于 `base.yux`：

```yux
fn assert_contains(haystack String&, needle String&)
fn assert_starts_with(s String&, prefix String&)
```

`assert_contains` 调 `String.contains(needle String&)`，`assert_starts_with` 调 `String.starts_with(prefix String&)`，两者都在条件不成立时调 `_yux_test_assert_failed()`。`String.contains` 当 `needle` 为空字符串时**应当**返回 `true`（与 `assert_starts_with("", "")` 一致）。

§11.3.5.3 断言失败语义：

- `assert_eq` 当 `actual != expected`、`assert_true` 当 `actual == false`、`assert_false` 当 `actual == true`、`fail` 在被调用时即视为失败；
- 失败时编译器合成的 IR **应当**：
  1. 调用 SDK 侧普通函数 `_yux_test_assert_failed()`（在 `assert.yux` 中以 yux 实现），其体内调用 Win32 `RaiseException` 抛出自定义异常码 `0xE0FA17ED`；
  2. 该异常由 `yux test` 的 SEH wrapper 捕获并显示为 `FAIL <module>#<fn> (SEH ASSERT_FAILED 0xe0fa17ed)`；先行的 `RUN <module>#<fn>` 行已足以定位失败位置。
- v1 **不**额外打印断言种类（`assert_eq` vs `assert_true` 等）或 `fail(msg)` 的实参文本：fail 的 `msg` 在 v1 仅用作源码自文档，运行时不输出。后续版本（与 §11.3.5.4 的 stringify 扩展同期）**可以**加上 `assertion failed at <file>:<line>: <kind>` 行。

§11.3.5.4 失败信息**不**打印实参的具体值（v1 限制：泛型 `T` 不要求 `to_string`）。后续版本**可以**在 `T` 满足某个内置约束（如 `Stringify`）时自动追加 `actual = ... / expected = ...` 行。

§11.3.5.5 这些函数**应当**只在 `*.test.yux` 文件内调用；在普通 `.yux` 文件中调用属于"调用 SDK `#CompilerInner` 函数"——v1 不主动拦截（与现有 `rc_leak_count` / `same_ref` 一致），但 SEH wrapper 不在普通 `yux build` 产出的 `.exe` 内，调用结果是直接异常退出，无诊断输出。

§11.3.5.6 这些函数**应当**与 §11.3.2 中的 `#Test` 函数签名约束兼容：`#Test` 函数无返回值、无参数，但其函数体内调用 `assert_*` / `fail` 不破坏该约束。

### §11.3.6 `#TestIsolate`（per-test 隔离修饰）

§11.3.6.1 `#TestIsolate` 是 `#Test` 的**修饰注解**：用于标记某个测试在默认 `--isolate=none` 模式下也**应当**走子进程派发；命中此注解的测试不受 SEH 同进程包裹模式下"跨帧异常漏报"风险影响。

§11.3.6.2 `#TestIsolate` **必须**与 `#Test` 同时出现在同一函数声明上；缺少 `#Test` 时编译器**应当**报 `E2033`。`#Test` 的其它约束（§11.3.2 / §11.3.3：仅 `.test.yux`、与 `#CompilerInner` 互斥、签名 `fn name(): void` 且必须有体）由 `#Test` 自身条款覆盖，`#TestIsolate` 不重复声明。

§11.3.6.3 `#TestIsolate` 不接受参数（语法形态 `#TestIsolate`，无 `(arg)` 槽）。

§11.3.6.4 行为（*informative*）：

- `yux test`（默认 `--isolate=none`）：命中 `#TestIsolate` 的测试**走 `--isolate=process` 的子进程派发协议**（与 §11.3.4.4 相同），未命中的测试仍在同进程 JIT 内执行；OK / FAIL 行末追加 `(isolated)` 标记。
- `yux test --isolate=process`：所有测试均走子进程，`#TestIsolate` 标记被覆盖（不生效也不报错）。
- `yux test --isolate=none` 显式指定：行为与默认相同。

§11.3.6.5 使用语义（*informative*）：`#TestIsolate` 是**临时绕过**手段，用于 JIT 跨帧 SEH 等已知运行时缺陷；编译器不会自动嗅探"SEH-prone" 模式。新增标记**应当**在源码注释 / 跟踪文档（如 `BUGS.md`）中记录缘由，并在底层缺陷修复后取消。

## §11.4 `#DraftLike`

### §11.4.1 语义

§11.4.1.1 `#DraftLike` 标记一个 `draft` 声明开放**结构化匹配**：在 `<T : D>` 边界场景中，编译器**应当**按 §12.3 检查类型 T 的方法集是否包含 D 的全部签名；命中即视为 T 实现 D，无需写 `Type : D { ... }` 显式实现块。详见 §12.4。

§11.4.1.2 未标 `#DraftLike` 的 draft 是**封闭契约**：调用方**应当**通过 `Type : D { ... }` 显式实现，**不得**绕过。

### §11.4.2 互锁规则

§11.4.2.1 `#DraftLike` **只能**附着在 `draft` 声明上；标在 `fn` / `struct` / `structImpl` / `globalConst` / `extern` 等其它位置**应当**报 `E1110`。

§11.4.2.2 `#DraftLike` **不得**与默认方法体共用（v1 draft 体本就只允许签名，前向兼容保留 `E1111`，详见 §12.4.3.2）。

§11.4.2.3 `#DraftLike` **不得**与含方法本地泛型的 draft 共用（与 §12.3.2 矛盾），违反报 `E1112`。

§11.4.2.4 `#DraftLike` 是**声明级**属性，**不得**在使用处（边界 / 参数 / 调用点）追加。

### §11.4.3 风格指引（*informative*）

§11.4.3.1 `#DraftLike` **应当**有明确语义动机（典型：跨包契约、不便修改的第三方类型）；仅为"少写 `:` 实现"开放属反模式（§12.4.3.1）。规范层不强制阻止，但建议代码评审拒绝该用法。

§11.4.3.2 设计强契约的 draft（典型：`ToString` / 操作符 draft 候选）**不应**标 `#DraftLike`，避免无关同名方法被误命中（§12.7.1.1）。

## §11.6 `#Const`

### §11.6.1 语义

§11.6.1.1 `#Const` 标记函数声明为**编译期常量函数**：函数体内**不得**修改外部状态。语义与 §6.1.2a 一致。

§11.6.1.2 `#Const` 仅可附着于 `fn`（顶层函数或 `structImpl` 内方法）。析构函数 `fn ~()` 与 const-mut 体系正交（§6.1.2 / [draft/DRAFT-const-mut.md](draft/DRAFT-const-mut.md) §[#1.L]），不接受 `#Const`。

### §11.6.2 检查清单

§11.6.2.1 `#Const fn` 函数体内禁止：

1. 写 `$.f`（成员函数情形）；
2. 写任何参数的字段：`p.f = ...`、`p[i] = ...`；
3. 写非 `cval` 的全局变量；
4. 调任何非 `#Const fn`（含 SDK / extern）。

违反 (1)–(3) 报 `E3110`，违反 (4) 报 `E3111`（[附录 D §D.3.3](附录D-诊断.md#d33-e3xxx--类型)）。

§11.6.2.2 允许：读 `$` / 参数 / 全局 `cval` / 全局 `val`；声明并写函数体内的局部 `var` / `val` / `cval`；调其它 `#Const fn`。

§11.6.2.3 v1 **不**做推断；必须显式标 `#Const`。callee 形态识别覆盖：(a) 自由函数（`LiteralObjNode`，按 file 自身 + `wildcardImports` 查表）；(b) 方法（`obj.method(...)`，receiver 是简单变量字面量含 `$`，按 receiver 类型剥 `Ref<T>` 后查 `Type.method`）。其它复杂 callee（编译器内置 / 间接调用）放行。

### §11.6.3 互锁规则

§11.6.3.1 `#Const` 与 `#CompilerInner` **可共存**：编译器内置的纯函数可同时标。

§11.6.3.2 `#Const` 不接受参数（语法形态 `#Const`，无 `(arg)` 槽）。

§11.6.3.3 v1 SDK 内化（`Array.size` / `String.size` 等纯方法补 `#Const`）属未做项；与 `#CompilerInner` 内置叠加 `#Const` 的形态待后续 commit 评估。

## §11.7 `#Frozen`

### §11.7.1 语义

§11.7.1.1 `#Frozen` 是**深不可变**限定，附着于参数或字段：

- **参数位置**（`fnParamStd` / `fnParamGroup` 上 `paramAnno`）：标记形参在函数体内不可重赋、不可写字段 / 下标、不可传给可写受方位（§6.2.2a）；
- **字段位置**（`filedDecl` 上 `buildAnno`）：标记字段在构造期外不可重赋、子字段写传染禁止（§7.1.4）。

§11.7.1.2 `#Frozen` 不接受参数。

### §11.7.2 检查清单（参数位）

§11.7.2.1 详见 §6.2.2a；错误码 `E3105`（未知参数注解）/ `E3106`（写 `#Frozen` 形参字段）/ `E3107`（`#Frozen` 表达式传给非 `#Frozen` 受方）。

### §11.7.3 检查清单（字段位）

§11.7.3.1 详见 §7.1.4；错误码 `E3108`（重复或未知字段注解 / 带实参糖）/ `E3109`（构造期外写 `#Val` / `#Frozen` 字段，含 `#Frozen` 深传染）。

### §11.7.4 脱 const 出口

§11.7.4.1 v1 唯一脱 `#Frozen` 路径为 builtin `copy_of:<T>(x T&) T`（§11.2.3.2 / §12.7.3）。`copy_of` 接受 `#Frozen` 形态时按 `T&` 看待——返回值不再带 `#Frozen` 痕迹。

## §11.9 `#Mut`

### §11.9.1 语义

§11.9.1.1 `#Mut` 是**局部 `let` 声明的可变性修饰**（[DRAFT-let-unify](draft/DRAFT-let-unify.md) §3）：默认 `let x` 浅不可变（重赋报 `E3093`），`#Mut let x` 放宽允许任意重赋。

§11.9.1.2 `#Mut` 形态唯一允许的"`let x T` 无初值"形态：`#Mut let x T`（保留旧 `var x T` 延后赋值语义）。默认 / `#Frozen` / `#Cval` 形态强制 init，违反报 `E3114`。

§11.9.1.3 `#Mut` 不接受参数；与 `#Cval` / `#Frozen` 三者**互斥**，叠加报 `E3115`。

### §11.9.2 可附着位置

§11.9.2.1 `#Mut` **只**附着于局部 `let` 声明（产生式 `statementLet` / `statementLetTuple`）；附着于其它声明位（字段 / fn / struct / 参数）由 g4 / ast_builder 拒收。参数位的"可变"语义另由 §6.2.2a / §11.7 框架表达（v1 默认形参可重赋的形态不再用 `#Mut` 表达，保留 `#Frozen` 单向收紧）。

§11.9.2.2 注解形态：inline，紧贴 `let` 之前；可与其它 inline 注解平铺（如 `#Mut #SomeFutureAnno let x = 1`）。formatter 规范化为 inline。

## §11.10 `#Cval`

### §11.10.1 语义

§11.10.1.1 `#Cval` 标记 `let` 声明为**编译期常量**（[DRAFT-let-unify](draft/DRAFT-let-unify.md) §3）：

- **局部位置**（`statementLet` 上）：等同旧 `cval` 局部声明（§5.1.5），初值须为常量表达式，否则报 `E3104`。
- **全局位置**（`letGlobal` 上）：等同旧 `cval NAME T = literal` 顶层声明（§5.1.4）；全局 `let` **必须**带 `#Cval`，缺则报 `E3116`。

§11.10.1.2 `#Cval let` 不可重赋（与默认 `let` 共享 E3093 路径）；其引用语义同旧 `cval`，可作为其它 `#Cval` 初值表达式的操作数。

§11.10.1.3 `#Cval` 不接受参数；与 `#Mut` / `#Frozen` 三者**互斥**。

### §11.10.2 可附着位置

§11.10.2.1 `#Cval` 附着于 `let` 声明（局部 `statementLet` / 全局 `letGlobal`）。**不**附着于字段 / fn / struct / 参数；字段位的"静态常量字段"未来通过独立 draft 引入。

§11.10.2.2 注解形态：
- 局部：inline，紧贴 `let`（`#Cval let MAX i32 = 50`）；
- 全局：顶行 + 换行（`#Cval` 独占一行，`let NAME T = literal` 紧随）。

## §11.8 `#Val`

### §11.8.1 语义

§11.8.1.1 `#Val` 是**浅不可变**字段限定（仅字段位，不接受参数 / 函数 / 其它位置）。语义见 §7.1.4：构造期内可写、其它成员函数不可重赋字段自身（子字段仍可改）。

§11.8.1.2 与 `#Frozen` 字段互斥；同一字段同时标二者报 `E3108`。

§11.8.1.3 `#Val` 不接受参数。

## §11.11 `#Static`

### §11.11.1 语义

§11.11.1.1 `#Static` 标记 `structImpl` 块内的方法为**关联函数**（静态函数）：编译器**不**为其注入接收者参数 `$`，方法在 IR 层是顶层函数；调用语法 `Type::name(...)`（§7.10.2）。

§11.11.1.2 `#Static fn` 体内**禁写** `$` / `$.field` / `&$`（报 E3128）；可写 `Self` 类型字面量（§7.10.3）与 `Self { ... }` 字段字面量（§7.10.3.4，仅在 `#Static fn` 体内合法）。

§11.11.1.3 `#Static` 不接受参数。

### §11.11.2 可附着位置

§11.11.2.1 `#Static` **仅**附着于 `structImpl` 块内的方法 `fn`；附着于顶层 fn / 字段 / draft 实现块内方法 / enum 上由 ast_builder / sema 拒收。

§11.11.2.2 与构造函数同名（即与结构体同名）**禁止**——`Type::Type(...)` 与 ctor 入口 `Type(...)` 形态冲突。

§11.11.2.3 与同名实例方法**共存允许**（调用形态 `Type::name` / `obj.name` 天然区分），sema 不报错。

§11.11.2.4 与 `#Const` 组合**允许**，语义为"无副作用的工厂"。与 `#Frozen` **不**组合（`#Frozen` 是字段 / 形参 / 局部 `let` 专用，§11.7）。

### §11.11.3 检查清单

§11.11.3.1 静态调用 sema 分流（§7.10.2.1）：错误码 `E3120`（误调实例方法）/ `E3121`（未找到静态 fn）/ `E3122`（LHS 既非 enum 也非已知 struct）。

§11.11.3.2 `Self` / `Self { ... }` 使用错误：`E3123`（`Self` 出在 `structImpl` 体外）/ `E3124`（`Self { ... }` 出在 `#Static fn` 体外）/ `E3125`（字段未覆盖全）/ `E3126`（未知字段）/ `E3127`（重复字段）。

§11.11.3.3 `#Static fn` 体内 `$` 误用：`E3128`。

## §11.5 其他注解

### §11.5.1 v1 注解集合

v1 已落地的注解：

| 注解 | 适用位置 | 语义 | 章节 |
|---|---|---|---|
| `#CompilerInner` | `struct` / `fn` / 方法 | 编译器合成实现 | §11.2 |
| `#Test` | `fn` / 方法（仅 `*.test.yux`） | 单元测试函数 | §11.3 |
| `#TestIsolate` | `fn` / 方法（必须与 `#Test` 同存） | per-test 隔离修饰（默认模式下强制子进程） | §11.3.6 |
| `#DraftLike` | `draft` 声明 | 开放结构化匹配 | §11.4 / §12.4 |
| `#Fallible(E)` | `fn` / `structImpl` 内方法 | 可能以 enum `E` 失败（草案，单参数糖） | §6.7 / DRAFT-错误.md §3 |
| `#NoReturn` | `fn` / `structImpl` 内方法 | 永不正常返回（草案，零参数） | DRAFT-错误.md §8.3 |
| `#Const` | `fn` / `structImpl` 内方法 | 编译期常量函数（不改外部状态） | §6.1.2a / §11.6 |
| `#Frozen` | `fnParamStd` / `fnParamGroup` / `filedDecl` / `statementLet` | 参数 / 字段 / 局部 `let` 深不可变限定 | §6.2.2a / §7.1.4 / §11.7 |
| `#Val` | `filedDecl` | 字段浅不可变限定 | §7.1.4 / §11.8 |
| `#Mut` | `statementLet` / `statementLetTuple` | 局部 `let` 可变档位修饰（inline） | §5.1.1 / §11.9 |
| `#Cval` | `statementLet` / `letGlobal` | `let` 编译期常量档位（局部 inline / 全局顶行） | §5.1.4 / §5.1.5 / §11.10 |
| `#Static` | `structImpl` 内方法 | 关联函数 / 静态函数（无 `$` 接收者，调用语法 `Type::name(...)`） | §7.10 / §11.11 |

§11.5.1.1 v1 五种正式注解：`#CompilerInner` / `#Test` / `#DraftLike` 已落地；`#Fallible(E)` / `#NoReturn` 由 [DRAFT-错误.md](draft/DRAFT-错误.md) 引入，与 §11.1.1.1 单参数糖同步解禁。其它注解形态属预留（§11.5.2）。

### §11.5.2 预留注解（informative）

§11.5.2.1 `extern` 块的 `buildAnnos` 在语法层已预留，未来**可以**用于指定链接库（如 `#Link("kernel32")`）。v1 接受语法但**不**赋予语义；用户**不应**写出。

§11.5.2.2 全局常量 `cval` 的 `buildAnnos` 在语法层已预留；v1 不赋予语义。

§11.5.2.3 enum / match（§3.10、§4、§5）**不**引入新注解：v1 形态的"声明 + 构造 + match"全部走纯语法路径，无 `#CompilerInner` 入口（编译器内部合成的 `__enum_drop_<E>` / `__enum_copy_<E>` 等是隐式派生函数，不暴露给用户代码，亦不挂注解）。

§11.5.2.4 候选未来注解（Open Issue）：

- `@sdk_only`（限定 `Ptr` 算术等仅 SDK 可用，§8.7.4.5 当前以 `_` 前缀私有函数替代）；
- `#Inline` / `#NoInline`；
- `#DebugOnly`。

## §11.6 用户自定义注解

§11.6.1 v1 **不**支持用户自定义注解：未在 §11.2 / §11.3 / §11.4 / §11.5 列表中的 `name` 一律编译报错（§11.1.3.1）。

§11.6.2 引入用户自定义注解需先解决：

- 注解可见性（跨模块识别）；
- 注解参数的字面量子集与求值时机；
- 注解作用域（声明级 vs 表达式级）；
- 与 `extern` 链接、SDK 标记的命名空间冲突。

§11.6.3 该方向 Open Issue 跟踪在本章末尾。
