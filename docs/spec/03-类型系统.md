# §3 类型系统

本章规范 yux 的类型构造、可赋值性、转换与禁忌。具体内置类型的语义合约（`Rc<T>`、`Array<T>` 等）见 §9；与所有权 / 引用相关的细节见 §8。

## §3.1 类型档位

yux 的类型按存储与传参语义分为四档（见 [draft/DRAFT-所有权与引用.md](draft/DRAFT-所有权与引用.md) §2 / §8）：

| 档位 | 写法 | 存储 | 传参语义 | 章节 |
|---|---|---|---|---|
| **值类型** | 内置标量 / 用户 `struct` | 栈 / 寄存器 | 按值复制（字段级 RC，§7.4） | §3.2 / §7 |
| **堆句柄** | `Rc<T>` / `Weak<T>` / `Array<T>` / `String` / `StringBuilder` | 堆（RC 头 + payload） | 句柄复制 + retain | §3.3 / §9 |
| **堆作用域句柄** | `Heap<T>` | 堆（无 RC 头，裸 payload） | 单 owner，按值禁 move（B 档可空 move 例外，§8.X） | §3.3 / §9 |
| **借用** | `T&` | 指向栈或堆 payload 的非空指针 | 传指针，不可逃逸 | §3.2.3 / §8.3 |
| **FFI 指针** | `Ptr` | 任意地址，类型擦除 | 裸指针，仅 FFI 边界 | §3.3 / §9 |

类型档位是**封闭集合**：用户**不得**自定义新档位或新堆句柄；新堆形态需在编译器与 SDK 中显式落地（§9）。

> `Heap<T>` 与 `Rc<T>` 形态相似但**不可互换**：`Rc<Heap<T>>` / `Array<Heap<T>>`、以及 `Heap<T>` 作 `Rc<U>` 内层结构体字段，皆禁（§8.X / 诊断 Exxx3）。

## §3.2 类型构造

### §3.2.1 基本类型

| 类型 | 说明 | LLVM 落地 |
|---|---|---|
| `i8` `i16` `i32` `i64` | 有符号整数 | `iN` |
| `u8` `u16` `u32` `u64` | 无符号整数 | `iN`（符号靠操作区分） |
| `f32` `f64` | IEEE 754 单 / 双精度浮点 | `float` / `double` |
| `bool` | 布尔 | `i1`（ABI 上视实现） |

§3.2.1.1 v1 不提供 `i128` / `u128` / `f16` / `f128`；不提供独立 `char` 类型（代码点用 `u32`，§1.6.5）。

§3.2.1.2 v1 不提供独立的 `unit` / `void` 关键字。函数无返回值在语法层表现为 `fnHeader` 省略 `retType`；`statementExpr` 后的可选 `;` 表示"按空类型丢弃此值"（§5）。

### §3.2.2 复合类型

| 形态 | 产生式 | 说明 |
|---|---|---|
| `T?` | `typeNullable` | Nullable，§3.6 |
| `Foo<T1, T2>` | `typeGeneric` | 泛型实例 |
| `[T * N]` | `typeArray` | 固定大小数组，编译期长度 `N` |
| `()` | `typeUnit` | 零元素元组（unit），§3.8.1.0 |
| `(T1, T2, ...)` | `typeTuple` | 元组，长度 ≥ 2，§3.8 |
| 用户 `struct` | §7 | 名义类型；类型名可为 `typePath`（§3.2.5） |
| 用户 `enum` | §3.10 | 名义类型，值类型；类型名可为 `typePath` |
| `Function<P..., Ret>` | `typeGeneric`（特殊泛型） | 函数类型，结构等同（§3.11） |

固定大小数组 `[T * N]` 是值类型；`Array<T>` 是堆句柄类型，二者**不得**互换（§3.3 / §9）。元组 `(T1, T2, ...)` 同样为值类型。

### §3.2.3 借用类型 `T&`

§3.2.3.1 `T&` 由 `typeWithRef` 产生，**仅允许**出现在以下位置（语法层白名单，见 §2.6）：

- 函数参数类型（含方法 receiver `$`，自动隐式 `Self&`）；
- 局部变量类型（`let d T& = ...`）；
- `& expr` 表达式的结果类型。

§3.2.3.2 `T&` 在以下位置由 `yux.g4` 直接拒绝：

- 结构体字段（`filedDecl ::= ID type`，无 `&`）；
- `Array<T>` 元素 / `Rc<T>` 内层 / `Weak<T>` 内层（泛型实参用 `type` 而非 `typeWithRef`）；
- 全局 `#Cval let` 声明为 `T&` 类型；
- 嵌套：`T& &`。

> 函数返回值 `T&` 由 g4 产生式 `typeWithRef` 放行；合法性由 §8.6.10 溯源约束在语义层保证。

§3.2.3.3 `T&` 寿命与绑定规则见 §8.3 / §8.5；本章只规范类型构造形态。

### §3.2.4 灵活整数字面量

§3.2.4.1 **灵活整数（flexible integer）**是无后缀的整数字面量（如 `42`），其默认类型为 `i32`，但携带"灵活"标记——编译器在能**唯一确定**目标类型时，自动将该字面量推断为目标类型。

§3.2.4.2 后缀写法：`42i8`、`100u32`、`0xFFu64`。格式：数字 + `i`/`u` + 位宽（8/16/32/64）。后缀字面量**不**带灵活标记，固定为该类型。

§3.2.4.3 自动推断**生效**的场景：

| 场景 | 示例 | 说明 |
|------|------|------|
| `let` 声明带类型标注 | `let a i64 = 100` | 目标类型 `i64` 驱动推断 |
| 标量运算符对侧类型已知 | `a_u8 + 1` | `1` 从 `u8` 推断 |
| 比较运算符 | `a_i16 == 5` | `5` 从 `i16` 推断 |
| 非泛型、非重载函数唯一匹配 | `take_i64(100)` | 形参 `i64` 唯一确定 |
| `assert_eq` 泛型推断后 | `assert_eq(a_i8, 42)` | `T` 已由第一实参推断为 `i8`，灵活整数不覆盖 |

§3.2.4.4 自动推断**不生效**的场景（需后缀）：

| 场景 | 示例 | 原因 |
|------|------|------|
| 方法调用参数 | `arr.get(100)` | 重载消歧不覆盖 |
| 数组字面量元素 | `[10u32, 20u32]` | 元素类型不从 `Array<T>` 反向推断 |
| 泛型函数反向推断失败 | `let a i64 = identity(100)` | 泛型 `T` 从实参推断为 `i32`，不从目标类型反向传播 |
| 无类型标注的 `let` | `let a = 255u8` | 类型完全由表达式决定 |
| 超 `i32` 范围的 `u32` 值 | `4000000000u32` | 无后缀默认 `i32` 会溢出 |
| 需消歧的重载 | `foo(42i8) vs foo(42i16)` | 只有一个匹配时自动推断才生效 |

§3.2.4.5 灵活整数推断在 `resolveFnOverload` 阶段执行（sema 层，0 LLVM 依赖）：先以默认 `i32` 匹配收集候选重载，若恰好一个候选则以灵活模式重新匹配并推断目标类型；若多个候选匹配则报 E6014（歧义）。

§3.2.4.6 灵活整数推断完成后，编译器按推断的类型对实参 node 重编译（codegen 层），产出正确的 LLVM ConstantInt。

### §3.2.5 限定类型路径

§3.2.5.1 类型位（`type` / `typeWithRef`、struct 字面量 LHS、`Type::…`、match 的 enum、静态字段）的名字是 `typePath ::= ID ('.' ID)*`，不是单 `ID`。例：`Point`、`geom.Point`、`yux.core.map.Map<i32, i32>`、`io.IoErr`。

§3.2.5.2 用户类型身份 = **声明模块 + 短名**（实现上 `TypeInfo.ownerModule` + `name`）。路径只是定位写法，不进入类型名。`io.IoErr` 与 `yux.io.IoErr` 若指向同一声明则同一类型。

§3.2.5.3 全限定**只消歧、不引入**。必须先 `use`（默认隐式 `use yux.core.*` 算已导入 `yux.core`）。未 `use yux.io` 时写 `yux.io.T` 非法。查找规则见 §10.2.5。

## §3.3 内置泛型与堆句柄

下列类型由编译器 / SDK 协同实现，构成 yux 的"堆句柄"封闭集合；语义合约见 §9。

| 类型 | 用途 | 可空形式 | 可变性 |
|---|---|---|---|
| `Rc<T>` | 持有 RC 堆对象的强句柄 | `Rc<T>?` | payload 通过 `T` 自身字段决定 |
| `Weak<T>` | 弱引用；v1 仅配 `Rc<T>` | **原生可空**；`Weak<T>?` 禁（§3.7） |
| `Heap<T>` | 作用域绑定的单 owner 堆对象 | `Heap<T>?`（启用 B 档 nullable move，§8.X） | payload 通过 `T` 自身字段决定 |
| `Array<T>` | 动态数组 | `Array<T>?` | 通过 `Array<T>&` 借用允许修改 |
| `String` | 不可变 UTF 字符串 | `String?` | immutable |
| `StringBuilder` | 可变字符串构造器 | `StringBuilder?` | 通过 `StringBuilder&` 修改 |
| `Ref<T>` | 不可空原始指针（FFI / SDK 用） | 不允许 `Ref<T>?` | — |
| `Ptr` | FFI 指针 | 由用法决定 | — |

> *informative*：本节描述类型形态；具体方法、ABI 与语义见 §9。

`Heap<T>` 与 `Rc<T>` 之间**不存在** widen 关系：互转禁；`Heap<T>` → `Heap<T>?` 隐式 widen 亦禁（§8.X / 诊断 Exxx6）。

## §3.4 类型相等与可赋值性

### §3.4.1 名义等同

§3.4.1.1 用户结构体按**名义**判等：两个结构体类型等同当且仅当它们由同一 `structDecl` 产生（含相同泛型实参）。

§3.4.1.2 内置标量类型按名等同：`i32` 与 `u32` 不等同，与 `i64` 不等同；不同位宽 / 不同符号需显式转换（§3.5）。

§3.4.1.3 泛型实例 `Foo<A>` 与 `Foo<B>` 等同当且仅当 `A` 与 `B` 等同，递归判定。

§3.4.1.4 元组类型按**结构等同**（§3.8.1.3）；函数类型 `Function<P..., Ret>` 同样按**结构等同**（§3.11.4），形参类型 / 返回类型逐位等同即可。这两档与名义类型并列，是 yux 中按结构判等的两种复合类型。

### §3.4.2 可赋值性

下列赋值在赋值 / 形参 / 返回值 / `#Cval let` 初始化等位置允许，**无**隐式标量转换：

- §3.4.2.1 同名义类型间互相赋值。
- §3.4.2.2 `T` 赋给 `T?`：隐式包装为 `Nullable:<T>(value)`（§3.6.4）。
- §3.4.2.3 `null` 字面量赋给 `T?`：构造空 `Nullable<T>`。
- §3.4.2.4 数组字面量 `[e1, ..., eN]` 赋给 `[T * N]`：按元素逐项可赋值即可（§4 `exprArray`）。
- §3.4.2.5 数组填充 `[v ... T?]` 赋给 `[T * N]`：`v` 可赋值给 `T`（§4 `exprArrayInit`）。
- §3.4.2.6 `T&` / `Rc<T>` / `Array<T>` / `String` / `Weak<T>` 作 `extern fn` 实参传给 `Ptr` 形参时，**自动转换**（§9 与 [DRAFT §9.3](draft/DRAFT-所有权与引用.md#93-自动转换仅-extern-边界)）。这是规范层唯一允许的隐式类型转换。

§3.4.2.7 上述以外，任何不同类型间的赋值需通过 §3.5 的显式转换实现。

## §3.5 类型转换

§3.5.1 yux **不存在**隐式标量转换。`i32` 不会自动扩展为 `i64`；`f32` 不会自动转为 `f64`；`u8` 不会自动转为 `i32`。

§3.5.2 显式转换通过内置方法 `to_<type>()` 完成；下列方法**应当**由编译器或 SDK 内置类型方法表提供：

| 起点 | 终点 | 方法 |
|---|---|---|
| 任意整数 / 浮点 / `bool` | `i8 / u8 / i16 / u16 / i32 / u32 / i64 / u64` | `to_i8()` … `to_u64()` |
| 任意整数 / 浮点 | `f32 / f64` | `to_f32()`、`to_f64()` |
| 任意整数 / 浮点 | `bool` | `to_bool()`（0 → `false`，非零 → `true`） |
| 任意基本类型 | `String` | `to_string()` |

§3.5.3 转换语义遵从 LLVM 同名指令（`zext` / `sext` / `trunc` / `fptosi` / `fptoui` / `sitofp` / `uitofp` / `fptrunc` / `fpext`）；溢出 / 精度丢失**不**抛错，按目标类型按位截断或舍入。

§3.5.4 用户结构体类型间没有内置转换；如需转换**应当**自定义 `to_xxx` 方法（§7）。

§3.5.5 显式转 `Ptr` 走编译器 baked builtin `ptr_of:<T>(obj)`（§9），不进入 `to_*` 体系。

## §3.6 Nullable 语义

### §3.6.1 形态与解糖

§3.6.1.1 `T?` 是语法糖，由编译器解糖为 SDK 提供的 `Nullable<T>` 结构体；二者在所有规范层位置等同。

§3.6.1.2 `T?` 与 `Nullable<T>` 互相赋值无需显式转换；显式构造写 `Nullable:<T>(v)`（持值）或 `Nullable:<T>()`（空值）。

§3.6.1.3 `null` 字面量自身**没有**独立类型；只能在 `T?` 形参 / 变量 / 返回值的上下文出现，否则报错。例外：`Ptr` 可直接赋 `null`（§9.7.2.2），不走 `T?`。

### §3.6.2 方法

| 方法 | 含义 |
|---|---|
| `has() bool` | 是否持值 |
| `get() T` | 取出内层值；为空时调用 `_exit(1)` 终止进程 |

### §3.6.3 `??` 与 `?.`

§3.6.3.1 `a ?? b`：`a` 类型须为 `T?`；持值时返回内层 `T`，空时返回 `b`。`b` 类型应当可赋值给 `T`（§3.4.2）。

§3.6.3.2 `a?.field`：`a` 类型须为 `T?` 且 `T` 是结构体；`a` 持值返回 `field 的类型?`（即包装），空返回空。链式 `a?.b?.c` 自然展开。

§3.6.3.3 `a?.method(args)`：`a` 类型须为 `T?` 且 `T` 有方法 `method`。持值时以内部 `T` 为 receiver 调用（与 `a.method(args)` 同一套方法查找 / receiver 约定），结果类型为 `<方法返回类型>?`；空时**不**调用方法、**不**求值实参，结果为空。方法省略返回类型时结果为 `()?`。`a?.foo()?.bar()` 按 §4.6.2.2 逐级展开。

### §3.6.4 隐式包装

§3.6.4.1 `T` 类型值赋给 `T?` 上下文（变量赋值、形参传入、`ret expr`）时，编译器**自动**包装为 `Nullable:<T>(v)`。

§3.6.4.2 在表达式上下文（非赋值 / 非形参 / 非返回）单独写 `T?` 字面量需走显式构造；不在隐式包装范围内。

### §3.6.5 与堆句柄的组合

§3.6.5.1 `Rc<T>?` 合法：表达"可空的 Rc 句柄"。

§3.6.5.2 `Array<T>?` / `String?` 合法。

§3.6.5.3 `Weak<T>` **原生可空**，故 `Weak<T>?` 在语义层禁（§3.7、§8.5）。

§3.6.5.4 `T& ?` / `T?&` 等带 `&` 与 `?` 组合的写法由 `typeWithRef` 限制，参见 §3.2.3 与 §8.3.1。

## §3.7 类型构造的禁忌

下列类型构造规范层**不得**出现；其中一部分由 `yux*.g4` 在产生式层直接拒绝（§2.6），其余由编译器在语义阶段拒绝。

| 形态 | 拒绝层 | 原因 |
|---|---|---|
| `T& &` | 语法层（§2.6.1） | 嵌套引用无意义 |
| 字段位置 `T&` | 语法层（§2.6.2） | 借用不可逃逸出栈帧 / 堆对象 |
| 全局 / `#Cval let` 声明为 `T&` 类型 | 语法层 | 全局存储类型不可为借用 |
| `Array<T&>` / `Rc<T&>` / `Weak<T&>` | 语法层（容器内层用 `type`） | 同上，借用不可放进堆容器 |
| `Weak<T>?` | 语义层（§3.6.5.3） | `Weak` 原生可空，避免双层可空歧义 |
| `Ptr` 出现在用户代码非 FFI 上下文 | 风格 / 编译器警告 | `Ptr` 仅 FFI 边界使用（§9） |
| `Weak<Array<T>>` / `Weak<String>` | v1 语义层 | v1 弱引用仅配 `Rc<T>`（§9 / DRAFT §5.1） |
| `Weak<T>` 上的 `==` / `!=` | 语义层 | 改走 `same_ref:<T>` / 先 `upgrade` 后比较 |
| `as_ref(Rc<T>?)` / `as_ref(非 Rc<T>)` | 类型层 | `as_ref` 仅接 `Rc<T>`（§8.3.5.5） |
| `Array<T>&` 借用期内调用修改方法 | 语义层 | 防 Block 内部状态错乱（§8.4.2.5） |
| 用户泛型形参 `T` 推断 / 显式为 `U&` | 语义层 | T 必须为 owned 类型（§8.6.7.1） |
| `Weak<Function<...>>` | 语义层（§3.11.1） | 函数值是值类型，无 RC 头，无法被 `Weak` 弱引用 |
| `Function<...>` 用于 `extern fn` 形参 / 返回类型 | 语义层（§3.11.1） | v1 不支持函数类型跨 FFI 边界，推 v0.x+1 |
| `Function<...>` 上的 `==` / `!=` | 语义层（§3.11.8） | 函数值无良定义的相等语义 |

§3.7.1 上述清单与 §8.9 "禁忌一览" 应当保持一致；若新增或解除禁忌**应当**同步更新两处（Phase 6 验收点）。

## §3.8 元组

### §3.8.1 形态

### §3.8.1.0 unit 类型 `()`

§3.8.1.0.1 `()` 是元组族的零元素成员，语义上表示"无值"（unit / void）。作为函数**声明**返回类型时，显式 `()` 与省略 retType 等价。作为函数**类型** `Function<...>` 的末位时，`()` 表示 unit 返回（不可省略，因为末位永远是返回类型）。

§3.8.1.0.2 `()` 是可写出的合法类型名，可用于：
- 局部变量类型标注：`let x () = ()`（虽然实践中极少需要）
- 泛型默认实参等需要"空类型占位"的场景
- `fn` 返回类型显式标注为 `()`（与省略等价）

§3.8.1.0.3 `()` 类型的唯一合法值是 `()`（`exprUnit`，§4.2.1）。它与 `exprParen` 的 `(e)` 不同：空括号对 `()` 在语法层由 `ParStart ParEnd` 直接匹配为 `exprUnit`，不经过 `exprParen`。

§3.8.1.1 元组类型由两个产生式组成：`typeUnit ::= '(' ')'`（元素数 = 0）和 `typeTuple ::= '(' type (',' type)+ ')'`（元素数 ≥ 2）。`()` 是**零元素元组**（unit 类型），表示"无值"——类似传统语言的 `void`，但 `()` 自身是合法的类型名，可出现在泛型实参等需要"空类型"的位置。单元素 `(T)` 在语法层归为 `exprParen`，不构成元组。

在 `typeWithRef` 位上另有 `typeUnitWithRef`（对应 `()` 不带 `&`）。

§3.8.1.2 元组是**值类型**（§3.1）：按值复制，按字段级 RC 处理含堆句柄的元素（§7.4 / §8.5）；LLVM 落地为匿名 `struct`，元素按出现顺序排列。

§3.8.1.3 元组按**结构等同**：`(T1, T2)` 与 `(U1, U2)` 等同当且仅当 `T1 ≡ U1` 且 `T2 ≡ U2`（递归判定，§3.4.1）。这是规范层唯一的结构等同复合类型；用户结构体仍按名义判等。

### §3.8.2 构造

§3.8.2.1 `exprTuple ::= '(' expr ',' expr (',' expr)* ')'` 产生元组值。元素从左到右求值（§4.1.1）。

§3.8.2.2 元组构造表达式的类型由各元素表达式类型按位组合，不存在隐式拓宽（§3.5.1）；如需对齐元素类型应当显式 `to_T()` 转换或显式标注外层目标类型驱动整数字面量推断。

### §3.8.3 成员访问

§3.8.3.1 `exprTupleMember ::= expr DOT_NUM`，其中 `DOT_NUM ::= '.' INT_10`（§1 词法）。多级访问 `t.0.0` 由词法层把 `.0.0` 切成两个 `DOT_NUM` token，由 `exprTupleMember` 的左递归后缀链承接。

§3.8.3.2 `t.N` 类型为元组第 `N` 个元素类型（0-based）。`N` **应当**是字面整数；越界报 [E3100]。

§3.8.3.3 取成员仅是**借用**元组临时值（§4.1.2.3），不消费它；含堆句柄的元素按字段访问的 RC 规则处理（§7.4 / §8.5）。

### §3.8.4 解构声明

§3.8.4.1 形态：`statementLetTuple ::= letAnno* 'let' '(' ID (',' ID)+ ')' typeWithRef? '=' expr codeLineEnd`。仅支持**一层平铺 ID**，不支持嵌套模式与 `_` 占位。

§3.8.4.2 RHS 类型须为元组（含别名链解析后），否则报 [E3101]；元素数与名字数须相等，否则报 [E3102]。

§3.8.4.3 每个名字按对应位置元素类型登记到符号表；`let` 档位（默认 / `#Mut`）遵循 §5.1.2。

### §3.8.5 成员赋值

§3.8.5.1 `statementAssign` 的左侧路径允许 `DOT_NUM` 形态：`obj.0`、`obj.0.1` 等；要求每层路径上的当前类型都是元组，最末段必须为元组成员，越界报 [E3100]。

§3.8.5.2 复合赋值（`+=` 等）按 §5.2.1.3 等价于 `lhs = lhs OP rhs`，对元组成员一致适用。

§3.8.5.3 当前 v1 不支持"struct 字段链穿入元组"再赋值（如 `obj.field.0 = e`）；该形态由编译器拒绝，待后续阶段补齐。

### §3.8.6 与别名 / 泛型的协作

§3.8.6.1 透明类型别名 `IPair = (i32, i32)` 不引入新类型；声明 `let p IPair = (1, 2)` 与 `let p (i32, i32) = (1, 2)` 等价（§3.9）。

§3.8.6.2 泛型别名 `Pair<T> = (T, T)` 在使用点按实参单态化解析，仍为元组（§3.9.2）。

## §3.9 类型别名

### §3.9.1 形态

§3.9.1.1 顶层声明 `aliasDecl ::= ID genericDef? '=' type codeLineEnd` 引入透明类型别名。别名仅出现在文件顶层（§2.2.1），不在 `struct` 体内、不在函数体内。

§3.9.1.2 别名为**透明 type alias**（编译期等价、可隐式互转），不构成新名义类型。两个别名指向同一目标类型时，互相可赋值无需转换（§3.4.1）。

§3.9.1.3 形态唯一：`A = T`；不复用 `struct` 关键字（v1 移除曾经的 `struct A = T` 草稿写法）。

### §3.9.2 泛型别名

§3.9.2.1 `Pair<T> = (T, T)`：别名的类型形参在右侧 `type` 中可见，使用点需提供类型实参（如 `Pair<i32>`）。

§3.9.2.2 单态化时按实参替换 `T`，再按别名规则继续解析；解析结果与展开形态在所有规范层位置等同。

### §3.9.3 解析与禁忌

§3.9.3.1 编译器在类型解析路径上对别名做**透明替换**（`Compiler::resolveAlias` + 接入 `applySubst`）；二元运算符四个入口、自定义算子方法、声明 / 调用侧 mangle 名等均经过别名归一化，保证 lookup 字面差异被消除。

§3.9.3.2 别名**禁止成环**（直接或间接）：解析时维护 visited 集合，遇环报 [E2016]。

§3.9.3.3 别名名与已有 `struct` / 别名同名报 [E2017]。

§3.9.3.4 别名右侧 `type` 不得含 `T&`（与全局 / 字段位置同理，§3.2.3.2）。

§3.9.3.5 别名不为目标类型新增方法解析路径；`A = i32` 时 `a A` 仍走 `i32` 的方法表（与 `Rc<A>` / `Array<A>` 等容器一致）。

## §3.10 枚举（enum）

### §3.10.1 形态与档位

§3.10.1.1 顶层声明 `enumDecl ::= 'enum' ID '{' (enumVariant | comment | codeLineEnd)* '}'` 引入一个**名义类型**（§3.4.1），与 `struct` 同档：值类型，按值复制，可作字段 / 形参 / 返回值 / 局部变量 / 容器元素出现。

§3.10.1.2 `enumVariant ::= ID ('(' type (',' type)* ')')?`，即"短名 + 可选 tuple-style payload 类型列表"。零参 variant 不写括号；payload tuple 至少含一个元素，零元 payload 由零参 variant 表达。

§3.10.1.3 enum **是值类型（§3.1）**：栈布局，含 RC payload 字段时按 tag dispatch retain / release（运行时细节见 §8 和草案 [draft/DRAFT-枚举.md](draft/DRAFT-枚举.md) §6）。要上堆用 `Rc<E>`，与既有 `Rc<T>` 协议复用。

### §3.10.2 声明位置与结构约束

§3.10.2.1 enum 仅出现在文件顶层（§2.2.1）；**不得**嵌套于函数体、struct 体、其它 enum 体。

§3.10.2.2 variant **一行一个**，行尾**不写** `,`（与 struct 字段同规约）；在同一行写多个 variant 属语法错误。

§3.10.2.3 同一 enum 内 variant 名**不得**重复，违者报 [E2018]；不同 enum 之间 variant 名互不干扰。

§3.10.2.4 enum 名进类型命名空间，受 §10 模块规则约束，与 `struct` / 类型别名 / 内置类型同名报 [E2017]。

§3.10.2.5 空 enum `enum E { }`（无 variant）**应当**在编译期拒绝；单 variant `enum E { Only }` 合法。

§3.10.2.6 v1 **不**支持泛型 enum `enum E<T> { ... }`、enum 上的 `impl` 块 / 方法 / draft 实现、struct-style payload `V { f: T }`、显式 discriminant `Red = 1`。

### §3.10.3 payload 类型限制

§3.10.3.1 payload 元素类型与"普通类型出现位置"一致：可为基础类型、struct、`Rc<T>` / `Array<T>` / `String` / `T?` / tuple `(T1, T2)`，以及类型别名。

§3.10.3.2 payload 中**不得**出现 `T&`（与 struct 字段同规约，§3.2.3.2）；产生式层 `enumVariant` 仅接 `type` 而非 `typeWithRef`。

### §3.10.4 variant 访问与全限定

§3.10.4.1 variant 名**不**进顶层命名空间，必须经 `E::` 限定访问（语义等同 C++ `enum class`）；裸 `V` 形式由编译器在表达式 / 模式位置拒绝。

§3.10.4.2 类型别名透明传递 variant 访问路径：`type C = E` 后 `C::V` 与 `E::V` 等价（沿用 §3.9 的别名透明替换）。别名同样**不**为裸 `V` 开口子。

### §3.10.5 discriminant 不可观测

§3.10.5.1 v1 **不**暴露 enum 的 tag 整数：禁止 `e as i32`、禁止显式 `Red = 1` 写法、禁止访问任何形如 `e.tag` 的字段。tag 类型（当前固定为 `i32`）与编码顺序为实现细节，**不**构成 ABI 承诺。

§3.10.5.2 enum 的唯一稳定读取通道是 `match` 表达式（§4 / §5，见 [draft/DRAFT-枚举.md](draft/DRAFT-枚举.md) §5）；不允许任何其它方式从 enum 取出 payload。

### §3.10.6 与既有特性的相容性

| 特性 | 行为（v1） |
|---|---|
| `Rc<E>` | 允许；按现有 Rc 协议 retain / release，析构按 tag dispatch payload 析构 |
| `Array<E>` | 允许；元素按值存储，移动 / 拷贝行为遵循 enum 自身规则 |
| `E?` | 允许；按 §3.6 Nullable 规则展开 |
| 类型别名 `type C = E` | 允许；`C::V ≡ E::V`（§3.9 / §3.10.4.2） |
| 泛型 enum `enum E<T> { ... }` | **不允许**（§3.10.2.6） |
| enum 上的方法 / `impl` 块 / draft 实现 | **不允许**（§3.10.2.6） |
| 显式 discriminant / `as i32` | **不允许**（§3.10.5.1） |
| 裸 variant `V` | **不允许**（§3.10.4.1） |

§3.10.6.1 enum 不参与隐式转换；`E1` 与 `E2` 是无关类型，即便 variant 名相同。

§3.10.6.2 enum 是**封闭**的：所有 variant 在声明处一次列全；不允许跨文件 / 跨模块追加。

### §3.10.7 构造与读取

§3.10.7.1 构造表达式 `E::V` / `E::V()` / `E::V(args)` 见 §4 与草案 [draft/DRAFT-枚举.md](draft/DRAFT-枚举.md) §4：零参形态 `E::V` 与 `E::V()` 等价；带 payload 形态实参与 variant payload 元素**按位置严格类型匹配**（无隐式转换）。

§3.10.7.2 读取仅经 `match`（§4 / §5）；arm 体为 `=> expr` 或 `=> { stmts }`（块值规则同 §5.4.4）。穷尽性、binding 形态、`else` 兜底等规则见对应章节及草案 §5。

§3.10.7.3 v1 实施进度（informative）：声明 / 全部构造形态 / `match` 最小子集（穷尽 + binding + `else`）已落地，回归位于 `sdk/yux/src/yux/core/enum.test.yux`。

## §3.11 函数类型 `Function<P..., Ret>`

§3.11 函数类型 `Function<P1, P2, ..., Ret>` 是值类型（§3.1）；运行时表示与 RC / ABI 见 §8。它是编译器内置的**特殊泛型**（与 `Rc` / `Array` 同档，不是新关键字），走已有 `typeGeneric` / `typeGenericWithRef` 产生式。函数**声明** `fn foo(...)` 仍用关键字 `fn`，与本节无关。

### §3.11.1 出现位置

可在以下位置使用：

- 局部变量类型：`let f Function<i32> = ...`
- 函数形参 / 返回类型（任意嵌套）：`fn map(f Function<i32, i32>)`、`fn make_counter() Function<i32>`
- 类型别名右侧（§3.9）：`Callback = Function<String, bool>`
- 元组元素：`(Function<i32>, i32)`
- 结构体字段、`Array<...>` / `Rc<...>` 内层：✅ 合法
- `Weak<...>` 内层：❌ 禁（函数值不是堆句柄，无 RC 头；§3.7）
- `T&` 借用：`Function<P..., Ret>&` 合法（§3.2.3.1）
- `extern fn` 形参 / 返回类型：❌ v1 禁（推 v0.x+1）

### §3.11.2 形态

`Function` 至少带 1 个类型实参；**末位永远是返回类型**，其前为形参类型（可为零个）：

| 写法 | 含义 |
|---|---|
| `Function<()>` | 0 参，返回 unit |
| `Function<i32>` | 0 参，返回 `i32` |
| `Function<i32, ()>` | 1 参 `i32`，返回 unit |
| `Function<i32, bool>` | 1 参 `i32`，返回 `bool` |
| `Function<i32, i32, bool>` | 2 参，返回 `bool` |

§3.11.2.1 裸 `Function`（无类型实参）与空 `Function<>` 皆非法。`genericDef` 不允许空 `<>`；裸名由语义层拒绝（与裸 `Rc` 同）。

§3.11.2.2 类型实参槽只写类型，**不**写形参名 / 组糖。文档用途走类型别名：`Callback = Function<String, bool>`。

§3.11.2.3 `Function` 不是用户可声明的 struct 名；与 `Rc` / `Array` 同为编译器保留的内置泛型名。

§3.11.2.4 LLVM 符号中的函数类型 mangle 与源码同形：`Function<i32,i32>`；unit 返回写 `()`（不再写 `void`）。含函数类型形参的函数符号如 `mod.apply(Function<i32,i32>,i32)`。

### §3.11.3 可空 `Function<...>?`

整个函数值可空走标准 `?` 后缀，与 `i32?` / `Rc<T>?` 同形：

| 写法 | 含义 |
|---|---|
| `Function<i32, i32>?` | 函数值可空 |
| `Function<i32, i32?>` | 函数值不可空，返回 `i32?` |
| `Function<i32, i32?>?` | 双层：函数值可空，且返回 `i32?` |

§3.11.3.1 可空函数值的运行时布局与非空相同：16 字节 fat-ptr `{ fn_ptr, captures }`。空值以 `fn_ptr == null` 表示，**不**套 `Nullable<T>` 的 `{has, value}` 外壳。

§3.11.3.2 `Function<...>?` 在语法上走 §3.6 `typeNullable`；实现层折叠为 fat-ptr 可空，不分配额外 `_has` 字段。

### §3.11.4 类型相等

`Function<P1, ..., Pn, R>` ≡ `Function<Q1, ..., Qm, S>` 当且仅当：

1. 类型实参数相等（含末位 Ret）：`n + 1 = m + 1`；
2. 各位置形参类型 §3.4.1 等同：`Pᵢ ≡ Qᵢ`；
3. 返回类型等同：`R ≡ S`（`()` 与省略的 unit 等同）；
4. 可空性等同：`Function<...>` ≢ `Function<...>?`。

与元组（§3.8.1.3）并列，是 yux 中第二档"按结构等同"的复合类型；用户 struct / enum 仍按名义判等。

### §3.11.5 与类型别名

复用 §3.9 透明替换，无新规则：

```yux
Callback = Function<String, bool>
Predicate<T> = Function<T, bool>

let p Callback = ...               ; 与 Function<String, bool> 等同
fn each<T>(arr Array<T>, p Predicate<T>) { ... }
```

### §3.11.6 与借用 `T&`

§3.11.6.1 形参位置 `T&` 合法：`Function<Rc<T>, T&, T?>`。`T&` 作为 `Function` 的类型实参目前仅在 `typeWithRef` 位（形参 / 返回 / 局部声明）可写——`genericDef` 实参槽不允许 `Type&`（与 `Dyn<D&>` 同缺口，待后续放开）。因此含 `T&` 形参的函数类型**暂不能**作 struct 字段。

§3.11.6.2 返回 `T&`：沿用 §8.6.10 溯源约束。函数类型本身不重新定义溯源规则；使用点（lambda 字面量 / fn 声明）须满足 §8.6.10。

§3.11.6.3 借用一个函数值 `Function<P..., Ret>&` 合法；寿命与传递规则见 §8。

### §3.11.7 写法示例

```yux
; 0 参 / unit
Function<()>
Function<i32>

; 单 / 多参（末位为返回类型）
Function<i32, i32>
Function<i32, ()>
Function<String, i32, bool>

; 嵌套 / 高阶
fn op(f Function<i32, i32, i32>) i32
fn make_adder(n i32) Function<i32, i32>

; 别名 / 容器 / nullable
Callback = Function<String, bool>
let p (Function<i32>, i32) = ...

let f Function<()>?                 ; 可空函数值
let g Function<i32>?
let h Function<String, i32?>        ; 函数值不可空，返回 i32?
let k Function<String, i32?>?       ; 双层 nullable
```

### §3.11.8 比较

§3.11.8.1 函数类型不实现 `==` / `!=`；规范层禁止用于函数类型。

§3.11.8.2 不提供地址相等 builtin（避免暴露 fn 指针 / captures 地址 / trampoline 共享等实现细节）。
