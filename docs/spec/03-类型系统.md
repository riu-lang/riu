# §3 类型系统

本章规范 yux 的类型构造、可赋值性、转换与禁忌。具体内置类型的语义合约（`Box<T>`、`Array<T>` 等）见 §9；与所有权 / 引用相关的细节见 §8。

## §3.1 类型档位

yux 的类型按存储与传参语义分为四档（见 [draft/DRAFT-所有权与引用.md](draft/DRAFT-所有权与引用.md) §2 / §8）：

| 档位 | 写法 | 存储 | 传参语义 | 章节 |
|---|---|---|---|---|
| **值类型** | 内置标量 / 用户 `struct` | 栈 / 寄存器 | 按值复制（字段级 RC，§7.4） | §3.2 / §7 |
| **堆句柄** | `Box<T>` / `Weak<T>` / `Array<T>` / `String` / `StringBuilder` | 堆（RC 头 + payload） | 句柄复制 + retain | §3.3 / §9 |
| **借用** | `T&` | 指向栈或堆 payload 的非空指针 | 传指针，不可逃逸 | §3.2.3 / §8.3 |
| **FFI 指针** | `Ptr` | 任意地址，类型擦除 | 裸指针，仅 FFI 边界 | §3.3 / §9 |

类型档位是**封闭集合**：用户**不得**自定义新的"堆句柄"类型；所有新堆句柄需在编译器与 SDK 中显式落地（§9）。

## §3.2 类型构造

### §3.2.1 基本类型

| 类型 | 说明 | LLVM 落地 |
|---|---|---|
| `i8` `i16` `i32` `i64` | 有符号整数 | `iN` |
| `u8` `u16` `u32` `u64` | 无符号整数 | `iN`（符号靠操作区分） |
| `f32` `f64` | IEEE 754 单 / 双精度浮点 | `float` / `double` |
| `bool` | 布尔 | `i1`（ABI 上视实现） |

§3.2.1.1 v1 不提供 `i128` / `u128` / `f16` / `f128`；不提供独立 `char` 类型（代码点用 `u32`，§1.6.5）。

§3.2.1.2 v1 不提供独立的 `unit` / `void` 关键字。函数无返回值在语法层表现为 `fnHeader` 省略 `retType`；`statementExpr` 后的可选 `;` 表示"按空类型丢弃此值"（§5）。

### §3.2.2 复合类型

| 形态 | 产生式 | 说明 |
|---|---|---|
| `T?` | `typeNullable` | Nullable，§3.6 |
| `Foo<T1, T2>` | `typeGeneric` | 泛型实例 |
| `[T * N]` | `typeArray` | 固定大小数组，编译期长度 `N` |
| 用户 `struct` | §7 | 名义类型 |

固定大小数组 `[T * N]` 是值类型；`Array<T>` 是堆句柄类型，二者**不得**互换（§3.3 / §9）。

### §3.2.3 借用类型 `T&`

§3.2.3.1 `T&` 由 `typeWithRef` 产生，**仅允许**出现在以下位置（语法层白名单，见 §2.6）：

- 函数参数类型（含方法 receiver `$`，自动隐式 `Self&`）；
- 局部变量类型（`var d T& = ...`）；
- `& expr` 表达式的结果类型。

§3.2.3.2 `T&` 在以下位置由 `yux.g4` 直接拒绝：

- 结构体字段（`filedDecl ::= ID type`，无 `&`）；
- `Array<T>` 元素 / `Box<T>` 内层 / `Weak<T>` 内层（泛型实参用 `type` 而非 `typeWithRef`）；
- 全局 `cval`；
- 函数返回值；
- 嵌套：`T& &`。

§3.2.3.3 `T&` 寿命与绑定规则见 §8.3 / §8.5；本章只规范类型构造形态。

## §3.3 内置泛型与堆句柄

下列类型由编译器 / SDK 协同实现，构成 yux 的"堆句柄"封闭集合；语义合约见 §9。

| 类型 | 用途 | 可空形式 | 可变性 |
|---|---|---|---|
| `Box<T>` | 持有 RC 堆对象的强句柄 | `Box<T>?` | payload 通过 `T` 自身字段决定 |
| `Weak<T>` | 弱引用；v1 仅配 `Box<T>` | **原生可空**；`Weak<T>?` 禁（§3.7） |
| `Array<T>` | 动态数组 | `Array<T>?` | 通过 `Array<T>&` 借用允许修改 |
| `String` | 不可变 UTF 字符串 | `String?` | immutable |
| `StringBuilder` | 可变字符串构造器 | `StringBuilder?` | 通过 `StringBuilder&` 修改 |
| `Ref<T>` | 不可空原始指针（FFI / SDK 用） | 不允许 `Ref<T>?` | — |
| `Ptr` | FFI 指针 | 由用法决定 | — |

> *informative*：本节描述类型形态；具体方法、ABI 与语义见 §9。

## §3.4 类型相等与可赋值性

### §3.4.1 名义等同

§3.4.1.1 用户结构体按**名义**判等：两个结构体类型等同当且仅当它们由同一 `structDecl` 产生（含相同泛型实参）。

§3.4.1.2 内置标量类型按名等同：`i32` 与 `u32` 不等同，与 `i64` 不等同；不同位宽 / 不同符号需显式转换（§3.5）。

§3.4.1.3 泛型实例 `Foo<A>` 与 `Foo<B>` 等同当且仅当 `A` 与 `B` 等同，递归判定。

### §3.4.2 可赋值性

下列赋值在赋值 / 形参 / 返回值 / `cval` 初始化等位置允许，**无**隐式标量转换：

- §3.4.2.1 同名义类型间互相赋值。
- §3.4.2.2 `T` 赋给 `T?`：隐式包装为 `Nullable:<T>(value)`（§3.6.4）。
- §3.4.2.3 `null` 字面量赋给 `T?`：构造空 `Nullable<T>`。
- §3.4.2.4 数组字面量 `[e1, ..., eN]` 赋给 `[T * N]`：按元素逐项可赋值即可（§4 `exprArray`）。
- §3.4.2.5 数组填充 `[v ... T?]` 赋给 `[T * N]`：`v` 可赋值给 `T`（§4 `exprArrayInit`）。
- §3.4.2.6 `T&` / `Box<T>` / `Array<T>` / `String` / `Weak<T>` 作 `extern fn` 实参传给 `Ptr` 形参时，**自动转换**（§9 与 [DRAFT §9.3](draft/DRAFT-所有权与引用.md#93-自动转换仅-extern-边界)）。这是规范层唯一允许的隐式类型转换。

§3.4.2.7 上述以外，任何不同类型间的赋值需通过 §3.5 的显式转换实现。

## §3.5 类型转换

§3.5.1 yux **不存在**隐式标量转换。`i32` 不会自动扩展为 `i64`；`f32` 不会自动转为 `f64`；`u8` 不会自动转为 `i32`。

§3.5.2 显式转换通过内置方法 `to_<type>()` 完成；下列方法**应当**由编译器或 SDK 内置类型方法表提供：

| 起点 | 终点 | 方法 |
|---|---|---|
| 任意整数 / 浮点 / `bool` | `i8 / u8 / i16 / u16 / i32 / u32 / i64 / u64` | `to_i8()` … `to_u64()` |
| 任意整数 / 浮点 | `f32 / f64` | `to_f32()`、`to_f64()` |
| 任意整数 / 浮点 | `bool` | `to_bool()`（0 → `false`，非零 → `true`） |
| 任意基本类型 | `String` | `to_string()` |

§3.5.3 转换语义遵从 LLVM 同名指令（`zext` / `sext` / `trunc` / `fptosi` / `fptoui` / `sitofp` / `uitofp` / `fptrunc` / `fpext`）；溢出 / 精度丢失**不**抛错，按目标类型按位截断或舍入。

§3.5.4 用户结构体类型间没有内置转换；如需转换**应当**自定义 `to_xxx` 方法（§7）。

§3.5.5 显式转 `Ptr` 走编译器 baked builtin `ptr_of:<T>(obj)`（§9），不进入 `to_*` 体系。

## §3.6 Nullable 语义

### §3.6.1 形态与解糖

§3.6.1.1 `T?` 是语法糖，由编译器解糖为 SDK 提供的 `Nullable<T>` 结构体；二者在所有规范层位置等同。

§3.6.1.2 `T?` 与 `Nullable<T>` 互相赋值无需显式转换；显式构造写 `Nullable:<T>(v)`（持值）或 `Nullable:<T>()`（空值）。

§3.6.1.3 `null` 字面量自身**没有**独立类型；只能在 `T?` 形参 / 变量 / 返回值的上下文出现，否则报错。

### §3.6.2 方法

| 方法 | 含义 |
|---|---|
| `has() bool` | 是否持值 |
| `get() T` | 取出内层值；为空时调用 `_exit(1)` 终止进程 |

### §3.6.3 `??` 与 `?.`

§3.6.3.1 `a ?? b`：`a` 类型须为 `T?`；持值时返回内层 `T`，空时返回 `b`。`b` 类型应当可赋值给 `T`（§3.4.2）。

§3.6.3.2 `a?.field`：`a` 类型须为 `T?` 且 `T` 是结构体；`a` 持值返回 `field 的类型?`（即包装），空返回空。链式 `a?.b?.c` 自然展开。v1 **不**支持 `a?.method(...)` 形式。

### §3.6.4 隐式包装

§3.6.4.1 `T` 类型值赋给 `T?` 上下文（变量赋值、形参传入、`ret expr`）时，编译器**自动**包装为 `Nullable:<T>(v)`。

§3.6.4.2 在表达式上下文（非赋值 / 非形参 / 非返回）单独写 `T?` 字面量需走显式构造；不在隐式包装范围内。

### §3.6.5 与堆句柄的组合

§3.6.5.1 `Box<T>?` 合法：表达"可空的 Box 句柄"。

§3.6.5.2 `Array<T>?` / `String?` 合法。

§3.6.5.3 `Weak<T>` **原生可空**，故 `Weak<T>?` 在语义层禁（§3.7、§8.5）。

§3.6.5.4 `T& ?` / `T?&` 等带 `&` 与 `?` 组合的写法由 `typeWithRef` 限制，参见 §3.2.3 与 §8.3.1。

## §3.7 类型构造的禁忌

下列类型构造规范层**不得**出现；其中一部分由 `yux*.g4` 在产生式层直接拒绝（§2.6），其余由编译器在语义阶段拒绝。

| 形态 | 拒绝层 | 原因 |
|---|---|---|
| `T& &` | 语法层（§2.6.1） | 嵌套引用无意义 |
| 字段位置 `T&` | 语法层（§2.6.2） | 借用不可逃逸出栈帧 / 堆对象 |
| 函数返回值 `T&` | 语法层（§2.6.3） | 借用不可逃逸出调用 |
| 全局 / `cval` 中的 `T&` | 语法层 | 全局存储无可追踪寿命 |
| `Array<T&>` / `Box<T&>` / `Weak<T&>` | 语法层（容器内层用 `type`） | 同上，借用不可放进堆容器 |
| `Weak<T>?` | 语义层（§3.6.5.3） | `Weak` 原生可空，避免双层可空歧义 |
| `Ptr` 出现在用户代码非 FFI 上下文 | 风格 / 编译器警告 | `Ptr` 仅 FFI 边界使用（§9） |
| `Weak<Array<T>>` / `Weak<String>` | v1 语义层 | v1 弱引用仅配 `Box<T>`（§9 / DRAFT §5.1） |
| `Weak<T>` 上的 `==` / `!=` | 语义层 | 改走 `same_ref:<T>` / 先 `upgrade` 后比较 |
| `as_ref(Box<T>?)` / `as_ref(非 Box<T>)` | 类型层 | `as_ref` 仅接 `Box<T>`（§8.3.5.5） |
| `Array<T>&` 借用期内调用修改方法 | 语义层 | 防 Block 内部状态错乱（§8.4.2.5） |
| 用户泛型形参 `T` 推断 / 显式为 `U&` | 语义层 | T 必须为 owned 类型（§8.6.7.1） |

§3.7.1 上述清单与 §8.9 "禁忌一览" 应当保持一致；若新增或解除禁忌**应当**同步更新两处（Phase 6 验收点）。

## Open Issues

- `unit` / `void` 是否升格为可写出的类型名（用于泛型默认实参等场景）。
- 用户自定义"零拷贝句柄"类型（如自定义 `Cow<T>`）的设计窗口。
- `to_string()` 的语义合约（栈分配 vs 堆 `String` vs FFI 字符串）尚需在 §9 单列条款。
