; 草案范本：yux 特性级提案

> 本文件是**草案的骨架范本**，不是某个具体特性的草案。
> 真正的特性草案命名为 `DRAFT-<特性名>.md`，与本文件同放在 `docs/spec/draft/` 下，**入 git**（见 [RULES.md](../../../RULES.md)）。
>
> **草案不一定实施**：本目录用于沉淀设计讨论与决议，是否落地以 `docs/spec/` 正文为准。草案与 spec 冲突时以 spec 为准；spec 未收口前，草案仅供参考、不构成实现承诺。
>
> 草案定型后，按本范本末尾「定型与归宿」段拆分迁入 `docs/spec/` 正文与 `docs/spec/CHANGELOG.md`；原 DRAFT 文件可保留为历史档（在头部标注「已落地，见 §N」）或删除，二选一。
>
> 适用对象：跨多个 spec 章节的语言面设计（如所有权、模块系统重构、泛型、错误处理）。
> 不适用：单点条款修订（直接改 spec + CHANGELOG），或纯实现细节（不触发 spec 回写）。

## 定型与归宿

草案定型后按以下步骤拆分迁入正式文档：

1. **§10.5 列出的每个 spec 章节**逐条改写，引用本草案条目编号（如 [#2.3.B]）保留可追溯性。
2. **`docs/spec/CHANGELOG.md`** 顶部追加一条，摘要 + 影响章节，日期为合并日。
3. **附录 A / B / C** 按 §10 同步。
4. **`CURRENT.md`** 的 Phase 列表从 §10 派生，每完成一个阶段就地更新；全部完成后归档到 `docs/dev/<topic>-impl-log.md`（剔除人名/路径/行号/测试计数）。
5. 处置 `docs/spec/draft/DRAFT-<特性名>.md`：要么删除，要么在头部加一句「已落地，见 §N.M」并保留为历史档。
