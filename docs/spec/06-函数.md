# §6 函数

本章规范 yux 函数的声明、参数、返回、泛型与调用 ABI。语法形态见 §2 / [附录 B §B.4](附录B-语法汇总.md#b4-函数)；调用约定与 RC 协议的实施细节见 §8.5；FFI 见 §9 与 §10。

## §6.1 函数声明

### §6.1.1 形态

```
fn ::= fnHeader fnBody?
fnHeader ::= buildAnno*
             'fn' genericDef? ID '(' fnParams? ')' (retType=type)?
fnBody ::= fnExprkBody | fnBlockBody
fnExprkBody ::= LineEnd? '=' expr codeLineEnd?
fnBlockBody ::= statementBlock
```

§6.1.1.1 函数名为 `ID`；以 `_` 起始者为模块私有（§10）。

§6.1.1.2 `fnHeader` 不带 `fnBody` 时**仅**允许两种位置：

- 在 `extern { ... }` 块内（FFI 声明，§6.6）；
- 顶层带 `buildAnno`（编译器内置 / 代码生成，例如 `#CompilerInner` 标注的内置签名）。

普通顶层 `fn` 缺 `fnBody` 属编译期错误。

§6.1.1.3 表达式体形态 `fn f(...) T = expr` 等价于 `fn f(...) T { ret expr }`：

- 不需要写 `ret`；
- `expr` 类型须可赋值给 `retType`；
- `=` 与 `expr` 之间的 `LineEnd` 可选（产生式 `LineEnd?`）。

§6.1.1.4 块体形态 `fn f(...) T { ... }` 内部的 `ret` 由 §5.6 规范。

### §6.1.2 析构函数 `fn ~()`

§6.1.2.1 形态 `fnClean ::= 'fn' '~' '(' ')' fnBody`；只能出现在 `structImpl` 块内（§7.5），且每个类型至多一个。

§6.1.2.2 析构函数无形参、无返回值；在结构体析构时由编译器在字段级 release 之**前**调用（详见 §7.5 / §8.5.5）。

§6.1.2.3 `fn ~()` 内部 `$` 类型为 `Self&`；可访问字段，但**不得**在析构序中再触发新的析构（v1 行为未定义；规范层不强制检查）。

### §6.1.3 构建注解 `buildAnno`

§6.1.3.1 形态 `'#' ID codeLineEnd`，可前置在 `fn` / `externDecl` / `globalConst` / `structDecl` / `structImpl` 之前。

§6.1.3.2 v1 已识别的注解集合见 §11；其它 `#Foo` 当前会被解析但不绑定语义，详见 §11 Open Issues。

## §6.2 参数

### §6.2.1 形态

```
fnParams ::= fnParam (',' fnParam)*
fnParam ::= fnParamStd | fnParamGroup
fnParamStd ::= ID typeWithRef
fnParamGroup ::= (ID ',')* ID typeWithRef
```

§6.2.1.1 `fnParamGroup` 让多个连续同类型形参共享类型声明：

```yux
fn add(a, b i32) i32 = a + b      ; ≡ fn add(a i32, b i32) i32 = a + b
fn calc(a, b i32, c f64) f64 { ... }
```

§6.2.1.2 形参类型用 `typeWithRef`，即允许尾部 `&` 表示借用形参（§3.2.3、§6.2.3）。

§6.2.1.3 形参名在函数体内为局部变量；隐含**不可重赋值**（v1 视形参为 `val` 风），但形参名内的字段对可变路径仍可写（详见 §5.2）。

### §6.2.2 普通参数

§6.2.2.1 普通参数按 §3.1 的类型档位决定传参语义：

| 形参类型档位 | 调用方语义 | callee 视角 |
|---|---|---|
| 值类型（标量 / 用户 `struct` / `[T * N]`） | 按值复制（含字段级 RC） | 局部值 |
| 堆句柄（`Box<T>` / `Array<T>` / `String` / `Weak<T>` / `StringBuilder`） | 句柄复制 + retain | 局部句柄，作用域结束 release |
| `T&` | 实参须显式 `&x` | 借用，禁止逃逸 |
| `Ptr` | 实参可为同类 `Ptr`，或在 extern 边界由堆句柄 / `T&` 自动转 | 裸指针 |

§6.2.2.2 用户结构体形参**默认按值传**（与 DRAFT §2 决定一致）；编译器可在 ABI 层用指针传大结构体作为不可观测优化。

### §6.2.3 引用参数 `T&`

§6.2.3.1 `T&` 形参的实参**必须**显式取址 `f(&x)`；**不**自动加 `&`（DRAFT §3.6）。

§6.2.3.2 `T&` 形参在 callee 内的寿命同函数体局部作用域；不可作为 `T&` 字段被存（语法层禁，§2.6.2），不可作为返回值（语法层禁，§2.6.3）。

§6.2.3.3 `T&` 形参可被进一步 `&`（结果为子字段的 `T&`），其寿命遵循 §8.4。

### §6.2.4 receiver `$`

§6.2.4.1 结构体方法的 receiver 由编译器隐式注入，类型恒为 `Self&`；调用方写 `obj.method(args)`，**不**写 `&obj`（DRAFT §3.6 / §1.G）。

§6.2.4.2 `$` 在方法体内可读字段、写字段（前提受 §5.2 约束）、传给接收 `Self&` 的辅助函数；**不**作为返回值或字段（§4.3.2 / §7.4.3）。

§6.2.4.3 v1 **不**引入 UFCS（`Type::method(self, ...)` 风），统一以 `obj.method(args)` 形式。

## §6.3 返回值

### §6.3.1 形态

§6.3.1.1 `retType` 由 `type`（**不**含 `&`）产生；故返回值**不得**为 `T&` 形态（§2.6.3）。

§6.3.1.2 缺 `retType` 表示函数无返回值（"返回空类型"）；与 `ret;` 配合使用（§5.6.1.2）。

### §6.3.2 返回值的所有权移交

§6.3.2.1 返回值类型为堆句柄类型时，`ret expr` 走 **move-return + 实现 i**：编译器在每条 `ret` 路径前为 `expr` 生成 retain；callee 末尾的析构 release 自然与之抵消，使调用方净得 `+1`（详见 §8.5.3）。

§6.3.2.2 返回值类型为用户 `struct` 时按值复制返回；含 RC 字段则字段级 retain（§8.5.5）。

§6.3.2.3 返回值类型为标量 / `[T * N]` 时直接按位返回，无 RC 行为。

### §6.3.3 类型匹配

§6.3.3.1 `ret expr` 中 `expr` 类型须可赋值给 `retType`（§3.4.2）。`T` → `T?` 的隐式包装在此适用（§3.6.4）。

§6.3.3.2 多分支返回（如 `if` 各分支均含 `ret`）的整体类型一致性由各 `ret expr` 自身的可赋值性单独保证；不要求各分支表达式类型完全一致。

## §6.4 泛型函数

### §6.4.1 声明

§6.4.1.1 形态：`fn <T1, T2, ...> name(params) RetType { ... }`。`genericDef` 列表中是类型形参名（按 `type` 产生式落于 `typeNormal`，即裸 `ID`）。

§6.4.1.2 v1 仅支持类型参数；**不**支持类型约束（trait bounds）、不支持值参数。

§6.4.1.3 类型形参在签名与函数体内可作 `type` 使用，包括嵌套泛型 `Box<T>`、`Array<T>` 等。

### §6.4.2 实例化与 turbofish

§6.4.2.1 调用形态 `name:<T1, T2>(args)` 显式指定类型实参。turbofish 前缀 `:` 让解析器明确进入泛型实例化分支，避免 `name<T>(args)` 被解析为比较表达式（§2.4 / `docs/函数.md`）。

§6.4.2.2 不写 turbofish 时编译器按实参类型推断；推断失败属编译期错误。

§6.4.2.3 编译器对每个具体实参组合**单态化**（每实参一份 IR 函数）。规范层不强制单态化形态，但承认这是 v1 的实施方式。

### §6.4.3 内置泛型函数

§6.4.3.1 编译器 baked 的 turbofish 内置：`weak:<T>` / `ptr_of:<T>` / `same_ref:<T>` / `Nullable:<T>` 等（§4.8.3）。这些不进入 SDK 用户代码。

## §6.5 调用 ABI 概要

### §6.5.1 callee-clean

§6.5.1.1 调用方 ABI 责任：

- 实参按 §4.1.1 从左到右求值；
- 堆句柄实参在传参**之前** retain（计数 +1）；
- 不参与 callee 内部的 release。

§6.5.1.2 被调用方 ABI 责任：

- 形参视为局部变量；
- 函数体结束 / 提前 `ret` 时按 §5.7.2 析构序 release。

§6.5.1.3 优势：参数与局部变量走同一条析构路径，不需要"参数特例"。

### §6.5.2 receiver 注入

§6.5.2.1 方法调用 `obj.method(args)` 在 LLVM 层落成 `method($, args)`，第一个形参为 `Self&`。

§6.5.2.2 receiver 不参与 retain（`Self&` 不持有所有权）。

### §6.5.3 move-return

详见 §6.3.2.1 与 §8.5.3。

### §6.5.4 LLVM 层指针表示

§6.5.4.1 `T&` / receiver `$` 落成**非空**指针；编译器假设永远有效，不做 null 检查。

§6.5.4.2 `Box<T>` / `Array<T>` / `String` / `Weak<T>` / `StringBuilder` 落成单一 handle（指向 RC Block 的指针）。

§6.5.4.3 `Box<T>?` / `Array<T>?` / `String?` 等可空堆句柄按 `Nullable<...>` 解糖（§3.6）。

## §6.6 外部声明 `extern`

### §6.6.1 形态

```
externDecl ::= buildAnno* 'extern' '{' (fnHeader | comment | codeLineEnd)* '}'
```

§6.6.1.1 `extern` 块内仅允许 `fnHeader`（无函数体）。

§6.6.1.2 `extern fn` **不**做名字 mangle，保留 C ABI 名（DRAFT §9.5）。

### §6.6.2 允许的形参 / 返回类型

§6.6.2.1 `extern fn` 形参 / 返回值**应当**仅使用：

| 允许 | 不允许 |
|---|---|
| 内置标量（`iN` / `uN` / `f32` / `f64` / `bool`） | `T&` |
| `Ptr` | `Box<T>` / `Array<T>` / `String` / `Weak<T>` / `StringBuilder` |
| `void`（缺 `retType`） | 用户 `struct` |

§6.6.2.2 上述约束在 v1 暂**不**强制；`extern` 是危险但开放的接口，便于 SDK 落地（DRAFT [#A.1]）。规范层只列要求，违反不报错。

### §6.6.3 自动 Ptr 转换（仅 extern 边界）

§6.6.3.1 在 `extern fn` 调用点，`T&` / `Box<T>` / `Array<T>` / `String` / `Weak<T>` 作实参传给 `Ptr` 形参时**自动转换**为指向 payload 的裸指针；这是规范层唯一允许的隐式类型转换（DRAFT §9.3、§3.4.2.6）。

§6.6.3.2 用户代码层显式转 `Ptr` 走 `ptr_of:<T>(obj)`（§4.8.3 / §9）。

§6.6.3.3 经由 §6.6.3.1 / §6.6.3.2 流出的指针**不得**在 yux 这边 release 后继续被 C 端持有；C 端不可保存超出本次调用（DRAFT §9.5）。
