# §6 函数

本章规范 riu 函数的声明、参数、返回、泛型与调用 ABI。语法形态见 §2 / [附录 B §B.4](附录B-语法汇总.md#b4-函数)；调用约定与 RC 协议的实施细节见 §8.5；FFI 见 §9 与 §10。

## §6.1 函数声明

### §6.1.1 形态

```
fn ::= fnHeader fnBody?
fnHeader ::= buildAnno*
             'fn' ID genericDef? '(' LineEnd* fnParams? ')' (retType=type)?
fnBody ::= fnExprkBody | fnBlockBody
fnExprkBody ::= LineEnd? '=' expr codeLineEnd?
fnBlockBody ::= statementBlock
```

§6.1.1.1 函数名为 `ID`；以 `_` 起始者为模块私有（§10）。恰好 `_` 不能当函数名（**E3161**，§1.4.3.1）。

§6.1.1.5 `fnHeader` 形参列表支持单行 / 多行两种写法（语法层等价，详见 §6.2.1）：

```riu
; 单行
fn add(a i32, b i32) i32 = a + b

; 多行（每参一行、`)` 单独一行；尾随 `,` 由格式化器强制写入，语法层可选）
fn add(
    a i32,
    b i32,
) i32 = a + b
```

格式化器（Phase 5 设计中）的折叠/合并规则为 *informative*：1 参强制单行；多参默认单行，超 120 列折成多行。

§6.1.1.2 `fnHeader` 不带 `fnBody` 时**仅**允许两种位置：

- 在 `extern { ... }` 块内（FFI 声明，§6.6）；
- 顶层带 `buildAnno`（编译器内置 / 代码生成，例如 `#Builtin` 标注的内置签名）。

普通顶层 `fn` 缺 `fnBody` 属编译期错误。

§6.1.1.3 表达式体形态 `fn f(...) T = expr` 等价于 `fn f(...) T { ret expr }`：

- 不需要写 `ret`；
- `expr` 类型须可赋值给 `retType`；
- `=` 与 `expr` 之间的 `LineEnd` 可选（产生式 `LineEnd?`）。

§6.1.1.4 块体形态 `fn f(...) T { ... }` 内部的 `ret` 由 §5.6 规范。

§6.1.1.6 本章规范的是顶层 / `structDecl` 体内的 `fn` **声明**。lambda **字面量**（`(args) Ret? => expr` / `(args) Ret? => { stmts }` / 调用尾随 `{ (args) Ret? => stmts }`）是表达式，落在 §4.11；其类型即 `Function<P..., Ret>`（§3.11），调用时复用本章 §6.5 的调用 ABI 与 §8.7.6 的函数值传递规则。

### §6.1.2 析构函数 `fn ~()`

§6.1.2.1 形态 `fnClean ::= 'fn' '~' '(' ')' fnBody`；只能出现在 `structDecl` 体内（§7.4），且每个类型至多一个。

§6.1.2.2 析构函数无形参、无返回值；在结构体析构时由编译器在字段级 release 之**前**调用（详见 §7.4 / §8.5.5）。

§6.1.2.3 `fn ~()` 内部 `$` 类型为 `Self&`。v1 **允许**写字段：析构不属 const-mut 体系（§6.1.2a.3 / §7.1.4.3），`$.f = ...` **不**触发 `E3109`。v1 **不**进一步限制可写性。

§6.1.2.4 析构体内**不得**在析构序中再触发新的析构（例如把字段 move 给会立刻析构的临时）；v1 行为未定义，规范层不强制检查。

### §6.1.2a 编译期常量函数 `#Const`

§6.1.2a.1 函数头可附 `#Const` 注解，声明该函数**不对外部状态产生副作用**（详见 §11.6）。语义检查清单：

1. 不写 `$.f`（成员函数情形）；
2. 不写任何参数的字段：`p.f = ...` / `p[i] = ...`；
3. 不写非 `cval` 的全局变量；
4. 不调任何非 `#Const fn`（含 SDK / extern）。

违反 (1)–(3) 报 `E3110`，违反 (4) 报 `E3111`。允许：读 `$` / 参数 / 全局 `cval` / 全局 `val`；声明并写函数体内的局部 `var` / `val` / `cval`；调其它 `#Const fn`。

§6.1.2a.2 v1 **不**做推断：`#Const` 必须显式标注，缺标即视为非 const。

§6.1.2a.3 `#Const` 可附在顶层 `fn` 与 `structDecl` 体内方法上。析构 `fn ~()` **不属** const-mut 体系（§6.1.2 / [draft/DRAFT-const-mut.md](draft/DRAFT-const-mut.md) §[#1.L]）。

### §6.1.3 构建注解 `buildAnno`

§6.1.3.1 形态见 §11.1；可前置在 `fn` / `externDecl` / `letGlobal` / `structDecl` 之前。

§6.1.3.2 v1 已识别的注解集合见 §11.5.1。未知注解名报 E2005（§11.1.3.1）；v1 不支持用户自定义注解（§11.15）。

## §6.2 参数

### §6.2.1 形态

```
fnParams ::= fnParam (',' LineEnd* fnParam)* ','? LineEnd*
fnParam ::= fnParamStd | fnParamGroup
fnParamStd ::= paramAnno* ID type
fnParamGroup ::= paramAnno* (ID ',')* ID type
paramAnno ::= '#' ID LineEnd?
```

`fnParams` 在 `(` 之后、参数间 `,` 之后、`)` 之前均允许 `LineEnd*`；末参后允许尾随 `,`。这些 `LineEnd` 仅作为分隔，不进入 AST，故单行 / 多行写法在 ASTBuilder 视角等价（§2 / 附录 B §B.4）。

§6.2.1.0 `paramAnno` 是参数位置的注解槽（与 `buildAnno` 形态相近但**省略** `buildAnno` 末尾的强制 `codeLineEnd`，便于内联到参数列表内）。v1 已识别注解：`#Frozen`（§6.2.2a）；其它注解名（含 `#Mut`）报 `E3105`。`fnParamGroup` 上的注解**作用于组内所有参数名**（与共享类型对齐）。

§6.2.1.1 `fnParamGroup` 让多个连续同类型形参共享类型声明：

```riu
fn add(a, b i32) i32 = a + b      ; ≡ fn add(a i32, b i32) i32 = a + b
fn calc(a, b i32, c f64) f64 { ... }
```

§6.2.1.2 形参类型用 `type`，即允许尾部 `&` 表示借用形参（§3.2.3、§6.2.3）。

§6.2.1.3 形参名在函数体内为局部变量；v1 恒为浅不可变绑定（重赋报 `E3093`，§5.2.1），但形参名内的字段对可变路径仍可写（详见 §5.2）。`#Frozen` 形参进一步禁字段写，详见 §6.2.2a。v1 **不**引入 `var p T` 形态（`var` 关键字已删，附录 A.1.1）；`#Mut` **不**在 `paramAnno` 白名单（报 `E3105`）。后续版本可以接 `#Mut` 形参（[DRAFT-let-unify](draft/DRAFT-let-unify.md) §3.2）。恰好 `_` 的形参是丢弃槽（§1.4.3.1）：占 ABI 位、调用仍须按位传实参、不进符号表；`fnParamGroup` 可写 `fn f(_, _ i32)`。

### §6.2.2 普通参数

§6.2.2.1 普通参数按 §3.1 的类型档位决定传参语义：

| 形参类型档位 | 调用方语义 | callee 视角 |
|---|---|---|
| 值类型（标量 / 用户 `struct` / `[T * N]`） | 按值复制（含字段级 RC） | 局部值 |
| 堆句柄（`Rc<T>` / `Array<T>` / `String` / `Weak<T>` / `StringBuilder`） | 句柄复制 + retain | 局部句柄，作用域结束 release |
| `T&` | 实参须显式 `&x` | 借用，禁止逃逸 |
| `Ptr` / `Ptr<T>` | 实参须同类 `Ptr<T>`（`T` 等同）；擦除 `Ptr` 形参另收 `Ptr<U>` 宽化 / extern 隐式 | 裸指针 |

§6.2.2.2 用户结构体形参**默认按值传**（与 DRAFT §2 决定一致）；编译器可在 ABI 层用指针传大结构体作为不可观测优化。

### §6.2.2a 不可变限定参数 `#Frozen`

§6.2.2a.1 形参可前置 `#Frozen` 注解（`paramAnno`，§6.2.1）声明**深不可变**。形态：

```riu
fn dump(#Frozen s String) {
  ; ...
}

; fnParamGroup 上的注解作用于组内每个名字
fn cmp(#Frozen a, b Config) bool { ... }   ; a 与 b 均 #Frozen
```

§6.2.2a.2 语义：`#Frozen` 形参在函数体内：

1. **不可重赋值**（与 §5.2.1 一致，报 `E3093`）；
2. **不可写其任意字段或下标**：`p.f = ...`、`p[i] = ...` 均报 `E3106`；
3. **不可作为非 `#Frozen` / 非 `val` 受方传递**：当 `#Frozen` 表达式承接到可写局部绑定（局部 `var` / `val` 声明 / 已声明可写局部重赋）时报 `E3107`。"`#Frozen` 表达式"v1 简化为顶层是 `#Frozen` 形参名（含括号包裹形态）的表达式。

§6.2.2a.3 脱 const 出口：v1 仅经显式深拷贝 `copy_of:<T>(x T&) T`（§11.2.3.2 / §12.7.3）取得 owned 视图。`copy_of` 接受 `#Frozen` 形态时按 `T&` 看待——返回值不再带 `#Frozen` 痕迹。

§6.2.2a.4 互斥：`#Frozen` 与 `T&` 形参形态正交；二者可同时出现（语义上等价"`Self&` + 禁写"）。其它参数注解 v1 未引入（含 `#Mut` 形参，§6.2.1.3），未知 `#Name` 报 `E3105`。

§6.2.2a.5 *未做*：含 `#Frozen` 字段类型的参数传递自动继承 `#Frozen` 约束（[draft/DRAFT-const-mut.md](draft/DRAFT-const-mut.md) §6.4），与 callsite "`#Frozen` 实参传给非 `#Frozen` 形参"的全形态检查合并到后续阶段。

### §6.2.3 引用参数 `T&`

§6.2.3.1 `T&` 形参的实参**应当**显式取址 `f(&x)`；**不**自动加 `&`（DRAFT §3.6）。

§6.2.3.2 `T&` 形参在 callee 内的寿命同函数体局部作用域；不可作为字段被存（持有位 **E4039**，§2.6.2）。自由函数不得把形参当返回源（E4020）；方法返回根须为 `$` 或静态（§8.6.10）。

§6.2.3.3 `T&` 形参可被进一步 `&`（结果为子字段的 `T&`），其寿命遵循 §8.4。

### §6.2.4 receiver `$`

§6.2.4.1 结构体方法的 receiver 由编译器隐式注入，类型恒为 `Self&`；调用方写 `obj.method(args)`，**不**写 `&obj`（DRAFT §3.6 / §1.G）。

§6.2.4.2 `$` 在方法体内可读字段、写字段（前提受 §5.2 约束）、传给接收 `Self&` 的辅助函数；**不**作为字段（§4.3.2 / §7.4.3）。**可**作为返回值（当 `retType` 为 `Self&` 或 `T&`，根为 `$`），见 §8.6.10。

§6.2.4.3 v1 **不**引入 UFCS（`Type::method(self, ...)` 风），统一以 `obj.method(args)` 形式。

## §6.3 返回值

### §6.3.1 形态

§6.3.1.1 `retType` 由 `type` 产生，**允许** `T&` 形态。返回 `T&` 时受 §8.6.10 溯源约束：根须为 `$`（方法）或静态借用（全局 / `#Static` / `#Cval`）。自由函数不得把形参 `T&` 当返回源（E4020）。

§6.3.1.1a 方法返回 `T&` 时根**应当**为 `$`，不允许溯源到 `T&` 形参。自由函数 / lambda 仅静态借用合法。

§6.3.1.2 缺 `retType` 表示函数无返回值（"返回空类型"）；与 `ret;` 配合使用（§5.6.1.2）。

### §6.3.2 返回值的所有权移交

§6.3.2.1 返回值类型为堆句柄类型时，`ret expr` 走 **move-return + 实现 i**：编译器在每条 `ret` 路径前为 `expr` 生成 retain；callee 末尾的析构 release 自然与之抵消，使调用方净得 `+1`（详见 §8.5.3）。

§6.3.2.2 返回值类型为用户 `struct` 时按值复制返回；含 RC 字段则字段级 retain（§8.5.5）。

§6.3.2.3 返回值类型为标量 / `[T * N]` 时直接按位返回，无 RC 行为。

### §6.3.3 类型匹配

§6.3.3.1 `ret expr` 中 `expr` 类型须可赋值给 `retType`（§3.4.2）。`T` → `T?` 的隐式包装在此适用（§3.6.4）。

§6.3.3.2 多分支返回（如 `if` 各分支均含 `ret`）的整体类型一致性由各 `ret expr` 自身的可赋值性单独保证；不要求各分支表达式类型完全一致。

## §6.4 泛型函数

### §6.4.1 声明

§6.4.1.1 形态：`fn name<T1, T2, ...>(params) RetType { ... }`。`genericDef` 列表中是类型形参名（裸 `ID`）。`fn f<T&>` 报 **E4037**；借用写在形参上：`fn f<T>(x T&)`。

§6.4.1.2 v1 仅支持类型参数、可选的 **spec 边界** `<T : D1 + D2>`（§6.4.4 / §12）、以及尾部可选默认 `= type`（§3.2.6）；**不**另引入 trait 系统，**不**支持值参数、`where` 子句、or 约束 `T : D1 | D2`（§12.8 项 8 / 13）。类型形参实参的档位限制见 §8.6.7.1（不接 `T&`）；形参在签名内可组合为 `T&` 形态使用见 §8.6.7.5。

§6.4.1.3 类型形参在签名与函数体内可作 `type` 使用，包括嵌套泛型 `Rc<T>`、`Array<T>` 等。

### §6.4.2 实例化与 turbofish

§6.4.2.1 调用形态 `name:<T1, T2>(args)` 显式指定类型实参。turbofish 前缀 `:` 让解析器明确进入泛型实例化分支，避免 `name<T>(args)` 被解析为比较表达式（§2.4 / `docs/函数.md`）。

§6.4.2.2 不写 turbofish 时编译器按实参类型推断；推断失败属编译期错误。

§6.4.2.3 编译器对每个具体实参组合**单态化**（每实参一份 IR 函数）。规范层不强制单态化形态，但承认这是 v1 的实施方式。v1 要求**调用方可见**被调泛型函数体（含带 `<T : D>` 边界的函数，§12）；**不**跨编译单元共享已实例化的边界 IR。与无边界 `<T>` 一致。

### §6.4.3 内置泛型函数

§6.4.3.1 编译器 baked 的 turbofish 内置：`weak:<T>` / `ptr_of:<T>` / `ptr_cast:<T, U>` / `same_ref:<T>` / `Nullable:<T>` / `copy_of:<T>` 等（§4.8.3 / §12.7）。这些不进入 SDK 用户代码。

### §6.4.4 spec 边界

详见 §12.4。本节给出函数声明侧的形态约束。产生式名 `draftBound` 保留 g4 历史名，语义即 spec 边界。

§6.4.4.1 形参的 `genericDef` 槽位中每个类型形参**应当**可选携带 spec 边界：

```
genericDef        ::= '<' typeParam        (',' typeParam)*        '>'
typeParam         ::= type (':' type ('+' type)*)? ('=' type)?
```

边界条目是 `type`：`D` / `D<A>` / `pkg.D<A>`。尾部可选 `= type` 见 §3.2.6。`genericDefWithRef` 的实参槽接 `type`（可含 `T&`）；声明头 `fn f<T&>` 本轮不支持，sema 当类型实参拒（E4037）。

§6.4.4.2 边界条目：

- `D` **应当**是当前编译单元可见的 spec（§12.2 / §10.3）；未知 spec 报错。
- `D` 声明带 N 个形参时，边界写 `D` 无实参、或实参数 ≠ N，报 **E1142**。
- 同一形参的多约束以 `+` 连接，无序，重复条目（含模块解析后等价）报错。
- v1 **不得**出现 `where` 子句、`|` or 约束、关联类型 / 关联常量。

§6.4.4.3 边界**仅**出现在声明位（`fn` / `struct` 头部的 `genericDef` 槽位）；调用点 turbofish `f:<T>(args)` 处**不得**重写边界，仅填实参类型（§6.4.2.1）。`struct Foo<T : D>` 形态 g4 尚未收（`structType` 的形参槽是 `types+=type`），本阶段只约束函数 / 方法形参。

§6.4.4.4 单态化期校验：每次实例化，编译器**应当**为每个 `<T : D<A>>` 先 subst `A`，再检查实参 T 是否有 `#Impl(D<A>)`（查找身份 `(S, D+实参)`，§12.3.2.3）。只查基名 `D` 不够。开 impl（`#Impl(D<T>) struct S<T>`）要把 `S` 的类型实参 subst 进 `#Impl` 实参再比。不满足报 **E1106**。形参方法查找同样带实参，使 `<I : To<T>>` 里 `x.to()` 的返回是 `T`。

§6.4.4.5 调用 ABI：边界泛型沿用 §6.5 既有调用约定，无 vtable / 无隐式签名表参数；方法分发直接 `call <Type>__<SpecPath>__<method>`（实施细节，详见 §12.4）。

### §6.4.5 泛型类型实参隐式推断

当调用点未显式写出 turbofish（`name:<T>(args)`），编译器**应当**按实参类型递归推断类型形参 `T`。本节规范推断的统一算法（`inferGenericFnTypeArgs`，sema 层）。

§6.4.5.1 **基本规则**：对每个形参-实参对，调用 `unify(形参类型, 实参类型)`，遇到裸类型形参名 `T`（即 `typeNormal` 且非内置类型）则将 `T` 绑定为实参类型。

§6.4.5.2 **`T&` 自动解引用**：当实参为 `T&` 而形参为按值 `T`（非 `T&`）时，自动剥引用——`unify(T, T&)` → `unify(T, 剥引用后类型)`。典型场景：`arr[0]` 返回 `T&`，传给期望 `T` 的泛型形参。

§6.4.5.3 **`Ref<T>` 自动取址推断**：当形参为 `Ref<T>`（即 `T&`）而实参为值类型（非 `T&`）时，剥形参的 `Ref` 壳后继续 `unify(T, 实参类型)`。典型场景：`copy_of:<T>(x T&)`，调用方写 `copy_of(v)`（v 为 `i32`），编译器推断 `T=i32` 并自动为实参取址。

§6.4.5.4 **`Nullable<T>` 剥壳推断**：当形参为 `Nullable<T>`（即 `T?`）而实参非 `Nullable` 时，剥形参的 `Nullable` 壳后继续 `unify(T, 实参类型)`。典型场景：`weak:<T>(box Rc<T>?)`，调用方传 `Rc<U>`（非 `Rc<U>?`），编译器推断 `T=U` 并隐式包装 `Nullable`。

§6.4.5.5 **灵活整数不覆盖已推断类型**：当实参为灵活整数字面量（§3.2.4）且其对应的类型形参 `T` 已由其它实参推断为整型（如 `i8`、`u64`）时，跳过该实参的 `unify`，避免灵活整数的默认 `i32` 覆盖已推断的正确类型。典型场景：`assert_eq(a_i8, 42)` 中 `T` 由第一实参 `a_i8` 推断为 `i8`，`42` 的灵活标记不将其覆盖为 `i32`。

§6.4.5.6 **泛型嵌套递归推断**：当形参与实参同为泛型 `G<A1, A2>` 且同名同元数时，递归 `unify` 各 typeArg。

§6.4.5.7 推断失败或歧义时分别报 E6013（无法推断）或 E6014（歧义重载）。推断完成后，编译器按推断的 typeArgs 对实参 node 重编译（灵活整数 → 目标整数类型、值类型实参 → 自动取址）。

## §6.5 调用 ABI 概要

### §6.5.1 callee-clean

§6.5.1.1 调用方 ABI 责任：

- 实参按 §4.1.1 从左到右求值；
- 堆句柄实参在传参**之前** retain（计数 +1）；
- 不参与 callee 内部的 release。

§6.5.1.2 被调用方 ABI 责任：

- 形参视为局部变量；
- 函数体结束 / 提前 `ret` 时按 §5.7.2 析构序 release。

§6.5.1.3 优势：参数与局部变量走同一条析构路径，不需要"参数特例"。

### §6.5.2 receiver 注入

§6.5.2.1 方法调用 `obj.method(args)` 在 LLVM 层落成 `method($, args)`，第一个形参为 `Self&`。

§6.5.2.2 receiver 不参与 retain（`Self&` 不持有所有权）。

### §6.5.3 move-return

详见 §6.3.2.1 与 §8.5.3。

### §6.5.4 LLVM 层指针表示

§6.5.4.1 `T&` / receiver `$` 落成**非空**指针；编译器假设永远有效，不做 null 检查。v1 违反该假设为未定义行为；**不**暴露 panic 模式、**不**插入运行时检查。运行时检查转错误模型。

§6.5.4.2 `Rc<T>` / `Array<T>` / `String` / `Weak<T>` / `StringBuilder` 落成单一 handle（指向 RC Block 的指针）。

§6.5.4.3 `Rc<T>?` / `Array<T>?` / `String?` 等可空堆句柄按 `Nullable<...>` 解糖（§3.6）。

### §6.5.5 函数值调用 ABI

§6.5.5.1 函数值（类型 `Function<P..., Ret>`，§3.11）在运行时表示为 fat-ptr `{ fn_ptr, captures }`：`fn_ptr` 指向编译器为 lambda / 顶层 fn 合成的目标实体，`captures` 为 `Rc<CapturesT>?`（零捕获时为 null）。

§6.5.5.2 调用 `f(args)` 翻译为 `f.fn_ptr(f.captures, args...)`：`captures` **永远**作为隐式首参传入，零捕获 lambda 的 fn_ptr 指向忽略首参的实现。该约定保证 `Function<...>` 在 ABI 层是单一类型，调用点不依据 `captures` 是否为 null 分流。

§6.5.5.3 函数值作实参 / 返回值 / 字段时，按值复制 fat-ptr 并对 `captures` 走 §7.4 字段级 retain / release（详见 §8.7.6）。

§6.5.5.4 函数值与 `extern fn` 边界不互通（§6.6.2.1）。

### §6.5.6 LLVM 符号名约定（informative）

本节描述 riu 源码标识符到 LLVM IR 符号名的映射规则（v0.17 统一后）。本节不构成 ABI 承诺——编译器保留在未来版本中变更符号名的权利；用户代码**不得**直接依赖 IR 符号名。

§6.5.6.1 **模块路径**：riu 模块名 `riu.core.array` 直接映射为 IR 前缀 `riu.core.array.`。

§6.5.6.2 **自由函数**：`<模块>.<fn名>(<形参类型…>)`。例：`riu.core.base.exit()`。形参类型与 riu 写法同形，用户类型带声明模块全限定（`riu.core.string.String`）；内建标量仍写短名（`i32`）。泛型函数：`<模块>.<fn名><实参…>(<形参…>)`，例 `riu.core.base.println<i32>(i32)`。同名不同参重载只靠形参表区分，不用 `_` 后缀。

§6.5.6.3 **结构体方法**（与源码调用同形）：
- 实例方法：`<模块>.<Struct>.<method>(…)`
- 静态方法（`#Static fn`）：`<模块>.<Struct>::<method>(…)`（`::` 对齐 `Type::name`）
- 析构函数 `~()`：`<模块>.<Struct>::~()`
- `@Spec` 消歧：`<模块>.<Struct>.<method>@<Spec>(…)`（对齐 `$.m@Spec()`）
- 泛型结构体：`<Struct>` 位写全限定实例，例 `riu.core.map.Map<i32,i32>::make()` / `.is_empty()`

§6.5.6.4 **泛型 / 复合类型**：尖括号 `Base<Arg1,Arg2>`（不用 `$`）。元组 `(T1,T2)`、函数类型 `Function<P,R>`、可空 `Function<…>?` 同理。用户类型实参同样带全限定。

§6.5.6.5 **Lambda**：`<模块>.__lambda_<line>_<col>`。line/col 为 lambda 字面量在源文件中的位置（编译器合成名，保留 `_`）。

§6.5.6.6 **运行时辅助符号**（不参与用户声明对齐）：
- `riu_rc_alloc` / `riu_rc_retain` / `riu_rc_release` / `riu_rc_release_need_dtor` / `riu_rc_drop_block`（riurt.lib；Rc 计数协议）
- `__riu_box_release_dtor`（lambda captures typed release）
- `__riu_array_alloc` / `__riu_array_grow` / `__riu_array_free_data`（Array 分配/扩容/释放）
- `__riu_heap_alloc` / `__riu_heap_free`（Heap 分配/释放）
- `__riu_dyn_release`（Dyn owned 析构）
- `__riu_vtable.<U全限定>.<D全限定>` / `__riu_dyn_thunk.<U>.<D>.<method>`
- `__riu_global_init.<module>`（全局变量初始化）
- `__riu_test_assert_failed`（测试断言失败入口）
- `__riu_rc_block_count`（RC 泄漏检测计数器；定义在 riurt）

§6.5.6.7 **ABI 符号（不变）**：`riu_main`（用户入口）、`mainStartup`（CRT 启动桥）、`riu_test_*` 系列保持原名，不参与上述映射。

§6.5.6.8 **Enum / Dyn / Reflect**：
- Enum 类型与析构：`<模块>.<Enum>` / `<模块>.<Enum>::~()`。泛型 enum 类型位写全限定实例，例 `<模块>.Box<i32>`（与 §6.5.6.3 泛型 struct 同形）。
- Dyn vtable：`__riu_vtable.<U全限定>.<D全限定>`（如 `riu.core.string.String` + `riu.core.ToString`）。
- Dyn thunk：`__riu_dyn_thunk.<U>.<D>.<method>`。
- Reflect rodata：`__riu_reflect.<模块>.<类型>`。
- 泛型实例在多编译单元各发一份时用 `linkonce_odr` + COMDAT 合并，符号以前缀为**定义模块**全限定，不用消费方模块当分隔。

## §6.6 外部声明 `extern`

### §6.6.1 形态

```
externDecl ::= buildAnno* 'extern' '{' (fnHeader | comment | codeLineEnd)* '}'
```

§6.6.1.1 `extern` 块内仅允许 `fnHeader`（无函数体）。

§6.6.1.2 `extern fn` **不**做 riu 名 mangle。riu 声明名按模块分区，与普通 `fn` 相同（`riu.core.SomeCFn` 与 `mymod.SomeCFn` 是两个 riu 函数）。链接 / LLVM 只用 C ABI 名。

§6.6.1.3 可选 `#CName("symbol")` 注解（单参，字符串或 ID）指定链接时使用的 C ABI 符号名。省略 `#CName` 时，链接符号名与 riu 声明名一致。riu 侧以声明名调用（含模块限定），LLVM IR 中以链接名作为外部符号。同一 LLVM 模块里同一链接名只声明一次。示例：

```riu
extern {
  #CName("MessageBoxA")
  fn MessageBox(hWnd Ptr, lpText Ptr, lpCaption Ptr, uType u32) i32
}
```

§6.6.1.4 多个模块**可以**声明同一 C 签名（同一链接名 + 同一形参 / 返回类型）：无限定名优先本模块；`mod.fn` / `riu.core.fn` 选指定模块的声明；LLVM 层没有区别。同一链接名但 C 签名不同 → [E2036]。

### §6.6.2 允许的形参 / 返回类型

§6.6.2.1 `extern fn` 形参 / 返回值**仅**允许下列类型（形参与返回同一张表；v1 强制诊断）：

| riu | C 侧 |
|---|---|
| 标量 `iN` / `uN` / `f32` / `f64` / `isize` / `usize` | 同宽整数 / 浮点 |
| `bool` | `_Bool`（边界 `i1`↔`i8`） |
| `Ptr` / `Ptr<T>` | `void*`（ABI 一律一指针字；`T` 不参与 size / align） |
| C-layout 用户 struct（§7.5.3.8） | 同序字段的 C struct，**按值 copy**（含 `#Packed` / `#Align` 之后的布局） |
| `void`（缺 `retType`） | `void` |

§6.6.2.2 **禁止**进签名（形参与返回都禁）：

| 类型 | 诊断 |
|---|---|
| `Heap<T>` | E4028 |
| `Function<...>` | E2031 |
| `Dyn<D>` / `Dyn<D&>` | E1136 |
| `Rc<T>` / `Weak<T>` / `Nullable<T>` / `Array<T>` / `String` / `StringBuilder` / `T&` / `Ref<T>` / 元组 / enum | E2034 |
| C-layout struct 字段出现上表类型或 `bool` | E2035 |

`extern fn` 上 `T ! E` / 函数值回调 v1 不做（§6.7.3.2）。v1 **不**引入 `unsafe`。

§6.6.2.3 传入（riu → C）：签名可写任意 `Ptr<T>`（含裸 `Ptr`）。值用 `ptr_of` / `ptr_cast`（§9.7.2.4）。调用点 `T&` / `Rc<T>` / `Array<T>` / `String` / `Weak<T>` **只**能自动转进擦除 `Ptr` / `Ptr<()>`（§6.6.3）；改成 `Ptr<u16>` 后 `String` / `Array<u16>` 不再隐式进入。签名里不能写 `Rc<T>`。

§6.6.2.4 返回（C → riu）：任意 `Ptr<T>` 都是不透明 handle——可存、可再传给 `extern fn`、可 `null` / `to_int` 比较。**不能**变成 `T&` / `Heap<T>` / `Rc<T>` / `Nullable<T>`。用户代码对 `Ptr` 调 `_ptr_as_ref` / `_ptr_write` / `_ptr_offset` 维持 SDK 私有（E6023 一类）。**不**开放 `Heap:<T>(Ptr)` / `_heap_take` 作为用户向 FFI 接管。跨 `T` 只走 `ptr_cast`。

### §6.6.3 自动 Ptr 转换（仅 extern 边界）

§6.6.3.1 在 `extern fn` 调用点，`T&` / `Rc<T>` / `Array<T>` / `String` / `Weak<T>` 作实参传给**擦除** `Ptr` / `Ptr<()>` 形参时**自动转换**为指向 payload 的裸指针；这是规范层唯一允许的隐式类型转换（§3.4.2.6）。不进 `Ptr<U>`（`U ≢ ()`）。`Ptr<T>` 实参可宽化进擦除 `Ptr` 形参。

§6.6.3.2 用户代码层显式转 `Ptr` 走 `ptr_of:<T>(obj)`；跨所指走 `ptr_cast:<T, U>`（§4.8.3 / §9.7.2.4）。

§6.6.3.3 经由 §6.6.3.1 / §6.6.3.2 流出的指针**不得**在 riu 这边 release 后继续被 C 端持有；C 端不可保存超出本次调用（DRAFT §9.5）。

## §6.7 失败签名 `T ! E`

错误模型（草案）见 [DRAFT-错误.md](draft/DRAFT-错误.md)、[DRAFT-fallible-sig.md](draft/DRAFT-fallible-sig.md)；本节给出函数声明侧的形态约束。语义细则、调用形态、诊断码 E7xxx 在草案章节。

### §6.7.1 形态

§6.7.1.1 函数签名末位可写 `! E`，声明该函数可能以错误 enum `E` 失败：`fn parse(s String) i32 ! ParseErr`。`E` **应当**是当前编译单元可见的 enum 类型（§3.10），比较 / 透传 / [E7008] / mangle 用**完整类型**（含泛型实参）：`Box<String>` 与 `Box<i32>` 不同。未知或非 enum 类型按 DRAFT §3 报错。

§6.7.1.2 成功返回类型 `T` 与 `! E` 并列：`fn parse(s String) i32 ! ParseErr` 表示成功返回 `i32`、失败返回 `ParseErr::*`。void 成功形态为 `fn main() ! AppErr`（无 `retType`，仅 `! E`）。

§6.7.1.3 `T ! E` 函数体内通过 `ret E::V` / `ret E::V(payload)` 抛出失败值（§5.6 + DRAFT §4.1）；`ret expr` 中 `expr` 类型为 `T` 时表示成功返回。成功类型 `T` 与 `E` **不得**等同（编译器无法分流），违者报 [E7008]（含泛型单态化重跑）。

### §6.7.2 调用约束

§6.7.2.1 调用 `T ! E` 函数有三种合法形态：

- 在 `try` 块内**裸调用**：失败自动路由到 `catch` 分支（§4.12.2）；
- 在外层同样是 `T ! E` 的函数体内写 `e!`：将失败原样上传（§4.12.1.3），要求外层 enum 与 `E` 一致（v1 单 enum；跨类型见 DRAFT §6），不一致报 [E7004]；
- 用 `try { ... } catch e E { ... }` 在使用点收口（§4.12.2）。

§6.7.2.2 上述形态外直接调用 `T ! E` 函数报 [E7006]（未处理失败）；非 `T ! E` 函数内 / try 外写 `!` 报 [E7001]。

### §6.7.3 互斥与位置

§6.7.3.1 `T ! E` 与 `#NoReturn`（DRAFT §8.3）**不得**同时出现在同一函数签名上；同时出现报 [E7013]。永不返回的函数无错误通道意义。

§6.7.3.2 `extern fn`（§6.6）**不得**写 `T ! E`：FFI 边界无 riu 错误通道，报 E2034。

§6.7.3.3 `T ! E` 可写在顶层 `fn` 与 `structDecl` 体内方法上；`fn ~()` 析构（§6.1.2）**不得**写 `! E`（析构不允许失败；DRAFT §6.5）。

§6.7.3.4 旧写法 `#Fallible(E)` 注解已于 v0.21 删除；出现时报 [E2005]，hint 指向 `T ! E`。
