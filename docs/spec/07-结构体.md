# §7 结构体

本章规范用户定义结构体的声明、方法块、构造与析构、字段访问与按值复制语义。结构体是 yux 的核心**值类型**（§3.1）；其字段可包含值、堆句柄、Nullable，但**不得**包含借用 `T&`（§3.2.3.2 / §2.6）。

## §7.1 声明

### §7.1.1 形态

```
structDecl ::= buildAnno*
               'struct' ID ('<' type (',' type)* '>')? '{'
                   ( filedDecl codeLineEnd? | comment | codeLineEnd )*
               '}'

filedDecl  ::= buildAnno* ID type
```

§7.1.1.1 `structDecl` 引入一个**名义类型**（§3.4.1）：两个结构体类型等同当且仅当源自同一 `structDecl`（含相同泛型实参）。

§7.1.1.2 字段类型只能用 `type`（**不**接受 `typeWithRef`）；语法层禁止字段为 `T&`（§2.6.2 / §3.2.3.2）。

§7.1.1.3 同一结构体内字段名**不得**重复；声明顺序即字段在内存中的逻辑顺序（实际布局含 padding 由实现决定，§7.5）。

### §7.1.2 泛型结构体

§7.1.2.1 泛型形参写为 `struct Foo<T1, T2> { ... }`；类型形参在 `filedDecl` / 方法块内可作普通 `type` 使用。

§7.1.2.2 泛型实例化为按需单态化：每个出现过的泛型实参组合产出独立的具体类型。

§7.1.2.3 v1 **不**支持 trait bound / where 子句；类型形参视为完全无约束。

### §7.1.3 字段类型限制

| 字段类型 | 允许 | 备注 |
|---|---|---|
| 值类型（标量、其它 `struct`、固定数组 `[T*N]`） | ✅ | 按值嵌入 |
| 堆句柄（`Rc<T>` / `Array<T>` / `String` / `StringBuilder` / `Weak<T>`） | ✅ | 句柄按值嵌入；析构走字段级 RC（§7.4） |
| `Heap<T>` / `Heap<T>?` | ✅ | 按值嵌入裸 payload 指针；构造期必须 first-init；析构走 §7.4.6 字段级 heap-free |
| Nullable `T?` | ✅ | 按 `Nullable<T>` 解糖（§3.6） |
| `Ref<T>` / `Ptr<T>` / `Ptr` | ✅ | 不参与 RC；用户应当仅在 FFI 上下文使用 |
| `T&` | ❌ | 语法层拒绝（§2.6.2） |
| 自身类型 `Self` | ❌ | 栈上自引用直接被语法拒绝；自引用须 `Rc<Self>?` / `Weak<Self>?`（§3.7 / §8） |

§7.1.3.1 含至少一个堆句柄字段、或 `Heap<T>` / `Heap<T>?` 字段（含递归含此类字段的子结构体）的结构体称为**非平凡结构体**；其余称为**平凡结构体**。该判定决定按值复制 / 析构的代码生成路径（§7.4 / §7.5）。

> `Heap<T>` 字段**不**计入"堆句柄" RC 字段集合；不参与 §7.4.3 retain / release，单独走 §7.4.6 路径。含 `Heap<T>` / `Heap<T>?` 字段的结构体按值复制**禁**（诊断 Exxx2）；只能整体重新装堆或通过借用传递。

### §7.1.4 字段可变性限定 `#Val` / `#Frozen`

§7.1.4.1 `filedDecl` 接受零或多条 `buildAnno`，写在字段头**上一行**（沿用 `buildAnno` 形态 `'#' ID codeLineEnd`，§11.1.1）。v1 已识别两类字段注解，互斥：

| 注解 | 字段语义 | 构造期 (`fn StructName(...)`) | 其它成员函数 / 析构函数 / 外部 |
|---|---|---|---|
| `#Val` | 浅不可变（仅禁字段自身重赋，子字段可改） | 可写 `$.f = ...` | `$.f = ...` 报 `E3109` |
| `#Frozen` | 深不可变（自身 + 子字段均禁写，传染） | 可写 `$.f = ...` | `$.f = ...` 与 `$.f.x = ...` 均报 `E3109` |

§7.1.4.2 同一字段**不得**同时标 `#Val` 与 `#Frozen`，**不得**重复标同一注解；违反者及未知 `#Name` / 带实参糖均报 `E3108`。

§7.1.4.3 构造函数（与结构体同名的方法，§7.3）内**首次**赋值 `$.f = ...` 走 §7.3.3 DAA first-init 路径，`#Val` 与 `#Frozen` 均放行；构造期内**重赋**同一字段亦放行（仍受 DAA 多次写规则约束）。**析构函数 `fn ~()`** 内对字段的写**不**触发 `E3109`（析构本就需修改自身，[draft/DRAFT-const-mut.md](draft/DRAFT-const-mut.md) §[#1.L]）。

§7.1.4.4 `#Frozen` 字段的**深传染**：方法体内 `obj.cfg.x = ...`、`obj.cfg[i] = ...` 等链长 ≥ 2 的写也报 `E3109`。v1 链长 ≥ 2 的传染仅覆盖第一跳字段为 `#Frozen` 的形态；更深层字段链按声明类型逐级 `#Val` / `#Frozen` 解析属未做项。

§7.1.4.5 字段层注解**凌驾**外层变量声明：`var o Outer = Outer(...)` 下 `o.cfg = ...`（其中 `cfg` 是 `#Frozen` 字段）仍报 `E3109`，外层 `var` 不解锁。

§7.1.4.6 形态示例：

```yux
struct Outer {
  inner Inner            ; 默认（无修饰）：可重赋字段、可改子字段
  #Val
  tag i32                ; 构造期外不可重赋；i32 无"子字段"概念
  #Frozen
  config Config          ; 构造期外不可重赋、不可改子字段
}
```

§7.1.4.7 字段层 `#Cval` / 关联常量 / 静态成员**不在 v1 范围**，移至 [draft/DRAFT-data-struct.md](draft/DRAFT-data-struct.md)（未来草案，工作名待定）。

## §7.2 方法块（structImpl）

### §7.2.1 形态

```
structImpl ::= buildAnno* ID ('<' type (',' type)* '>')? '{'
                   codeLineEnd
                   fnClean?
                   ( fn | comment | codeLineEnd )*
               '}'
```

§7.2.1.1 方法块以结构体名（含泛型实参）开头，紧跟 `{ ... }`。同一结构体的方法**应当**集中在一个方法块内；多块写法语义等价但不推荐。

§7.2.1.2 方法块内允许：

- 至多一个析构函数 `fnClean`（写为 `fn ~()`），若存在**应当**在第一位（§7.4）。
- 任意多个普通方法 / 构造函数 `fn`（§6 / §7.3）。
- 注释与空行。

§7.2.1.3 方法块**不得**重复声明字段；新增字段须改 `structDecl`。

### §7.2.2 接收者 `$`

§7.2.2.1 方法块内的非构造方法，编译器隐式注入接收者参数 `$`；其类型为 `Self&`（§6.2）。

§7.2.2.2 `$.field` 访问当前实例字段；`$` 单独作为表达式表示当前实例本身（值视图，§4.7）。

§7.2.2.3 `$` 不可逃逸：`ret $` 视作返回 `Self&`，被 §3.2.3.2 / §6.3 直接拒绝（也包括把 `$` 存入任何 `T&` 字段——结构体没有 `T&` 字段）。

§7.2.2.4 `$` 的字段访问遵守借用规则（§8）：在借用期内 `$` 自身不得被赋值替换。

### §7.2.3 运算符重载

§7.2.3.1 用户结构体的运算符语义通过特定名称的方法重载实现；运算符出现时编译器**应当**重写为对应的方法调用。重载方法**应当**是该结构体的成员函数（不接受顶层函数）。

§7.2.3.2 可重载方法清单：

| 运算符 | 方法 | 形参 | 返回值 |
|---|---|---|---|
| `+` `-` `*` `/` `%` | `plus` `minus` `mul` `div` `mod` | 1（`Self&`） | 通常同类型 |
| `==` `!=` `<` `<=` `>` `>=` | `eq` `ne` `lt` `le` `gt` `ge` | 1（`Self&`） | `bool` |
| `&` `\|` `^` | `and` `or` `xor` | 1（`Self&`） | 通常同类型 |
| `<<` `>>` | `shl` `shr` | 1（`Self&`） | 通常同类型 |
| 一元 `-` `~` `!` | `neg` `inv` `not` | 0 | `neg`/`inv` 通常同类型；`not` 返回 `bool` |

§7.2.3.3 二元运算符方法的形参类型**应当**为 `Self&`（接收者类型的借用，§8.3）。形参为 `Self`（按值）或其它类型时该方法只是普通方法，不可被运算符触发。**理由**：避免按值复制成本（POD 整体 memcpy；含 RC 字段时还要走字段级 retain，析构时再 release），并与 `$` 接收者一致（§7.2.2.1）。

§7.2.3.4 比较类方法返回 `bool`；其余类**应当**返回与接收者同类型（按值新对象），但语言层不强制。

§7.2.3.5 内置标量类型的运算符方法由编译器内部提供（标记为 `#CompilerInner`），用户**不得**为其增补重载。

§7.2.3.6 运算符 `a OP b` 在编译期重写为 `a.method(&b)`：右操作数自动取址。这是 §6.2 / §8.3 "调用方显式 `&`" 一般规则的运算符位置局部例外，**仅**适用于本节列举的运算符触发的方法分发；用户写 `obj.eq(other)` 直接调用该方法时无此例外，仍须按形参类型显式取址。

## §7.3 构造函数

### §7.3.1 形态

§7.3.1.1 构造函数是一个方法名与结构体名一致的方法；其语法从属 `fn`，无返回类型标注，编译器隐式将其返回类型视为 `Self`（按值返回，§7.3.4）。

§7.3.1.2 构造函数内的接收者 `$` 仍是 `Self&`，但其字段在入口处全部处于"未初始化"状态，受 §7.3.3 的定性赋值分析（DAA）约束。

§7.3.1.3 调用构造函数的语法与普通函数调用一致：`Foo(arg1, arg2)`；调用结果是一个 `Foo` 类型的值（按值返回）。

### §7.3.2 结构体字面量

§7.3.2.1 v1 提供受限的**结构体字段字面量** `Self { .field = expr ... }`，**仅**在 `#Static fn` 体内合法（§7.10.3）；普通表达式位写出 `Foo { ... }` 形态由语法层拒收。构造统一通道为：调用构造函数 `Foo(...)` 或调用静态工厂 `Foo::name(...)`。

§7.3.2.2 因此，"创建一个结构体值"的规范方式有二：(a) 调用一个用户定义的构造函数（§7.3.1）；(b) 调用一个 `#Static fn` 工厂（§7.10），其体内可通过 `Self { ... }` 字段字面量产出本类型值。对**没有任何构造函数也没有 RC 字段**的纯值结构体走默认构造在 v1 仍**不**提供，所有结构体都**应当**至少声明一个构造函数或一个返回 `Self` 的 `#Static fn`。

### §7.3.3 定性赋值分析（DAA）

§7.3.3.1 含 RC 字段或 Nullable 字段或非平凡子结构体字段的结构体在构造完成时若字段未被初始化，析构会对垃圾值调 release，导致未定义行为。因此构造函数**应当**通过 DAA 在编译期保证全字段已初始化。该规则对所有结构体一视同仁（含纯值结构体），以保持一致性。

§7.3.3.2 DAA 规则：

1. **入口**：所有字段标记*未初始化*。
2. **写 `$.field = expr`**：字段转*已初始化*；`expr` 内可引用其它*已初始化*字段、参数、外部变量。
3. **读 `$.field`**（在 RHS、作为方法 receiver、作为 `& $.field` 来源、作为另一字段写的依赖）：编译器**应当**检查该字段处于*已初始化*状态，否则**应当**报错。
4. **分支汇合**：字段在所有分支均被赋值后视为*已初始化*；任一分支未赋视为*未初始化*。
5. **循环**：循环体内的写仅让"循环结束后"视为*已初始化*；循环内读则要求该字段在进入循环前已*已初始化*。
6. **首次写 vs 重赋**：首次写按 first-init 直接 store（不释放旧值，因旧值是垃圾）；后续重赋按 §7.4.4 的 retain-then-release。编译器**应当**为每个 `$.field = expr` 选择正确的代码生成路径。
7. **函数出口**（`ret;` 或函数末尾）：所有字段**应当**处于*已初始化*；否则**应当**报错。

§7.3.3.3 DAA 仅对构造函数内的 `$.field` 写读链做局部分析；将 `$` 传入接收 `Self&` 的辅助函数时，保守视该辅助函数读取所有字段，要求当前所有字段均已*已初始化*。Open Issue：是否对辅助函数做更细粒度签名标注。

§7.3.3.4 DAA 不涉及"字段默认值"。即使字段是 `Weak<T>` / `T?` / 数值标量，构造时也**应当**显式赋值（如 `Weak(null)` / `null` / `0`）。语言**不得**为字段提供隐式默认值。

### §7.3.4 返回与 ABI

§7.3.4.1 构造函数返回 `Self`，沿用 §6.3 的按值返回 ABI；含 RC 字段时按 §7.4 的字段级语义生成派生代码。

§7.3.4.2 调用构造函数得到的临时值的寿命遵循 §4.1 的临时值边界规则；若立即绑定到 `var` / `val`，编译器**应当**省去多余的临时拷贝（move-construct，TODO 实现侧落地）。

## §7.4 析构函数与字段级 RC

### §7.4.1 析构函数 `fn ~()`

§7.4.1.1 析构函数写为 `fn ~()`，无参数、无返回值；若声明，**应当**在 `structImpl` 中位列第一位（§7.2.1.2）。

§7.4.1.2 析构函数在结构体值的作用域结束、或被赋值替换、或作为字段被释放时由编译器自动调用。用户**不得**显式调用 `~()`。

§7.4.1.3 析构函数体可访问 `$.field`；该处所有字段视为*已初始化*（构造期 DAA 已保证）。

§7.4.1.4 若结构体未声明析构函数：

- 平凡结构体：编译器**不**生成析构代码（按位 memcpy / 直接释放）。
- 非平凡结构体：编译器**应当**派生默认析构（仅做字段级 RC release，§7.4.3），无需用户写空 `fn ~()`。

§7.4.1.5 用户写的析构函数体**应当**只包含与"清理"相关的语义；其后编译器仍会自动追加字段级 RC release 序列（§7.4.3）。两段顺序：先用户体，再字段 release（按字段声明逆序）。

### §7.4.2 平凡 / 非平凡判定

§7.4.2.1 平凡结构体：所有字段递归地不含 `Rc<T>` / `Weak<T>` / `Array<T>` / `String` / `StringBuilder` / `Heap<T>` / `Heap<T>?`，也不含含上述的子结构体或子结构体字段。

§7.4.2.2 非平凡结构体：包含至少一个堆句柄字段或 `Heap<T>` / `Heap<T>?` 字段（直接或递归通过子结构体）。

§7.4.2.3 该判定为编译期纯结构判定，**应当**对每个具体类型（含泛型实例）独立计算。

### §7.4.3 字段级 retain / release

对**非平凡结构体**，编译器**应当**生成与字段级语义一致的派生代码：

- **复制**（包括按值传参、按值返回、`val a = b`、字面量赋值）：按字段声明顺序逐字段处理；RC 字段执行 retain；嵌套非平凡子结构体递归调用其字段级复制；平凡子段按位 memcpy。
- **析构**：先调用用户析构体（若有）；再按字段声明**逆序**对每个 RC 字段 release；嵌套非平凡子结构体递归析构。

§7.4.3.1 v1 IR 落地形态：内联展开（与现有 `compiler_destructor.cpp` 风格一致）。Open Issue：派生独立 `__copy_S` / `__destroy_S` 函数以缩减代码体积。

§7.4.3.2 字段级派生不会调用任何用户运算符方法（如 `eq` / `plus`）；与运算符重载完全正交。

### §7.4.4 赋值的 retain-then-release

§7.4.4.1 对非平凡结构体的赋值（`s = expr` 或 `s.field = expr`）**应当**按以下顺序执行：

1. 计算 `expr`，得到新值 `v`；
2. 对 `v` 的所有 RC 字段 retain（拷入新值的语义）；
3. 用 `v` 覆写 `s`（或 `s.field`）；
4. 对**被覆盖前**的旧值的所有 RC 字段 release。

§7.4.4.2 此顺序避免 `s = s` 或别名（如 `s = s.boxField.box_back_to_s`）情形下先 release 后 retain 读到已释放对象。规范层用 retain-then-release，编译器**应当**保留这一序。

### §7.4.5 字段读 / 写

§7.4.5.1 字段读 `s.field` 拿到的是字段值的"借用视角"，本身**不**触发 retain；当读出值被存入新变量、参数、字段时按复制语义 retain（§7.4.3）。

§7.4.5.2 字段写 `s.field = expr` 走 §7.4.4 的 retain-then-release。

§7.4.5.3 数组元素读 / 写与字段读 / 写对称（§9.2）。

### §7.4.6 `Heap<T>` 字段的构造 / 复制 / 析构

对含 `Heap<T>` / `Heap<T>?` 字段的非平凡结构体，编译器**应当**额外生成 heap-free 序列；该路径独立于 §7.4.3 字段级 RC，二者在同一结构体内可并存。

§7.4.6.1 **构造**：每个 `Heap<T>` 字段在构造体内必须 first-init（DAA 强制，§7.3.3）；`Heap<T>?` 字段可由 first-init 或显式 `null` 满足。

§7.4.6.2 **复制**：含 `Heap<T>` / `Heap<T>?` 字段的结构体按值复制**禁**（诊断 Exxx2），与 `Heap<T>` 本身按值禁 move 一致；用户应当整体重新装堆（`Heap:<S>(s)`）或借用传递（`S&`）。

§7.4.6.3 **析构**：先调用用户析构体（若有）；再按字段声明**逆序**释放——`Heap<T>` 字段调 `__yux_heap_free<T>`；`Heap<T>?` 字段若 slot 非空则 free，null 则跳过；RC 字段按 §7.4.3 release。同一结构体内字段释放顺序为"字段声明逆序"，按字段类型分发到 §7.4.3 / §7.4.6.3 各自的处理路径。

§7.4.6.4 **字段 move-out**（B 档场景，§8.X）：`Built { buf: b.buf }` 形态消费源结构体的 `Heap<T>?` 字段后，源 slot 写 null；源结构体析构看到 null 跳 free。源字段类型必须是 `Heap<T>?` 才允许 move-out；`Heap<T>` 非空字段不可 move-out（诊断 Exxx2）。

§7.4.6.5 `s.heap_field = expr` 的赋值**不**走 §7.4.4 retain-then-release；按"先 free 旧 slot，再写入新 owner"序：

1. 计算 `expr`（必须是 first-time `Heap` 构造表达式、§7.4.6.4 字段 move-out 形态、或 §8.3a.4.4 C 档 `Heap<T>?` 左值搬移，否则 `Exxx2`）；
2. 若旧 slot 非空（`Heap<T>?` 可能 null），调 `__yux_heap_free<T>`；
3. 写入新 payload 指针。

### §7.4.6.6 复合 move（含 Heap 的 struct / Array 按值传递）

含 `Heap<T>` / `Heap<T>?` 字段（递归）的结构体、`Array<Heap<T>>`、`Heap<Heap<T>>` 等复合类型，按值复制**禁**（§7.4.6.2）；按值传参 / 局部赋值 / `ret` 等左值搬移场景走**复合 move**——与 §8.3a.4.4 一致，**复合 move 只覆盖可空复合 slot**（如 `Builder?`、`Array<Heap<T>>?` 等），非空形态保持按值禁。

§7.4.6.6.1 **触发**：`let lhs S? = rhs` / `f(rhs)` 按值形参 / `ret rhs`，其中 S 含 Heap 子项、LHS / RHS / 形参 类型同为 `S?`，RHS 为左值。

§7.4.6.6.2 **效果**：源 slot 整体写 null（不递归遍历子字段，O(1) 指针搬移）；目标 slot 接管所有权。

§7.4.6.6.3 **源结构体析构**：源 `S?` slot 在原作用域出口按 null 跳过析构；目标 slot 按正常作用域出口走 §7.4.6.3 字段级 heap-free + RC release。

§7.4.6.6.4 示例（builder 模式）：

```yux
struct Builder {
  buf Heap<Bytes>?
  len i32
}

Builder {
  fn Builder(cap i32) {
    $.buf = Heap:<Bytes>(cap)
    $.len = 0
  }
}

fn finish(b Builder?) Heap<Bytes>? {
  if b != null {
    let out = b.buf     ; ✅ §8.3a.4.4 C 档字段 move-out，b.buf 写 null
    ret out
  }
  ret null
}

fn use() {
  let b Builder? = Builder(1024)       ; ✅ Heap 构造期 widen 到 ?
  let final = finish(b)                ; ✅ 复合 move：b 整体搬入 finish，本地 b = null
  ; 此处 b == null，需 ?. / narrow 再读
}
```

§7.4.6.6.5 **非空形态 `let b Builder = ...; finish(b)`**：在 Heap-containing 复合上**禁**——`finish(b)` 报 `Exxx2`（含 Heap 的复合按值搬移须经 `?` slot）。这避免引入 use-after-move 跟踪，与 §8.3a.4.4 同口径。

## §7.5 字段访问与可变性

### §7.5.1 可变性

§7.5.1.1 yux 不区分"const struct" / "mut struct"；变量级别由 `var` / `val` 决定（§5.1）。`val s = ...` 后 `s.field = ...` **不得**通过（编译报错），因为 `s` 自身是只读绑定。

§7.5.1.2 即使 `val s = ...`，若 `s` 持有的是 `Rc<T>` / `Array<T>` 等堆句柄，对句柄指向的堆对象的修改并不通过 `s` 自身的赋值表达，因此与 `val` 不冲突。是否允许通过 `val` 绑定的堆句柄修改 payload，由各堆句柄各自约束（§9）。

### §7.5.2 字段访问语法

§7.5.2.1 `s.field`、`$.field`：见 §4.7。

§7.5.2.2 链式访问 `s.a.b.c` 按从左到右逐字段展开，每层都参与 §7.5.1 的可变性判断。

§7.5.2.3 `&s.field`：见 §4.7 / §8.3；语法层允许，寿命由 §8.3.5 校验。

### §7.5.3 内存布局

§7.5.3.1 字段在内存中按声明顺序依次排列；padding、align 由实现根据目标 ABI 决定。规范层**不**承诺 POD 布局与 C 同构；与 C 互操作时**应当**通过 `extern` + `Ptr` 边界（§9 / §6.6）。

§7.5.3.2 `Rc<T>` / `Array<T>` / `String` / `StringBuilder` 字段在结构体内按其句柄宽度（v1：单指针）嵌入；payload 不嵌入结构体。

§7.5.3.3 v1 **不**保证字段重排优化；编译器**可以**在未来版本对非 `extern` 类型重排字段以减少 padding（informative）。

## §7.6 按值复制语义

### §7.6.1 终态

§7.6.1.1 用户结构体**默认按值复制**：函数实参、返回值、变量初始化、字段写入均按 §7.4.3 的字段级复制语义执行。"结构体通过指针传递"在规范层**不存在**——编译器若在 ABI 层用指针传大结构体，是不可观测的优化（§3.1）。

§7.6.1.2 与 §3.4 / §6.3 的"按值赋值 / 按值返回"一致；本节是其在结构体上下文的具体落实。

### §7.6.2 复制不调用用户方法

§7.6.2.1 字段级复制是编译器派生的 retain / memcpy 序列；**不**调用用户的 `eq` / `plus` / 析构等方法。

§7.6.2.2 用户**不得**通过运算符重载或方法定义改变默认按值复制语义；如需特殊复制行为，**应当**显式提供 `clone` 方法并在调用方手动调用。

### §7.6.3 与 `T&` 的差异

§7.6.3.1 函数形参写 `Foo` 与写 `Foo&` 语义不同：前者按值复制（字段级 RC retain），后者借用句柄不复制。规范层**不**自动取址；调用方写 `f(x)` 与 `f(&x)` 选择不同的形参重载（§6.2 / §8.3）。

§7.6.3.2 方法接收者 `$` 是隐式 `Self&`（§7.2.2.1）；调用 `obj.method()` 不触发对 `obj` 的字段级复制。

## §7.7 结构体与堆句柄的组合

§7.7.1 自引用 / 双向引用结构体**应当**经堆：字段须写为 `Rc<Self>?` / `Weak<Self>?`，栈上自引用结构体**不得**通过编译（§3.7 / §8）。

§7.7.2 含 `Weak<T>` 字段的结构体在构造时**应当**显式给定初值（如 `Weak(null)`）；DAA 不为 `Weak` 提供"自然空值"豁免（§7.3.3.4）。

§7.7.3 含 `Rc<T>` 字段的结构体在父对象析构时按 §7.4.3 自动 release `Rc`；payload 是否真正释放由 RC 决定（§8）。

## §7.8 draft 实现块

详见 §12。本节仅给出对结构体方法块语法的扩展，语义以 §12 为准。

### §7.8.1 形态

§7.8.1.1 在 §7.2.1 `structImpl` 头部增加可选的 draft 列表：

```
structImpl ::= buildAnno* ID ('<' type (',' type)* '>')?
                   (':' draftBound ('+' draftBound)*)? '{'
                   codeLineEnd
                   fnClean?
                   ( fn | comment | codeLineEnd )*
               '}'

draftBound ::= modulePath? ID genericDef?
```

§7.8.1.2 不带 `:` 的方法块为**普通方法块**（§7.2 既有形态），可写构造 / 析构 / 普通方法 / 运算符方法。

§7.8.1.3 带 `:` 的方法块为 **draft 实现块**：块内方法集**应当**与所列 draft 的签名集严格相等（既不缺也不多）。详见 §12.3。

§7.8.1.4 同一 `Type : D` 的实现块**不得**重复出现（同包跨包均不允许）；跨包是否允许实现由 §12.5 orphan 规则决定。

### §7.8.2 与普通方法块的关系

§7.8.2.1 辅助方法 / 构造函数 / 析构函数**应当**写在普通方法块；**不得**混入 draft 实现块。

§7.8.2.2 同一结构体内同时存在普通方法块与 draft 实现块时，块内方法名共享同一命名空间：同包内"普通块定义 `m()` + draft 块也实现 `m()`（D 含 `m()` 签名）"按 §12.4.1 情形 A 报错（重复定义）。

§7.8.2.3 receiver `$` 在 draft 实现块内的语义与普通方法块一致（§7.2.2，类型 `Self&`）。

### §7.8.3 与 `T&` 的关系

§7.8.3.1 draft 实现位点限定为 owned 类型 T；**不得**写形如 `T& : D { ... }` 的实现块（参见 §12.4.3 / §8.6.7.5）。

§7.8.3.2 `obj: T&` 上调用 D 方法走 §8.6.7.3 receiver 归一，无需为 `T&` 单独实现。

## §7.9 与 enum 的对照（informative）

§7.9.1 enum（§3.10）与 struct 同属"用户名义值类型"档（§3.1）：

- 两者均为**值类型**：栈布局、按值复制；要上堆用 `Rc<E>` / `Rc<S>`，与既有 `Rc<T>` 协议一致。
- 两者按**名义判等**（§3.4.1）：声明源决定身份，结构等同的两个声明仍是无关类型。
- 含 RC 字段时按字段级派生 retain / release / 析构（§7.4 / §8）；enum 在此基础上额外按 tag dispatch（[draft/DRAFT-枚举.md](draft/DRAFT-枚举.md) §6）。

§7.9.2 形态差异：

| 维度 | struct | enum |
|---|---|---|
| 字段 / variant 形态 | 命名字段集合（积类型） | 命名变体集合（和类型），可携带 tuple-style payload |
| 读取通道 | `obj.field` 直接访问 | 仅 `match`（§3.10.5 / §4 / §5），不暴露 tag |
| 方法块 / draft 实现 | 允许（§7.2 / §7.8） | v1 **不**允许（§3.10.2.6） |
| 泛型 | 允许（§7.1.2） | v1 **不**允许（§3.10.2.6） |
| 字段 / payload 含 `T&` | 拒绝（§3.2.3.2） | 拒绝（§3.10.3.2） |

§7.9.3 选用建议（informative）：用 struct 表示"对象具有一组始终存在的字段"，用 enum 表示"对象处于若干互斥状态之一"。

## §7.10 静态函数（关联函数）

引入自 [draft/DRAFT-static-fn.md](draft/DRAFT-static-fn.md)。本节规范"不带接收者"的结构体函数（关联函数 / 静态函数），调用语法 `Type::name(...)`，并配套 `Self` 类型字面量与 `Self { ... }` 字段字面量。

### §7.10.1 声明

§7.10.1.1 形态：`#Static` 注解紧贴 `fn` 头，函数体所在的 `structImpl` 块内合法。

```yux
Point {
  #Static
  fn make(x i32, y i32) Point {
    ret Self {
      .x = x
      .y = y
    }
  }

  fn sum() i32 = $.x + $.y
}
```

§7.10.1.2 `#Static fn` **不**注入接收者参数 `$`；其在 IR 层是顶层函数。可附着位置见 §11.11。

§7.10.1.3 `#Static fn` 仅能在普通方法块内声明，**不**进 draft 实现块（§7.8.2.1 扩展）；**不**作为运算符重载方法；**不**等同析构 `fn ~()`。

§7.10.1.4 同一结构体内 `#Static fn` 与同名实例 `fn` 共存允许（调用形态 `Type::name` / `obj.name` 天然区分），sema **不**报错。与构造函数同名（即与结构体同名）**禁止**——`Point::Point(...)` 与 `Point(...)` ctor 入口冲突。

### §7.10.2 调用

§7.10.2.1 调用语法 `Type::name(args)`；token `::` 即 `SymbolColonColon`，与 enum 构造 `Enum::Variant(args)` 共用 parser 节点（`ExprPathCallNode`），sema 按 LHS 类型分流：

- LHS 解析为 enum → enum 构造路径（§3.10）；
- LHS 解析为 struct 且 RHS 是 `#Static fn` → 静态调用；
- LHS 解析为 struct 但 RHS 是实例方法 / 构造函数 → 报 **E3120**；
- LHS 解析为 struct 但 RHS 不存在 → 报 **E3121**；
- LHS 既非 enum 又非已知 struct → 报 **E3122**。

§7.10.2.2 泛型形态：

```
staticCall ::= (typeName | 'Self') (':' genericDef)? '::' ID (':' genericDef)? '(' args? ')'
```

第一段 turbofish 给 struct 类型参数，第二段给静态 fn 类型参数；任一段可省。

§7.10.2.3 在 `structImpl` 体内（含实例方法体 / 静态 fn 体 / 构造函数体）**可以**写 `Self::name(...)` 调用本类型静态 fn，等同当前类型名做 LHS。

§7.10.2.4 静态调用没有 receiver，**不**触发字段级 retain / release（§7.4.3 与本特性无关）；mangle 形态 `Type::name(args)`，receiver 槽位缺省。

### §7.10.3 `Self` 类型字面量

§7.10.3.1 `Self` 是保留字（附录 A.1），lexer token `SelfType`；在 `structImpl` 体内绑定为所属结构体类型（含泛型实参当前绑定）。

§7.10.3.2 允许位置：

- **类型位**：fn 返回类型、fn 形参类型（含 `Self&`）、局部 `let` 类型标注、turbofish 实参；
- **调用 LHS**：`Self::name(...)`（§7.10.2.3）；
- **字段字面量 LHS**：`Self { ... }`（§7.10.3.4）。

§7.10.3.3 字段类型位**禁用** `Self`（§7.1.3）；自引用须 `Rc<Self>?` / `Weak<Self>?`。`structImpl` 体外出现 `Self` 报 **E3123**。

§7.10.3.4 `Self { ... }` 字段字面量：

```
exprStructLit ::= 'Self' '{' LineEnd ( fieldInit | LineEnd )* '}'
fieldInit     ::= '.' ID '=' expr LineEnd
```

字段名前的 `.` 强制；每条 `fieldInit` 一行（多行强制 + 行内 `LineEnd` 强制）；字段之间无逗号。

§7.10.3.5 字段字面量出现位严格限定为 `#Static fn` 体内，**且** LHS 是 `Self`：

- 出现在普通方法体 / 构造函数体 / 顶层 / lambda 体 → 报 **E3124**；
- 跨类型 `Other { .x = ... }` 形态 → 由语法层拒收（仅 `Self` 是合法 LHS）；
- 缺字段：所列字段必须**覆盖全字段**（DAA 退化形态），缺一字段报 **E3125**；
- 字段名不在结构体声明中报 **E3126**；同一字段重复出现报 **E3127**。

§7.10.3.6 字段字面量是低层构造原语：句柄字段 RHS 的所有权语义与 `$.field = value` 一致（§7.4.4），fresh 源（数组字面量、临时调用值）走转移 +1；非 fresh 源走 retain。`#Val` / `#Frozen` 字段限定（§7.1.4）的"构造期"在此重定义为"`#Static fn` 体内通过 `Self { ... }` 产出 `Self` 的那个表达式位"——该位放行字段写。

### §7.10.4 与 `$` 的关系

§7.10.4.1 `#Static fn` 体内**禁写** `$` / `$.field` / `&$`：sema 检测到报 **E3128**。`Self` 是访问 receiver-side 类型的唯一通道（§7.10.3）。

§7.10.4.2 静态 fn 可调用 ctor 构造 `Self`（如 `Self::origin() { Point(0, 0) }`）；该路径下 `Point(0, 0)` 是普通 ctor 调用，照走 §7.3。

### §7.10.5 泛型与单态化

§7.10.5.1 泛型结构体的 `#Static fn` 跟随结构体单态化：`Vec<i32>::with_capacity` 与 `Vec<String>::with_capacity` 是不同实例。

§7.10.5.2 静态 fn 自身可带类型参数（双 turbofish 形态，§7.10.2.2）；推断规则与现有泛型 fn 调用一致。

### §7.10.6 SDK 试点

v0.13 落地的 `#Static` 工厂（与同名 ctor 并存）：

| 类型 | 工厂 | 等价 ctor |
|---|---|---|
| `String` | `String::empty()` | `String()` |
| `String` | `String::from(buf Array<u32>)` | `String(buf)` |

后续构造模型重构（DRAFT §7）规划砍 ctor 通道，构造唯一通道改为 `#Static fn` + `Self { ... }`；当前阶段两条通道并存，不留过渡期由后续版本决议。
