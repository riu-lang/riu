# §7 结构体

本章规范用户定义结构体的声明、方法、构造（仅经 `#Static fn` 工厂 + `Self { ... }` 字段字面量，§7.3 / §7.10）、析构、字段访问与按值复制语义。结构体是 yux 的核心**值类型**（§3.1）；其字段可包含值、堆句柄、Nullable，但**不得**包含借用 `T&`（§3.2.3.2 / §2.6）。

## §7.1 声明

### §7.1.1 形态

```
structDecl ::= buildAnno*                              ; 可含顶行 #Spec / #Impl(D) / #Builtin 等
               'struct' ID ('<' type (',' type)* '>')? '{'
                   ( filedDecl | staticFieldDecl | LineEnd )*
                   fnClean?
                   ( fn LineEnd | LineEnd )*
               '}'

filedDecl       ::= buildAnno* ID type
staticFieldDecl ::= buildAnno* ID type '=' expr LineEnd  ; 必须含 #Static，可叠 #Mut
```

§7.1.1.1 `structDecl` 引入一个**名义类型**（§3.4.1）：两个结构体类型等同当且仅当源自同一 `structDecl`（含相同泛型实参）。

§7.1.1.2 字段类型只能用 `type`（**不**接受 `typeWithRef`）；语法层禁止字段为 `T&`（§2.6.2 / §3.2.3.2）。

§7.1.1.3 同一结构体内字段名**不得**重复；声明顺序即字段在内存中的逻辑顺序（实际布局含 padding 由实现决定，§7.5）。

§7.1.1.4 spec-unify v1（2026-05-19）将 struct 声明与方法块合一：字段段在前、可选 `fnClean`（析构 `fn ~()`）居中、方法 `fn` 段在后；spec 实现关系由顶行 `#Impl(D)` 注解承载（§7.8 / §12.2）。早期 `Type { ... }` 独立方法块与 `Type : D { ... }` 外置 spec 实现块已废弃，所有形态均落到本节单一 `structDecl` 内。

### §7.1.2 泛型结构体

§7.1.2.1 泛型形参写为 `struct Foo<T1, T2> { ... }`；类型形参在 `filedDecl` / 方法块内可作普通 `type` 使用。

§7.1.2.2 泛型实例化为按需单态化：每个出现过的泛型实参组合产出独立的具体类型。

§7.1.2.3 v1 **不**支持 trait bound / where 子句；类型形参视为完全无约束。

### §7.1.3 字段类型限制

| 字段类型 | 允许 | 备注 |
|---|---|---|
| 值类型（标量、其它 `struct`、固定数组 `[T*N]`） | ✅ | 按值嵌入 |
| 堆句柄（`Rc<T>` / `Array<T>` / `String` / `StringBuilder` / `Weak<T>`） | ✅ | 句柄按值嵌入；析构走字段级 RC（§7.4） |
| `Heap<T>` / `Heap<T>?` | ✅ | 按值嵌入裸 payload 指针；构造期必须 first-init；析构走 §7.4.6 字段级 heap-free |
| Nullable `T?` | ✅ | 按 `Nullable<T>` 解糖（§3.6） |
| `Ref<T>` / `Ptr<T>` / `Ptr` | ✅ | 不参与 RC；用户应当仅在 FFI 上下文使用 |
| `T&` | ❌ | 语法层拒绝（§2.6.2） |
| 自身类型 `Self` | ❌ | 栈上自引用直接被语法拒绝；自引用须 `Rc<Self>?` / `Weak<Self>?`（§3.7 / §8） |

§7.1.3.1 含至少一个堆句柄字段、或 `Heap<T>` / `Heap<T>?` 字段（含递归含此类字段的子结构体）的结构体称为**非平凡结构体**；其余称为**平凡结构体**。该判定决定按值复制 / 析构的代码生成路径（§7.4 / §7.5）。

> `Heap<T>` 字段**不**计入"堆句柄" RC 字段集合；不参与 §7.4.3 retain / release，单独走 §7.4.6 路径。含 `Heap<T>` / `Heap<T>?` 字段的结构体按值复制**禁**（诊断 Exxx2）；只能整体重新装堆或通过借用传递。

### §7.1.4 字段可变性限定 `#Val` / `#Frozen`

§7.1.4.1 `filedDecl` 接受零或多条 `buildAnno`，写在字段头**上一行**（沿用 `buildAnno` 形态 `'#' ID codeLineEnd`，§11.1.1）。v1 已识别两类字段注解，互斥：

| 注解 | 字段语义 | 构造位（`#Static fn` 体内 `Self { ... }` 字面量） | 其它成员函数 / 析构函数 / 外部 |
|---|---|---|---|
| `#Val` | 浅不可变（仅禁字段自身重赋，子字段可改） | 字段写允许 | `$.f = ...` 报 `E3109` |
| `#Frozen` | 深不可变（自身 + 子字段均禁写，传染） | 字段写允许 | `$.f = ...` 与 `$.f.x = ...` 均报 `E3109` |

§7.1.4.2 同一字段**不得**同时标 `#Val` 与 `#Frozen`，**不得**重复标同一注解；违反者及未知 `#Name` / 带实参糖均报 `E3108`。

§7.1.4.3 构造统一通道为 `#Static fn` 工厂 + `Self { .f = expr ... }` 字段字面量（§7.10.3）。字段字面量出现位严格限定为 `#Static fn` 体内（§7.10.3.5）；该位上 `#Val` / `#Frozen` 字段写**放行**（与"构造期"等价语义）。**析构函数 `fn ~()`** 内对字段的写**不**触发 `E3109`（析构本就需修改自身，[draft/DRAFT-const-mut.md](draft/DRAFT-const-mut.md) §[#1.L]）。

§7.1.4.4 `#Frozen` 字段的**深传染**：方法体内 `obj.cfg.x = ...`、`obj.cfg[i] = ...` 等链长 ≥ 2 的写也报 `E3109`。v1 链长 ≥ 2 的传染仅覆盖第一跳字段为 `#Frozen` 的形态；更深层字段链按声明类型逐级 `#Val` / `#Frozen` 解析属未做项。

§7.1.4.5 字段层注解**凌驾**外层变量声明：`let o Outer = Outer::make(...)` 下 `o.cfg = ...`（其中 `cfg` 是 `#Frozen` 字段）仍报 `E3109`，外层 `let` 档位（默认 / `#Mut` / `#Frozen`）不解锁。

§7.1.4.6 形态示例：

```yux
struct Outer {
  inner Inner            ; 默认（无修饰）：可重赋字段、可改子字段
  #Val
  tag i32                ; 构造期外不可重赋；i32 无"子字段"概念
  #Frozen
  config Config          ; 构造期外不可重赋、不可改子字段
}
```

§7.1.4.7 字段层 `#Cval` / 关联常量**不在 v1 范围**，移至 [draft/DRAFT-data-struct.md](draft/DRAFT-data-struct.md)（未来草案，工作名待定）。**静态字段**（`#Static` 字段，关联于类型而非实例）已落地，见 §7.11。

## §7.2 方法（struct body 内 fn 段）

### §7.2.1 形态

spec-unify v1 起，方法直接写在 `structDecl` body 内 `fn` 段（§7.1.1）；不再存在独立的"方法块" `Type { ... }` 形态。

§7.2.1.1 一个 struct 的所有方法、静态工厂、析构函数 `fn ~()` 均集中在该 struct 的声明体内。

§7.2.1.2 struct body 内出现顺序由 g4 固定：

1. 字段段（`filedDecl`* + `staticFieldDecl`*，实例字段与静态字段混合书写）；
2. 至多一个析构函数 `fnClean`（写为 `fn ~()`，§7.4），位于其它 `fn` **之前**；
3. 任意多个实例方法 / 静态函数（`#Static fn`，§7.10）`fn`（§6 / §7.10）；
4. 注释与空行可穿插。

构造函数（"与结构体同名的方法 `fn StructName(...)`"）形态在 spec-unify v1 / DRAFT-static-fn 落地后**已删除**；构造唯一通道为 `#Static fn` 工厂 + `Self { ... }` 字段字面量（§7.3 / §7.10）。

§7.2.1.3 struct body 内字段段写出后**不得**再追加字段；新增字段须改 struct 声明本身。

### §7.2.2 接收者 `$`

§7.2.2.1 struct body 内的实例方法，编译器隐式注入接收者参数 `$`；其类型为 `Self&`（§6.2）。`#Static fn`（§7.10）**不**注入 `$`。

§7.2.2.2 `$.field` 访问当前实例字段；`$` 单独作为表达式表示当前实例本身（值视图，§4.7）。

§7.2.2.3 `$` 不可逃逸：`ret $` 视作返回 `Self&`，被 §3.2.3.2 / §6.3 直接拒绝（也包括把 `$` 存入任何 `T&` 字段——结构体没有 `T&` 字段）。

§7.2.2.4 `$` 的字段访问遵守借用规则（§8）：在借用期内 `$` 自身不得被赋值替换。

### §7.2.3 运算符重载

§7.2.3.1 用户结构体的运算符语义通过特定名称的方法重载实现；运算符出现时编译器**应当**重写为对应的方法调用。重载方法**应当**是该结构体的成员函数（不接受顶层函数）。

§7.2.3.2 可重载方法清单：

| 运算符 | 方法 | 形参 | 返回值 |
|---|---|---|---|
| `+` `-` `*` `/` `%` | `plus` `minus` `mul` `div` `mod` | 1（推荐 `Self&`，不强制） | 通常同类型 |
| `==` `!=` `<` `<=` `>` `>=` | `eq` `ne` `lt` `le` `gt` `ge` | 1（推荐 `Self&`，不强制） | `bool` |
| `&` `\|` `^` | `and` `or` `xor` | 1（推荐 `Self&`，不强制） | 通常同类型 |
| `<<` `>>` | `shl` `shr` | 1（推荐 `Self&`，不强制） | 通常同类型 |
| 一元 `-` `~` `!` | `neg` `inv` `not` | 0 | `neg`/`inv` 通常同类型；`not` 返回 `bool` |

§7.2.3.3 二元运算符方法的形参**推荐**为 `Self&`（避免不必要复制），但语言层不强制。运算符 `a OP b` 触发时，编译器在左操作数类型的方法表中查找名为 `<methodName>` 的全部候选，按以下优先级选最优者：

1. **精确匹配**：右操作数类型与形参类型一致（不含 `&` 的裸类型等价），无需自动取址。
2. **自动取址匹配**：形参为 `T&` 且右操作数类型与 `T` 一致——此时编译器自动为右操作数取址（§7.2.3.6）。
3. **泛型匹配**：形参为泛型参数且右操作数类型满足其 bound（如有）。

同一优先级内存在多个候选时报歧义错误（E6014）。无任何匹配时报 E3073。

**理由**：`Self&` 仍是推荐的默认选择（避免按值复制、与 `$` 一致），但用户可为特定场景声明 `fn mul(scalar f64) Self` 等跨类型重载；编译器按常规重载解析规则选取，行为可预测。

§7.2.3.3a 当二元运算符方法的形参为按值 `T` 且 `T` 为**非内置类型**（用户 struct / `[T * N]` / tuple 等）时，编译器**应当**发出警告，推荐改用 `T&`。内置标量类型（`iN` / `uN` / `f32` / `f64` / `bool`）按值传参不触发此警告。

§7.2.3.4 比较类方法返回 `bool`；其余类**应当**返回与接收者同类型（按值新对象），但语言层不强制。

§7.2.3.5 内置标量类型的运算符方法由编译器内部提供（标记为 `#Builtin`），用户**不得**为其增补重载。

§7.2.3.6 运算符 `a OP b` 编译期重写为 `a.method(args)`，`args` 按声明的形参类型决定是否自动取址：

- 形参为 `T&` → 右操作数自动取址（等价于 `a.method(&b)`）。
- 形参为按值 `T` → 右操作数按值传递（等价于 `a.method(b)`）。

这是 §6.2 / §8.3 "调用方显式 `&`" 一般规则的运算符位置局部例外，**仅**适用于本节列举的运算符触发的方法分发。用户写 `obj.eq(other)` 直接调用该方法时无此例外，仍须按形参类型显式取址。

## §7.3 构造

构造统一通道：`#Static fn` 工厂 + `Self { .field = expr ... }` 字段字面量。语义详见 §7.10；本节给出在 §7 框架下的契约要点。

### §7.3.1 唯一通道：`#Static fn` 工厂

§7.3.1.1 yux **没有**构造函数关键字 / 形态；与结构体同名的实例方法 `fn StructName(...)` 在 v1 **禁止声明**（与 §7.10.1.4 一致）。

§7.3.1.2 "创建一个结构体值"的规范形态：在 struct body 内声明一个返回 `Self` 的 `#Static fn`，其体内通过 `Self { ... }` 字段字面量（§7.10.3）产出本类型值。调用点写 `Type::factory(args)`（§7.10.2）。

```yux
struct Point {
  x i32
  y i32

  #Static
  fn make(x i32, y i32) Point {
    ret Self {
      .x = x
      .y = y
    }
  }
}

fn caller() {
  let p Point = Point::make(3, 4)
}
```

§7.3.1.3 所有结构体（含纯值结构体、无 RC 字段的平凡结构体）都**应当**至少声明一个返回 `Self` 的 `#Static fn`。语言**不**为任何结构体提供"默认构造"或字段默认值（§7.3.3.2）。

### §7.3.2 字段字面量 `Self { ... }`

§7.3.2.1 struct 字面量 `<TypeName> { .field = expr ... }` 可在**任意 expr 位置**出现：`#Static fn` 体内（`Self { ... }` 形态）、普通 fn body、全局 `#Cval` RHS、`#Const fn` body、嵌套字面量字段值等。多行块格式不变（多行 + 无逗号 + 全字段）。LHS 可以是 `Self`（struct body 内）或任意可见类型名（`Point { ... }` / `Counter { ... }` 等）。各位置的字段初值要求见 §7.10.3.5 出现位置矩阵。

§7.3.2.2 字段字面量必须**覆盖全字段**（每个声明字段恰好一次）；缺字段报 **E3125**，未知字段名报 **E3126**，重复字段报 **E3127**。这是 §7.3.3 DAA 的退化形态——单条表达式即完成全字段 first-init，无需流敏感分析。

§7.3.2.3 字段字面量字段间无逗号；每条 `.f = expr` 一行，多行强制 + 行内 `LineEnd` 强制（§7.10.3.4）。

### §7.3.3 字段初始化与所有权

§7.3.3.1 含 RC 字段、Nullable 字段、`Heap<T>` 字段或非平凡子结构体字段的结构体在构造完成时若字段未被初始化，析构会对垃圾值调 release / heap-free，导致未定义行为。`Self { ... }` 字段字面量**应当**列出全部字段（§7.3.2.2）即保证全字段已初始化；该规则对所有结构体一视同仁（含纯值结构体）。

§7.3.3.2 语言**不得**为字段提供隐式默认值。即使字段是 `Weak<T>` / `T?` / 数值标量，`Self { ... }` 也**应当**显式赋值（如 `.w = Weak:<T>(null)` / `.opt = null` / `.n = 0`）。

§7.3.3.3 字段字面量是低层构造原语：句柄字段 RHS 的所有权语义见 §7.10.3.6——fresh 源（数组字面量、临时调用值）走转移 +1；非 fresh 源走 retain。`#Val` / `#Frozen` 字段限定（§7.1.4）在 `Self { ... }` 位放行字段写。

§7.3.3.4 `Heap<T>` 字段在 `Self { ... }` 位通过 first-init 表达式完成构造（§7.4.6.1）；`Heap<T>?` 字段可由 first-init 或显式 `null` 满足。

### §7.3.4 返回与 ABI

§7.3.4.1 工厂 `#Static fn` 的返回类型**应当**显式标注（v1 不推断 `Self`）；返回 `Self` 沿用 §6.3 的按值返回 ABI，含 RC 字段时按 §7.4 的字段级语义生成派生代码。

§7.3.4.2 调用 `Type::factory(args)` 得到的临时值寿命遵循 §4.1；若立即绑定到 `let`，编译器**应当**省去多余的临时拷贝（move-construct，TODO 实现侧落地）。

## §7.4 析构函数与字段级 RC

### §7.4.1 析构函数 `fn ~()`

§7.4.1.1 析构函数写为 `fn ~()`，无参数、无返回值；若声明，**应当**居于 struct body 字段段之后、其它 `fn` 段之前（§7.2.1.2）。

§7.4.1.2 析构函数在结构体值的作用域结束、或被赋值替换、或作为字段被释放时由编译器自动调用。用户**不得**显式调用 `~()`。

§7.4.1.3 析构函数体可访问 `$.field`；该处所有字段视为*已初始化*（`Self { ... }` 全字段覆盖规则保证，§7.3.2.2）。

§7.4.1.4 若结构体未声明析构函数：

- 平凡结构体：编译器**不**生成析构代码（按位 memcpy / 直接释放）。
- 非平凡结构体：编译器**应当**派生默认析构（仅做字段级 RC release，§7.4.3），无需用户写空 `fn ~()`。

§7.4.1.5 用户写的析构函数体**应当**只包含与"清理"相关的语义；其后编译器仍会自动追加字段级 RC release 序列（§7.4.3）。两段顺序：先用户体，再字段 release（按字段声明逆序）。

### §7.4.2 平凡 / 非平凡判定

§7.4.2.1 平凡结构体：所有字段递归地不含 `Rc<T>` / `Weak<T>` / `Array<T>` / `String` / `StringBuilder` / `Heap<T>` / `Heap<T>?`，也不含含上述的子结构体或子结构体字段。

§7.4.2.2 非平凡结构体：包含至少一个堆句柄字段或 `Heap<T>` / `Heap<T>?` 字段（直接或递归通过子结构体）。

§7.4.2.3 该判定为编译期纯结构判定，**应当**对每个具体类型（含泛型实例）独立计算。

### §7.4.3 字段级 retain / release

对**非平凡结构体**，编译器**应当**生成与字段级语义一致的派生代码：

- **复制**（包括按值传参、按值返回、`val a = b`、字面量赋值）：按字段声明顺序逐字段处理；RC 字段执行 retain；嵌套非平凡子结构体递归调用其字段级复制；平凡子段按位 memcpy。
- **析构**：先调用用户析构体（若有）；再按字段声明**逆序**对每个 RC 字段 release；嵌套非平凡子结构体递归析构。

§7.4.3.1 v1 IR 落地形态：内联展开（与现有 `compiler_destructor.cpp` 风格一致）。Open Issue：派生独立 `__copy_S` / `__destroy_S` 函数以缩减代码体积。

§7.4.3.2 字段级派生不会调用任何用户运算符方法（如 `eq` / `plus`）；与运算符重载完全正交。

### §7.4.4 赋值的 retain-then-release

§7.4.4.1 对非平凡结构体的赋值（`s = expr` 或 `s.field = expr`）**应当**按以下顺序执行：

1. 计算 `expr`，得到新值 `v`；
2. 对 `v` 的所有 RC 字段 retain（拷入新值的语义）；
3. 用 `v` 覆写 `s`（或 `s.field`）；
4. 对**被覆盖前**的旧值的所有 RC 字段 release。

§7.4.4.2 此顺序避免 `s = s` 或别名（如 `s = s.boxField.box_back_to_s`）情形下先 release 后 retain 读到已释放对象。规范层用 retain-then-release，编译器**应当**保留这一序。

### §7.4.5 字段读 / 写

§7.4.5.1 字段读 `s.field` 拿到的是字段值的"借用视角"，本身**不**触发 retain；当读出值被存入新变量、参数、字段时按复制语义 retain（§7.4.3）。

§7.4.5.2 字段写 `s.field = expr` 走 §7.4.4 的 retain-then-release。

§7.4.5.3 数组元素读 / 写与字段读 / 写对称（§9.2）。

### §7.4.6 `Heap<T>` 字段的构造 / 复制 / 析构

对含 `Heap<T>` / `Heap<T>?` 字段的非平凡结构体，编译器**应当**额外生成 heap-free 序列；该路径独立于 §7.4.3 字段级 RC，二者在同一结构体内可并存。

§7.4.6.1 **构造**：每个 `Heap<T>` 字段在 `Self { ... }` 字段字面量内**必须** first-init（§7.3.2.2 全字段覆盖规则）；`Heap<T>?` 字段可由 first-init 或显式 `null` 满足。

§7.4.6.2 **复制**：含 `Heap<T>` / `Heap<T>?` 字段的结构体按值复制**禁**（诊断 Exxx2），与 `Heap<T>` 本身按值禁 move 一致；用户应当整体重新装堆（`Heap:<S>(s)`）或借用传递（`S&`）。

§7.4.6.3 **析构**：先调用用户析构体（若有）；再按字段声明**逆序**释放——`Heap<T>` 字段调 `__yux_heap_free<T>`；`Heap<T>?` 字段若 slot 非空则 free，null 则跳过；RC 字段按 §7.4.3 release。同一结构体内字段释放顺序为"字段声明逆序"，按字段类型分发到 §7.4.3 / §7.4.6.3 各自的处理路径。

§7.4.6.4 **字段 move-out**（B 档场景，§8.X）：`Built { buf: b.buf }` 形态消费源结构体的 `Heap<T>?` 字段后，源 slot 写 null；源结构体析构看到 null 跳 free。源字段类型必须是 `Heap<T>?` 才允许 move-out；`Heap<T>` 非空字段不可 move-out（诊断 Exxx2）。

§7.4.6.5 `s.heap_field = expr` 的赋值**不**走 §7.4.4 retain-then-release；按"先 free 旧 slot，再写入新 owner"序：

1. 计算 `expr`（必须是 first-time `Heap` 构造表达式、§7.4.6.4 字段 move-out 形态、或 §8.3a.4.4 C 档 `Heap<T>?` 左值搬移，否则 `Exxx2`）；
2. 若旧 slot 非空（`Heap<T>?` 可能 null），调 `__yux_heap_free<T>`；
3. 写入新 payload 指针。

### §7.4.6.6 复合 move（含 Heap 的 struct / Array 按值传递）

含 `Heap<T>` / `Heap<T>?` 字段（递归）的结构体、`Array<Heap<T>>`、`Heap<Heap<T>>` 等复合类型，按值复制**禁**（§7.4.6.2）；按值传参 / 局部赋值 / `ret` 等左值搬移场景走**复合 move**——与 §8.3a.4.4 一致，**复合 move 只覆盖可空复合 slot**（如 `Builder?`、`Array<Heap<T>>?` 等），非空形态保持按值禁。

§7.4.6.6.1 **触发**：`let lhs S? = rhs` / `f(rhs)` 按值形参 / `ret rhs`，其中 S 含 Heap 子项、LHS / RHS / 形参 类型同为 `S?`，RHS 为左值。

§7.4.6.6.2 **效果**：源 slot 整体写 null（不递归遍历子字段，O(1) 指针搬移）；目标 slot 接管所有权。

§7.4.6.6.3 **源结构体析构**：源 `S?` slot 在原作用域出口按 null 跳过析构；目标 slot 按正常作用域出口走 §7.4.6.3 字段级 heap-free + RC release。

§7.4.6.6.4 示例（builder 模式）：

```yux
struct Builder {
  buf Heap<Bytes>?
  len i32

  #Static
  fn make(cap i32) Builder {
    ret Self {
      .buf = Heap:<Bytes>(cap)
      .len = 0
    }
  }
}

fn finish(b Builder?) Heap<Bytes>? {
  if b != null {
    let out = b.buf     ; ✅ §8.3a.4.4 C 档字段 move-out，b.buf 写 null
    ret out
  }
  ret null
}

fn use() {
  let b Builder? = Builder::make(1024)  ; ✅ Heap 构造期 widen 到 ?
  let final = finish(b)                 ; ✅ 复合 move：b 整体搬入 finish，本地 b = null
  ; 此处 b == null，需 ?. / narrow 再读
}
```

§7.4.6.6.5 **非空形态 `let b Builder = ...; finish(b)`**：在 Heap-containing 复合上**禁**——`finish(b)` 报 `Exxx2`（含 Heap 的复合按值搬移须经 `?` slot）。这避免引入 use-after-move 跟踪，与 §8.3a.4.4 同口径。

## §7.5 字段访问与可变性

### §7.5.1 可变性

§7.5.1.1 yux 不区分"const struct" / "mut struct"；变量级别由 `let` 默认 / `#Mut let` 决定（§5.1 / let-unify）。默认 `let s = ...` 后 `s.field = ...` **不得**通过（编译报错），因为 `s` 自身是只读绑定；`#Mut let s = ...` 解锁字段重赋。

§7.5.1.2 即使默认 `let s = ...`，若 `s` 持有的是 `Rc<T>` / `Array<T>` 等堆句柄，对句柄指向的堆对象的修改并不通过 `s` 自身的赋值表达，因此与默认 `let` 不冲突。是否允许通过默认 `let` 绑定的堆句柄修改 payload，由各堆句柄各自约束（§9）。

### §7.5.2 字段访问语法

§7.5.2.1 `s.field`、`$.field`：见 §4.7。

§7.5.2.2 链式访问 `s.a.b.c` 按从左到右逐字段展开，每层都参与 §7.5.1 的可变性判断。

§7.5.2.3 `&s.field`：见 §4.7 / §8.3；语法层允许，寿命由 §8.3.5 校验。

### §7.5.3 内存布局

§7.5.3.1 字段在内存中按声明顺序依次排列；padding、align 由实现根据目标 ABI 决定。规范层**不**承诺 POD 布局与 C 同构；与 C 互操作时**应当**通过 `extern` + `Ptr` 边界（§9 / §6.6）。

§7.5.3.2 `Rc<T>` / `Array<T>` / `String` / `StringBuilder` 字段在结构体内按其句柄宽度（v1：单指针）嵌入；payload 不嵌入结构体。

§7.5.3.3 v1 **不**保证字段重排优化；编译器**可以**在未来版本对非 `extern` 类型重排字段以减少 padding（informative）。

## §7.6 按值复制语义

### §7.6.1 终态

§7.6.1.1 用户结构体**默认按值复制**：函数实参、返回值、变量初始化、字段写入均按 §7.4.3 的字段级复制语义执行。"结构体通过指针传递"在规范层**不存在**——编译器若在 ABI 层用指针传大结构体，是不可观测的优化（§3.1）。

§7.6.1.2 与 §3.4 / §6.3 的"按值赋值 / 按值返回"一致；本节是其在结构体上下文的具体落实。

### §7.6.2 复制不调用用户方法

§7.6.2.1 字段级复制是编译器派生的 retain / memcpy 序列；**不**调用用户的 `eq` / `plus` / 析构等方法。

§7.6.2.2 用户**不得**通过运算符重载或方法定义改变默认按值复制语义；如需特殊复制行为，**应当**显式提供 `clone` 方法并在调用方手动调用。

### §7.6.3 与 `T&` 的差异

§7.6.3.1 函数形参写 `Foo` 与写 `Foo&` 语义不同：前者按值复制（字段级 RC retain），后者借用句柄不复制。规范层**不**自动取址；调用方写 `f(x)` 与 `f(&x)` 选择不同的形参重载（§6.2 / §8.3）。

§7.6.3.2 方法接收者 `$` 是隐式 `Self&`（§7.2.2.1）；调用 `obj.method()` 不触发对 `obj` 的字段级复制。

## §7.7 结构体与堆句柄的组合

§7.7.1 自引用 / 双向引用结构体**应当**经堆：字段须写为 `Rc<Self>?` / `Weak<Self>?`，栈上自引用结构体**不得**通过编译（§3.7 / §8）。

§7.7.2 含 `Weak<T>` 字段的结构体在 `Self { ... }` 字段字面量内**应当**显式给定初值（如 `.w = Weak:<T>(null)`）；语言不为 `Weak` 提供"自然空值"豁免（§7.3.3.2）。

§7.7.3 含 `Rc<T>` 字段的结构体在父对象析构时按 §7.4.3 自动 release `Rc`；payload 是否真正释放由 RC 决定（§8）。

## §7.8 spec 实现：`#Impl(D)` 顶行注解

详见 §12。本节仅给出对结构体声明的扩展，语义以 §12 为准。

### §7.8.1 形态

§7.8.1.1 在 `structDecl` 顶行 `buildAnno*` 槽内可重复出现 `#Impl(D)`，宣告该 struct 实现 spec `D`；多 spec 由多条 `#Impl(D)` 平铺。

```yux
#Impl(ToString)
#Impl(To<i32>)
struct Counter {
  v i64

  fn Counter(init i64) {
    $.v = init
  }

  fn to_string() String {
    $.v.to_string()
  }

  fn to() i32 {
    $.v.to_i32()
  }
}
```

§7.8.1.2 `#Impl(D)` 注解通过 `buildAnno` 的"单参数糖" `(ID genericDef?)` 槽承载（§11.1.1.1）；不带 `(...)` 视为参数缺失，报 **E2010**。

§7.8.1.3 struct body 内提供的方法集**应当**穷尽覆盖所有所列 spec 的签名并集（按 §12.3 等价规则）；缺任一 spec 签名报 **E1137**。**不再**对"多余于 spec 的方法"报错——未命中任何 `#Impl(D)` 的方法视为该 struct 自身的普通方法（v1 早期 E1102 已废弃；严格隔离留 [`draft/DRAFT-extension-blocks.md`](draft/DRAFT-extension-blocks.md)）。

§7.8.1.4 同一 struct 上同一 spec **不得**重复宣告：写两条 `#Impl(D)` 报 **E1103**。

### §7.8.2 spec 与普通方法共享命名空间

§7.8.2.1 struct body 内方法名按全局唯一原则定义；同一名字仅一份实现，可同时满足多条 `#Impl(Di)` 的同名签名要求（若签名等价）。签名不等价的同名要求按 §12.3 等价判定下报 **E1137**（无法同时满足）。

§7.8.2.2 实例方法 / 静态工厂 / 析构函数与 spec 契约方法**共存于同一 body**；调用方按 §12.2.3 走静态分发。

§7.8.2.3 receiver `$` 在 struct body 内方法体的语义统一（§7.2.2，类型 `Self&`），不论该方法是否对应某个 `#Impl(D)` 的契约。

### §7.8.3 与 `T&` 的关系

§7.8.3.1 spec 实现宣告限定为 owned 类型 T；语法层不可能在 struct 头位写 `T&`（§7.1）。

§7.8.3.2 `obj: T&` 上调用 spec 方法走 §8.6.7.3 receiver 归一，无需为 `T&` 单独实现。

### §7.8.4 `#Spec` 与 `#Impl` 互斥

§7.8.4.1 `#Spec` 顶行注解把 struct 声明转为 spec（仅含签名，§12.1.1）；`#Spec` 与 `#Impl(D)` **不得**在同一声明上共存（spec 自身不实现别的 spec；继承 / super-trait 由 §12.8 项 8 禁止）。违反报 **E1110**。

## §7.9 与 enum 的对照（informative）

§7.9.1 enum（§3.10）与 struct 同属"用户名义值类型"档（§3.1）：

- 两者均为**值类型**：栈布局、按值复制；要上堆用 `Rc<E>` / `Rc<S>`，与既有 `Rc<T>` 协议一致。
- 两者按**名义判等**（§3.4.1）：声明源决定身份，结构等同的两个声明仍是无关类型。
- 含 RC 字段时按字段级派生 retain / release / 析构（§7.4 / §8）；enum 在此基础上额外按 tag dispatch（[draft/DRAFT-枚举.md](draft/DRAFT-枚举.md) §6）。

§7.9.2 形态差异：

| 维度 | struct | enum |
|---|---|---|
| 字段 / variant 形态 | 命名字段集合（积类型） | 命名变体集合（和类型），可携带 tuple-style payload |
| 读取通道 | `obj.field` 直接访问 | 仅 `match`（§3.10.5 / §4 / §5），不暴露 tag |
| 方法 / spec 实现 | 允许（§7.2 / §7.8） | v1 **不**允许（§3.10.2.6） |
| 泛型 | 允许（§7.1.2） | v1 **不**允许（§3.10.2.6） |
| 字段 / payload 含 `T&` | 拒绝（§3.2.3.2） | 拒绝（§3.10.3.2） |

§7.9.3 选用建议（informative）：用 struct 表示"对象具有一组始终存在的字段"，用 enum 表示"对象处于若干互斥状态之一"。

## §7.10 静态函数（关联函数）

引入自 [draft/DRAFT-static-fn.md](draft/DRAFT-static-fn.md)。本节规范"不带接收者"的结构体函数（关联函数 / 静态函数），调用语法 `Type::name(...)`，并配套 `Self` 类型字面量与 `Self { ... }` 字段字面量。

### §7.10.1 声明

§7.10.1.1 形态：`#Static` 注解紧贴 `fn` 头，函数声明位于 struct body 内（§7.2.1）合法。

```yux
Point {
  #Static
  fn make(x i32, y i32) Point {
    ret Self {
      .x = x
      .y = y
    }
  }

  fn sum() i32 = $.x + $.y
}
```

§7.10.1.2 `#Static fn` **不**注入接收者参数 `$`；其在 IR 层是顶层函数。可附着位置见 §11.11。

§7.10.1.3 `#Static fn` 仅能在 struct body 内声明（§7.2.1）；**不**作为运算符重载方法；**不**等同析构 `fn ~()`；**不**进 spec body（spec 体内只允许实例方法签名，§12.1.1.1）。

§7.10.1.4 同一结构体内 `#Static fn` 与同名实例 `fn` 共存允许（调用形态 `Type::name` / `obj.name` 天然区分），sema **不**报错。构造函数（与结构体同名的实例方法）形态已删除（§7.3.1.1），原"`Type::Type(...)` 与 ctor 入口冲突"的禁忌不再适用——但实例方法名仍**不应**与结构体名同名以避免阅读歧义。

### §7.10.2 调用

§7.10.2.1 调用语法 `Type::name(args)`；token `::` 即 `SymbolColonColon`，与 enum 构造 `Enum::Variant(args)` 共用 parser 节点（`ExprPathCallNode`），sema 按 LHS 类型分流：

- LHS 解析为 enum → enum 构造路径（§3.10）；
- LHS 解析为 struct 且 RHS 是 `#Static fn` → 静态调用；
- LHS 解析为 struct 但 RHS 是实例方法 → 报 **E3120**；
- LHS 解析为 struct 但 RHS 不存在 → 报 **E3121**；
- LHS 既非 enum 又非已知 struct → 报 **E3122**。

§7.10.2.2 泛型形态：

```
staticCall ::= (typeName | 'Self') (':' genericDef)? '::' ID (':' genericDef)? '(' args? ')'
```

第一段 turbofish 给 struct 类型参数，第二段给静态 fn 类型参数；任一段可省。

§7.10.2.3 在 struct body 内（含实例方法体 / 静态 fn 体 / 析构函数体）**可以**写 `Self::name(...)` 调用本类型静态 fn，等同当前类型名做 LHS。

§7.10.2.4 静态调用没有 receiver，**不**触发字段级 retain / release（§7.4.3 与本特性无关）；mangle 形态 `Type::name(args)`，receiver 槽位缺省。

### §7.10.3 `Self` 类型字面量

§7.10.3.1 `Self` 是保留字（附录 A.1），lexer token `SelfType`；在 struct body内绑定为所属结构体类型（含泛型实参当前绑定）。

§7.10.3.2 允许位置：

- **类型位**：fn 返回类型、fn 形参类型（含 `Self&`）、局部 `let` 类型标注、turbofish 实参；
- **调用 LHS**：`Self::name(...)`（§7.10.2.3）；
- **字段字面量 LHS**：`Self { ... }`（§7.10.3.4）。

§7.10.3.3 字段类型位**禁用** `Self`（§7.1.3）；自引用须 `Rc<Self>?` / `Weak<Self>?`。struct body外出现 `Self` 报 **E3123**。

§7.10.3.4 struct 字面量：

```
exprStructLit ::= typeName '{' LineEnd ( fieldInit | LineEnd )* '}'
fieldInit     ::= '.' ID '=' expr LineEnd
```

LHS `typeName` 可以是 `Self`（struct body 内）或任意可见类型名（如 `Point` / `Counter`）。字段名前的 `.` 强制；每条 `fieldInit` 一行（多行强制 + 行内 `LineEnd` 强制）；字段之间无逗号。

§7.10.3.5 struct 字面量出现位置矩阵（const-eval 落地后，[DRAFT-const-eval](draft/DRAFT-const-eval.md) §5）：

| 位置 | 允许 | 字段初值要求 | 备注 |
|---|---|---|---|
| `#Static fn` 内 `Self { ... }` | ✅ | 可 runtime | 既有形态，未变 |
| 普通 fn body 内 `<Type> { ... }` | ✅ | 可 runtime | LHS 放宽到任意类型名 |
| 全局 `#Cval let` RHS | ✅ | 全 const | 走 const-eval 通路 emit ConstantStruct |
| `#Const fn` body / 返回 | ✅ | 全 const | 同上 |
| 嵌套（其它 struct 字面量的字段值） | ✅ | 上下文决定 | const 位字段值仍要 const |

字段约束与 §7.3.2.2 一致：全字段公开、全填（每字段恰好一次）、顺序无关。缺字段报 **E3125**，未知字段名报 **E3126**，重复字段报 **E3127**。含非公开字段 struct 的字面量构造 → **E3142**（v1 占位，当前无 `#Private` 修饰故事实不触发）。

§7.10.3.6 字段字面量是低层构造原语：句柄字段 RHS 的所有权语义与 `$.field = value` 一致（§7.4.4），fresh 源（数组字面量、临时调用值）走转移 +1；非 fresh 源走 retain。`#Val` / `#Frozen` 字段限定（§7.1.4）的"构造期"在此重定义为"`#Static fn` 体内通过 `Self { ... }` 产出 `Self` 的那个表达式位"——该位放行字段写。

### §7.10.4 与 `$` 的关系

§7.10.4.1 `#Static fn` 体内**禁写** `$` / `$.field` / `&$`：sema 检测到报 **E3128**。`Self` 是访问 receiver-side 类型的唯一通道（§7.10.3）。

§7.10.4.2 静态 fn 可调用本类型其它静态 fn 构造 `Self`（如 `fn origin() Point { ret Self::make(0, 0) }`）；也可直接写 `Self { ... }` 字面量产出值（§7.10.3.4）。

### §7.10.5 泛型与单态化

§7.10.5.1 泛型结构体的 `#Static fn` 跟随结构体单态化：`Vec<i32>::with_capacity` 与 `Vec<String>::with_capacity` 是不同实例。

§7.10.5.2 静态 fn 自身可带类型参数（双 turbofish 形态，§7.10.2.2）；推断规则与现有泛型 fn 调用一致。

### §7.10.6 SDK 形态

SDK 内典型 `#Static` 工厂（构造唯一通道）：

| 类型 | 工厂 |
|---|---|
| `String` | `String::empty()` / `String::from(buf Array<u32>)` |
| `StringBuilder` | `StringBuilder::empty()` |
| `Nullable<T>` | `Nullable:<T>::some(v T)` / `Nullable:<T>::none()` |

同名 ctor 通道（v0.x `String(buf Array<u32>)` 等形态）已删除（spec-unify v1 / DRAFT-static-fn 落地）；调用点统一写 `Type::factory(args)`。

## §7.11 静态字段

引入自 [draft/DRAFT-static-vars.md](draft/DRAFT-static-vars.md)。本节规范 struct body 内的**静态字段**（关联于类型而非实例的命名空间字段），读写语法 `Type::FIELD` / `Type::FIELD = v`，运行时初始化走 `_yux_global_init` ABI。

### §7.11.1 声明

§7.11.1.1 形态：`#Static` 注解紧贴字段名（顶行），字段声明位于 struct body 内字段段（与 `filedDecl` 混合书写），独立产生式 `staticFieldDecl`：

```yux
struct Counter {
  value i32                       ; 实例字段

  #Static
  DEFAULT_STEP i32 = 1            ; 静态 val 字段

  #Mut
  #Static
  total_created i64 = 0           ; 静态可变字段

  fn inc() {
    $.value = $.value + Counter::DEFAULT_STEP
  }
}
```

§7.11.1.2 静态字段**无 `let` 关键字**（沿用字段段约定，[yux-syntax.md](../../.claude/rules/yux-syntax.md) §2）。注解必须含 `#Static`（缺 → 走 `filedDecl` 解析），可选叠加 `#Mut`（可变静态字段）。`#Static` 不接受参数。

§7.11.1.3 v1 静态字段**必须** init（缺 → `E3150`）；v1 **不**支持泛型 struct 上的静态字段（报 `E3157`）。

§7.11.1.4 LLVM GlobalVariable 命名：`<Mod>::<Struct>::FIELD`（与 `#Static fn` 一致，复用 mangler）。默认 `internal` 链接性；跨模块访问按既有模块导出规则（private → `E3156`）。

§7.11.1.5 初始化时机与全局 `let` 一致（§5.1.4.2）：非 const-evaluable → `_yux_global_init`；const-evaluable → LLVM Constant。init 内禁 `try / catch`（`E3155`）。

### §7.11.2 读写路径

§7.11.2.1 **读**：`Type::FIELD`，复用 `ExprPathCallNode` parser 路径（与 `#Static fn` 调用 `Type::name(args)` 同源），sema 按 LHS 类型 + RHS 名分流为静态字段读 → LoadInst on GlobalVariable。

§7.11.2.2 **写**：`Type::FIELD = v`（仅 `#Mut` 静态字段），codegen 验 `#Mut` 后 StoreInst on GlobalVariable。非 `#Mut` 静态字段被赋值 → `E3151`。

§7.11.2.3 **实例访问拒绝**：`obj.FIELD`（通过实例访问静态字段）→ sema 报错（`E3152`，v1 占位未落地；当前走既有字段查找路径自然找不到并报 `E3040`）。

### §7.11.3 与实例字段对照

| 维度 | 实例字段（`filedDecl`） | 静态字段（`staticFieldDecl`） |
|---|---|---|
| 引入符 | 无（`name Type`） | `#Static` 顶行 + `name Type = expr` |
| 所属 | 实例 | 类型 |
| 访问 | `obj.field` / `$.field` | `Type::FIELD` |
| 可变性 | `#Val` / `#Frozen` 注解（§7.1.4） | 默认浅不可变 / `#Mut` 放宽 |
| init | `Self { ... }` 字段字面量（§7.3.2） | 声明处 `= expr`（必须） |
| 初始化时机 | 构造期 | 全局 init（`_yux_global_init`） |
| 泛型 struct | 允许 | v1 禁（`E3157`） |
