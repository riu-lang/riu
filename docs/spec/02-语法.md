# §2 语法

本章规范 yux 的语法（grammar），即由 token 流（§1）到抽象语法树的形成规则。权威定义在 [`yux/ast/yuxParser.g4`](../../yux/ast/yuxParser.g4)；本章是其规范化叙述，附录 B 给出主要产生式的精简摘录。冲突时**应当**以 `.g4` 与编译器实现为准，并回写本规范。

## §2.1 文法约定

### §2.1.1 元语法

本规范使用如下扩展 BNF 记号：

| 记号 | 含义 |
|---|---|
| `X ::= ...` | 产生式定义 |
| `A B` | 串联 |
| `A \| B` | 可选分支 |
| `A?` | 0 或 1 次 |
| `A*` | 0 或多次 |
| `A+` | 1 或多次 |
| `( ... )` | 分组 |
| `'...'` | 字面 token（含运算符 / 关键字） |
| `UPPER` | 词法 token（与 `yux.g4` lexer 规则同名） |
| `lower` | 语法非终结符 |

### §2.1.2 与 `yux.g4` 的对应

- 本章产生式名与 `yux.g4` 中的 parser 规则名一致；分支标签（如 `# exprDot`）保留以便交叉引用。
- 词法 token（`ID`、`INT`、`STR_LINE`、`SymbolDot` 等）大写或带 `Symbol` 前缀，与 `yux.g4` 同名。
- 本规范不复刻全部产生式；附录 B 只列出主要产生式的简化形式。条款引用细节时**应当**写明 `.g4` 中的规则名（如"见 `expr` 规则"）。

## §2.2 编译单元

### §2.2.1 顶层结构

`program` 是单个 yux 源文件的根产生式：

```
program ::= comment*
            imports*
            ( fn
            | externDecl
            | globalConst
            | structDecl
            | structImpl
            | comment
            | codeLineEnd
            )*
            EOF
```

约束：

- §2.2.1.1 文件**应当**以 0 或多个顶层注释起始；这些注释属于文件级注释（*informative*）。
- §2.2.1.2 紧随其后的是 0 或多个 `imports` 声明；`imports` **不得**出现在第一个非 `imports` 顶层声明之后（由 `program` 产生式保证）。
- §2.2.1.3 顶层声明（`fn` / `externDecl` / `globalConst` / `structDecl` / `structImpl`）的相对顺序自由，可与 `comment` / `codeLineEnd` 任意混排。

### §2.2.2 顶层声明类别

| 产生式 | 形态 | 章节 |
|---|---|---|
| `imports` | `use a.b.c` / `use a.*` | §10 |
| `fn` | `fn name(...) ret { ... }` | §6 |
| `externDecl` | `extern { fnHeader* }` | §6 / §10 |
| `globalConst` | `let NAME T = expr`（含 `#Cval` / `#Mut` 注解档位） | §5.1 |
| `structDecl` | `struct Name<...> { field T }` | §7 |
| `structImpl` | `Name<...> { fnClean? fn* }` | §7 |

### §2.2.3 codeLineEnd

```
codeLineEnd ::= LineEndComment? LineEnd
```

`codeLineEnd` 是终结一条声明 / 语句的最小单位。除显式形态（如表达式体函数 `fn f() = e codeLineEnd?`）外，几乎所有顶层声明、语句、`use`、`buildAnno` 都以 `codeLineEnd` 终结。

## §2.3 空白即语法

### §2.3.1 空格的语法地位

§1.2 已规定空格的字符级形态。在语法层面：

- §2.3.1.1 关键字（`fn` `let` `if` 等）与其后跟随的 `ID` / 表达式之间**应当**至少有一个空格，否则将与之黏合为单个 `ID` token。
- §2.3.1.2 二元运算符两侧**应当**各有空格；这是风格层要求，不全由语法器强制。
- §2.3.1.3 一元运算符 `-` / `~` / `!` 紧贴操作数（无空格），由 `exprUnary` 产生式保证（§4）。

### §2.3.2 换行的语法地位

`LineEnd`（§1.1.2）是**显式**语法符号：

- §2.3.2.1 顶层声明、语句、`buildAnno`、`use`、`globalConst` 之类一律由 `codeLineEnd` 终结；省略 `LineEnd` 等同于"未结束"语法错误。
- §2.3.2.2 例外：表达式体函数 `fn f() = expr` 的 `codeLineEnd?` 可省，文件可在表达式后立即接 `EOF`。
- §2.3.2.3 控制流构造 `if` / `loop` 的 `statementBlock` 内部首尾各占一个 `codeLineEnd`，参见 `statementBlock` 产生式（§5）。
- §2.3.2.4 表达式与语句**不允许**跨行（v1 不支持反斜杠续行 / 隐式续行）。

## §2.4 多字符运算符的语法组合

部分多字符运算符在 `yux.g4` 中由词法层的单字符 token 在语法层拼合：

| 形态 | 产生式 | 说明 |
|---|---|---|
| `<<` / `>>` | `opShift ::= '<' '<' \| '>' '>'` | 移位（§4） |
| `<<=` / `>>=` | `opAssign` 内拼接 | 复合赋值（§5） |
| `>=` / `<=` | `opCompare` 内拼接 | 比较（§4） |
| `??` | `expr '?' '?' expr` | Nullable 默认值（§4 / §3.6） |
| `?.` | `expr '?' '.' ID` | 安全字段访问（§4 / §3.6） |
| `<-` | `expr '<' '-' expr` | 移入赋值（§4 / §8） |

约束：拼合 token 之间**不得**有空格（如 `< <` 不等于 `<<`），由表达式产生式保证。

## §2.5 产生式总览

按主题分组列出主要 parser 产生式，详见 [附录 B](附录B-语法汇总.md)：

- 顶层：`program` / `imports` / `externDecl` / `globalConst` / `buildAnno`
- 类型：`type` / `typeWithRef` / `genericDef` / `genericDefWithRef`
- 字面量：`literal` / `number` / `numInt` / `numFloat`
- 函数：`fn` / `fnHeader` / `fnParams` / `fnParam` / `fnParamStd` / `fnParamGroup` / `fnBody` / `fnExprkBody` / `fnBlockBody` / `fnClean`
- 结构体：`structDecl` / `structImpl` / `filedDecl`
- 表达式：`expr`（含 `exprParen` / `exprGetRef` / `exprGet` / `exprDot` / `exprCall` / `exprUnary` / `exprBinOp` / `exprShift` / `exprMulDivMod` / `exprAddSub` / `exprCompare` / `exprEq` / `exprBool` / `exprArray` / `exprArrayInit` / `exprIfElse` / `exprOneLineIfElse` / `exprNullElse` / `exprMoveAssign` / `exprThis` / `exprLiteral`）
- 语句：`statement` / `statementBlock` / `statementLet` / `statementLetTuple` / `statementSet` / `statementLoop` / `statementAssign` / `statementExpr` / `statementRet` / `statementRetVoid` / `statementBreak`
- 运算符：`opShift` / `opCompare` / `opEq` / `opBool` / `opAssign`

## §2.6 语法层禁忌

下列形态在 `yux.g4` 层就被产生式直接拒绝（不进入语义阶段）；与 §3.7 / §8 列出的语义层禁忌区别开：

- §2.6.1 `T& &`（嵌套引用）：`typeWithRef` 不允许 `T&` 作为内层 type，且自身只允许尾部一个 `&`。
- §2.6.2 字段位置出现 `T&`：`filedDecl ::= ID type`，`type` 不含 `&`，故结构体字段无法写 `T&`。
- §2.6.3 `Weak<T>?`：v1 由编译器在解析 `type` 后语义层拒绝（产生式允许，语义禁；详见 §3.7、§8.5）。
- §2.6.4 `&` 作用于非左值：`exprGetRef` 仅形如 `& obj (.subs)*`，无法写 `&f()` / `&arr[i]`（§4、§8.3.4）。
