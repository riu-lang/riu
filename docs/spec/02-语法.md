# §2 语法

本章规范 yux 的语法（grammar），即由 token 流（§1）到抽象语法树的形成规则。权威定义在 [`yux/ast/yuxParser.g4`](../../yux/ast/yuxParser.g4)；本章是其规范化叙述，附录 B 给出主要产生式的精简摘录。冲突时**应当**以 `.g4` 与编译器实现为准，并回写本规范。

## §2.1 文法约定

### §2.1.1 元语法

本规范使用如下扩展 BNF 记号：

| 记号 | 含义 |
|---|---|
| `X ::= ...` | 产生式定义 |
| `A B` | 串联 |
| `A \| B` | 可选分支 |
| `A?` | 0 或 1 次 |
| `A*` | 0 或多次 |
| `A+` | 1 或多次 |
| `( ... )` | 分组 |
| `'...'` | 字面 token（含运算符 / 关键字） |
| `UPPER` | 词法 token（与 `yux.g4` lexer 规则同名） |
| `lower` | 语法非终结符 |

### §2.1.2 与 `yux.g4` 的对应

- 本章产生式名与 `yux.g4` 中的 parser 规则名一致；分支标签（如 `# exprDot`）保留以便交叉引用。
- 词法 token（`ID`、`INT`、`STR_LINE`、`SymbolDot` 等）大写或带 `Symbol` 前缀，与 `yux.g4` 同名。
- 本规范不复刻全部产生式；附录 B 只列出主要产生式的简化形式。条款引用细节时**应当**写明 `.g4` 中的规则名（如"见 `expr` 规则"）。
- 附录 B 是手工摘录，**不**提供与 `yux.g4` 的自动一致性脚本。冲突时以 `.g4` 为准并修订附录 B / 本章（附录 B.9）。

## §2.2 编译单元

### §2.2.1 顶层结构

`program` 是单个 yux 源文件的根产生式（与 `yuxParser.g4` 对齐）：

```
program ::= LineEnd*
            imports*
            ( fn
            | externDecl
            | globalConst
            | aliasDecl
            | enumDecl
            | structDecl
            | LineEnd
            )*
            EOF
```

约束：

- §2.2.1.1 顶行注释（`LineComment`）与尾随注释（`LineEndComment`）进入 HIDDEN 通道（§1.3），**不**出现在 `program` 产生式中。文件仍可以 0 或多条顶行注释起始（*informative*：文件级注释）。
- §2.2.1.2 紧随文件头空白之后的是 0 或多个 `imports` 声明；`imports` **不得**出现在第一个非 `imports` 顶层声明之后（由 `program` 产生式保证）。
- §2.2.1.3 顶层声明（`fn` / `externDecl` / `globalConst` / `aliasDecl` / `enumDecl` / `structDecl`）的相对顺序自由，可与 `LineEnd`（空行）混排。结构体方法写在 `structDecl` 体内，无独立 `structImpl` 产生式。

### §2.2.2 顶层声明类别

| 产生式 | 形态 | 章节 |
|---|---|---|
| `imports` | `use a.b.c` / `use a.*` | §10 |
| `fn` | `fn name(...) ret { ... }` | §6 |
| `externDecl` | `extern { fnHeader* }` | §6 / §10 |
| `globalConst` | `let NAME T = expr`（含 `#Cval` / `#Mut` 注解档位） | §5.1 |
| `aliasDecl` | `Name = type` / `Name<T> = type` | §3.9 |
| `enumDecl` | `enum Name { ... }` | §3.10 |
| `structDecl` | `struct Name<...> { fields; fnClean?; fn* }` | §7 |

### §2.2.3 codeLineEnd

```
codeLineEnd ::= LineEndComment? LineEnd
```

`codeLineEnd` 是规范层对"一行结束"的称呼：`LineEndComment` 在词法上走 HIDDEN，parser 只看见 `LineEnd`。除显式形态（如表达式体函数 `fn f() = e codeLineEnd?`）外，几乎所有顶层声明、语句、`use`、`buildAnno` 都以换行终结。

## §2.3 空白即语法

### §2.3.1 空格的语法地位

§1.2 已规定空格的字符级形态。在语法层面：

- §2.3.1.1 关键字（`fn` `let` `if` 等）与其后跟随的 `ID` / 表达式之间**应当**至少有一个空格，否则将与之黏合为单个 `ID` token。
- §2.3.1.2 二元运算符两侧**应当**各有空格；这是风格层要求，不全由语法器强制。
- §2.3.1.3 一元运算符 `-` / `~` / `!` 紧贴操作数（无空格），由 `exprUnary` 产生式保证（§4）。

### §2.3.2 换行的语法地位

`LineEnd`（§1.1.2）是**显式**语法符号：

- §2.3.2.1 顶层声明、`buildAnno`、`use`、`globalConst` 之类一律由 `codeLineEnd` 终结；省略 `LineEnd` 等同于"未结束"语法错误。
- §2.3.2.2 例外：表达式体函数 `fn f() = expr` 的 `codeLineEnd?` 可省，文件可在表达式后立即接 `EOF`。
- §2.3.2.3 `statementBlock`（函数体 / `if` / `loop` / `try`·`catch` / lambda 语句体）的 `{` 后、语句后、`}` 前换行均可省：`fn f() { ret 1 }` 与多行写法等价。块内多条语句之间仍以换行（或下一条语句的起始 token）分隔。
- §2.3.2.4 v1 **不**支持反斜杠续行，也**不**承认隐式续行（不会因行末 token 自动把下一行拼进来）。`LineEnd` 是有意义的语法 token（非 HIDDEN）；只有产生式写明 `LineEnd*` / `LineEnd?` / `LineEnd` 的位置才允许或要求换行。
- §2.3.2.5 当前允许换行的槽位（摘自 `yuxParser.g4`）：
  - 文件头 / 顶层声明之间的空行（`program` 的 `LineEnd*` / `LineEnd`）。
  - 形参与实参列表：`fnHeader` / `lambdaParams` / `exprCall` / `exprEnumCtor` 的 `(` 后、`,` 后、`)` 前。
  - 索引与数组字面量：`exprGet` / `exprArray` 的 `[` 后、`,` 后、`]` 前。
  - 成员链：`exprDot` / `exprTupleMember` / `exprGetRef` 在 `.` / `?.` / `DOT_NUM` **之前**（方法链拆行走这条，见 §4.7.2.5）。
  - 块：`statementBlock` / `trailingLambda` 的 `{` 后（§2.3.2.3，可省）。
  - 强制多行：`structDecl` / `exprStructLit` / `exprMatch` 的 `{` 后至少一处 `LineEnd`。
- §2.3.2.6 下列位置**不得**换行（产生式无 `LineEnd*`）：二元运算符与其操作数之间（`a + b` 不能写成 `a +\n b`）；拼合运算符内部（`??` 的两个 `?` 之间、`?.` 的 `?` 与 `.` 之间、`<<` / `<=` 等同理）。

## §2.4 多字符运算符的语法组合

部分多字符运算符由词法层的**单字符** token 在语法层拼合（与 `==` / `&&` / `<-` 等词法预合成 token 相对）：

| 形态 | 产生式 | 说明 |
|---|---|---|
| `<<` / `>>` | `opShift ::= '<' '<' \| '>' '>'` | 移位（§4）。`<` / `>` 兼作泛型括号，故不在词法层预合成。 |
| `<<=` / `>>=` | `opAssign` 内拼接 | 复合赋值（§5） |
| `>=` / `<=` | `opCompare` 内拼接 | 比较（§4） |
| `??` | `exprNullElse ::= expr '?' '?' expr` | Nullable 默认值（§4.6.1） |
| `?.` | `exprDot ::= expr LineEnd* '?'? '.' ID` | 安全字段 / 方法访问（§4.6.2）；`?` 是 `exprDot` 上的可选前缀，不是独立二元算符 |
| `...` | `exprArrayInit` 内 `'.' '.' '.'` | 填充数组（§4） |

§2.4.1 **不**把 `??` / `?.` 升格为独立词法 token。优先级与结合性由 `expr` 分支顺序决定（§4.2.1），与运算符是 1 个还是 2 个 token 无关。`?` 同时是可空类型后缀（`T?`），保持单字符与 `<<` / `<=` 同一策略。

§2.4.2 风格上拼合 token 之间**不得**插空格（写 `??` 不写 `? ?`）。`Space` 走 HIDDEN 通道，语法器仍会把 `a ? ? b` / `a < < b` 认成 `??` / `<<`；格式化器输出紧贴形态（`??` / `?.` / `<<`）。

§2.4.3 `<-` 是词法 token `SymbolLtSub`（§1.7.1），**不是** `'<' '-'` 拼合。

## §2.5 产生式总览

按主题分组列出主要 parser 产生式，详见 [附录 B](附录B-语法汇总.md)。分支标签顺序以 `yuxParser.g4` 的 `expr` 为准（§4.2.1）：

- 顶层：`program` / `imports` / `externDecl` / `globalConst` / `aliasDecl` / `enumDecl` / `buildAnno`
- 类型：`type` / `typeWithRef` / `genericDef` / `genericDefWithRef`
- 字面量：`literal` / `number` / `stringTemplate`
- 函数：`fn` / `fnHeader` / `fnParams` / `fnParam` / `fnParamStd` / `fnParamGroup` / `fnBody` / `fnExprkBody` / `fnBlockBody` / `fnClean`
- 结构体：`structDecl` / `filedDecl` / `fieldInit`
- 枚举：`enumDecl` / `enumVariant` / `enumPattern` / `matchArm`
- lambda：`lambdaParams` / `lambdaParam` / `lambdaBody` / `trailingLambda`
- 表达式：`expr`（`exprLambdaParen` / `exprStructLit` / `exprParen` / `exprGetRef` / `exprGet` / `exprTryCatch` / `exprOneLineIfElse` / `exprIfElse` / `exprMatch` / `exprEnumCtor` / `exprArrayInit` / `exprDot` / `exprTupleMember` / `exprArray` / `exprCall` / `exprCallTrailingOnly` / `exprUnary` / `exprShift` / `exprBinOp` / `exprMulDivMod` / `exprAddSub` / `exprCompare` / `exprEq` / `exprBool` / `exprMoveAssign` / `exprLiteral` / `exprNullElse` / `exprUnit` / `exprTuple` / `exprThis`）
- 语句：`statement` / `statementBlock` / `statementLet` / `statementLetTuple` / `statementSet` / `statementStaticFieldSet` / `statementLoop` / `statementForIn` / `statementAssign` / `statementExpr` / `statementRet` / `statementRetVoid` / `statementBreak` / `statementContinue`
- 运算符：`opShift` / `opCompare` / `opEq` / `opBool` / `opAssign`

## §2.6 语法层禁忌

下列形态在 `yux.g4` 层就被产生式直接拒绝（不进入语义阶段）；与 §3.7 / §8 列出的语义层禁忌区别开：

- §2.6.1 `T& &`（嵌套引用）：`typeWithRef` 不允许 `T&` 作为内层 type，且自身只允许尾部一个 `&`。
- §2.6.2 字段位置出现 `T&`：`filedDecl ::= ID type`，`type` 不含 `&`，故结构体字段无法写 `T&`。
- §2.6.3 `Weak<T>?`：v1 由编译器在解析 `type` 后语义层拒绝（产生式允许，语义禁；详见 §3.7、§8.5）。
- §2.6.4 `&` 作用于非左值：`exprGetRef` 仅形如 `& obj (.subs)*`，无法写 `&f()` / `&arr[i]`（§4、§8.3.4）。
