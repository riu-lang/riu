# §8 所有权与引用

本章规范 yux 的所有权模型、引用计数协议、借用类型 `T&` 的寿命检查、调用 ABI、临时值清单与禁忌一览。本章是 v1 内存安全模型的中央条款；§7 / §9 / §6 在涉及所有权处均向本章引用。

> 具体实现的版本化记录见 [`docs/dev/ownership-impl-log.md`](../dev/ownership-impl-log.md)。当 spec 与 impl 日志冲突时，**应当**修订 spec 而**不得**反向修改实现以迁就过时文字（§8.10）。

## §8.1 概述

### §8.1.1 类型档位

§8.1.1.1 yux 的类型按所有权语义分为四档（与 §3.1 同表，本节给出语义视角）：

| 档位 | 写法 | 复制语义 | 析构 | 语义层 |
|---|---|---|---|---|
| **值类型** | 标量 / 用户 `struct` / `[T*N]` / 元组 / `Function<...>` | 字段级递归（§7.4） | 用户 `~()` + 字段 release | §7 / §8.7.6 |
| **堆句柄** | `Rc<T>` / `Weak<T>` / `Array<T>` / `String` / `StringBuilder` | 句柄复制 + RC retain | RC release，归零时 free | §8.2–§8.5 / §9 |
| **借用** | `T&` | 不复制，绑同一目标 | 不参与 RC，作用域结束即丢弃指针 | §8.6 |
| **FFI 指针** | `Ptr` | 裸指针赋值 | 不参与 RC | §9.7 |

§8.1.1.2 类型档位是**封闭集合**：用户**不得**自定义新堆句柄；新增堆句柄类型须在编译器 / SDK 中显式落地。

### §8.1.2 设计原则

§8.1.2.1 *无借用检查器、无生命周期标注*：寿命检查 O(1) 局部规则（§8.6.5），不做数据流分析。

§8.1.2.2 *kotlin 思维*：堆句柄共享语义；用户不写 retain / release / move。

§8.1.2.3 *栈分配优先*：用户 `struct` 默认栈分配按值复制；要堆分配走 `Rc<T>` 显式装箱（§9.5）。

§8.1.2.4 *FFI 友好*：与 C 互操作通过 `Ptr` + `extern` 边界，零摩擦（§9.7 / §6.6）。

§8.1.2.5 *v1 不在范围*：借用检查器 / 默认移动语义 / cycle collector / 多线程 / 字段默认值（§8.10）。闭包已在 v1 范围（§8.7.6 / §3.11）。

## §8.2 句柄与 RC 协议

### §8.2.1 Block 结构

§8.2.1.1 每个堆句柄类型在堆上分配一个 Block；Block 头部固定为 RC 头：

```
struct RcHeader {
  strong: u32   ; offset 0
  weak:   u32   ; offset 4
}
```

§8.2.1.2 各堆句柄的具体 Block layout：

| 类型 | Block layout |
|---|---|
| `Rc<T>` | `{ rc, payload: T }`，payload 偏移 8 |
| `Array<T>` | `{ rc, len: i64, cap: i64, data: *T }` |
| `String` | `{ data: Array<u32> }`（v1 形态：句柄套 Array<u32>，详见 §9.3） |
| `Weak<T>` | 不持自有 Block；持指向 `Rc<T>` 的 Block 的弱句柄 |

§8.2.1.3 Block 由 OS 堆分配（v1 实现侧用 Windows `HeapAlloc` / `HeapFree`，规范层不强制）。

### §8.2.2 strong / weak 计数协议

§8.2.2.1 `strong` 计外部强引用数；`weak` 计 `(外部弱引用数 + 1 if strong > 0)`——所有强引用整体算作一份 weak（标准 Rc 范式）。

§8.2.2.2 `Rc<T>` retain：`strong++`。

§8.2.2.3 `Rc<T>` release：

```
if (--strong == 0) {
  destruct payload;            ; 字段级 release，§7.4
  if (--weak == 0) free(block);
}
```

§8.2.2.4 `Weak<T>` 创建（绑定活 box）：`weak++`，复制 handle。

§8.2.2.5 `Weak<T>` retain：`weak++`。

§8.2.2.6 `Weak<T>` release：`if (--weak == 0) free(block);`。

§8.2.2.7 `upgrade`：

```
if (strong > 0) { strong++; return Rc(handle); }
else            { return null; }
```

§8.2.2.8 空 Weak（handle == null）：所有计数操作 no-op。

### §8.2.3 哨兵与字面量

§8.2.3.1 落 `.rodata` 段的常量 Block（典型：`String` 字面量、空 `String`）的 RC 头**应当**置为：

```
strong = 0xFFFFFFFF
weak   = 0xFFFFFFFF
```

§8.2.3.2 runtime 入口检查到哨兵跳过 retain / release：

```c
static inline void __rc_inc(Block* b) { if (b->strong != UINT32_MAX) b->strong++; }
static inline void __rc_dec(Block* b) { if (b->strong == UINT32_MAX) return; ... }
```

§8.2.3.3 v1 仅 `String` 字面量走静态字面量路径；`Array` / 用户 `Rc` 暂未走（Open Issue）。

### §8.2.4 线程模型

§8.2.4.1 v1 单线程：RC 用普通 `add` / `sub`，**不**上原子操作。

§8.2.4.2 RC 头字段类型固定为 `u32`，未来切原子时**不**改 ABI。

§8.2.4.3 多线程下 RC 行为**未定义**；用户**不得**在 v1 跨线程共享堆句柄。

## §8.3 `Rc<T>`

### §8.3.1 语义

§8.3.1.1 `Rc<T>` 是持有 RC 堆对象的强句柄；不可空（可空写 `Rc<T>?`，§3.6.5.1）。

§8.3.1.2 句柄复制 = retain；多个 `Rc<T>` 共享同一 Block（§8.2.2.2）。

§8.3.1.3 `Rc<T>` 自身**没有**用户可见方法；`box.field` / `box.method(args)` 自动解引用到 payload `T` 上分发（§9.5.3 / DRAFT §4.2）。

### §8.3.2 构造

§8.3.2.1 `Rc<T>` 的构造形态由上下文驱动：把 `T` 类型值赋给 `Rc<T>` 上下文（变量 / 形参 / 字段 / 返回），编译器**应当**自动堆分配并把 payload 写入 Block。

§8.3.2.2 v1 **不**提供独立的 `Rc(value)` 构造函数（§9.5.2.2）。

### §8.3.3 复制与赋值

§8.3.3.1 `Rc<T>` 之间赋值走 retain-then-release（§7.4.4）：先对 RHS 句柄 retain（+1），写入槽位，再对槽位**原值**句柄 release。这一序对自赋值 / 别名安全。

§8.3.3.2 fresh 句柄（来自 `Rc(...)` / 数组字面量 / `make()` 返回）已携带 +1，赋值时**应当**省略 retain 而直接消费临时（§8.8）。

### §8.3.4 析构

§8.3.4.1 `Rc<T>` 局部变量在作用域结束时 release（§8.2.2.3）；归零时先析构 payload（按 §7.4 字段级），再判断 weak 计数决定 free Block。

§8.3.4.2 含 `Rc<T>` 字段的结构体析构遵循 §7.4 的字段级 release 序，按字段声明**逆序**（§7.4.3 末段）。

### §8.3.5 与 `T&` 的关系

§8.3.5.1 `&box` → `Rc<T>&`：借用 Rc **句柄本身**，不是 payload。`Rc<T>` 是单字句柄值，`&box` 对该值取址得到 `Rc<T>&`。可传给接收 `Rc<T>&` 的函数；callee 通过自动解引用访问 payload。

§8.3.5.2 `&box.field` → `FieldType&`：`box.field` 自动解引用到 payload 后取字段，`&` 取址结果绑到 `box` 句柄存活期；详见 §8.6.4 / §8.6.5。

§8.3.5.3 没有直接的**语法形态**得到"整个 payload `T&`"。把 Rc payload 整体借给接收 `T&` 的函数有三条路：

1. 把函数签名改为接收 `Rc<T>&`（调用方写 `f(&box)`，零开销；callee 用自动解引用访问字段）；
2. 把函数拆成接收具体字段引用，调用方写 `f(&box.field)`；
3. 通过内置 `as_ref:<T>(box) T&` 显式获取 payload 借用（§8.3.5.5）。

§8.3.5.4 *无隐式降级*：`&box` 永远生成 `Rc<T>&`，不会因上下文期望 `T&` 而隐式转为 payload 借用；要 `T&` **应当**显式写 `as_ref(box)`。

§8.3.5.5 `as_ref` 是编译器 baked 内置，v1 含两种重载：

- `as_ref:<T>(box Rc<T>) T&`：返回的 `T&` 指向 Block 内 payload 起点（跳过 RC 头）；
- `as_ref:<T>(h Heap<T>) T&`：返回的 `T&` 指向 Heap payload 起点（GEP 偏移 0，无 RC 头）。

二者根对象**应当**视为源句柄本身（`box` 或 `h`），受 §8.6.5 一切寿命规则约束。turbofish 可省，T 由实参推断；接受 `Rc<T>?` / `Heap<T>?` 在类型层报错（应当先 narrow / `?.`）。

§8.3.5.6 `as_ref` 是 v1 唯一允许"以 `T&` 形态借用堆 payload 整体"的途径：禁止 `&*box` / `&box[]` / `*h` / 隐式降级等任何形式的语法糖。`Array<T>` / `String` / `Weak<T>` 不参与本机制（见 §8.4.2 / §8.4.3 / §8.5）。Rc / Heap 走同一 `as_ref` 入口，仅 GEP 偏移不同。

§8.3.5.7 FFI 走 `ptr_of:<Rc<T>>(box)` / `ptr_of:<Heap<T>>(h)`：得到 payload 首地址（Rc 跳过 RC 头，Heap 偏移 0）；这是用户层唯一能拿到"裸 payload 指针"的口子，且仅 FFI 边界使用（§9.7.2.4）。`Heap<T>` 形态额外交出所有权（源 slot 标 moved_out，详见 §8.3a.5.3）。

## §8.3a `Heap<T>`

### §8.3a.1 语义

§8.3a.1.1 `Heap<T>` 是单 owner 的堆作用域句柄：layout = 裸 `T*`，**无** RC 头；句柄持有唯一所有权，作用域结束自动 free。

§8.3a.1.2 与 `Rc<T>` 的差异：无 retain / release；按值禁 move（B 档 nullable move 例外，§8.3a.4）；不可装容器（§8.3a.5）。

### §8.3a.2 构造

§8.3a.2.1 `Heap:<T>(args)` 表达式（turbofish 可省，由上下文反推）：runtime `__yux_heap_alloc<T>` 分配 + 调 T 的 ctor，返回 `Heap<T>`。

§8.3a.2.2 OOM 处理 / ZST / 对齐协议见 §9。

### §8.3a.3 析构与作用域

§8.3a.3.1 `Heap<T>` 局部变量在所在块出口自动 `__yux_heap_free<T>`（调 T 的 dtor + free 内存）。

§8.3a.3.2 `Heap<T>` 不参与按值复制 / 赋值：`let a Heap<T> = other_heap` 与 `a = other_heap` 均报 `Exxx2`。

§8.3a.3.3 `ret heap_var` 触发 A 档 NRVO（§8.3a.4.1）；不满足 NRVO 条件时报 `Exxx1`（escape）。

### §8.3a.4 `Heap<T>?` 与 nullable move

§8.3a.4.1 **A 档 NRVO**：当 fn 返回类型为 `Heap<T>` / `Heap<T>?` 且 `ret a` 中 `a` 为局部 `Heap<T>` / `Heap<T>?` 时，编译器**应当**折叠"分配 + free"为"分配 + 接管 + 源 slot 标 moved_out"；多候选 / 多 ret 来源不同 / 与外发借用并存时报 `Exxx5`，不退化为 `Exxx1`。

§8.3a.4.2 **B 档 nullable move**：以下三条件同时满足时，调用点自动改写实参 slot 为 null：

- 形参类型为 `Heap<T>?` 按值（非借用、非 `Heap<T>?&`）；
- 实参为 `Heap<T>?` 左值（具名 slot）；
- 调用本身按值传递。

被消费的 slot 在调用返回后值为 null；后续访问按 nullable 规则（§5.4 / §3.6）必须 `?.` 或 narrow 分支。

§8.3a.4.3 **隐式 widen 禁**：`Heap<T>` → `Heap<T>?` 隐式 widen 报 `Exxx6`；用户应当显式重构（fn 签名直接写 `Heap<T>?`，体内构造 `Heap:<T>(...)` 由 §3.6.4 widen 处理）。narrow 分支 `if a != null { ... }` 的非空断言**不**消解此禁——分支内 `let b Heap<T> = a` 等"narrow → 非空 slot"形态仍报 `Exxx6`；想 move 必须用 `Heap<T>?` 中转。

§8.3a.4.4 **C 档 局部 / 字段 move（限 `Heap<T>?` 形态）**：左值赋值 `lhs = rhs` 或 `let lhs X = rhs`，当 LHS / RHS 类型同为 `Heap<T>?`（含字段、元素、局部、形参）且 RHS 为左值（非构造表达式 / 非函数返回值 / 非借用）时，编译器**应当**走 O(1) 指针搬移：源 slot 写 null（与 B 档复用同一协议），不复制 payload。

`Heap<T>` 非空形态保持 §8.3a.3.2 的 `Exxx2` 禁——想 movable 必须在源头声明 `Heap<T>?`，或经 `Heap:<T>(...)` 重新装堆。该简化避免引入 use-after-move 跟踪。

C 档与 A 档（NRVO）、B 档（调用点改写）三档独立：
- A 档仅覆盖 `ret heap_local`；
- B 档仅覆盖按值调用的 `Heap<T>?` 实参；
- C 档仅覆盖局部 slot 间赋值。

示例（narrow + B 档 + 借用）：

```yux
fn some_nullable(h Heap<A>?) { ... }

fn use() {
  let a Heap<A>? = Heap:<A>(...)
  if a != null {
    a.v                ; ✅ narrow 后直接读
    as_ref(a)          ; ✅ as_ref 取借用，不消费
    some_nullable(a)   ; ⚠ 触发 B 档：调用后 a 重新 null，narrow 失效
    ; 此处再读 a 须重新 ?. / narrow
  }
}
```

### §8.3a.5 与容器 / 借用 / FFI 的关系

§8.3a.5.1 **容器规则**：
- **禁**：`Rc<Heap<T>>` / `Weak<Heap<T>>`、`Heap<T>` 作 `Rc<U>` 内层结构体字段——类型层报 `Exxx3`。理由：`Rc` / `Weak` 是共享语义，与 Heap 单 owner 互斥。
- **允许**：`Heap<Heap<T>>`（多级 Heap）、`Array<Heap<T>>`、`struct { h Heap<T>? ... }`（普通字段）。
- **传染**：含 `Heap` 子项（字段 / 元素 / 多级 payload）的复合类型 `U` 整体按 Heap 生命计——单 owner、按值禁 copy（按 §7.4.6.6 走 move）、作用域绑定 free。`Array<Heap<T>>` 因此**不参与**普通 Array 的句柄复制 + retain 语义（§9.2 / §8.4.1）。

§8.3a.5.2 **借用**：通过 `as_ref:<T>(h Heap<T>) T&` 获取 payload 借用（§8.3.5.5 重载形态）；`&h` 取 `Heap<T>&` 句柄借用。

§8.3a.5.3 **FFI 互转**：`ptr_of:<Heap<T>>(h) Ptr` 交出所有权（slot 标 moved_out）；`Heap:<T>(p Ptr) Heap<T>` 从裸指针接管；详见 §9。`extern fn` 形参 / 返回禁 `Heap<T>`，违者 `Exxx7`。

## §8.4 `Array<T>` 与 `String`

### §8.4.1 共同点

§8.4.1.1 `Array<T>` / `String` 都是 `{ _handle: *Block }` 单一句柄（§9.2.1 / §9.3.1）。

§8.4.1.2 复制 = 句柄复制 + retain（§8.2.2）；多个变量共享同一 Block。

§8.4.1.3 字段 / 容器 / 返回值 / 全局位置均可使用（与 `T&` 不同，§3.2.3.2）。

### §8.4.2 `Array<T>` 共享 + 可变

§8.4.2.1 `Array<T>` 通过 `Array<T>&` 借用允许 push / 修改元素（§9.2.3.2）。

§8.4.2.2 多个句柄同视图：任一句柄修改对其他句柄可见——这是预期语义，不是 bug。

§8.4.2.3 realloc 安全：因为 `_handle` 是单一指针指向 Block，Block 内部 `data` 指针变化**不**影响外部句柄。具体扩容路径用 runtime helper `_array_grow(handle, elemSize, newCap)` 在 Block 内原地更新 `cap` / `data`（impl 详见 ownership-impl-log Phase 1b）。

§8.4.2.4 深拷贝走 `copy_of:<T>(x T&) T` 内置函数（v1 已提供，见 §9.2）。

§8.4.2.5 *借用期不可变*：在任一指向某 `Array<T>` 句柄的 `Array<T>&` 借用存活区间内，对该句柄调用任何**会修改 Block 内部 `len` / `cap` / `data` 的方法**（含 `push` / `pop` / `insert` / `remove` / `clear` / `set_len` / 容量 grow 等，详见 §9.2 方法表）**应当**编译期报错。理由：尽管单一 handle 的 realloc 不影响其他句柄观测到的 handle 值（§8.4.2.3），realloc 后 callee 内部缓存的 `data` 指针 / 元素地址会失效；本规则避免此类内部状态错乱。仅元素读 / `at` / `len` / `cap` 等只读访问不在此禁列。

§8.4.2.6 由于 `&arr[i]` 在语法层已禁（§8.6.4.1），不存在"借用某元素 + push"的形态；本节禁止的是"借 handle 本身 + 改 Block"。

### §8.4.3 `String` 不可变

§8.4.3.1 `String` 是不可变堆句柄；所有"修改"语义返回新 `String`，没有原地修改方法（§9.3.4.1）。

§8.4.3.2 不可变下复制 = 句柄共享；深层独立拷贝走 `copy_of`（分配新缓冲）。

§8.4.3.3 字面量落 `.rodata`，RC 头哨兵（§8.2.3）。

§8.4.3.4 mutable 用例走 `StringBuilder`（§9.4）；自定义码点缓冲走 `Array<u32>` + `String(buf)`（§9.3.3）。

## §8.5 `Weak<T>` 与 `upgrade`

### §8.5.1 范围（v1）

§8.5.1.1 `Weak<T>` v1 **仅配** `Rc<T>`：`Weak<Array<T>>` / `Weak<String>` 不支持（§3.7、§9.6.1.1）。

§8.5.1.2 v1 不实现 cycle collector；父子 / 双向引用**应当**用 `Weak` 打破，否则视为预期内的循环引用泄漏（§8.10）。

### §8.5.2 语义

§8.5.2.1 `Weak<T>` 持指向某 `Rc<T>` Block 的弱引用，**不**阻止 payload 析构。

§8.5.2.2 `Weak<T>` **原生可空**：自带"空 / 已失效"状态；`Weak<T>?` 双层可空在语义层禁（§3.6.5.3 / §3.7）。

§8.5.2.3 `Weak<T>` 上的 `==` / `!=` v1 **禁用**（§3.7、§8.9）；要比对走 `same_ref`（§8.7）或先 `upgrade` 后比 payload。

### §8.5.3 API

| 形式 | 说明 |
|---|---|
| `Weak(box Rc<T>?)` | 构造函数：传 `null` 得空 weak；传活 box 绑定并 weak++ |
| `weak:<T>(box Rc<T>?) Weak<T>` | 编译器 baked，与构造函数等价 |
| `upgrade(w Weak<T>) Rc<T>?` | 强引用还在则返回持值 `Rc<T>?`，已释放或空 weak 返回空 |

§8.5.3.1 含 `Weak<T>` 字段的结构体在构造时**应当**显式给定初值（如 `Weak(null)`），DAA 不为其提供豁免（§7.3.3.4）。

§8.5.3.2 `Weak<T>` 可作为字段、`Array` 元素、全局、返回值（与 `T&` 不同，§5.4）。

## §8.6 借用 `T&`

### §8.6.1 形态

§8.6.1.1 `T&` 由 `typeWithRef` 产生（§3.2.3）；只能在以下白名单位置出现：

- 函数参数类型（含方法 receiver `$`，自动隐式 `Self&`）；
- 局部变量类型（`let d T& = ...`）；
- `& expr` 表达式的结果类型；
- 函数返回值类型（受 §8.6.10 溯源约束）。

§8.6.1.2 在结构体字段、容器内层、嵌套 `T& &` 位置出现 `T&`，由 `yux.g4` / 语义层直接拒绝（§3.2.3.2、§3.7、§2.6）。
§8.6.1.3 函数返回值 `T&` 的源须来自形参 `T&`（外发借用）或全局 / `#Static` / `#Cval`（静态借用），详见 §8.6.10。
§8.6.1.4 `&global_var` / 全局 `#Cval let` 取全局 / 静态引用时，借用根登记为 `"$rodata"`（永不过期哨兵），寿命检查自动通过。

### §8.6.2 不参与 RC

§8.6.2.1 `T&` 是非空指针；**不**参与 retain / release。其指向的对象由所有者负责寿命管理。

§8.6.2.2 `T&` 类型的局部变量析构时**不**做任何动作。

### §8.6.3 绑定与赋值

§8.6.3.1 *rebind 禁*：`T&` 局部变量**应当**在声明处初始化；之后赋值改的是被引对象：

```yux
let c = 1
let d i32& = &c   ; d 绑到 c
d = 3             ; ✅ c 变 3
                  ; ❌ d 不能重指向别的变量
```

§8.6.3.2 *拷贝绑定*：从一个 `T&` 复制绑定**不**写 `&`：

```yux
let d2 i32& = d   ; ✅ d2 与 d 绑同一目标
```

§8.6.3.3 *`&d` 报错*：对 `T&` 再取址结果是 `T& &`，由语法拒绝。

§8.6.3.4 *无 default*：`T&` 形参 / `let d T&` 局部变量的"写权"由源对象决定，与 `let` 的可变档位（默认 / `#Mut`）无关。

### §8.6.4 取地址表达式 `&`

§8.6.4.1 `&` 只能作用于**左值**：

| 形式 | 允许 | 结果类型 | 备注 |
|---|---|---|---|
| `&局部变量` | ✅ | `T&`（变量类型为 T） | |
| `&函数参数` | ✅ | `T&` | |
| `&$.field` | ✅ | `FieldType&` | 方法内 receiver 字段 |
| `&box`（box 是 `Rc<T>` 局部 / 形参） | ✅ | `Rc<T>&` | 借用**句柄本身**（§8.3.5.1） |
| `&box.field` | ✅ | `FieldType&` | Rc 自动解引用后取字段，借用绑到 box 句柄存活期 |
| `&任意 RC 字段链` | ✅ | 终点字段类型的 `&` | 只要每一层都是字段访问 |
| `&arr[i]` | ❌ | — | `[]` 返回 `T&`，`&` 作用于 `T&` 形成 `T& &`（嵌套引用）被 §2.6.1 拒绝 |
| `&f()` / `&任何方法调用` | ❌ | — | `&` 语法层限定接命名 ID / `$`，不接受调用表达式 |
| `&global_var` / 全局 `#Cval let` / `&#Static FIELD` | ✅ | `T&` | 静态借用，根登记为 `"$rodata"`（永不过期） |

§8.6.4.2 `& expr` 由 `exprGetRef: SymbolAnd obj=(ID|SymbolThis) (SymbolDot subs+=ID)*` 在语法层限定：`&` 只接命名 ID / `$`，后接零或多个字段子选择（§B.6）。这从语法层挡掉 `&调用结果` / `&临时表达式`。

### §8.6.5 寿命检查（O(1) 静态规则）

§8.6.5.1 *唯一规则*：`T&` 变量的初始化来源（追到 `&` 的根对象 / 形参 `T&`）所在**声明作用域** ⊇ 该 `T&` 变量自身的**声明作用域**。

§8.6.5.2 这是 O(N) 单遍 AST 检查（每函数一遍），**不**做数据流分析、**不**做借用检查器。

§8.6.5.3 拷绑透传：`let r2 T& = d` 的根 = `refToRoot[d]`（追到终极根对象）；`let r T& = &x.f.f` 的根 = `x`。

§8.6.5.4 例：

```yux
fn foo(b Rc<Pair>&) {
  let r i32& = &b.field   ; ✅ b 是参数，作用域 ⊇ r
}

fn bar() {
  let b Rc<Pair> = ...
  let r i32& = &b.field   ; ✅ 同作用域
  if cond {
    let r2 i32& = &b.field ; ✅ b 作用域 ⊇ r2
  }
  ; ❌ let r3 i32& = if cond { &b.field } else { &c }
  ;    cond 分支里如果引入了更窄作用域的源对象，就违反规则
}
```

§8.6.5.5 *根对象重赋禁*：在 `T&` 的存活区间内，其根对象**不得**被赋值 / 移交。Rc 句柄的"赋值"等价 release-旧 + retain-新，借用期内禁此操作即可（纯本地检查）。

§8.6.5.6 *临时不可绑*：`T&` 不能绑定临时值——临时的"作用域"是当前语句 / 表达式，比任何 `let` 声明都小，由 §8.6.5.1 自动拒绝。

§8.6.5.7 *`as_ref` 站点根追溯*：`let r T& = as_ref(box)` 中 `r` 的根对象 = `box` 的根（拷绑透传同 §8.6.5.3）；编译器**应当**把这一站点视同对 `box` 整体 payload 的借用，受 §8.6.5.5 根重赋禁约束。

§8.6.5.8 *作用域粒度*：本节"声明作用域"按 §5 块作用域计——块内声明的变量在块出口失效，块内借用在块出口失效。函数级扁平作用域是 v1 实施侧曾经的简化（impl log Phase 4d），v0.4 已对齐至块作用域。

§8.6.5.9 *Heap 句柄登记为根*：`Heap<T>` 局部 / 形参 / `Heap<T>?` slot 与 `Rc<T>` 句柄同等视为根对象；`as_ref(h)` 的根追溯走 §8.6.5.7 同一路径；B 档 nullable move 调用站点（§8.3a.4.2）视为对源 slot 的"重赋为 null"，触发 §8.6.5.5 根重赋禁——若该 slot 借用期内存活，调用编译期拒绝。

### §8.6.6 receiver `$`

§8.6.6.1 方法 receiver `$` 永远隐式 `Self&`（§7.2.2、§6.2 末段）。调用方写 `obj.method(args)`；**不**引入 UFCS（`T::method(self, args)` 风），避免风格混乱。

§8.6.6.2 LLVM 层 `T&` / receiver `$` 落成非空指针。

§8.6.6.3 构造统一通道走 `#Static fn` + `Self { ... }`（§7.3 / §7.10）：`#Static fn` 体内**禁** `$`（§7.10.4）；`Self { ... }` 字段字面量是单条表达式，全字段一次性 init（§7.3.2.2）。析构 `fn ~()` 中 `$` 是 `Self&`，字段视为已初始化（§7.4.1.3）。

### §8.6.7 借用与泛型边界匹配

本节规定 `T&` 与泛型类型形参在引入类型边界（spec，§12）后的交互前置规则。

§8.6.7.1 *类型形参档位限定*：`fn name<T>(...)` / 未来 `<T : Bound>` 中类型形参 `T` 的实参**应当**为 owned 类型（值类型 / 堆句柄 / `Ptr`），**不得**为 `T&` 或容器内含 `T&`。即 `genericDef` 与类型推断结果必须由 §3.2.3.1 `type` 产生，不接受 `typeWithRef`。

§8.6.7.2 推论：调用 `f:<U>` 时若类型推断结果为某 `V&`，**应当**回退为 `V` 重试推断；若回退后仍无法满足实参类型，编译期报错。

§8.6.7.3 *方法分发归一*：`obj.method(args)` 落成 `method($, args)` 时，receiver 形参始终为 `Self&`（§8.6.6.1）。当 obj 类型为 `Rc<U>` 时，按 §8.3.1.3 自动解引用规则，`$` 为 `U&`，**不**为 `Rc<U>&`；这意味着 `#Impl(D) struct U { fn m(...) }` 中 `m` 的 receiver 与对 `Rc<U>` 调 `m` 时一致，无需为 `Rc<U>` 单独 forward。

§8.6.7.4 *`as_ref` 与泛型函数协作*：泛型函数 `fn use_ref<T>(x T&)` 接受 `T&` 形参（参 §8.6.7.5）；调用方对 `Rc<U>` 写 `use_ref(as_ref(box))`，T 推断为 U；`box` 在该调用语句存活区间内不可重赋（§8.6.5.5 由 `as_ref` 借用根扩散到调用语句边界，§8.8.1.4 临时消费规则）。

§8.6.7.5 *类型形参组合为 `T&`*：在泛型函数签名（参数类型 / 局部变量类型）与函数体中，类型形参可与 `&` 组合为 `T&` 形态使用，例如 `fn same_ref:<T>(a T&, b T&) bool`。T 本身仍受 §8.6.7.1 限制——绑定到 owned 类型；`T&` 仅作为该 owned 类型的借用形态在签名局部出现，不构成对 §8.6.7.1 的破坏。

### §8.6.10 返回引用的溯源约束

§8.6.10.1 `fn` 声明返回 `T&` 时，编译器**应当**在 fn body 检查阶段对每条 `ret expr` 计算其引用根（同 §8.6.5.7 的根判定算法），并要求该根 ∈ "允许源集"。否则报 `E4020`。

§8.6.10.2 *允许源集*：

- 方法（receiver 在 scope 内为 `$`，类型 `Self&`）：允许源集 = `{ $ } ∪ { 全局 / #Static / #Cval }`。
- 自由函数：允许源集 = 函数声明中的全部 `T&` 形参 ∪ `{ 全局 / #Static / #Cval }`。
- *静态借用*：根为全局变量 / `#Static FIELD` / `#Cval` 时，借用登记为 `"$rodata"`（immortal 哨兵），寿命自动通过（全局作用域 ⊇ 任何局部）。

§8.6.10.3 *v1 单源约束*：函数声明本身**应当**保证允许源集中**最多**一个 `T&` 形参元素，否则报 `E4021`：

- 方法返回 `T&` 时只允许 `$` 作 `T&` 源；不允许溯源到 `T&` 形参（即便方法存在 `T&` 形参，也不算源）。
- 自由函数返回 `T&` 时**应当**声明 0 或 1 个 `T&` 形参；≥2 个 `T&` 形参时报 `E4021`。
- 0 个 `T&` 形参时，仅静态借用（`{ 全局 / #Static / #Cval }`）合法；ret 局部或形参会触发 `E4020`。
- ≥2 个 `T&` 形参的放松（多源返回）推 v2。

§8.6.10.4 *调用点根扩散*：调用 `fn` 返回 `T&` 时，调用点结果借用的根按下列规则确定：

- 方法调用 `recv.method(args)`：根 = `recv` 的根。
- 自由函数调用 `f(args)`，`f` 有 1 个 `T&` 形参：根 = 该形参对应实参的根（按 `f` 形参索引取实参，按 §8.6.5.7 推根）。
- 自由函数调用 `f(args)`，`f` 有 0 个 `T&` 形参：根 = `"$rodata"`（仅静态借用路径可达）。

§8.6.10.5 *寿命*：调用点结果借用的存活期受 §8.6.5 全部规则约束——其根的可见性 / 重赋禁忌 / 借用期间不变性 等，等同于在调用点直接写 `&<根表达式>`。

§8.6.10.6 *`Self&` 等价性*：方法返回 `Self&` 与方法返回 `Self`（按值复制）语义不同；后者拷贝所有字段（含 RC retain）并交给调用方所有权，前者只借用 receiver。两者**不可**混用，类型必须严格匹配（§3.4.2 不做 `Self` ↔ `Self&` 的隐式转换）。

§8.6.10.7 v1 限制（Open Issue / 后续版本扩展）：

- 多源 `T&` 返回（多个 `T&` 形参中任一可作根）需要在签名层引入"返回源标注"或借用检查器扩展，v1 不在范围。
- 链式调用 `obj.foo().bar()`、嵌套 receiver 等的根扩散仅在简单形态（receiver 为局部变量名）下被识别；复杂形态可能落入根追踪保守拒绝路径，需用户显式拆出中间局部。

## §8.7 调用 ABI

### §8.7.1 callee-clean retain / release

§8.7.1.1 *实参取址显式*：`fn f(a i32&) { ... }` 调用方写 `f(&x)`，**不**自动加 `&`（§8.3.5）。

§8.7.1.2 *receiver 例外*：方法 receiver `$` 的 `Self&` 取址由编译器隐式注入；调用方写 `obj.method(args)`（§8.6.6.1）。

§8.7.1.3 *callee-clean*：调用方在传堆句柄实参前 retain（计数 +1）；被调用方把堆句柄参数视为自己的局部变量，在作用域结束时 release。优势：参数和局部变量走同一条析构路径，不需要"参数特例"。

§8.7.1.4 适用范围：堆句柄（`Rc<T>` / `Weak<T>` / `Array<T>` / `String` / `StringBuilder` / 含 RC 字段的非平凡用户 struct）。值类型（标量、平凡 struct）不参与 retain / release。

§8.7.1.5 fresh 实参（来自 `Rc(...)` / 数组字面量 / 直接函数调用结果）已携带 +1，调用方**应当**省略 retain 而直接消费临时（§8.8）。

### §8.7.2 move-return retain 注入

§8.7.2.1 编译器对 `ret box_expr`（返回类型为堆句柄或含 RC 字段 struct）**应当**生成 retain；所有分支汇聚后净效果是 +1 给调用方；callee 末尾的析构 release 自然抵消多余 retain。

§8.7.2.2 fresh 返回值省略 retain（§8.7.1.5）。

§8.7.2.3 peephole 优化：编译器**可以**抵消 IR 上的 retain / release 对（informative，v1 暂不做）。

### §8.7.3 用户结构体按值 ABI

§8.7.3.1 用户 struct 默认按值复制（§7.6）。

§8.7.3.2 编译器**可以**在 ABI 层用指针传大结构体（不可观测优化）。判定：平凡 struct 倾向按值传；非平凡 struct（含 RC 字段）按值传 + 字段级 retain。具体边界条件随实现版本变化（impl log Phase 3c）。

§8.7.3.3 receiver `$` 始终按指针传（隐式 `Self&`，§8.6.6）。

### §8.7.4 extern fn 边界

§8.7.4.1 `extern fn` 签名 v1 允许：内置标量、`Ptr`。**不**允许 `T&` / `Rc<T>` / `Array<T>` / `String` / `Weak<T>` / 用户 struct（§6.6 / §9.7）。

§8.7.4.2 v1 **不强制** LLVM 落地约束——extern 在 v1 是危险但开放的接口，便于 SDK 落地。Open Issue：参照 Rust `unsafe` 收紧。

§8.7.4.3 自动转 Ptr：`T&` / `Rc<T>` / `Weak<T>` / `Array<T>` / `String` 作 extern 实参传给 `Ptr` 形参时**自动转换**。这是规范层唯一的隐式跨档位转换（§3.4.2.6）。

§8.7.4.4 显式转 Ptr 走编译器 baked 内置 `ptr_of:<T>(obj)`（§9.7.2.4）：

| 源类型 T | 结果指向 | 备注 |
|---|---|---|
| `U&` | U | 短寿命；C 端不可保存超出本次调用 |
| `Rc<U>` | U payload | 跳过 RC 头 |
| `Array<U>` | 元素首地址 | |
| `String` | 码点首地址 | 不带 NUL 终止 |
| 内置标量 | — | **不**允许 |

§8.7.4.5 `Ptr` 算术（偏移 / 加减）**仅 SDK 内**可用；用户代码出现 Ptr 算术**应当**编译报错。v1 实现以"私有函数 `_ptr_offset`"替代标记机制（impl log Phase 7d）。

§8.7.4.6 *FFI 注意*：`box.payload` 经 `Ptr` 流出后，C 端**不可保存超出本次调用**——yux 这边 release 时 payload 会析构。

### §8.7.5 比较 ABI

§8.7.5.1 *内容相等* `==`：

| 类型 | 语义 |
|---|---|
| 内置标量 | 值相等（IEEE 754 浮点遵从 ordered，§9.1.2.1） |
| 用户 struct | 字段递归 `==`（编译器派生），或用户重载 `eq` |
| `Rc<T>` | 解引用后比 payload 内容 |
| `Array<T>` | 长度 + 元素逐个 `==` |
| `String` | 内容逐字节（码点逐位） |
| `Weak<T>` | v1 **禁用** `==` / `!=`（§8.9） |

§8.7.5.2 *地址相等* `same_ref:<T>(a, b) bool`：编译器 baked 内置；接受 `Rc<T>` / `Weak<T>` / `T&` / `Array<T>` / `String`，比对底层 handle 指针。空 Weak 与任何活句柄不等。

### §8.7.6 函数值与闭包传递

> 本节为闭包捕获模型的规范摘要；完整决议与细则见 `docs/spec/draft/DRAFT-closure-capture.md`（v0.16 已落地）。三档捕获模式（move / retain / borrow）、捕获包 layout、RC 协议、`Heap<T>` B 档 move 捕获、静态检查规则均已定型。

§8.7.6.1 *档位*：`Function<P..., Ret>` 是值类型（§3.1 / §8.1.1.1），运行时表示 fat-ptr `{ fn_ptr, captures: Rc<CapturesT>? }`（§6.5.5）。`fn_ptr` 不参与 RC；`captures` 按 §7.4 字段级 RC 处理。零捕获 lambda 的 `captures = null`，retain / release 早返 NOP，零开销。

§8.7.6.2 *作实参 / 字段 / 返回值 / 容器元素*：按值复制 fat-ptr 16 bytes（LP64）；`captures != null` 时 retain（`Rc::retain`）。callee / 字段宿主 / 容器在析构时 release `captures`。整体走 §8.7.1 callee-clean 与 §8.7.2 move-return 同款路径，`Function<...>` 不需要新规则。

§8.7.6.3 *字段 / 容器合法性*（[#17] / §3.11.1）：
- ✅ struct 字段、`Array<Function<...>>`、`Rc<Function<...>>`、`Function<...>?`、`Function<...>&`；
- ❌ `Weak<Function<...>>`（函数值不是堆句柄，无 RC 头；§8.9）；
- ❌ `extern fn` 形参 / 返回（§6.6.2.1）。
- 含 `T&` 形参的 `Function<...>` 暂不能作 struct 字段（`genericDef` 实参不允许 `Type&`，§3.11.6.1）。

§8.7.6.4 *闭包捕获自动推断*（[#18]）：lambda 体引用的非形参 / 非全局标识符自动入 `CapturesT`，按外层变量类型选语义：

| 外层类型 | captures 字段 | 捕获语义 |
|---|---|---|
| 标量 / 用户 struct / 元组 / enum（值类型） | 同类型，按值复制（字段级 retain） | 一次性复制 |
| 堆句柄（`Rc` / `Array` / `String` / `StringBuilder` / `Weak`） | 同类型（句柄复制 + retain） | 共享句柄 |
| `T&` | 同 `T&`（栈嵌入，不可 Rc，§8.7.6.5） | 借用透传 |

不引入显式捕获列表语法。

§8.7.6.5 *含 `T&` 捕获 → 不可逃逸*（[#19]）：`CapturesT` 含 `T&` 字段时，`Rc<CapturesT>` 由 §3.2.3.2 字段位置禁 `T&` 直接拒绝；编译器改为**栈嵌入** `CapturesT`，fat-ptr 的 `captures` 字段是栈借用 `&CapturesT`。该 lambda 按"广义 `T&`"处理：
- 不可作 `ret expr`（除非满足 §8.6.10 溯源约束，§8.7.6.7）；
- 不可入字段 / 容器 / `Rc<...>`；
- 不可赋给寿命外延的变量（§8.6.5）。

判定 `O(1)`：`FV(λ)` 中是否存在 `T&` 类型变量。两条路径（栈嵌入 vs `Rc`）在调用 ABI 层（§6.5.5.2）一致，`fn_ptr` 隐式首参签名都是 `Ptr`。

§8.7.6.6 *方法体内 lambda 引用 `$`*（[#20]）：合法；`$` 视作隐式 `Self&` 形参参与 `FV(λ)`，按 §8.7.6.4 表中 `T&` 行处理 → 触发 §8.7.6.5 不可逃逸约束。闭包寿命 ≤ `$` 借用寿命 = 方法 frame。

§8.7.6.7 *lambda 返回 `T&` 与 §8.6.10 衔接*（[#21]）：lambda 的"允许源集"= 形参为 `T&` 者；**捕获来的 `T&` 不进允许源集**。理由：lambda 字面量出现处与被调用处可能跨函数，§8.6.10.4 调用点根扩散假设根来自调用 site 的实参，对捕获根不能给出稳定语义。违者报 [E4020]（与 §8.6.10 共用错误段）。

§8.7.6.8 *lambda 体禁止对捕获变量赋值*（[#26]）：lambda 体内不得对 `FV(λ)` 中的标识符执行 `=` / `+= -= *= /= ...` / 重新绑定堆句柄；违者编译错。理由：标量按值复制后赋值仅影响 captures 副本对外层静默无效；放开此口需要 `#Inline` / DAA 透传等机制（推 v0.x+1，§8.10）。要修改外层状态走"堆对象 mutator 方法"或"`T&` 形参显式传入"。

§8.7.6.9 *AST 模型*（[#27]）：lambda 字面量在 AST 层是普通表达式，作 fn 实参时与其它实参同等处理；`try` / `run` / `catch` / `each` 等 stdlib callonce builder 是普通 fn，不享有 inline / callonce / 非局部返回等特殊语义。v1 不引入 `#Inline` / `#CallOnce`（§8.10）。

### §8.7.7 `<-` 移入赋值的 RC 所有权协议

§8.7.7.1 `a <- b`（§4.13）的 RC 所有权管理分三端：

- **旧值移出**：从 LHS 槽 load 旧值时**不**额外 retain——ownership 从 LHS 槽直接移交给表达式结果；
- **新值写入**：RHS 新值即将存入 LHS 槽（LHS 成为新 owner）→ 需 retain。若 RHS 为新鲜临时（构造/调用返回值，§8.8.1.2），则消费该临时（跳 retain）；否则 `retainHandleAtCallSite`；
- **结果记账**：旧值作为表达式结果返回；若其类型含 RC 字段，记入临时帧（`recordTemp`，§8.8.1.2），作用域末尾正常 release。

§8.7.7.2 该协议与下列既有路径一致：
- 旧值处理 = §8.7.2 move-return 的"返回值不额外 retain"对称（callee 端析构抵消）；
- 新值处理 = §8.7.1 callee-clean 的实参 retain（多一个 owner 的通用协议）；
- 结果记账 = §8.8.1 临时值清单的 fresh 登记。

§8.7.7.3 `<-` 适用于**任意类型**（标量、Rc、Heap、Array、String、含 RC 字段的用户 struct 等）。`Heap<T>?` B 档 nullable move（§8.3a.4.2）是调用点的自动 move-out，不与 `<-` 重叠；两者在"ownership 转移、跳 retain"上走同一套协议。

## §8.8 临时值与作用域

### §8.8.1 临时值清单

§8.8.1.1 每条**语句 / 顶层表达式 / 代码块**边界维护一个"未消费的堆句柄临时值"清单（_temp frame_）；边界处对仍在清单中的临时值统一 release。

§8.8.1.2 *fresh 临时*：来自 `ExprCallNode`（callee 已 move-return retain）/ `ExprArrayNode`（数组字面量，`_array_alloc` 给 strong=1）的结果是 fresh +1，**应当**记入临时帧。

§8.8.1.3 *不消费临时*：receiver / 字段访问 / 借用 `&` 只是借用临时，**不**夺所有权；临时靠"边界 release"自然 keep-alive 直到访问完成。

§8.8.1.4 *消费*（从清单移除）：

- 作为参数传入 callee-clean 调用（§8.7.1）；
- 绑定到 `let`（§5.1）；
- 写入字段（§7.4.4）；
- 作为 `ret` 表达式（§8.7.2）；
- 作为另一表达式被进一步消费。

§8.8.1.5 *分支汇合*：每分支独立维护临时帧；phi 汇合后归一为 +1 句柄（具体路径见 impl log Phase 8d.3）。

### §8.8.2 fresh 判定与 retain 跳过

§8.8.2.1 编译器**应当**对每个 retain 站点判定 fresh：fresh 实参 / fresh 赋值源 / fresh 返回值跳过 retain（§8.3.3.2、§8.7.1.5、§8.7.2.2）。

§8.8.2.2 旧值 release 不参与 fresh 判定，无条件执行（保证自赋值 / 别名安全靠先 retain 再 release，fresh 路径直接 release，新值带入的 +1 抵消）。

### §8.8.3 链式调用 keep-alive

§8.8.3.1 链式 `make().method()`：fresh `Rc` 作为 receiver 进入 method，caller 处的 fresh 句柄记到 statement 帧；语句结束时 release。SSA use-def 自动让该 Value 在整条 method 调用期间 live（call 指令的 use 阻止 release 提前发出）。

§8.8.3.2 `&make_box()` 在语法层禁（§8.6.4.2）。

### §8.8.4 RC leak 检测

§8.8.4.1 runtime 维护 `_rc_block_count` 全局：每次 `_box_alloc` / `_array_alloc` 入口 +1，每次实际 `HeapFree` 后 -1。

§8.8.4.2 公开内置 `rc_leak_count() i64` 返回当前未释放 Block 数（无 `_` 前缀，调试 / 测试可用，§9.10）。

§8.8.4.3 测试约定：每条含 RC 句柄的语句跑完后，`rc_leak_count() - base` **应当**为 0；这是 v1 临时值清单设计的可观测验收（impl log Phase 8e）。

## §8.9 禁忌一览

下表汇总规范层的禁忌；该表与 §3.7 保持同步，二者增删**应当**联动（§3.7.1）。

| 形态 | 拒绝层 | 原因 | 章节 |
|---|---|---|---|
| `T& &` | 语法层 | 嵌套引用无意义 | §3.2.3.2 / §2.6.1 |
| 字段位置 `T&` | 语法层 | 借用不可逃逸出栈帧 / 堆对象 | §3.2.3.2 / §2.6.2 |
| 全局 / `#Cval let` 声明为 `T&` 类型 | 语法层 | 全局存储类型不可为借用 | §3.2.3.2 |

| `Weak<T>?` | 语义层 | `Weak` 原生可空，避免双层可空歧义 | §3.6.5.3 / §8.5.2.2 |
| `Weak<T>` 上的 `==` / `!=` | 语义层 | 改走 `same_ref:<T>` / 先 `upgrade` 后比较 | §8.5.2.3 / §8.7.5 |

## §8.10 v1 不在范围

§8.10.1 下列功能 v1 **不**实现，规范层留作未来版本设计窗口：

- 借用检查器、生命周期标注；
- 默认移动语义（已否决，§8.1.2；v1 移动语义走显式 `move:<T>(x)` + `<-` 移入赋值，§7.6a / §8.7.7）；
- 跟踪 GC / Arena 分配器；
- 多线程；
- cycle collector（`Weak<T>` 是用户侧打破循环的唯一手段）；
- 字段级默认值语法（`field T = expr` 在 struct 定义处给默认值，§7.7.2）；
- 函数类型跨 FFI 边界（`extern fn` 含 `Function<...>` / `Ptr` ↔ 函数值 builtin，§3.11.1 / §6.6.2.1，推 v0.x+1）；
- 泛型 lambda / 泛型 fn 类型字面量（`<T>(x T) => x` / `fn<T>(T)T`，推 v0.x+1）；
- `#Inline` / `#CallOnce` 注解（解锁 lambda 内对外层 `#Mut let` 变量赋值 / 性能优化 / 非局部返回，推 v0.x+1）。

§8.10.2 v1 已知接受的妥协：

- 循环引用泄漏：用户**应当**用 `Weak<T>` 打破；若不打破，v1 接受泄漏。
- `extern fn` 签名类型 v1 不强制约束；**应当**未来收紧。
- `same_ref` / `ptr_of` 的 `T&` 源类型 v0.4 已通过 §8.6.7.5 解决（类型形参可组合为 `T&`）。
