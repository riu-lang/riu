# §8 所有权与引用

本章规范 yux 的所有权模型、引用计数协议、借用类型 `T&` 的寿命检查、调用 ABI、临时值清单与禁忌一览。本章是 v1 内存安全模型的中央条款；§7 / §9 / §6 在涉及所有权处均向本章引用。

> 具体实现的版本化记录见 [`docs/dev/ownership-impl-log.md`](../dev/ownership-impl-log.md)。当 spec 与 impl 日志冲突时，**应当**修订 spec 而**不得**反向修改实现以迁就过时文字（§8.10）。

## §8.1 概述

### §8.1.1 类型档位

§8.1.1.1 yux 的类型按所有权语义分为四档（与 §3.1 同表，本节给出语义视角）：

| 档位 | 写法 | 复制语义 | 析构 | 语义层 |
|---|---|---|---|---|
| **值类型** | 标量 / 用户 `struct` / `[T*N]` | 字段级递归（§7.4） | 用户 `~()` + 字段 release | §7 |
| **堆句柄** | `Box<T>` / `Weak<T>` / `Array<T>` / `String` / `StringBuilder` | 句柄复制 + RC retain | RC release，归零时 free | §8.2–§8.5 / §9 |
| **借用** | `T&` | 不复制，绑同一目标 | 不参与 RC，作用域结束即丢弃指针 | §8.6 |
| **FFI 指针** | `Ptr` | 裸指针赋值 | 不参与 RC | §9.7 |

§8.1.1.2 类型档位是**封闭集合**：用户**不得**自定义新堆句柄；新增堆句柄类型须在编译器 / SDK 中显式落地。

### §8.1.2 设计原则

§8.1.2.1 *无借用检查器、无生命周期标注*：寿命检查 O(1) 局部规则（§8.6.5），不做数据流分析。

§8.1.2.2 *kotlin 思维*：堆句柄共享语义；用户不写 retain / release / move。

§8.1.2.3 *栈分配优先*：用户 `struct` 默认栈分配按值复制；要堆分配走 `Box<T>` 显式装箱（§9.5）。

§8.1.2.4 *FFI 友好*：与 C 互操作通过 `Ptr` + `extern` 边界，零摩擦（§9.7 / §6.6）。

§8.1.2.5 *v1 不在范围*：借用检查器 / 默认移动语义 / cycle collector / 多线程 / 闭包 / 字段默认值（§8.10）。

## §8.2 句柄与 RC 协议

### §8.2.1 Block 结构

§8.2.1.1 每个堆句柄类型在堆上分配一个 Block；Block 头部固定为 RC 头：

```
struct RcHeader {
  strong: u32   ; offset 0
  weak:   u32   ; offset 4
}
```

§8.2.1.2 各堆句柄的具体 Block layout：

| 类型 | Block layout |
|---|---|
| `Box<T>` | `{ rc, payload: T }`，payload 偏移 8 |
| `Array<T>` | `{ rc, len: i64, cap: i64, data: *T }` |
| `String` | `{ data: Array<u32> }`（v1 形态：句柄套 Array<u32>，详见 §9.3） |
| `Weak<T>` | 不持自有 Block；持指向 `Box<T>` 的 Block 的弱句柄 |

§8.2.1.3 Block 由 OS 堆分配（v1 实现侧用 Windows `HeapAlloc` / `HeapFree`，规范层不强制）。

### §8.2.2 strong / weak 计数协议

§8.2.2.1 `strong` 计外部强引用数；`weak` 计 `(外部弱引用数 + 1 if strong > 0)`——所有强引用整体算作一份 weak（标准 Rc 范式）。

§8.2.2.2 `Box<T>` retain：`strong++`。

§8.2.2.3 `Box<T>` release：

```
if (--strong == 0) {
  destruct payload;            ; 字段级 release，§7.4
  if (--weak == 0) free(block);
}
```

§8.2.2.4 `Weak<T>` 创建（绑定活 box）：`weak++`，复制 handle。

§8.2.2.5 `Weak<T>` retain：`weak++`。

§8.2.2.6 `Weak<T>` release：`if (--weak == 0) free(block);`。

§8.2.2.7 `upgrade`：

```
if (strong > 0) { strong++; return Box(handle); }
else            { return null; }
```

§8.2.2.8 空 Weak（handle == null）：所有计数操作 no-op。

### §8.2.3 哨兵与字面量

§8.2.3.1 落 `.rodata` 段的常量 Block（典型：`String` 字面量、空 `String`）的 RC 头**应当**置为：

```
strong = 0xFFFFFFFF
weak   = 0xFFFFFFFF
```

§8.2.3.2 runtime 入口检查到哨兵跳过 retain / release：

```c
static inline void __rc_inc(Block* b) { if (b->strong != UINT32_MAX) b->strong++; }
static inline void __rc_dec(Block* b) { if (b->strong == UINT32_MAX) return; ... }
```

§8.2.3.3 v1 仅 `String` 字面量走静态字面量路径；`Array` / 用户 `Box` 暂未走（Open Issue）。

### §8.2.4 线程模型

§8.2.4.1 v1 单线程：RC 用普通 `add` / `sub`，**不**上原子操作。

§8.2.4.2 RC 头字段类型固定为 `u32`，未来切原子时**不**改 ABI。

§8.2.4.3 多线程下 RC 行为**未定义**；用户**不得**在 v1 跨线程共享堆句柄。

## §8.3 `Box<T>`

### §8.3.1 语义

§8.3.1.1 `Box<T>` 是持有 RC 堆对象的强句柄；不可空（可空写 `Box<T>?`，§3.6.5.1）。

§8.3.1.2 句柄复制 = retain；多个 `Box<T>` 共享同一 Block（§8.2.2.2）。

§8.3.1.3 `Box<T>` 自身**没有**用户可见方法；`box.field` / `box.method(args)` 自动解引用到 payload `T` 上分发（§9.5.3 / DRAFT §4.2）。

### §8.3.2 构造

§8.3.2.1 `Box<T>` 的构造形态由上下文驱动：把 `T` 类型值赋给 `Box<T>` 上下文（变量 / 形参 / 字段 / 返回），编译器**应当**自动堆分配并把 payload 写入 Block。

§8.3.2.2 v1 **不**提供独立的 `Box(value)` 构造函数（§9.5.2.2）。

### §8.3.3 复制与赋值

§8.3.3.1 `Box<T>` 之间赋值走 retain-then-release（§7.4.4）：先对 RHS 句柄 retain（+1），写入槽位，再对槽位**原值**句柄 release。这一序对自赋值 / 别名安全。

§8.3.3.2 fresh 句柄（来自 `Box(...)` / 数组字面量 / `make()` 返回）已携带 +1，赋值时**应当**省略 retain 而直接消费临时（§8.8）。

### §8.3.4 析构

§8.3.4.1 `Box<T>` 局部变量在作用域结束时 release（§8.2.2.3）；归零时先析构 payload（按 §7.4 字段级），再判断 weak 计数决定 free Block。

§8.3.4.2 含 `Box<T>` 字段的结构体析构遵循 §7.4 的字段级 release 序，按字段声明**逆序**（§7.4.3 末段）。

### §8.3.5 与 `T&` 的关系

§8.3.5.1 `&box` → `Box<T>&`：借用 Box **句柄本身**，不是 payload。`Box<T>` 是单字句柄值，`&box` 对该值取址得到 `Box<T>&`。可传给接收 `Box<T>&` 的函数；callee 通过自动解引用访问 payload。

§8.3.5.2 `&box.field` → `FieldType&`：`box.field` 自动解引用到 payload 后取字段，`&` 取址结果绑到 `box` 句柄存活期；详见 §8.6.4 / §8.6.5。

§8.3.5.3 **没有**直接得到"整个 payload `T&`"的语法。把 Box payload 整体借给接收 `T&` 的函数有两条路：

1. 把函数签名改为接收 `Box<T>&`（推荐，调用方写 `f(&box)`，零开销；callee 用自动解引用访问字段）；
2. 把函数拆成接收具体字段引用，调用方写 `f(&box.field)`。

§8.3.5.4 FFI 走 `ptr_of:<Box<T>>(box)`：得到 payload 首地址（跳过 RC 头）；这是用户层唯一能拿到"裸 payload 指针"的口子，且仅 FFI 边界使用（§9.7.2.4）。

## §8.4 `Array<T>` 与 `String`

### §8.4.1 共同点

§8.4.1.1 `Array<T>` / `String` 都是 `{ _handle: *Block }` 单一句柄（§9.2.1 / §9.3.1）。

§8.4.1.2 复制 = 句柄复制 + retain（§8.2.2）；多个变量共享同一 Block。

§8.4.1.3 字段 / 容器 / 返回值 / 全局位置均可使用（与 `T&` 不同，§3.2.3.2）。

### §8.4.2 `Array<T>` 共享 + 可变

§8.4.2.1 `Array<T>` 通过 `Array<T>&` 借用允许 push / 修改元素（§9.2.3.2）。

§8.4.2.2 多个句柄同视图：任一句柄修改对其他句柄可见——这是预期语义，不是 bug。

§8.4.2.3 realloc 安全：因为 `_handle` 是单一指针指向 Block，Block 内部 `data` 指针变化**不**影响外部句柄。具体扩容路径用 runtime helper `_array_grow(handle, elemSize, newCap)` 在 Block 内原地更新 `cap` / `data`（impl 详见 ownership-impl-log Phase 1b）。

§8.4.2.4 深拷贝**应当**显式 `.clone()`（v1 是否提供见 §9.2 Open Issue）。

### §8.4.3 `String` 不可变

§8.4.3.1 `String` 是不可变堆句柄；所有"修改"语义返回新 `String`，没有原地修改方法（§9.3.4.1）。

§8.4.3.2 不可变下复制 = 句柄共享，深拷贝无意义；**无** `clone()`。

§8.4.3.3 字面量落 `.rodata`，RC 头哨兵（§8.2.3）。

§8.4.3.4 mutable 用例走 `StringBuilder`（§9.4）；自定义码点缓冲走 `Array<u32>` + `String(buf)`（§9.3.3）。

## §8.5 `Weak<T>` 与 `upgrade`

### §8.5.1 范围（v1）

§8.5.1.1 `Weak<T>` v1 **仅配** `Box<T>`：`Weak<Array<T>>` / `Weak<String>` 不支持（§3.7、§9.6.1.1）。

§8.5.1.2 v1 不实现 cycle collector；父子 / 双向引用**应当**用 `Weak` 打破，否则视为预期内的循环引用泄漏（§8.10）。

### §8.5.2 语义

§8.5.2.1 `Weak<T>` 持指向某 `Box<T>` Block 的弱引用，**不**阻止 payload 析构。

§8.5.2.2 `Weak<T>` **原生可空**：自带"空 / 已失效"状态；`Weak<T>?` 双层可空在语义层禁（§3.6.5.3 / §3.7）。

§8.5.2.3 `Weak<T>` 上的 `==` / `!=` v1 **禁用**（§3.7、§8.9）；要比对走 `same_ref`（§8.7）或先 `upgrade` 后比 payload。

### §8.5.3 API

| 形式 | 说明 |
|---|---|
| `Weak(box Box<T>?)` | 构造函数：传 `null` 得空 weak；传活 box 绑定并 weak++ |
| `weak:<T>(box Box<T>?) Weak<T>` | 编译器 baked，与构造函数等价 |
| `upgrade(w Weak<T>) Box<T>?` | 强引用还在则返回持值 `Box<T>?`，已释放或空 weak 返回空 |

§8.5.3.1 含 `Weak<T>` 字段的结构体在构造时**应当**显式给定初值（如 `Weak(null)`），DAA 不为其提供豁免（§7.3.3.4）。

§8.5.3.2 `Weak<T>` 可作为字段、`Array` 元素、全局、返回值（与 `T&` 不同，§5.4）。

## §8.6 借用 `T&`

### §8.6.1 形态

§8.6.1.1 `T&` 由 `typeWithRef` 产生（§3.2.3）；只能在以下白名单位置出现：

- 函数参数类型（含方法 receiver `$`，自动隐式 `Self&`）；
- 局部变量类型（`var d T& = ...`）；
- `& expr` 表达式的结果类型。

§8.6.1.2 在结构体字段、容器内层、全局 / `cval`、函数返回值、嵌套 `T& &` 位置出现 `T&`，由 `yux.g4` / 语义层直接拒绝（§3.2.3.2、§3.7、§2.6）。

### §8.6.2 不参与 RC

§8.6.2.1 `T&` 是非空指针；**不**参与 retain / release。其指向的对象由所有者负责寿命管理。

§8.6.2.2 `T&` 类型的局部变量析构时**不**做任何动作。

### §8.6.3 绑定与赋值

§8.6.3.1 *rebind 禁*：`T&` 局部变量**应当**在声明处初始化；之后赋值改的是被引对象：

```yux
var c = 1
var d i32& = &c   ; d 绑到 c
d = 3             ; ✅ c 变 3
                  ; ❌ d 不能重指向别的变量
```

§8.6.3.2 *拷贝绑定*：从一个 `T&` 复制绑定**不**写 `&`：

```yux
var d2 i32& = d   ; ✅ d2 与 d 绑同一目标
```

§8.6.3.3 *`&d` 报错*：对 `T&` 再取址结果是 `T& &`，由语法拒绝。

§8.6.3.4 *无 default*：`T&` 形参 / `val d T&` 局部变量的"写权"由源对象决定，与 `var` / `val` 无关。

### §8.6.4 取地址表达式 `&`

§8.6.4.1 `&` 只能作用于**左值**：

| 形式 | 允许 | 结果类型 | 备注 |
|---|---|---|---|
| `&局部变量` | ✅ | `T&`（变量类型为 T） | |
| `&函数参数` | ✅ | `T&` | |
| `&$.field` | ✅ | `FieldType&` | 方法内 receiver 字段 |
| `&box`（box 是 `Box<T>` 局部 / 形参） | ✅ | `Box<T>&` | 借用**句柄本身**（§8.3.5.1） |
| `&box.field` | ✅ | `FieldType&` | Box 自动解引用后取字段，借用绑到 box 句柄存活期 |
| `&任意 RC 字段链` | ✅ | 终点字段类型的 `&` | 只要每一层都是字段访问 |
| `&arr[i]` | ❌ | — | `[]` 调用 `at` 成员函数，结果是值；要修改用 `arr.set(i, ...)` |
| `&f()` / `&任何方法调用` | ❌ | — | 函数返回值是右值临时 |

§8.6.4.2 `& expr` 由 `exprGetRef: SymbolAnd obj=(ID|SymbolThis) (SymbolDot subs+=ID)*` 在语法层限定：`&` 只接命名 ID / `$`，后接零或多个字段子选择（§B.6）。这从语法层挡掉 `&调用结果` / `&临时表达式`。

### §8.6.5 寿命检查（O(1) 静态规则）

§8.6.5.1 *唯一规则*：`T&` 变量的初始化来源（追到 `&` 的根对象 / 形参 `T&`）所在**声明作用域** ⊇ 该 `T&` 变量自身的**声明作用域**。

§8.6.5.2 这是 O(N) 单遍 AST 检查（每函数一遍），**不**做数据流分析、**不**做借用检查器。

§8.6.5.3 拷绑透传：`var r2 T& = d` 的根 = `refToRoot[d]`（追到终极根对象）；`var r T& = &x.f.f` 的根 = `x`。

§8.6.5.4 例：

```yux
fn foo(b Box<Pair>&) {
  var r i32& = &b.field   ; ✅ b 是参数，作用域 ⊇ r
}

fn bar() {
  var b Box<Pair> = ...
  var r i32& = &b.field   ; ✅ 同作用域
  if cond {
    var r2 i32& = &b.field ; ✅ b 作用域 ⊇ r2
  }
  ; ❌ var r3 i32& = if cond { &b.field } else { &c }
  ;    cond 分支里如果引入了更窄作用域的源对象，就违反规则
}
```

§8.6.5.5 *根对象重赋禁*：在 `T&` 的存活区间内，其根对象**不得**被赋值 / 移交。Box 句柄的"赋值"等价 release-旧 + retain-新，借用期内禁此操作即可（纯本地检查）。

§8.6.5.6 *临时不可绑*：`T&` 不能绑定临时值——临时的"作用域"是当前语句 / 表达式，比任何 `var` 声明都小，由 §8.6.5.1 自动拒绝。

### §8.6.6 receiver `$`

§8.6.6.1 方法 receiver `$` 永远隐式 `Self&`（§7.2.2、§6.2 末段）。调用方写 `obj.method(args)`；**不**引入 UFCS（`T::method(self, args)` 风），避免风格混乱。

§8.6.6.2 LLVM 层 `T&` / receiver `$` 落成非空指针。

§8.6.6.3 构造函数中的 `$` 仍是 `Self&`，但其字段在入口处全部处于*未初始化*状态，受 §7.3.3 DAA 约束；`$` 自身**不**可逃逸（§7.2.2.3）。

## §8.7 调用 ABI

### §8.7.1 callee-clean retain / release

§8.7.1.1 *实参取址显式*：`fn f(a i32&) { ... }` 调用方写 `f(&x)`，**不**自动加 `&`（§8.3.5）。

§8.7.1.2 *receiver 例外*：方法 receiver `$` 的 `Self&` 取址由编译器隐式注入；调用方写 `obj.method(args)`（§8.6.6.1）。

§8.7.1.3 *callee-clean*：调用方在传堆句柄实参前 retain（计数 +1）；被调用方把堆句柄参数视为自己的局部变量，在作用域结束时 release。优势：参数和局部变量走同一条析构路径，不需要"参数特例"。

§8.7.1.4 适用范围：堆句柄（`Box<T>` / `Weak<T>` / `Array<T>` / `String` / `StringBuilder` / 含 RC 字段的非平凡用户 struct）。值类型（标量、平凡 struct）不参与 retain / release。

§8.7.1.5 fresh 实参（来自 `Box(...)` / 数组字面量 / 直接函数调用结果）已携带 +1，调用方**应当**省略 retain 而直接消费临时（§8.8）。

### §8.7.2 move-return retain 注入

§8.7.2.1 编译器对 `ret box_expr`（返回类型为堆句柄或含 RC 字段 struct）**应当**生成 retain；所有分支汇聚后净效果是 +1 给调用方；callee 末尾的析构 release 自然抵消多余 retain。

§8.7.2.2 fresh 返回值省略 retain（§8.7.1.5）。

§8.7.2.3 peephole 优化：编译器**可以**抵消 IR 上的 retain / release 对（informative，v1 暂不做）。

### §8.7.3 用户结构体按值 ABI

§8.7.3.1 用户 struct 默认按值复制（§7.6）。

§8.7.3.2 编译器**可以**在 ABI 层用指针传大结构体（不可观测优化）。判定：平凡 struct 倾向按值传；非平凡 struct（含 RC 字段）按值传 + 字段级 retain。具体边界条件随实现版本变化（impl log Phase 3c）。

§8.7.3.3 receiver `$` 始终按指针传（隐式 `Self&`，§8.6.6）。

### §8.7.4 extern fn 边界

§8.7.4.1 `extern fn` 签名 v1 允许：内置标量、`Ptr`。**不**允许 `T&` / `Box<T>` / `Array<T>` / `String` / `Weak<T>` / 用户 struct（§6.6 / §9.7）。

§8.7.4.2 v1 **不强制** LLVM 落地约束——extern 在 v1 是危险但开放的接口，便于 SDK 落地。Open Issue：参照 Rust `unsafe` 收紧。

§8.7.4.3 自动转 Ptr：`T&` / `Box<T>` / `Weak<T>` / `Array<T>` / `String` 作 extern 实参传给 `Ptr` 形参时**自动转换**。这是规范层唯一的隐式跨档位转换（§3.4.2.6）。

§8.7.4.4 显式转 Ptr 走编译器 baked 内置 `ptr_of:<T>(obj)`（§9.7.2.4）：

| 源类型 T | 结果指向 | 备注 |
|---|---|---|
| `U&` | U | 短寿命；C 端不可保存超出本次调用 |
| `Box<U>` | U payload | 跳过 RC 头 |
| `Array<U>` | 元素首地址 | |
| `String` | 码点首地址 | 不带 NUL 终止 |
| 内置标量 | — | **不**允许 |

§8.7.4.5 `Ptr` 算术（偏移 / 加减）**仅 SDK 内**可用；用户代码出现 Ptr 算术**应当**编译报错。v1 实现以"私有函数 `_ptr_offset`"替代标记机制（impl log Phase 7d）。

§8.7.4.6 *FFI 注意*：`box.payload` 经 `Ptr` 流出后，C 端**不可保存超出本次调用**——yux 这边 release 时 payload 会析构。

### §8.7.5 比较 ABI

§8.7.5.1 *内容相等* `==`：

| 类型 | 语义 |
|---|---|
| 内置标量 | 值相等（IEEE 754 浮点遵从 ordered，§9.1.2.1） |
| 用户 struct | 字段递归 `==`（编译器派生），或用户重载 `eq` |
| `Box<T>` | 解引用后比 payload 内容 |
| `Array<T>` | 长度 + 元素逐个 `==` |
| `String` | 内容逐字节（码点逐位） |
| `Weak<T>` | v1 **禁用** `==` / `!=`（§8.9） |

§8.7.5.2 *地址相等* `same_ref:<T>(a, b) bool`：编译器 baked 内置；接受 `Box<T>` / `Weak<T>` / `T&` / `Array<T>` / `String`，比对底层 handle 指针。空 Weak 与任何活句柄不等。

## §8.8 临时值与作用域

### §8.8.1 临时值清单

§8.8.1.1 每条**语句 / 顶层表达式 / 代码块**边界维护一个"未消费的堆句柄临时值"清单（_temp frame_）；边界处对仍在清单中的临时值统一 release。

§8.8.1.2 *fresh 临时*：来自 `ExprCallNode`（callee 已 move-return retain）/ `ExprArrayNode`（数组字面量，`_array_alloc` 给 strong=1）的结果是 fresh +1，**应当**记入临时帧。

§8.8.1.3 *不消费临时*：receiver / 字段访问 / 借用 `&` 只是借用临时，**不**夺所有权；临时靠"边界 release"自然 keep-alive 直到访问完成。

§8.8.1.4 *消费*（从清单移除）：

- 作为参数传入 callee-clean 调用（§8.7.1）；
- 绑定到 `var` / `val`（§5.1）；
- 写入字段（§7.4.4）；
- 作为 `ret` 表达式（§8.7.2）；
- 作为另一表达式被进一步消费。

§8.8.1.5 *分支汇合*：每分支独立维护临时帧；phi 汇合后归一为 +1 句柄（具体路径见 impl log Phase 8d.3）。

### §8.8.2 fresh 判定与 retain 跳过

§8.8.2.1 编译器**应当**对每个 retain 站点判定 fresh：fresh 实参 / fresh 赋值源 / fresh 返回值跳过 retain（§8.3.3.2、§8.7.1.5、§8.7.2.2）。

§8.8.2.2 旧值 release 不参与 fresh 判定，无条件执行（保证自赋值 / 别名安全靠先 retain 再 release，fresh 路径直接 release，新值带入的 +1 抵消）。

### §8.8.3 链式调用 keep-alive

§8.8.3.1 链式 `make().method()`：fresh `Box` 作为 receiver 进入 method，caller 处的 fresh 句柄记到 statement 帧；语句结束时 release。SSA use-def 自动让该 Value 在整条 method 调用期间 live（call 指令的 use 阻止 release 提前发出）。

§8.8.3.2 `&make_box()` 在语法层禁（§8.6.4.2）。

### §8.8.4 RC leak 检测

§8.8.4.1 runtime 维护 `_rc_block_count` 全局：每次 `_box_alloc` / `_array_alloc` 入口 +1，每次实际 `HeapFree` 后 -1。

§8.8.4.2 公开内置 `rc_leak_count() i64` 返回当前未释放 Block 数（无 `_` 前缀，调试 / 测试可用，§9.10）。

§8.8.4.3 测试约定：每条含 RC 句柄的语句跑完后，`rc_leak_count() - base` **应当**为 0；这是 v1 临时值清单设计的可观测验收（impl log Phase 8e）。

## §8.9 禁忌一览

下表汇总规范层的禁忌；该表与 §3.7 保持同步，二者增删**应当**联动（§3.7.1）。

| 形态 | 拒绝层 | 原因 | 章节 |
|---|---|---|---|
| `T& &` | 语法层 | 嵌套引用无意义 | §3.2.3.2 / §2.6.1 |
| 字段位置 `T&` | 语法层 | 借用不可逃逸出栈帧 / 堆对象 | §3.2.3.2 / §2.6.2 |
| 函数返回值 `T&` | 语法层 | 借用不可逃逸出调用 | §3.2.3.2 / §2.6.3 / §6.3 |
| 全局 / `cval` 中的 `T&` | 语法层 | 全局存储无可追踪寿命 | §3.2.3.2 |
| `Array<T&>` / `Box<T&>` / `Weak<T&>` | 语法层 | 容器内层用 `type` 而非 `typeWithRef`；借用不可放进堆容器 | §3.2.3.2 |
| `Weak<T>?` | 语义层 | `Weak` 原生可空，避免双层可空歧义 | §3.6.5.3 / §8.5.2.2 |
| `Weak<T>` 上的 `==` / `!=` | 语义层 | 改走 `same_ref:<T>` / 先 `upgrade` 后比较 | §8.5.2.3 / §8.7.5 |
| `Weak<Array<T>>` / `Weak<String>` | v1 语义层 | v1 弱引用仅配 `Box<T>` | §8.5.1.1 |
| `Ptr<T>` 出现在用户代码非 FFI 上下文 | 风格 / 编译器警告 | `Ptr` 仅 FFI 边界使用 | §9.7.2 |
| `&调用结果` / `&临时表达式` | 语法层（`exprGetRef` 限定） | 借用不可绑临时 | §8.6.4 / §B.6 |
| `&arr[i]` | 语法层（`exprGetRef` 限定） | `[]` 是方法调用，结果是右值临时 | §8.6.4 |
| `var d T&` 无初始化（rebind 禁） | 语法层 | `T&` 应当在声明处绑定 | §8.6.3.1 |
| `&d`（d 是 `T&`） | 语法层 / 语义层 | 结果是 `T& &` | §8.6.3.3 |
| `ret $` 构造函数中 | 语义层（DAA） | `$` 是 `Self&`，借用不可逃逸 | §7.2.2.3 / §7.3.3 |
| 多线程跨线程共享堆句柄 | 文档层（v1 未定义） | RC 非原子 | §8.2.4.3 |

§8.9.1 上述清单的修订**应当**与 §3.7 同步落入；新增 / 解除禁忌需更新两处（Phase 6 验收点）。

## §8.10 v1 不在范围

§8.10.1 下列功能 v1 **不**实现，规范层留作未来版本设计窗口：

- 借用检查器、生命周期标注；
- 默认移动语义（已否决，§8.1.2）；
- 跟踪 GC / Arena 分配器；
- 多线程 / 闭包；
- cycle collector（`Weak<T>` 是用户侧打破循环的唯一手段）；
- 字段级默认值语法（`field T = expr` 在 struct 定义处给默认值，§7.7.2）。

§8.10.2 v1 已知接受的妥协：

- 循环引用泄漏：用户**应当**用 `Weak<T>` 打破；若不打破，v1 接受泄漏。
- `extern fn` 签名类型 v1 不强制约束；**应当**未来收紧。
- `same_ref` / `ptr_of` 的 `T&` 源类型暂不支持（需放宽 `genericDef` 接受 `T&` turbofish）。
