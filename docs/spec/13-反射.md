# §13 反射

本章规范 riu 的**编译期反射**机制：通过内置 spec `Reflect` 暴露类型的元数据（类型名、字段、方法、变体），数据以 rodata 常量形式 emit 到产物中，运行时通过普通 `for` 遍历访问。

> 本章对应草案 [`draft/DRAFT-spec-reflect.md`](draft/DRAFT-spec-reflect.md)（2026-06-09 已落地）。反射 API 由编译器隐式 `#Impl(Reflect)` + `#Static #Frozen` 字段段提供，`Field.value` 走 sema 期纯改名；`#Inline for` / IR-before unroll pass **永不引入**（见 §13.7）。

涉及交叉章节：§7.10（静态函数与 `Type::name` 调用形态）、§7.11（`#Static` 字段段）、§11.12（`#Reflect` 注解）、§12.1（spec 声明）、§12.8（不在范围）、附录 D（E1138 / E3133–E3136）。

## §13.1 概念

§13.1.1 riu 提供**编译期反射**：通过内置 spec `Reflect`，编译器**隐式**为每个用户定义的 struct 与 enum 类型生成 `#Impl(Reflect)` 实现。反射元数据在编译期静态确定，以 `.rodata` 常量形式 emit 到目标文件中。

§13.1.2 反射数据走 **runtime 数组**：`Self::fields` 是普通定长数组引用 `[Field& * N]&`，可通过下标索引、取 len、`for` 遍历——无编译期循环展开（`#Inline for` 永不引入，见 §13.7）。

§13.1.3 反射 API 的四个入口均为**静态字段**（`#Static #Frozen`）：

| 字段 | 类型 | 含义 |
|---|---|---|
| `type` | `Type` | 类型名（值 copy） |
| `fields` | `[Field& * N]&` | 实例字段数组引用（不含 `#Static` 字段） |
| `methods` | `[Method& * 0]&` | 方法数组引用（v1 未填充，占位空数组） |
| `variants` | `[Variant& * 0]&` | 变体数组引用（仅 enum 填充；非 enum 访问 → E3135） |

全部为值类型或数组引用——元数据统一按值 copy（rodata → stack），不引入 `T&`。

## §13.2 Reflect spec 形态

§13.2.1 `Reflect` 是编译器的**内置 spec**，在 `sdk/riu/src/riu/core/base.ut` 中以 `#Spec struct Reflect { ... }` 声明。编译器在 codegen 阶段识别该 spec 并自动为每个 struct / enum 类型合成 `#Impl(Reflect)`，用户**不得**手写 `#Impl(Reflect)`。

```riu
#Spec
struct Reflect {
  #Static
  #Frozen
  type Type

  #Static
  #Frozen
  fields [Field& * 0]          ; 0 = 编译期占位，按 implementer 自动填长度

  #Static
  #Frozen
  methods [Method& * 0]

  #Static
  #Frozen
  variants [Variant& * 0]      ; 仅 enum；非 enum 访问 → E3135
}
```

§13.2.2 访问形态：**仅类型形**（`Counter::type` / `Counter::fields` / `Self::fields`）。实例形访问（`c.type` / `$.type` 等）→ E1138（实例调静态成员）。

§13.2.3 `#Static #Frozen` 组合语义：字段为静态（关联于类型而非实例，§7.11）且深不可变（§7.1.4 / §11.7 / §11.11）。编译器在 `.rodata` 中 emit 只读全局变量承载其值。

## §13.3 反射数据类型

全部为 `#Builtin` struct（§11.2），LLVM 布局由编译器硬编码。

### §13.3.1 Type

```riu
#Builtin
struct Type {
  #Frozen
  name String                     ; 全限定类型名（如 "riu.core.Counter"）
}
```

§13.3.1.1 `Type` 仅含 `name` 字段（全限定类型名）。`fields` / `methods` / `variants` **不**作为 Type 的成员字段，而是通过 `T::fields` / `T::methods` / `T::variants` 独立静态路径访问（Reflect spec 上的 `#Static` 字段）。

### §13.3.2 Field

```riu
#Builtin
struct Field {
  #Frozen
  name String
  ; value                   ; phantom：sema 期改名为 <receiver>.<f.name>（§13.5）
}
```

§13.3.2.1 `Field.name` 为实例字段名（编译期常量 String，不含 `#Static` 字段）。

§13.3.2.2 `Field.value` 是 **dependent-typed phantom**：`.value` 的类型按 `f` 静态绑定的具体字段而定，riu 类型系统当前无法用单一类型表达。编译器在 sema 期将其改写为 `<receiver>.<f.name>`（见 §13.5）。

§13.3.2.3 `type` / `offset` 等字段暂不包含——使用时上下文已知遍历哪个 struct 的 fields，有需求时再加。

### §13.3.3 Method / Variant

```riu
#Builtin
struct Method {
  #Frozen
  name String
}

#Builtin
struct Variant {
  #Frozen
  name String
}
```

§13.3.3.1 `methods` 与 `variants` 在 v1 未填充（N=0），声明保留供后续扩展。

## §13.4 静态字段访问

§13.4.1 `<StructName>::type` / `<StructName>::fields` / `Self::fields` 等静态字段访问走 `ExprPathCallNode` 路径（§7.10.2.1）。sema 期优先匹配已知 struct 上的 `#Static` 字段（包括编译器合成的 `Reflect` 字段），再到 enum 构造器 / spec 静态方法。

§13.4.2 `Counter::type` 返回 `Type`（值 copy，栈上 load 整个 rodata 全局）。`Counter::fields` 返回 `[Field& * N]&`（指向 rodata 中 refs 数组的引用）。

§13.4.3 `Counter::fields[N]` 索引访问返回 `Field&`（指向 rodata 中第 N 个 Field data 元素的引用）。`Counter::fields.at(N)` 等效（语法糖）。

§13.4.4 实例形访问（`c.type` / `$.fields` 等）→ **E1138**。编译器在 `ExprDotNode` 顶部检测 receiver 为实例而 member 为已知 `#Static` 字段时报错，提示改用 `<Type>::field` 形态。

## §13.5 Field.value sema 期改名

§13.5.1 通过 `Field.value` 访问字段的实际值**不经过运行时 dispatch**：编译器在 sema 期识别 `<staticFieldsExpr>[<intLit>].value` pattern，解析出该 Field 的 `name` 静态值后，将整个表达式**改写**为 `<receiver>.<f.name>`。改写后走既有字段访问通路（含 const-mut 检查）。

§13.5.2 编译期可定判定：

| 上下文 | `f.value` 解析 |
|---|---|
| `f` 是编译期可确定的具体 `Field&`（`Counter::fields[0]` / `Self::fields[N]` 下标位字面量） | 改写为 `<receiver>.<f.name>`；类型 = 该字段实际类型 |
| `f` 是 runtime 变量（普通 `for f in Self::fields` 内的循环变量） | **E3133** "`Field.value` 要求 f 编译期可定" |
| 在普通方法体外（无 `$` receiver 上下文） | **E3134** "`Field.value` 改名无 receiver 绑定" |

§13.5.3 写形态 `f.value = expr` 等价 `$.<f.name> = expr`，受常规 const-mut 检查（无注解的默认可变字段允许写，`#Val` / `#Frozen` 字段写报 E3109）。

§13.5.4 实现路径：sema 期识别 AST pattern `ExprCallNode→ExprDotNode(".at")→ExprPathCallNode("fields")` + `ExprGetNode` 索引形态 → resolve Field.name 静态值 → 返回改写后的 `ExprDotNode(receiver, fieldName)`，不引入 IR-before pass / unroll 机制。

§13.5.5 限制：v1 仅支持 `$` receiver（方法体内的 receiver 绑定）。显式 receiver 形态（`other::fields[0].value` → `other.fieldName`）留后续扩展。

## §13.6 .rodata emit 与 DCE

§13.6.1 编译器在 codegen 阶段为每个 struct / enum 类型 lazy emit 以下 rodata 全局变量：

- **Type 全局**：`__riu_reflect_<mod>_<name>__type`，linkonce_odr，`{ String name }`
- **Field data 数组**：`[N x Field]`，PrivateLinkage
- **Field refs 数组**：`[N x ptr]`，每个元素为 constexpr GEP 指向 data 数组对应 Field 元素。`Counter::fields` 返回该数组引用 `[Field& * N]&`

全部为只读（`isConstant=true`），不可变 String 走 immortal Block（`strong=0xFFFFFFFF`，无 RC 开销）。

§13.6.2 链接期 `--gc-sections` 自动删除未被源码引用的反射数据。

§13.6.3 `#Reflect` 注解（§11.12）：标在 struct 上的零参注解，强制编译器将该类型的反射 rodata 全局加入 `llvm.compiler.used`，防止 `--gc-sections` 误删。适用于反射数据仅在外部工具（如序列化框架）中引用、源码层未直接访问的场景。

## §13.7 不在范围

v1 **明确不做**：

1. `#Inline for` 编译期循环 unroll / IR-before unroll pass —— **永不引入**。
2. 按字段递归自动 derive 默认体（如 `ToJson.to_json` 自动遍历字段填 JSON）—— **永不引入**。
3. `#NoReflect` 反向注解（强制不 emit 反射数据）。
4. 运行时方法 dispatch（永不开放，沿用 `Dyn<Spec>` §12.9）。
5. 编译期方法 dispatch（调 cval Type 上的方法）。
6. `#Static #Frozen` 之外其它静态字段档位（`#Cval` / `#Mut` 静态字段等，留 `DRAFT-data-struct.md`）。
7. `Field.type` / `Field.offset` 等额外反射字段。
8. `Self::type` / `Self::fields` 在非 struct 方法体内的访问（当前仅 struct 方法体内可用）。
