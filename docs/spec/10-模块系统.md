# §10 模块系统

本章规范 yux 的项目布局、模块导入、命名解析、包级再导出与可见性边界（`pkg` 文件）、可见性，以及与 SDK / `base.yux` 的协作。

## §10.1 项目结构

### §10.1.1 `yux.toml`

§10.1.1.1 项目根由 `yux.toml` 标记。该文件**应当**位于项目根目录。字段定义：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | 字符串 | ✅ | 项目 / 产物名 |
| `version` | 字符串 | ✅ | 版本号 |
| `entry` | 字符串 | 可执行项目必填 | 入口源文件，相对源根（§10.1.3） |
| `[lib]` 节 | 表 | 库项目用 | 见 §10.1.2 |
| `[link]` 节 | 表 | 系统链接库声明 | 见 §10.1.1.6 |

§10.1.1.2 `[lib]` 子表（可选）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | 字符串 | 库类型（v1：`"static"` 等） |

§10.1.1.3 可执行项目示例：

```toml
name = "myproject"
version = "1.0.0"
entry = "main.yux"
```

§10.1.1.4 库项目示例（如 SDK 自举）：

```toml
name = "yux"
version = "1.0.0"

[lib]
type = "static"
```

§10.1.1.5 `name` 的 UTF-8 字符串内容由实现解析（v1 `toml11` 原生支持中文）。

§10.1.1.6 `[link]` 子表（可选）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `libs` | 字符串数组 | 链接时追加的系统库名（不含 `.lib` 后缀）。实现自动补全为 `<name>.lib` 传 `lld-link` |
| `lib_dirs` | 字符串数组 | 额外库搜索路径，传 `lld-link` 为 `/libpath:<dir>`。相对路径相对项目根 |

```toml
[link]
libs = ["user32", "shell32"]
lib_dirs = ["lib"]
```

### §10.1.2 项目模式与单文件模式

§10.1.2.1 *项目模式*（推荐）：以 `yux.toml` 为根。命令 `yux build [<name>]` **应当**在 `yux.toml` 所在目录执行；`<name>` 可省略，省略时驱动**应当**取 `yux.toml` 中 `name` 字段；显式给出时**应当**与 `name` 字段一致，否则驱动以非零退出码报错。最终产物落在 `<projectRoot>/build/<name>.exe`（可执行项目）或 `<projectRoot>/build/<name>.lib`（静态库）。中间产物 obj / IR 镜像源文件相对项目根的路径放在 `<projectRoot>/build/<src-rel>.obj`（典型 `<projectRoot>/build/src/<rel>.obj`）；每个目录视为一个包，目录内所有 `.yux` 的元信息聚合到该目录下的 `<dirname>.cache` 增量缓存。

§10.1.2.2 *单文件模式*（v1 已弃用）：忽略 `yux.toml`，产物扁平放在源文件目录。新增代码、示例、文档**应当**一律走项目模式。

### §10.1.3 源根 `src/`

§10.1.3.1 项目模式下的**源根**（source root）是模块 / 包的解析起点：

- 若 `<projectRoot>/src/` 存在且为目录，源根 = `<projectRoot>/src/`；
- 否则源根回退为 `<projectRoot>/`。

§10.1.3.2 `entry` 字段是相对源根的路径（典型 `main.yux` 表示 `<src>/main.yux`）。

- `entry` **不得**为绝对路径，否则报 [E5013]。
- 解析 (`canonical`) 后 `entry` 仍**应当**位于 `<src>/` 子树内；逃出源根（典型形态 `../foo.yux`）默认报 [E5014] warning（约定违例 + obj 镜像路径可能走样）。可通过 `--Werror` / `--deny=E5014` 升级为 error。

§10.1.3.3 模块 `a.b.c` 解析为以下之一（按存在性顺序）：

- `<src>/a/b/c.yux`（文件模块）；
- `<src>/a/b/c/`（包模块，配合 `pkg` 文件，§10.2.4）。

§10.1.3.4 同名 `.yux` 文件与同名子目录并存属冲突，编译器**应当**报错。

### §10.1.4 项目结构示例（informative）

```
myproject/
├── yux.toml
└── src/
    ├── main.yux
    ├── math.yux
    └── ops/
        ├── pkg              ; 包再导出清单（§10.2.4）
        ├── add.yux
        └── sub/
            └── inner.yux
build/
├── myproject.exe              ; 最终产物（exe / lib）
└── src/                       ; 中间产物：镜像 src/ 目录树
    ├── main.obj
    ├── math.obj
    ├── src.cache              ; 顶层"src 包"的增量缓存
    └── ops/
        ├── add.obj
        ├── ops.cache          ; ops 包缓存（覆盖 add.yux 与 sub/ 包之外的 ops/ 直系源）
        └── sub/
            ├── inner.obj
            └── sub.cache
```

§10.1.4.1 缓存文件 `<dir>/<dirname>.cache` 第 1 行为编译器指纹（当前 `yux.exe` 的 mtime+size，TAB 分隔）；后续每行为 `<filename>\t<src-mtime-ns>\t<src-size>`。指纹不匹配即整个文件作废，触发该包内全量重编。

## §10.2 模块导入

### §10.2.1 形态

```
imports ::= 'use' typePath ('.' '*')? codeLineEnd
```

§10.2.1.1 `use` 形态：

| 写法 | 语义 | 章节 |
|---|---|---|
| `use a.b.c` | 把路径末段 `c` 登记为模块 / 包别名；其后用 `c.member`（包则 `c.child.member`） | §10.2.2 |
| `use a.b.*` | 按文件模块扁平、或按 `pkg` / 无 `pkg` 默认规则展开到当前命名空间；同时登记末段别名 `b` 与已 use 的路径前缀 | §10.2.3 |
| `use a.b.MyType` | 先当模块路径；不存在则把父模块 `a.b` 的公开类型 `MyType` 注入裸名（L2） | §10.2.2.3 |

§10.2.1.2 `use` **应当**出现在源文件顶部 `LineEnd*` 之后、其它顶层声明之前（`yuxParser.g4` 的 `program`：`imports*` 不能与 `fn` / `struct` 等交错）。`imports` 之间可以有空行。

### §10.2.2 命名导入（非通配）

§10.2.2.1 `use a.b.c` **不**把目标成员注入当前命名空间；只把路径末段 `c` 登记为别名：

- 命中 `<src>/a/b/c.yux`（文件模块）：`c` 为模块别名，调用方写 `c.member`；
- 命中 `<src>/a/b/c/`（包模块）：`c` 为包别名，调用方写 `c.child.member`（含子目录链，如 `ops.sub.inner.fn()`，`tests/projects/imports_package_chain` / `imports_deep_nesting`）。有 `pkg` 时 `child` 须对该调用方可见（§10.2.4）；
- 同名 `.yux` 与目录并存 → [E2003]（§10.1.3.4）。

§10.2.2.1.1 别名与当前文件已有本地符号冲突 → 导入时报 [E2004]。

§10.2.2.1.2 **不得**经 `use a.b.c`（目标是模块 / 包）用裸名访问目标成员。裸名只来自：当前文件自己的声明、`use path.Name` 的具名类型注入（§10.2.2.3）、`use ...*` 的扁平注入（§10.2.3），以及默认 `yux.core.*` 回退（§10.4.1.3）。

§10.2.2.2 例（`tests/projects/imports_module_alias`）：

```yux
use math
fn main() {
    println(math.square(7))
}
```

§10.2.2.3 `use a.b.MyType`：先按模块路径解析 `a.b.MyType`（文件 / 包）。若不存在，且父路径 `a.b` 是已有模块、末段 `MyType` 是其公开类型（`struct` / `enum` / 别名，非 `_` 前缀），则把 `MyType` 注入当前文件裸名（L2 具名导入），并登记路径前缀以便写 `a.b.MyType`。例：`tests/projects/named_type_import`。

### §10.2.3 通配导入

§10.2.3.1 `use a.b.*` 的展开因目标是文件还是包而不同：

- 若 `a.b` 是文件模块（`<src>/a/b.yux`）：把该文件的全部**公开**顶层声明（`fn` / `struct` / `enum` / 类型别名 / spec / 全局 `let`；`_` 前缀除外）注入当前模块，可裸名使用；
- 若 `a.b` 是包模块（`<src>/a/b/`）：按 `pkg` 文件展开（§10.2.4）；只展开对该调用方可见的项（公开项，以及 `to` 名单含该调用方的定向项）。

§10.2.3.1.1 若包目录**不含** `pkg` 文件，语义**等价于** `pkg` 文件中按文件名排序逐行列出所有 `.yux` 子模块（`name` 形式，**不做** `name.*` 扁平再导出）及子目录。即调用方通过 `use pkg.*` 后以 `child.fn()` 访问各子模块成员，不能直接用裸名 `fn()`。此即 2026-06-29 决议保留的「无 `pkg` 默认别名导出」，不是扁平。

§10.2.3.2 仅文件模块通配、以及 `pkg` 的 `name.*` 扁平再导出，公开成员可裸名使用。包通配的 `name` 形态仍走子模块前缀（§10.2.3.1.1）。

### §10.2.4 `pkg` 文件（包再导出与可见性边界）

§10.2.4.1 包目录可含一个**无后缀**的纯文本文件 `pkg`，描述该包的再导出清单。目录**有** `pkg` 时，清单同时是**包外**可见性边界（§10.2.4.6）：未列出的子模块对包外不可见。目录**没有** `pkg` 时走 §10.2.3.1.1，不设清单门控。

§10.2.4.2 `pkg` 文件每行一条导出项。`as` 与 `to` 都可选。语法如下：

| 行形态 | 语义 |
|---|---|
| 空行 / 仅空白 | 忽略 |
| `;...` 注释行 | 忽略（行首 `;`，与 yux 注释一致） |
| `name` | **公开**：把同包下的子模块 `name`（文件 `name.yux` 或子目录 `name/`）以导出名 `name` 再导出 |
| `name.*` | **公开**：把子模块 `name` 的全部公开成员扁平再导出到该包名空间。不做 `name.* as` / `name.* to` |
| `name as alias` | **公开**：把子模块 `name` 以导出名 `alias` 再导出；调用方以 `alias.member` 访问，不能再用 `name` |
| `name to t1; t2; …` | **定向开放**：仅所列目标可用导出名 `name` |
| `name as alias to t1; t2; …` | **定向开放**：仅所列目标可用导出名 `alias`（不能再用 `name`） |

§10.2.4.2.1 `;`：行首 `;`（trim 后）仍是整行注释。无 `to` 的行仍允许行尾 `;` 注释（如 `add.*    ; 扁平`）。**带 `to` 的行**上 `;` **只**当目标分隔，不再支持行尾注释。

§10.2.4.2.2 `to` 后面是**全限定**包名或模块名，`;` 分隔。每个目标**应当**在当前项目源树或已加载依赖里真实存在（含 SDK：`yux.core` / `yux.io`，以及已加载的 `yux.core.<stem>`）。不存在 → [E5019]。

§10.2.4.2.3 非法行**应当**报 [E5020]，**不得**静默跳过：

- `name.* to …`、`name.* as alias`（及二者组合）；
- 同一子模块出现多于一行（不能既公开又 `to`，也不能两行公开）；
- 带 `to` 但目标列表为空。

§10.2.4.3 目录是否为包模块由是否存在该目录决定（§10.1.3.3），与有无 `pkg` 无关。

- **无** `pkg`：走 §10.2.3.1.1。包外仍可 `use a.c` / `a.c.xxx`。
- **有** `pkg`：包外**只能**走清单。未列出的子模块（例：`a/c.yux` 而 pkg 只有 `b`）不能 `use a.c`、也不能 `a.c.xxx` → [E5018]。`use <pkg-path>.*` 只展开对该调用方可见的项。非通配 `use <pkg-path>` 仍把该目录登记为包别名，但点链孩子同样受清单门控。

§10.2.4.4 例（`tests/projects/pkg_wildcard_export/src/mymath/`）：

```
; src/mymath/pkg
add.*    ; 把 add 模块的所有公开成员扁平导出
sub      ; 把 sub 模块作为别名导出
```

调用方：

```yux
use mymath.*
fn main() {
    println(add(10, 5))     ; add 来自 add.yux，扁平
    println(sub.sub(10, 5)) ; sub 作为别名，需 sub.sub
}
```

§10.2.4.4.1 重命名导出例（`tests/projects/pkg_rename_export/src/mymath/`）：

```
; src/mymath/pkg
add as addition    ; 把 add 模块以 addition 别名导出
sub.*              ; 把 sub 模块的所有公开成员扁平导出
```

调用方：

```yux
use mymath.*
fn main() {
    println(sub(10, 3))          ; sub 来自 sub.yux，扁平
    println(addition.add(7, 2))  ; add 模块以 addition 别名访问
}
```

§10.2.4.4.2 定向开放例（informative）：

```
; src/a/pkg
b
c as xxx to yux.io; other.mod
```

- 包外普通调用方：可用 `b`；不能 `a.c` / `use a.c` / `a.xxx`。
- `yux.io` 与 `other.mod`：写 `use a.xxx` / `a.xxx.f()`；不能再写 `a.c`。

§10.2.4.5 `pkg` 文件**只读**，不参与编译；其语法独立于 `.yux`，仅在模块解析阶段被读取。

§10.2.4.6 一个目录可同时含 `pkg` 文件与 `.yux` 文件 / 子目录。有 `pkg` 时：

| 调用方 | 相对该 `pkg` | 清单 |
|---|---|---|
| 同目录兄弟 `.yux` | **包内** | 不受挡，互相可直接用未列出的子模块 |
| 子目录包 / 别的包 / 用户代码 | **包外** | 只认清单：公开项对所有包外可见；`to` 项只对名单内的目标可见 |

包外**不得**以全名 `pkg.sub` 钻未导出子模块。无 `pkg` 时不设此边界。

§10.2.4.7 友方与公开调用方一样，只认 `pkg` 给出的**导出名**。`c as xxx` 或 `c as xxx to …` 时写 `xxx`，不能写源名 `c`。未改名的公开 / 定向项用 `name` 本身。

### §10.2.5 命名解析

§10.2.5.1 裸名 `N`（单独一个 `ID`）按层查找。**同一层**内按声明身份（声明模块 + 短名）去重：同一声明经两条 `use` 进来只算一个。该层去重后 0 个则看下一层；1 个则用它；>1 → [E5015]（列出候选）。上层盖住下层；被盖住的仍可用路径 / 全限定引用。

| 层 | 来源 |
|---|---|
| L0 | 内层局部 / 参数 |
| L1 | 本文件顶层 `fn` / `struct` / `enum` / 别名 / 全局 `let` |
| L2 | 具名导入：`use path.Name`（§10.2.2.3） |
| L3 | 通配：`use x.*`、`use yux.io.*`、默认 `yux.core.*` |

§10.2.5.2 对照：

| 导入 | 裸名 `Ty` |
|---|---|
| `use a.*` + `use b.Ty` | `b.Ty`（L2 压过 L3）；`a.Ty` / `b.Ty` 路径仍合法 |
| `use a.Ty` + `use b.Ty` | [E5015]（L2 两个具名） |
| `use a.*` + `use b.*`（都导出 `Ty`） | [E5015]（L3 两个通配） |
| 本文件 `struct Ty` + 任何导入的 `Ty` | 本文件的（L1） |
| 本文件 `struct Map` + 默认 core `Map` | 本文件的；core 用 `yux.core.map.Map` 或 `map.Map` |

§10.2.5.3 路径前缀（`use a.b` 的 `a` / `b`、默认 `math` / `map` / `yux`）是编译期定位符，**不能当值**（[E5016]）。类型不能当值（[E5017]）。路径指向函数（`io.read_file`、`math.abs`）作为函数值合法。`T { }` / `T::f()` / `E::V`（可带路径）合法。

§10.2.5.4 点链首段**既是**已登记路径前缀 **又是**当前作用域的变量 / 参数时 → [E5015]（允许定义，禁止歧义使用）。字段 `obj.b` 永远按接收者查，不占裸名。

§10.2.5.5 全限定不引入未 `use` 的包。`packageChild` 只返回已经 load / `use` 过的子模块。未 `use yux.io` 时 `yux.io.xxx` 非法（[E6001]）。

§10.2.5.6 其它导入期冲突：非通配别名与当前文件本地符号（模块 / 包 / L1 类型 / 函数）冲突 → [E2004]；两个通配贡献同名**模块别名** → 使用点 [E2008]。

### §10.2.6 循环依赖

§10.2.6.1 v1 **禁止**模块间循环依赖：`a use b` 且 `b use a`（直接或传递）**应当**编译报错 [E5011]，错误信息**应当**给出环路（`a -> b -> a`）。

§10.2.6.2 该约束允许编译器按拓扑序逐模块编译。v1 **不**引入 forward 声明放宽此限制。若将来放宽，与 v1.x 包管理同期设计。

## §10.3 可见性

### §10.3.1 默认可见性

§10.3.1.1 顶层声明（`fn` / `struct` / `enum` / 类型别名 / spec / 全局 `let` / `extern` 块）默认**公开**：可被其它模块通过 `use` 导入。

§10.3.1.2 yux **不**引入 `pub` / `private` 等可见性修饰符（永久决议）。声明可见性靠命名约定（§10.3.2）；子模块对包外的可见性靠有无 `pkg` 清单（§10.2.4）。

### §10.3.2 `_` 前缀私有

§10.3.2.1 以下划线 `_` 开头的标识符为**私有**：仅在当前模块（同一 `.yux` 文件）可见，跨模块访问**应当**编译报错。

§10.3.2.2 适用范围：

- 顶层 `fn`（如 `fn _internal_helper()`）；
- 顶层 `struct`（如 `struct _State`）；
- 全局 `#Cval let`（如 `#Cval let _MAX_RETRIES i32 = 3`）；
- 结构体方法、字段（同模块外不可见）。

§10.3.2.3 编译器内部使用的 runtime helper（如 `_box_alloc` / `_array_grow` / `_ptr_offset`）也**应当**遵循该前缀约定（§8 / impl log）。

§10.3.2.4 `_` 前缀**不**影响同一模块内的可见性；同模块内可自由调用。

§10.3.2.5 `pkg` 文件的再导出**不得**穿透私有边界：`_foo` 这类私有符号**不**可被 `pkg` 文件以 `name.*` 形态再导出。经模块 / 包别名调用私有函数同样报错（[E6003] / [E6004] / [E6006]）。

### §10.3.3 嵌套模块：无可见性下沉

§10.3.3.1 v1 **无**可见性下沉。每个 `.yux` 文件是独立的可见性单元：

- 父包**不能**看见子模块的 `_` 前缀项；
- 子模块**不能**看见父模块的 `_` 前缀项；
- 嵌套的公开项通过别名链（`a.b.c.fn()`）或 `pkg` 再导出到达调用方，**不**自动提升为父包的公开成员。

§10.3.3.2 `_` 前缀只作用于**声明名**（§10.3.2），**不**作用于模块路径段。名为 `_helper.yux` 的文件或 `_helper/` 目录**不是**因下划线而私有：无 `pkg` 时仍可被 `use` / 默认别名导出。有 `pkg` 时包级私有靠清单：未公开列出的子模块对包外不可见（§10.2.4.6），可用 `to` 定向开放给指定包 / 模块。仍**不**引入 `pub` / `private`。

## §10.4 SDK 与 `base.yux`

### §10.4.1 `yux.core` 模块

§10.4.1.1 `sdk/yux/` 是 yux 的内置 SDK，作为库项目（`[lib] type="static"`）发布。其源在 `sdk/yux/src/yux/core/*.yux`，逻辑模块名 `yux.core`。

§10.4.1.2 `yux.core` 包含 `base.yux`（约定俗称）：定义内置类型（`i32` / `f64` / `bool` / `String` / `Array<T>` / `Rc<T>` / `Weak<T>` / `Nullable<T>` / `StringBuilder` / `Ptr`）的占位声明、内置方法签名与部分用户态实现。

§10.4.1.3 编译器把 `yux.core` 设为每个用户模块的 parent scope：本模块未命中的符号回退到 SDK（等价于隐式 `use yux.core.*`）。源文件仍**可以**显式写出 `use yux.core.*`（不重复加载，§10.4.3.2）。`_` 前缀的 SDK 符号仍受 §10.3.2 约束（如 `_ptr_offset` → [E6023]）。

§10.4.1.3.1 SDK 公开面以 `sdk/yux/src/yux/core/pkg` 为准（§10.2.4）。core 下每个 `.yux` **仍加载**（同包测试、链接需要）。对**用户** parent scope：

| pkg 行 | 扁平进 `yux.core`（隐式 `use yux.core.*`） | 登记 `stem` 别名与 `yux.core.<stem>` |
|---|---|---|
| 公开 `name.*` | 是（该子模块公开成员） | 是（`map.Map` 与扁平 `Map` 并存） |
| 公开 `name` / `name as alias` | 否 | 是（`math.abs`；有 `as` 则用导出名） |
| 未列出，或仅 `to` | 否 | 否 |

扁平进 `yux.core` 的成员也可写 `yux.core.name`（如公开 `base.*` 中的 `yux.core.println`），解析到 SDK 壳的通配导入。`helper to yux.io` 的 Win32 内部模块只给 `yux.io` 与 core 同包模块使用，不进用户 parent scope；用户不能以裸名或 `yux.core.GetStdHandle` 访问其中声明。

**不**登记 `io`，也**不**把 `yux` 做成可点任意子包的根。`yux.io` 见 §10.4.1.4。

用户项目写 `use yux.core.math` / `use yux.core.map.*` 只命中**已对用户登记**的 SDK 模块（§10.4.5.1），**不**在用户源根查找 `<src>/yux/core/…`。未登记的 `yux.core.<stem>` → [E5018]。

§10.4.1.4 独立包 `yux.io`：源文件 `sdk/yux/src/yux/io.yux`（文件模块，**不是** `io/` 目录）。公开 `enum IoErr`（`Eof` / `NotFound` / `AccessDenied` / `InvalidUtf8` / `Other(u32)`）、`read_line() String ! IoErr`、`read_file` / `write_file` / `append_file`、`exists` / `remove` / `remove_all` / `mkdir` / `list_dir` / `cwd` / `env`、路径 `join` / `dirname` / `basename` / `abs`、类型 `is_dir` / `is_file` / `is_link`、链接 `symlink` / `hardlink` / `junction`。路径 UTF-16；文件内容 UTF-8。`read_line` 遇 EOF 为 `IoErr::Eof`。`eprint` / `eprintln` 仍在 `base.yux`。

| 函数 | 返回 | 说明 |
|---|---|---|
| `exists(path String&)` | `bool` | 路径是否存在（文件或目录） |
| `remove(path String&)` | `! IoErr` | 删文件；失败再试删空目录 |
| `mkdir(path String&)` | `! IoErr` | 建一层目录；已存在报错 |
| `list_dir(path String&)` | `Array<String> ! IoErr` | 列出目录项名字（不含 `.` / `..`） |
| `cwd()` | `String ! IoErr` | 当前工作目录 |
| `env(name String&)` | `String?` | 环境变量；未定义 → `null` |
| `join(a String&, b String&)` | `String` | 拼接路径；缺分隔符时插入 `\` |
| `dirname(path String&)` | `String` | 父路径；无分隔符 → `"."` |
| `basename(path String&)` | `String` | 最后一段；空路径 → `""` |
| `abs(path String&)` | `String ! IoErr` | 绝对路径（`GetFullPathNameW`）；目标不必存在 |
| `is_dir(path String&)` | `bool` | 存在且带目录属性（含 junction） |
| `is_file(path String&)` | `bool` | 存在且不带目录属性 |
| `is_link(path String&)` | `bool` | 存在且为 reparse point（软链 / junction） |
| `remove_all(path String&)` | `! IoErr` | 递归删除；reparse 只删链接本身；缺路径成功 |
| `symlink(target String&, link String&)` | `! IoErr` | 软链；`link` 已存在则失败。无权限不自动改 junction |
| `hardlink(target String&, link String&)` | `! IoErr` | 文件硬链；目录 → `Other(1)` |
| `junction(target String&, link String&)` | `! IoErr` | 目录 junction；非目录 → `Other(1)` |

须显式 `use yux.io` 或 `use yux.io.*` 之后才有 `io.xxx` / `yux.io.xxx` / 裸名 `IoErr`（仅 `.*`）。未 use 时用户可有自己的 `src/io.yux` / `use io`，与 SDK 无关。`use yux.io` 与用户模块别名 `io` 并存 → [E2004]。

§10.4.1.5 `map.yux` / `set.yux`（`pkg` 行 `map.*` / `set.*` 扁平进 `yux.core`）：

- 纯 yux `Map<K, V>` 用平行 `Array<K>` / `Array<V>` 线性查找。公开 `make` / `insert` / `get` / `get_or` / `contains` / `remove` / `len` / `is_empty` / `keys` / `values` / `clear`。`insert` 遇已有键覆盖值。`get` / `remove` 未命中返回 `null`（`V?`）；`get_or(key K&, default V) V` 命中时显式复制值，未命中时返回 `default`。
- 纯 yux `Set<T>` 内嵌 `Map<T, bool>` 去重。公开 `make` / `insert` / `contains` / `remove` / `len` / `is_empty` / `keys` / `clear`；`remove` 返回是否实际删除。`keys()` 返回独立克隆，遍历写 `for x in s.keys()`。
- `Map` / `Set` 均为 `#NoCopy`；所有权转移走 `move`。键类型 `K` / `T` 须可 `==`（标量或 `String`）；v1 **不**引入哈希 trait，**不**承诺 O(1)。类型名靠扁平；亦可用 `map.Map` / `set.Set` 或相应的 `yux.core.*` 全限定路径。两者的遍历均不引入 `Iter<T>`。

§10.4.1.6 进程（`base.yux` 扁平进 `yux.core`）：

| 函数 | 返回 | 说明 |
|---|---|---|
| `args()` | `Array<String>` | 当前进程命令行。`[0]` 是可执行文件路径（Windows 下多为绝对路径）；用户实参从 `[1]` 起。实现走 `GetCommandLineW` + `CommandLineToArgvW`（UTF-16 → String，代理对与 `from_c_chars` 同样对非法序列收 U+FFFD）。失败得 `[]`。 |
| `tick_ms()` | `u32` | 自开机起的毫秒（`GetTickCount`）。约 49.7 天回绕；**不**承诺高分辨率或单调时钟。 |
| `exit(code u32)` | `#NoReturn` | 立即终止进程；见 `exit.yux` / DRAFT-错误.md §8.7。 |

`fn main() i32` 作退出码 v1 **不**提供；用户要非零退出调 `exit`。

### §10.4.2 `#Builtin`

§10.4.2.1 `base.yux` 中标 `#Builtin` 的声明由编译器内部合成实现（§11.2）；其余按普通用户代码编译。

§10.4.2.2 SDK 与编译器的版本绑定：任何 ABI / 临时帧 / RC 协议改动**应当**触发 SDK 重 build；CI / 自动构建链路**应当**强制 SDK 与编译器同步重 build（impl log Phase 8d.5）。

### §10.4.3 编译顺序

§10.4.3.1 编译器**应当**在每个用户模块加载前先创建 `yux.core` 的 `FileNode`（隐式占位），使其声明在命名解析中作为兜底空间存在（§10.2.5.1 第 3 步）。

§10.4.3.2 `yux.core` 一旦创建，对一次编译会话**不**重复加载，避免多份 SDK 互相覆盖。

### §10.4.4 用户对内置类型的限制

§10.4.4.1 用户**不得**对内置类型新增方法、重载运算符或修改字段（§7.2.3.5、§9.10）。v1 **不**引入 `extension` / `extend`；窗口见 §12（扩展实现块）。

§10.4.4.2 用户**可以**定义与 `yux.core` 扁平符号同名的本文件顶层声明。裸名走 §10.2.5（L1 盖住 L3）；SDK 侧用路径（`map.Map` / `yux.core.map.Map`）。**不**在声明点禁止与 core 同名。

### §10.4.5 第三方库（v1 不解析）

§10.4.5.1 v1 用户模块只解析 `<src>/...`（§10.1.3.3）。SDK `yux.core` / `yux.io` 由编译器按安装路径特判加载，**不**走用户源根。

§10.4.5.2 v1 **不**解析 SDK 以外的第三方库路径，也**不**在 `yux.toml` 声明依赖。引入路径随 v1.x 包管理。
