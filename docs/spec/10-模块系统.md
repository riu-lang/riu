# §10 模块系统

本章规范 riu 的项目布局、模块导入、命名解析、包级再导出与可见性边界（`pkg` 文件）、可见性，以及与 SDK / `base.ut` 的协作。

## §10.1 项目结构

### §10.1.1 `riu.toml`

§10.1.1.1 项目根由 `riu.toml` 标记。该文件**应当**位于项目根目录。一个 `riu.toml` 描述**一个项目**（身份）和它的**若干产物**（可执行文件 / 库）。项目名**不是**默认输出文件名。

§10.1.1.2 顶层只记录项目身份：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | 字符串 | ✅ | 项目身份（包名）。**不是**默认输出文件名 |
| `version` | 字符串 | ✅ | 版本。v1 只记录，不强制 semver 语法 |

不再有顶层 `entry`、`[lib]`、`[link]`。写出这些字段**应当**报 [E5021]。至少要有一个 `[library]` 或一条 `[[executable]]`，否则报 [E5005]。二者**可以**同时存在，各自编译。v1 **不**定义同 toml 产物互链。

§10.1.1.3 每项目最多一个 `[library]`（普通 TOML 表，**没有** `[library.foo]`）。可执行文件用数组表 `[[executable]]`，可写零到多条。产出文件名（产物 `name` 字段，缺省见下）在同一文件里**应当**唯一（比较时忽略大小写），否则报 [E5008]。产出名**不得**为空、`.`、`..`、含路径分隔符，也**不得**为 Windows 设备名（`nul` / `con` / `aux` / `com1`–`com9` / `lpt1`–`lpt9` 等，忽略大小写、忽略扩展名），否则报 [E5028]。

§10.1.1.4 `[[executable]]`：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | 字符串 | 否 | 输出文件名（无扩展名），兼 `riu build <name>` 的 id。缺省 = 顶层项目 `name`。Windows：`build/<name>.exe` |
| `entry` | 字符串 | ✅ | 含 `fn main` 的源文件，相对源根（§10.1.3）。规则同 §10.1.3.2 |
| `external_links` | 内联表数组 | 否 | 见 §10.1.1.6。缺省 = 空 |

没有 `lib_mod`、没有 `type`。

单 exe 示例（产出名缺省为项目名）：

```toml
name="echo"
version="1.0.0"

[[executable]]
entry="main.ut"
```

`riu build` / `riu build echo` → `build/echo.exe`。

多条时每条都要能区分：

```toml
[[executable]]
name="mytool"
entry="cli.ut"

[[executable]]
name="helper"
entry="helper.ut"
```

§10.1.1.5 `[library]`：最多一份。与 `[[executable]]` 相同的 `name`、`external_links`，再加上库专用字段。没有 `entry`。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | 字符串 | 否 | 输出文件名（无扩展名）。缺省 = 顶层项目 `name` |
| `type` | 字符串 | 否 | `"static"`（缺省）或 `"dynamic"`。其它值报 [E5006] |
| `lib_mod` | 字符串 | ✅ | 本库拥有的模块根，点分路径 `a.b.c`（非法 → [E5033]） |
| `external_links` | 内联表数组 | 否 | 同 executable |

`lib_mod` 决定编进这个库的源：

- 命中包目录（`<src>/a/b/c/`）：该目录树下全部非 `*.test.ut` 的 `.ut`（含子包）。
- 命中文件模块（`<src>/a/b/c.ut`）：该文件，以及它 `use` 闭包里、仍属于本项目源根的模块。
- 同名文件与目录冲突仍走 §10.1.3.4。

SDK：stdlib 的 `lib_mod="riu"` → 编 `src/riu/` 整棵；core 的 `lib_mod="riu.core"` → 编 `src/riu/core/`。`*.test.ut` 仍只归 `riu test`（§11.3.3.2）。toml 见 §10.4.1.1。

输出：

- `type="static"` → `build/<name>.lib`
- `type="dynamic"` → `build/<name>.dll` + 导入库 `build/<name>.lib`（Windows）

库项目示例：

```toml
name="utils"
version="1.0.0"

[library]
type="static"
lib_mod="utils"
```

§10.1.1.6 `external_links`：每个元素是内联表。不是数组、或元素不是表 → [E5031]；缺 `path` → [E5032]。

```toml
external_links=[
  { path="//kernel32" },
  { path="//shell32" },
  { path="./lib/ffi_demo", dll="./lib/ffi_demo" },
]
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `path` | 字符串 | ✅ | 链接输入。必须带 §10.1.1.7 两种前缀之一。**不写**库后缀 |
| `dll` | 字符串 | 否 | 运行时动态库，前缀规则与 `path` 相同，同样不写后缀。有则链接完成后**复制**到该产物输出目录（与 exe / dll 同级）。不做 delay-load |

数组顺序**应当**即传给链接器的参数顺序。

§10.1.1.7 `path` / `dll` 两种前缀（无前缀、其它前缀 → [E5026]）：

| 前缀 | 含义 | 配置写法 |
|---|---|---|
| `//` | 系统库 | `//kernel32`：名字本身，无后缀、无 `lib` 前缀。交给该目标链接器按系统规则搜 |
| `./` | 本项目文件 | 相对**项目根**的目录 + 逻辑名，如 `./lib/ffi_demo`。指向的是 stem，不是已带后缀的文件 |

`path` / `dll` **不得**写出库后缀（`.lib` `.dll` `.so` `.a` `.dylib`）。写出 → [E5027]。

驱动按**当前链接目标**补文件名。v1 落地 Windows / COFF：`path` 试探 `<stem>.lib`；`dll` 试探 `<stem>.dll`。`//` 不在项目树里找文件：Windows 传 `<name>.lib` 走默认 libpath。一条都找不到 → 链接错误。ELF / Mach-O 的试探顺序与 rpath / `$ORIGIN` 见 [#10](prop/10-multi-target.md)，不在本条写死。

§10.1.1.8 `dll` 只复制，不改链接方式：`path` 仍是传给链接器的导入库 / 静态库；`dll` 是跑起来要能找到的那份文件。目标已存在且内容相同**可以**跳过；复制失败 → 非零退出。系统目录里的 `//` 可省略 `dll`（加载器自己找）。

§10.1.1.9 链接一个产物时并入：

1. 它自己的 `external_links`；
2. 依赖图中全部库的 `.lib`，以及它们的 `external_links`（静态库传递：用户 exe 链 core / stdlib 时带上各包声明的 `//kernel32` 等，含 `dll`）；
3. 编译器自带的 `riurt`（运行时，**不**写进 toml）。

驱动**不得**再写死 `kernel32.lib` / `shell32.lib`。hello-world 只 `println`、自己没有 `external_links` 时，从隐式 core 传递过来。`use riu.io` 等还要把 stdlib 的链接声明带上（stdlib 须在图中，§10.4.1.1）。

§10.1.1.10 其它项目级段（不是产物）：

| 段 | 说明 |
|---|---|
| `[fmt]` | `line_width` 整数；`riu format` 向上查找 toml。语义不变 |
| `[dependencies]` | 三方 / 跨项目 / 工具链 SDK 包。见 §10.1.1.12 |

§10.1.1.11 `name` 的 UTF-8 字符串内容由实现解析（v1 `toml11` 原生支持中文）。顶层 `name` 仍**不得**恰好为 `_`（丢弃名，[E3161]）。

§10.1.1.12 `[dependencies]`：项目级段。无此段 = 无显式依赖（core 仍隐式，§10.4.1.1）。依赖是**钉死版本的源码**（一个含 `riu.toml` + `[library]` 的 riu 项目）。`.ud` / `.lib` 是本机构建缓存，不是下载物。一条依赖恰好一种来源：

```toml
name="echo"
version="1.0.0"

[dependencies]
stdlib = { sdk = "stdlib" }
utils = { path = "../utils" }
http = { git = "https://example.com/http.git", rev = "a1b2c3d4e5f6789012345678901234567890abcd" }

[[executable]]
entry="main.ut"
```

| 约束 | 规则 |
|---|---|
| 表键 | = 对方顶层 `name`。不一致 → [E5037] |
| 来源 | `sdk` / `path` / `git` 恰好一个。混写 → [E5034]；缺来源 → [E5035] |
| `sdk` | 字符串，工具链包目录名。查找：相对 riu.exe → `.../sdk/<id>/`。`sdk="core"` → [E5036] |
| `path` | 相对**本项目根**（可绝对）。目标必须含 `riu.toml` 且有 `[library]` |
| `git` | 仓库 URL。`rev` 必填且须成对（缺一 → [E5042]） |
| `rev` | 完整 40 位十六进制 commit。非此格式 → [E5044]。不写 branch / tag |
| 形态 | 依赖必须是库项目；exe-only → [E5038]。v1 **不**写 `dir`（[E5039]）：`riu.toml` 必须在源根。未知键 → [E5040] |

递归读每包自己的 `[dependencies]` 构成有向图。**同一 `name` 只能有一个钉死源**（同一 `sdk` id，或同一规范化 `path`，或同一 `git` URL + `rev`）。冲突 → [E5041]。

`use` 可写图中任一包的 `lib_mod` 前缀（含传递）。未进图的模块路径 → 找不到。调用方**不**把依赖源扫进自己的 `src/`。

git：检出到调用方 `build/dependences/<name>/`（§10.1.1.13）。已存在且 HEAD 即为该 `rev` 则跳过网络。检出当不可变；目录在但被改过 → [E5043]。clone / fetch / checkout 失败 → **随 git 报错**（透传 stderr 与退出码，非零退出），不另发明文案。不进版本库。v1 无 `riu fetch`。

v1 **不**做：中心仓库、semver 区间、lockfile、`{ sdk = "core" }`、浮动 branch / 仅 tag、git `dir`、限制 `use` 仅直接依赖、全局缓存。

§10.1.1.13 本次 `riu build` 所在项目的 `build/` 是唯一写入树。根项目自己的最终产物、中间产物路径不变（§10.1.2.1）。依赖另两层，都在调用方 `build/` 下：

| 层 | 路径 | 内容 |
|---|---|---|
| git 源码 | `build/dependences/<name>/` | 按 `rev` 检出的树（仓库根即项目根）。**不写** obj / `.lib` / `.ud` |
| 依赖产物 | `build/deps/<name>/` | 该包的 `.lib` / `.dll`、obj、`.ud`、`.cache`。布局相对**该包项目根**镜像，与根项目 `build/` 对 `src/` 的规则相同 |

`<name>` = 包顶层 `name`（与 toml 表键相同）。依赖库文件：`build/deps/<name>/<library.name>.lib`。Unix 上的库后缀随 [#10](prop/10-multi-target.md)，本条不写死。

例：调用方声明了 stdlib 与一个 git 包 `http`：

```
build/
├── echo.exe
├── src/                  ; 本项目中间产物（§10.1.2.1）
├── tests/                ; 现行
├── dependences/
│   └── http/             ; git 源码 only
└── deps/
    ├── core/             ; 隐式 core 不新鲜时落在这里
    │   └── riu.core.lib
    ├── stdlib/
    │   └── riu.lib
    └── http/
        └── http.lib
```

按来源，**源码**从哪读、**产物**写哪：

| 来源 | 读源码 | 写产物 |
|---|---|---|
| 本项目（根） | 自己的 `src/` | 自己的 `build/`（§10.1.2.1） |
| `sdk` | 工具链 `sdk/<id>/`（不拷贝） | 见下：新鲜则直接链工具链产物，否则编进调用方 `build/deps/<id>/` |
| `path` | 该目录（不拷贝） | 调用方 `build/deps/<name>/`。增量按**对方源文件 mtime**（规则同本项目 `.cache`） |
| `git` | `build/dependences/<name>/` | 调用方 `build/deps/<name>/` |
| core（隐式） | 工具链 `sdk/core/` | 同 sdk |

**禁止**把本次构建的 obj / `.lib` / `.ud` 写入：git 检出（`build/dependences/` 内）、path 指向的那个项目自己的 `build/`、工具链 `sdk/<id>/`（用户构建当只读；短路只**读**其已有 `build/`）。

**sdk 短路（允许）**：工具链该包自己的 `build/<library.name>.lib` 相对其源码新鲜（按源 mtime / 现行 freshness）→ 链接器直接用这份，不在调用方 `build/deps/<id>/` 再编。不新鲜或缺失 → 从工具链源码编进 `build/deps/<id>/`。不改安装树。

该包**自己就是根**（`cd sdk/stdlib && riu build`，或 `cd ../utils && riu build`）时走 §10.1.2.1：产物在**自己的** `build/`。别人消费它时不读、不写它的 `build/`（sdk 短路除外），在消费者 `build/deps/<name>/` 再编一份（隔离；两份缓存可以并存）。

`riu test` 仍只跑**当前根**的 `*.test.ut`，产出 `build/tests/`。不自动跑依赖的测试。清掉 `build/` = 清掉本图全部缓存（含 git 检出）。

`riu build` / `riu test` / `riu format` 子命令不变。构建根项目前：解析图 → 缺的 git 检出（失败随 git）→ 按依赖序：sdk 新鲜则直接链，否则与 path/git 一样编进 `build/deps/<name>/` → 再编根产物。

### §10.1.2 项目模式与单文件模式

§10.1.2.1 *项目模式*（推荐）：以 `riu.toml` 为根。命令 `riu build [<name>]` **应当**在 `riu.toml` 所在目录执行。

- 省略 `<name>`：驱动**应当**编本项目全部产物：先 `[library]`（若有），再按声明顺序所有 `[[executable]]`。
- 写出 `<name>`：驱动**应当**按产物产出名匹配（某条 `[[executable]]`，或 `[library]`）。缺省时产出名 = 顶层项目 `name`，所以单产物项目 `riu build` / `riu build <项目名>` 仍都能用。未知名 → 非零退出。exe 与库的产出名撞车已是配置错误（[E5008]）；v1 不搞 `--lib` / `--bin` 消歧。
- `riu build --test` / `riu test` 仍按 §11.3 扫 `*.test.ut`，不在 toml 里再开 `[[test]]`。

最终产物落在 `<projectRoot>/build/`：executable `name="echo"` → `build/echo.exe`；library static `name="riu"` → `build/riu.lib`；library dynamic `name="foo"` → `build/foo.dll` 与导入库 `build/foo.lib`。中间产物 obj / IR 镜像源文件相对项目根的路径放在 `<projectRoot>/build/<src-rel>.obj`（典型 `<projectRoot>/build/src/<rel>.obj`）；每个目录视为一个包，目录内所有 `.ut` 的元信息聚合到该目录下的 `<dirname>.cache` 增量缓存。SDK 自构建探测认顶层 `name=="core"` / `"stdlib"`。依赖的 git 源码与编译产物见 §10.1.1.13（`build/dependences/`、`build/deps/`）。

§10.1.2.2 *单文件模式*（v1 已弃用）：忽略 `riu.toml`，产物扁平放在源文件目录。新增代码、示例、文档**应当**一律走项目模式。

### §10.1.3 源根 `src/`

§10.1.3.1 项目模式下的**源根**（source root）是模块 / 包的解析起点：

- 若 `<projectRoot>/src/` 存在且为目录，源根 = `<projectRoot>/src/`；
- 否则源根回退为 `<projectRoot>/`。

§10.1.3.2 `[[executable]]` 的 `entry` 字段是相对源根的路径（典型 `main.ut` 表示 `<src>/main.ut`）。

- `entry` **不得**为绝对路径，否则报 [E5013]。
- 解析 (`canonical`) 后 `entry` 仍**应当**位于 `<src>/` 子树内；逃出源根（典型形态 `../foo.ut`）默认报 [E5014] warning（约定违例 + obj 镜像路径可能走样）。可通过 `--Werror` / `--deny=E5014` 升级为 error。

§10.1.3.3 模块 `a.b.c` 解析为以下之一（按存在性顺序）：

- `<src>/a/b/c.ut`（文件模块）；
- `<src>/a/b/c/`（包模块，配合 `pkg` 文件，§10.2.4）。

§10.1.3.4 同名 `.ut` 文件与同名子目录并存属冲突，编译器**应当**报错。

### §10.1.4 项目结构示例（informative）

```
myproject/
├── riu.toml
└── src/
    ├── main.ut
    ├── math.ut
    └── ops/
        ├── pkg              ; 包再导出清单（§10.2.4）
        ├── add.ut
        └── sub/
            └── inner.ut
build/
├── myproject.exe              ; 最终产物（exe / lib）
└── src/                       ; 中间产物：镜像 src/ 目录树
    ├── main.obj
    ├── math.obj
    ├── src.cache              ; 顶层"src 包"的增量缓存
    └── ops/
        ├── add.obj
        ├── ops.cache          ; ops 包缓存（覆盖 add.ut 与 sub/ 包之外的 ops/ 直系源）
        └── sub/
            ├── inner.obj
            └── sub.cache
```

§10.1.4.1 缓存文件 `<dir>/<dirname>.cache` 第 1 行为编译器指纹（当前 `riu.exe` 的 mtime+size，TAB 分隔）；后续每行为 `<filename>\t<src-mtime-ns>\t<src-size>`。指纹不匹配即整个文件作废，触发该包内全量重编。

## §10.2 模块导入

### §10.2.1 形态

```
imports ::= 'use' typePath ('.' '*')? codeLineEnd
```

§10.2.1.1 `use` 形态：

| 写法 | 语义 | 章节 |
|---|---|---|
| `use a.b.c` | 把路径末段 `c` 登记为模块 / 包别名；其后用 `c.member`（包则 `c.child.member`） | §10.2.2 |
| `use a.b.*` | 按文件模块扁平、或按 `pkg` / 无 `pkg` 默认规则展开到当前命名空间；同时登记末段别名 `b` 与已 use 的路径前缀 | §10.2.3 |
| `use a.b.MyType` | 先当模块路径；不存在则把父模块 `a.b` 的公开类型 `MyType` 注入裸名（L2） | §10.2.2.3 |

§10.2.1.2 `use` **应当**出现在源文件顶部 `LineEnd*` 之后、其它顶层声明之前（`riu.bnf` 的 `program`：`imports*` 不能与 `fn` / `struct` 等交错）。`imports` 之间可以有空行。

### §10.2.2 命名导入（非通配）

§10.2.2.1 `use a.b.c` **不**把目标成员注入当前命名空间；只把路径末段 `c` 登记为别名：

- 命中 `<src>/a/b/c.ut`（文件模块）：`c` 为模块别名，调用方写 `c.member`；
- 命中 `<src>/a/b/c/`（包模块）：`c` 为包别名，调用方写 `c.child.member`（含子目录链，如 `ops.sub.inner.fn()`，`tests/projects/imports_package_chain` / `imports_deep_nesting`）。有 `pkg` 时 `child` 须对该调用方可见（§10.2.4）；
- 同名 `.ut` 与目录并存 → [E2003]（§10.1.3.4）。

§10.2.2.1.1 别名与当前文件已有本地符号冲突 → 导入时报 [E2004]。

§10.2.2.1.2 **不得**经 `use a.b.c`（目标是模块 / 包）用裸名访问目标成员。裸名只来自：当前文件自己的声明、`use path.Name` 的具名类型注入（§10.2.2.3）、`use ...*` 的扁平注入（§10.2.3），以及默认 `riu.core.*` 回退（§10.4.1.3）。

§10.2.2.2 例（`tests/projects/imports_module_alias`）：

```riu
use math
fn main() {
    println(math.square(7))
}
```

§10.2.2.3 `use a.b.MyType`：先按模块路径解析 `a.b.MyType`（文件 / 包）。若不存在，且父路径 `a.b` 是已有模块、末段 `MyType` 是其公开类型（`struct` / `enum` / 别名，非 `_` 前缀），则把 `MyType` 注入当前文件裸名（L2 具名导入），并登记路径前缀以便写 `a.b.MyType`。例：`tests/projects/named_type_import`。

### §10.2.3 通配导入

§10.2.3.1 `use a.b.*` 的展开因目标是文件还是包而不同：

- 若 `a.b` 是文件模块（`<src>/a/b.ut`）：把该文件的全部**公开**顶层声明（`fn` / `struct` / `enum` / 类型别名 / spec / 全局 `let`；`_` 前缀除外）注入当前模块，可裸名使用；
- 若 `a.b` 是包模块（`<src>/a/b/`）：按 `pkg` 文件展开（§10.2.4）；只展开对该调用方可见的项（公开项，以及 `to` 名单含该调用方的定向项）。

§10.2.3.1.1 若包目录**不含** `pkg` 文件，语义**等价于** `pkg` 文件中按文件名排序逐行列出所有 `.ut` 子模块（`name` 形式，**不做** `name.*` 扁平再导出）及子目录。即调用方通过 `use pkg.*` 后以 `child.fn()` 访问各子模块成员，不能直接用裸名 `fn()`。此即 2026-06-29 决议保留的「无 `pkg` 默认别名导出」，不是扁平。

§10.2.3.2 仅文件模块通配、以及 `pkg` 的 `name.*` 扁平再导出，公开成员可裸名使用。包通配的 `name` 形态仍走子模块前缀（§10.2.3.1.1）。

### §10.2.4 `pkg` 文件（包再导出与可见性边界）

§10.2.4.1 包目录可含一个**无后缀**的纯文本文件 `pkg`，描述该包的再导出清单。目录**有** `pkg` 时，清单同时是**包外**可见性边界（§10.2.4.6）：未列出的子模块对包外不可见。目录**没有** `pkg` 时走 §10.2.3.1.1，不设清单门控。

§10.2.4.2 `pkg` 文件每行一条导出项。`as` 与 `to` 都可选。语法如下：

| 行形态 | 语义 |
|---|---|
| 空行 / 仅空白 | 忽略 |
| `;...` 注释行 | 忽略（行首 `;`，与 riu 注释一致） |
| `name` | **公开**：把同包下的子模块 `name`（文件 `name.ut` 或子目录 `name/`）以导出名 `name` 再导出 |
| `name.*` | **公开**：把子模块 `name` 的全部公开成员扁平再导出到该包名空间。不做 `name.* as` / `name.* to` |
| `name as alias` | **公开**：把子模块 `name` 以导出名 `alias` 再导出；调用方以 `alias.member` 访问，不能再用 `name` |
| `name to t1; t2; …` | **定向开放**：仅所列目标可用导出名 `name` |
| `name as alias to t1; t2; …` | **定向开放**：仅所列目标可用导出名 `alias`（不能再用 `name`） |

§10.2.4.2.1 `;`：行首 `;`（trim 后）仍是整行注释。无 `to` 的行仍允许行尾 `;` 注释（如 `add.*    ; 扁平`）。**带 `to` 的行**上 `;` **只**当目标分隔，不再支持行尾注释。

§10.2.4.2.2 `to` 后面是**全限定**包名或模块名，`;` 分隔。每个目标**应当**在当前项目源树或已加载依赖里真实存在（含 SDK：`riu.core` / `riu.io` / `riu.time`，以及已加载的 `riu.core.<stem>`）。不存在 → [E5019]。

§10.2.4.2.3 非法行**应当**报 [E5020]，**不得**静默跳过：

- `name.* to …`、`name.* as alias`（及二者组合）；
- 同一子模块出现多于一行（不能既公开又 `to`，也不能两行公开）；
- 带 `to` 但目标列表为空。

§10.2.4.3 目录是否为包模块由是否存在该目录决定（§10.1.3.3），与有无 `pkg` 无关。

- **无** `pkg`：走 §10.2.3.1.1。包外仍可 `use a.c` / `a.c.xxx`。
- **有** `pkg`：包外**只能**走清单。未列出的子模块（例：`a/c.ut` 而 pkg 只有 `b`）不能 `use a.c`、也不能 `a.c.xxx` → [E5018]。`use <pkg-path>.*` 只展开对该调用方可见的项。非通配 `use <pkg-path>` 仍把该目录登记为包别名，但点链孩子同样受清单门控。

§10.2.4.4 例（`tests/projects/pkg_wildcard_export/src/mymath/`）：

```
; src/mymath/pkg
add.*    ; 把 add 模块的所有公开成员扁平导出
sub      ; 把 sub 模块作为别名导出
```

调用方：

```riu
use mymath.*
fn main() {
    println(add(10, 5))     ; add 来自 add.ut，扁平
    println(sub.sub(10, 5)) ; sub 作为别名，需 sub.sub
}
```

§10.2.4.4.1 重命名导出例（`tests/projects/pkg_rename_export/src/mymath/`）：

```
; src/mymath/pkg
add as addition    ; 把 add 模块以 addition 别名导出
sub.*              ; 把 sub 模块的所有公开成员扁平导出
```

调用方：

```riu
use mymath.*
fn main() {
    println(sub(10, 3))          ; sub 来自 sub.ut，扁平
    println(addition.add(7, 2))  ; add 模块以 addition 别名访问
}
```

§10.2.4.4.2 定向开放例（informative）：

```
; src/a/pkg
b
c as xxx to riu.io; other.mod
```

- 包外普通调用方：可用 `b`；不能 `a.c` / `use a.c` / `a.xxx`。
- `riu.io` 与 `other.mod`：写 `use a.xxx` / `a.xxx.f()`；不能再写 `a.c`。

§10.2.4.5 `pkg` 文件**只读**，不参与编译；其语法独立于 `.ut`，仅在模块解析阶段被读取。

§10.2.4.6 一个目录可同时含 `pkg` 文件与 `.ut` 文件 / 子目录。有 `pkg` 时：

| 调用方 | 相对该 `pkg` | 清单 |
|---|---|---|
| 同目录兄弟 `.ut` | **包内** | 不受挡，互相可直接用未列出的子模块 |
| 子目录包 / 别的包 / 用户代码 | **包外** | 只认清单：公开项对所有包外可见；`to` 项只对名单内的目标可见 |

包外**不得**以全名 `pkg.sub` 钻未导出子模块。无 `pkg` 时不设此边界。

§10.2.4.7 友方与公开调用方一样，只认 `pkg` 给出的**导出名**。`c as xxx` 或 `c as xxx to …` 时写 `xxx`，不能写源名 `c`。未改名的公开 / 定向项用 `name` 本身。

### §10.2.5 命名解析

§10.2.5.1 裸名 `N`（单独一个 `ID`）按层查找。**同一层**内按声明身份（声明模块 + 短名）去重：同一声明经两条 `use` 进来只算一个。该层去重后 0 个则看下一层；1 个则用它；>1 → [E5015]（列出候选）。上层盖住下层；被盖住的仍可用路径 / 全限定引用。

| 层 | 来源 |
|---|---|
| L0 | 内层局部 / 参数 |
| L1 | 本文件顶层 `fn` / `struct` / `enum` / 别名 / 全局 `let` |
| L2 | 具名导入：`use path.Name`（§10.2.2.3） |
| L3 | 通配：`use x.*`、`use riu.io.*`、默认 `riu.core.*` |

§10.2.5.2 对照：

| 导入 | 裸名 `Ty` |
|---|---|
| `use a.*` + `use b.Ty` | `b.Ty`（L2 压过 L3）；`a.Ty` / `b.Ty` 路径仍合法 |
| `use a.Ty` + `use b.Ty` | [E5015]（L2 两个具名） |
| `use a.*` + `use b.*`（都导出 `Ty`） | [E5015]（L3 两个通配） |
| 本文件 `struct Ty` + 任何导入的 `Ty` | 本文件的（L1） |
| 本文件 `struct Map` + 默认 core `Map` | 本文件的；core 用 `riu.core.map.Map` 或 `map.Map` |

§10.2.5.3 路径前缀（`use a.b` 的 `a` / `b`、默认 `math` / `map` / `riu`）是编译期定位符，**不能当值**（[E5016]）。类型不能当值（[E5017]）。路径指向函数（`io.read_file`、`math.abs`）作为函数值合法。`T { }` / `T::f()` / `E::V`（可带路径）合法。

§10.2.5.4 点链首段**既是**已登记路径前缀 **又是**当前作用域的变量 / 参数时 → [E5015]（允许定义，禁止歧义使用）。字段 `obj.b` 永远按接收者查，不占裸名。

§10.2.5.5 全限定不引入未 `use` 的包。`packageChild` 只返回已经 load / `use` 过的子模块。未 `use riu.io` 时 `riu.io.xxx` 非法（[E6001]）；`riu.time` 同。

§10.2.5.6 其它导入期冲突：非通配别名与当前文件本地符号（模块 / 包 / L1 类型 / 函数）冲突 → [E2004]；两个通配贡献同名**模块别名** → 使用点 [E2008]。

### §10.2.6 循环依赖

§10.2.6.1 v1 **禁止**模块间循环依赖：`a use b` 且 `b use a`（直接或传递）**应当**编译报错 [E5011]，错误信息**应当**给出环路（`a -> b -> a`）。

§10.2.6.2 该约束允许编译器按拓扑序逐模块编译。v1 **不**引入 forward 声明放宽此限制。若将来放宽，与 v1.x 包管理同期设计。

## §10.3 可见性

### §10.3.1 默认可见性

§10.3.1.1 顶层声明（`fn` / `struct` / `enum` / 类型别名 / spec / 全局 `let` / `extern` 块）默认**公开**：可被其它模块通过 `use` 导入。

§10.3.1.2 riu **不**引入 `pub` / `private` 等可见性修饰符（永久决议）。声明可见性靠命名约定（§10.3.2）；子模块对包外的可见性靠有无 `pkg` 清单（§10.2.4）。

### §10.3.2 `_` 前缀私有

§10.3.2.1 以下划线 `_` 开头的标识符为**私有**：仅在当前模块（同一 `.ut` 文件）可见，跨模块访问**应当**编译报错。恰好 `_` **不是**私有标识符，是丢弃槽（§1.4.3.1），不适用本节。

§10.3.2.2 适用范围：

- 顶层 `fn`（如 `fn _internal_helper()`）；
- 顶层 `struct`（如 `struct _State`）；
- 全局 `#Cval let`（如 `#Cval let _MAX_RETRIES i32 = 3`）；
- 结构体方法、字段（同模块外不可见）。

§10.3.2.3 编译器内部使用的 runtime helper（如 `_box_alloc` / `_array_grow` / `_ptr_offset`）也**应当**遵循该前缀约定（§8 / impl log）。

§10.3.2.4 `_` 前缀**不**影响同一模块内的可见性；同模块内可自由调用。

§10.3.2.5 `pkg` 文件的再导出**不得**穿透私有边界：`_foo` 这类私有符号**不**可被 `pkg` 文件以 `name.*` 形态再导出。经模块 / 包别名调用私有函数同样报错（[E6003] / [E6004] / [E6006]）。

### §10.3.3 嵌套模块：无可见性下沉

§10.3.3.1 v1 **无**可见性下沉。每个 `.ut` 文件是独立的可见性单元：

- 父包**不能**看见子模块的 `_` 前缀项；
- 子模块**不能**看见父模块的 `_` 前缀项；
- 嵌套的公开项通过别名链（`a.b.c.fn()`）或 `pkg` 再导出到达调用方，**不**自动提升为父包的公开成员。

§10.3.3.2 `_` 前缀只作用于**声明名**（§10.3.2），**不**作用于模块路径段。名为 `_helper.ut` 的文件或 `_helper/` 目录**不是**因下划线而私有：无 `pkg` 时仍可被 `use` / 默认别名导出。有 `pkg` 时包级私有靠清单：未公开列出的子模块对包外不可见（§10.2.4.6），可用 `to` 定向开放给指定包 / 模块。仍**不**引入 `pub` / `private`。

## §10.4 SDK 与 `base.ut`

*informative*：本节省加载图与 **`riu.core`** 公开面。stdlib（`riu.io` / `riu.time` / `riu.platform` 等）的类型与方法以 `sdk/stdlib` 源码为准，**不再写入本规范**；既有 §10.4.1.4 / §10.4.1.7 为历史条款。提案 / spec 范围见 [index](index.md)。

### §10.4.1 `riu.core` 模块

§10.4.1.1 SDK 拆成安装树下的独立项目，各一份 `riu.toml`、各一份 `[library]`（§10.1.1.3）。查找 `{ sdk = "<id>" }`：相对 riu.exe → `.../sdk/<id>/`。

| 目录 | 顶层 `name` | `[library].name` | `lib_mod` | 产物文件 |
|---|---|---|---|---|
| `sdk/core/` | `core` | `riu.core` | `riu.core` | `riu.core.lib` |
| `sdk/stdlib/` | `stdlib` | `riu` | `riu` | `riu.lib` |

**core 隐式**：始终进图，toml **不得**声明 `{ sdk = "core" }`（[E5036]）。parent scope、隐式 `use riu.core.*` 不变（§10.4.1.3）。**stdlib 显式**：与 path / git 一样走 `[dependencies]`；须本包声明，或由传递依赖带进图，才能 `use riu.io` / `riu.time` / `riu.platform.*`。hello-world 只 `println` 可以不声明 stdlib。v1 **不**建空 `sdk/net/`。

```toml
; sdk/core/riu.toml
name="core"
version="1.0.0"

[library]
name="riu.core"
type="static"
lib_mod="riu.core"
external_links=[
    { path="//kernel32" },
    { path="//shell32" },
]
```

```toml
; sdk/stdlib/riu.toml
name="stdlib"
version="1.0.0"

[library]
name="riu"
type="static"
lib_mod="riu"
external_links=[
    { path="//kernel32" },
    { path="//shell32" },
]
```

stdlib **依赖 core**，写法与普通项目相同：**不写** `{ sdk = "core" }`。core 由编译器注入。各包自己的 `external_links` 传到用户 exe（§10.1.1.9）。


§10.4.1.2 `riu.core` 包含 `base.ut`（约定俗称）：定义内置类型（`i32` / `f64` / `bool` / `String` / `Array<T>` / `Rc<T>` / `Weak<T>` / `Nullable<T>` / `StringBuilder` / `Ptr`）的占位声明、内置方法签名与部分用户态实现。

§10.4.1.3 编译器把 `riu.core` 设为每个用户模块的 parent scope：本模块未命中的符号回退到 SDK（等价于隐式 `use riu.core.*`）。源文件仍**可以**显式写出 `use riu.core.*`（不重复加载，§10.4.3.2）。`_` 前缀的 SDK 符号仍受 §10.3.2 约束（如 `_ptr_offset` → [E6023]）。

§10.4.1.3.1 SDK 公开面以 `sdk/core/src/riu/core/pkg` 为准（§10.2.4）。core 下每个 `.ut` **仍加载**（同包测试、链接需要）。对**用户** parent scope：

| pkg 行 | 扁平进 `riu.core`（隐式 `use riu.core.*`） | 登记 `stem` 别名与 `riu.core.<stem>` |
|---|---|---|
| 公开 `name.*` | 是（该子模块公开成员） | 是（`map.Map` 与扁平 `Map` 并存） |
| 公开 `name` / `name as alias` | 否 | 是（`math.abs`；有 `as` 则用导出名） |
| 未列出，或仅 `to` | 否 | 否 |

扁平进 `riu.core` 的成员也可写 `riu.core.name`（如公开 `base.*` 中的 `riu.core.println`），解析到 SDK 壳的通配导入。未在 pkg 公开列出、或仅 `to` 定向开放的 core 子模块不进用户 parent scope。

**不**登记 `io` / `time`，也**不**把 `riu` 做成可点任意子包的根。`riu.io` 见 §10.4.1.4；`riu.time` 见 §10.4.1.7。

用户项目写 `use riu.core.math` / `use riu.core.map.*` 只命中**已对用户登记**的 SDK 模块（§10.4.5.1），**不**在用户源根查找 `<src>/riu/core/…`。未登记的 `riu.core.<stem>` → [E5018]。

§10.4.1.4 独立包 `riu.io`（stdlib）：源文件 `sdk/stdlib/src/riu/io.ut`（文件模块，**不是** `io/` 目录）。图中须有 `stdlib`（本包声明或传递，§10.4.1.1）。路径在 Win32 边界编码为 UTF-16；文本文件内容按 UTF-8 编解码。`IoErr` 公开 `Eof` / `NotFound` / `AccessDenied` / `InvalidUtf8` / `Closed` / `Other(u32)`；`Closed` 表示在显式关闭后继续读、写或刷新文件流。`read_line` 遇 stdin EOF 为 `IoErr::Eof`，文件流读到 EOF 则成功返回空数组。`eprint` / `eprintln` 仍在 `base.ut`。

文件 API 分为五个公开类型：

| 类型 | 职责 | 资源 / 复制语义 |
|---|---|---|
| `Path` | 纯路径值；构造、拼接、分解和绝对化 | 不访问磁盘，可复制；内部路径字段为 `#Val` |
| `File` | 一个路径所指向的文件系统条目；查询、列举和删除 | 不持有句柄，可复制；构造不要求条目存在 |
| `FileInfo` | `File.info()` 时取得的属性快照 | 可复制；`kind` / `size` / `readonly` / `mtime` 均为 `#Val` |
| `FileInputStream` | 持有只读文件句柄及当前位置 | `#NoCopy`，只能显式 `move` 转移 |
| `FileOutputStream` | 持有只写文件句柄及当前位置 | `#NoCopy`，只能显式 `move` 转移 |

`Path` 公开 `from(raw String&)` / `cwd()`、`to_string()` / `join(child String&)` / `parent()` / `name()` / `extension()` / `stem()` / `with_extension(ext String&)` / `absolute()` / `is_empty()` / `same_as(other Path&)`；`join` 只做与模块函数 `join` 相同的字符串拼接，不做 canonicalize，`absolute` 的目标不必存在。`same_as` 先绝对化再按大小写不敏感比较；绝对化失败则回退比较原始字符串。`extension` / `stem` / `with_extension` 只看 `basename` 的**最后一个** `.`；`.gitignore` 这类点文件扩展名为 `""`、stem 为整段；`foo.tar.gz` 的 stem 为 `foo.tar`、扩展名为 `gz`。`with_extension("")` 去掉扩展名。`Path` `#Impl(ToString)`。

`FileKind` 为 `Regular` / `Directory` / `Link` / `Other`。`FileInfo.size` 只稳定承诺普通文件的字节数；`FileInfo.mtime` 为最后写入时间的 Unix 秒（`i64`，Win32 `FILETIME`）。`FileInfo` 是快照，不随文件系统自动刷新。`kind` 依次判定 reparse point（含软链和 junction）为 `Link`、目录为 `Directory`、设备为 `Other`，其余为 `Regular`。

`File` 公开 `at(path Path&)` / `from(raw String&)`、`path()` / `to_string()` / `exists()` / `is_dir()` / `is_file()` / `is_link()` / `same_as(other File&)` / `info()` / `list()` / `mkdir()` / `mkdir_all()` / `copy_to(dest File&)` / `rename_to(dest File&)` / `read_bytes()` / `write_bytes(bytes Array<u8>&)` / `remove()` / `remove_all()` / `symlink_to(target File&)` / `hardlink_to(target File&)` / `junction_to(target File&)`。`list()` 返回直接子项的完整路径 `Array<File>`，不递归且不追踪链接；需要裸文件名时仍使用兼容函数 `list_dir()`。`is_dir` / `is_file` / `is_link` 与同名 facade 语义一致（junction 的 `is_dir` 为真，但 `info().kind` 仍为 `Link`）。`mkdir_all` / `copy_to` / `rename_to` / `read_bytes` / `write_bytes` 与同名 facade 一致。链接方法的接收者是要创建的链接，`target` 是指向的条目；行为与 facade `symlink` / `hardlink` / `junction` 相同。`File` `#Impl(ToString)`，文本即路径。

`FileInputStream::open(path Path&)` 打开只读流。`read(max_bytes)` 从当前位置最多返回指定字节数，`max_bytes == 0` 或已到 EOF 均返回空数组；`read_to_end()` 从当前位置读到 EOF；`read_to_string()` 严格按 UTF-8 解码，非法序列返回 `InvalidUtf8`。

`FileOutputStream::create(path Path&)` 创建或截断文件，`FileOutputStream::append(path Path&)` 创建或打开并定位末尾。`write(bytes Array<u8>&)` / `write_string(content String&)` 保证处理短写，空输入成功；`flush()` 调用系统刷新。

两种流均公开 `is_open()` / `close()` 并在析构时 best-effort 关闭。`close()` 幂等；调用后句柄无论系统关闭成功与否都进入关闭态，以免再次操作同一句柄。析构没有错误通道，需观察关闭错误时应显式调用 `close()`。

原有函数 facade 全部保留兼容：`read_file` / `write_file` / `append_file` / `read_bytes` / `write_bytes`、`exists` / `remove` / `remove_all` / `mkdir` / `mkdir_all` / `list_dir` / `cwd` / `chdir` / `env` / `set_env` / `unset_env` / `temp_dir`、路径 `join` / `dirname` / `basename` / `abs` / `extension` / `stem` / `with_extension`、类型 `is_dir` / `is_file` / `is_link`、文件 `copy_file` / `rename`、链接 `symlink` / `hardlink` / `junction`。

§10.4.1.5 `map.ut` / `set.ut`（`pkg` 行 `map.*` / `set.*` 扁平进 `riu.core`）：

- 纯 riu `Map<K, V>` 用平行 `Array<K>` / `Array<V>` 线性查找。公开 `make` / `insert` / `get` / `get_or` / `contains` / `remove` / `len` / `is_empty` / `keys` / `values` / `clear`。`insert` 遇已有键覆盖值。`get` / `remove` 未命中返回 `null`（`V?`）；`get_or(key K&, default V) V` 命中时显式复制值，未命中时返回 `default`。`#Impl(Indexed<K>)`：`at(i)` 返回 `$._keys[i]` 的 `K&`。直接 `for k in m` 走 Indexed，不 clone `keys()`。
- 纯 riu `Set<T>` 内嵌 `Map<T, bool>` 去重。公开 `make` / `insert` / `contains` / `remove` / `len` / `is_empty` / `keys` / `clear`；`remove` 返回是否实际删除。`#Impl(Indexed<T>)`：`at` 转发 `$._items.at(i)`（不碰 Map 的 `_keys`，E3042）。直接 `for x in s` 走 Indexed。`keys()` 仍返回独立克隆快照。
- `Map` / `Set` 均为 `#NoCopy`；所有权转移走 `move`。键类型 `K` / `T` 须可 `==`（标量或 `String`）；v1 **不**引入哈希 trait，**不**承诺 O(1)。类型名靠扁平；亦可用 `map.Map` / `set.Set` 或相应的 `riu.core.*` 全限定路径。遍历走 Indexed（§5.5.4.4 / §12.7.6），**不** `#Impl(Iter)`。

§10.4.1.6 进程（`base.ut` 扁平进 `riu.core`）：

| 函数 | 返回 | 说明 |
|---|---|---|
| `args()` | `Array<String>` | 当前进程命令行。`[0]` 是可执行文件路径（Windows 下多为绝对路径）；用户实参从 `[1]` 起。实现走 `GetCommandLineW` + `CommandLineToArgvW`（UTF-16 → String，代理对与 `from_c_chars` 同样对非法序列收 U+FFFD）。失败得 `[]`。 |
| `tick_ms()` | `u32` | 自开机起的毫秒（`GetTickCount`）。约 49.7 天回绕；**不**承诺高分辨率或单调时钟。 |
| `exit(code u32)` | `#NoReturn` | 立即终止进程，退出码为 `code`；不打模板。见 `exit.ut`。 |
| `abort()` | `#NoReturn` | 不可恢复终止（越界 / 空 `get` / OOM / 用户显式调用）。无消息、无退出码约定；实施走 `riurt_abort`。与 `panic(msg)` 同通道，不入 `T ! E`。 |

`fn main() i32` 作退出码 v1 **不**提供；用户要非零退出调 `exit`。`abort` 不是业务退出码。

§10.4.1.7 独立包 `riu.time`（stdlib）：源文件 `sdk/stdlib/src/riu/time.ut`（文件模块，与 `riu.io` 同级）。图中须有 `stdlib`。须显式 `use riu.time` 或 `use riu.time.*`。此后 `time.Duration` / `riu.time.Duration` / 裸名 `Duration`（仅 `.*`）。未 use 时 `riu.time.xxx` 非法（[E6001]）；用户可有自己的 `src/time.ut`。`tick_ms()` 仍在 `riu.core`（§10.4.1.6），不迁入本包。

公开类型：

| 类型 | 职责 | 表示 |
|---|---|---|
| `Duration` | 有符号时长 | 纳秒 `i64`（约 ±292 年）。算术溢出与整数一样回绕；`abs` / `neg` 在 `i64::MIN` 时饱和到 `i64::MAX`。 |
| `Instant` | 单调时钟上的点 | `QueryPerformanceCounter` 换算的纳秒；与墙上时钟无关，不因校时回跳。两点之差可以是负时长。 |
| `SystemTime` | UTC 墙上时钟 | Win32 `FILETIME`（100ns，1601-01-01 起）。`now` 走 `GetSystemTimePreciseAsFileTime`。 |
| `DateTime` | 民用日历字段 | `year` / `month` / `day` / `hour` / `minute` / `second` / `nanos` / `weekday`（0=周日，同 Win32）/ `utc_offset_min`（东为正，分钟）。快照，不随时钟刷新。 |

`Duration` 公开 `zero` / `from_ns` / `from_us` / `from_ms` / `from_secs` / `from_mins` / `from_hours`、`as_*`（向 0 截断）、`is_zero` / `is_negative` / `abs`、运算符 `+` `-` `*` `/` 一元 `-`、`==` 与序。`to_string`：`0s`；否则按 `h` / `m` / `s` / `ms` / `us` / `ns` 拼接非零段，负值前加 `-`。

`Instant` 公开 `now` / `elapsed` / `duration_since`、与 `Duration` 的 `+` `-`、`==` 与序。`to_string` 为调试形 `Instant(<ns>)`，原点无墙上意义。

`SystemTime` 公开 `now` / `from_unix(secs, nanos)` / `unix` / `unix_subsec_nanos` / `duration_since`、与 `Duration` 的 `+` `-`、`to_utc` / `to_local`、`==` 与序。`to_string` 即 `to_utc().to_string()`。Unix 秒与 `FILETIME` 之差为 11644473600s；子秒精度 100ns。

`DateTime` 公开 `utc_now` / `local_now` / `from_ymd_hms(...) DateTime?`（UTC；非法日历 → `null`）、`is_utc`（`utc_offset_min == 0`）、`to_system_time` / `to_utc` / `to_local`。`to_string` 为 `YYYY-MM-DDTHH:MM:SS.mmm` + `Z` 或 `±HH:MM`（毫秒 = `nanos / 10^6`）。`from_ymd_hms` 不接受闰秒以外 Win32 拒收的字段。本地偏移由 `FileTimeToLocalFileTime` 相对 UTC 计算，含当前 DST。

自由函数：`sleep(d Duration)` / `sleep_ms(ms u32)`。零或负时长立即返回、不调用 `Sleep`；超过 `u32` 毫秒则分段睡。**不**承诺睡眠精度。v1 **不**含 IANA 时区库、定时器、deadline、解析任意日期字符串。

### §10.4.2 `#Builtin`

§10.4.2.1 `base.ut` 中标 `#Builtin` 的声明由编译器内部合成实现（§11.2）；其余按普通用户代码编译。

§10.4.2.2 SDK 与编译器的版本绑定：任何 ABI / 临时帧 / RC 协议改动**应当**触发 SDK 重 build；CI / 自动构建链路**应当**强制 SDK 与编译器同步重 build（impl log Phase 8d.5）。

### §10.4.3 编译顺序

§10.4.3.1 编译器**应当**在每个用户模块加载前先创建 `riu.core` 的 `FileNode`（隐式占位），使其声明在命名解析中作为兜底空间存在（§10.2.5.1 第 3 步）。

§10.4.3.2 `riu.core` 一旦创建，对一次编译会话**不**重复加载，避免多份 SDK 互相覆盖。

### §10.4.4 用户对内置类型的限制

§10.4.4.1 用户**不得**对内置类型新增方法、重载运算符或修改字段（§7.2.3.5、§9.10）。v1 **不**引入 `extension` / `extend`；窗口见 §12（扩展实现块）。

§10.4.4.2 用户**可以**定义与 `riu.core` 扁平符号同名的本文件顶层声明。裸名走 §10.2.5（L1 盖住 L3）；SDK 侧用路径（`map.Map` / `riu.core.map.Map`）。**不**在声明点禁止与 core 同名。

### §10.4.5 依赖图

§10.4.5.1 用户模块只解析本项目 `<src>/...`（§10.1.3.3）。进了解析图的其它包（sdk / path / git，含传递）按各自源根解析；`use` 可写图中任一 `lib_mod`（§10.1.1.12）。SDK 包从安装路径加载，**不**走用户源根。用户项目写 `use riu.core.math` / `use riu.core.map.*` 只命中**已对用户登记**的 SDK 模块，**不**在用户源根查找 `<src>/riu/core/…`。未登记的 `riu.core.<stem>` → [E5018]。未进图的 `riu.io` / `riu.time` 等 → 找不到。toml 与产物路径见 §10.1.1.12–13。
