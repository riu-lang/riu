# §10 模块系统

本章规范 yux 的项目布局、模块导入、命名解析、包级再导出（`pkg` 文件）、可见性，以及与 SDK / `base.yux` 的协作。

## §10.1 项目结构

### §10.1.1 `yux.toml`

§10.1.1.1 项目根由 `yux.toml` 标记。该文件**应当**位于项目根目录。字段定义：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | 字符串 | ✅ | 项目 / 产物名 |
| `version` | 字符串 | ✅ | 版本号 |
| `entry` | 字符串 | 可执行项目必填 | 入口源文件，相对源根（§10.1.3） |
| `[lib]` 节 | 表 | 库项目用 | 见 §10.1.2 |
| `[link]` 节 | 表 | 系统链接库声明 | 见 §10.1.1.6 |

§10.1.1.2 `[lib]` 子表（可选）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | 字符串 | 库类型（v1：`"static"` 等） |

§10.1.1.3 可执行项目示例：

```toml
name = "myproject"
version = "1.0.0"
entry = "main.yux"
```

§10.1.1.4 库项目示例（如 SDK 自举）：

```toml
name = "yux"
version = "1.0.0"

[lib]
type = "static"
```

§10.1.1.5 `name` 的 UTF-8 字符串内容由实现解析（v1 `toml11` 原生支持中文）。

§10.1.1.6 `[link]` 子表（可选）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `libs` | 字符串数组 | 链接时追加的系统库名（不含 `.lib` 后缀）。实现自动补全为 `<name>.lib` 传 `lld-link` |

```toml
[link]
libs = ["user32", "shell32"]
```

### §10.1.2 项目模式与单文件模式

§10.1.2.1 *项目模式*（推荐）：以 `yux.toml` 为根。命令 `yux build [<name>]` **应当**在 `yux.toml` 所在目录执行；`<name>` 可省略，省略时驱动**应当**取 `yux.toml` 中 `name` 字段；显式给出时**应当**与 `name` 字段一致，否则驱动以非零退出码报错。最终产物落在 `<projectRoot>/build/<name>.exe`（可执行项目）或 `<projectRoot>/build/<name>.lib`（静态库）。中间产物 obj / IR 镜像源文件相对项目根的路径放在 `<projectRoot>/build/<src-rel>.obj`（典型 `<projectRoot>/build/src/<rel>.obj`）；每个目录视为一个包，目录内所有 `.yux` 的元信息聚合到该目录下的 `<dirname>.cache` 增量缓存。

§10.1.2.2 *单文件模式*（v1 已弃用）：忽略 `yux.toml`，产物扁平放在源文件目录。新增代码、示例、文档**应当**一律走项目模式。

### §10.1.3 源根 `src/`

§10.1.3.1 项目模式下的**源根**（source root）是模块 / 包的解析起点：

- 若 `<projectRoot>/src/` 存在且为目录，源根 = `<projectRoot>/src/`；
- 否则源根回退为 `<projectRoot>/`。

§10.1.3.2 `entry` 字段是相对源根的路径（典型 `main.yux` 表示 `<src>/main.yux`）。

- `entry` **不得**为绝对路径，否则报 [E5013]。
- 解析 (`canonical`) 后 `entry` 仍**应当**位于 `<src>/` 子树内；逃出源根（典型形态 `../foo.yux`）默认报 [E5014] warning（约定违例 + obj 镜像路径可能走样）。可通过 `--Werror` / `--deny=E5014` 升级为 error。

§10.1.3.3 模块 `a.b.c` 解析为以下之一（按存在性顺序）：

- `<src>/a/b/c.yux`（文件模块）；
- `<src>/a/b/c/`（包模块，配合 `pkg` 文件，§10.2.4）。

§10.1.3.4 同名 `.yux` 文件与同名子目录并存属冲突，编译器**应当**报错。

### §10.1.4 项目结构示例（informative）

```
myproject/
├── yux.toml
└── src/
    ├── main.yux
    ├── math.yux
    └── ops/
        ├── pkg              ; 包再导出清单（§10.2.4）
        ├── add.yux
        └── sub/
            └── inner.yux
build/
├── myproject.exe              ; 最终产物（exe / lib）
└── src/                       ; 中间产物：镜像 src/ 目录树
    ├── main.obj
    ├── math.obj
    ├── src.cache              ; 顶层"src 包"的增量缓存
    └── ops/
        ├── add.obj
        ├── ops.cache          ; ops 包缓存（覆盖 add.yux 与 sub/ 包之外的 ops/ 直系源）
        └── sub/
            ├── inner.obj
            └── sub.cache
```

§10.1.4.1 缓存文件 `<dir>/<dirname>.cache` 第 1 行为编译器指纹（当前 `yux.exe` 的 mtime+size，TAB 分隔）；后续每行为 `<filename>\t<src-mtime-ns>\t<src-size>`。指纹不匹配即整个文件作废，触发该包内全量重编。

## §10.2 模块导入

### §10.2.1 形态

```
imports ::= 'use' ID ('.' ID)* ('.' '*')? codeLineEnd
```

§10.2.1.1 `use` 形态：

| 写法 | 语义 | 章节 |
|---|---|---|
| `use a.b.c` | 导入文件模块 / 包模块 `a.b.c`；其后用 `c.member` / 直接公开符号访问 | §10.2.2 |
| `use a.b.*` | 导入 `a.b` 的全部公开成员到当前模块命名空间 | §10.2.3 |

§10.2.1.2 `use` 语句**应当**集中在源文件顶部 `comment*` 之后；语法层允许穿插 `comment` / `codeLineEnd`，但**不应**与其它顶层声明混排。

### §10.2.2 文件模块导入

§10.2.2.1 `use a.b.c` 命中 `<src>/a/b/c.yux`：

- 该文件的全部公开顶层声明（`fn` / `struct` / 全局 `let`）注册到当前模块；
- 调用方可写 `c.member`（模块名作前缀），亦可在无歧义时直接使用裸名（实现细节随版本）。

§10.2.2.2 例（`tests/projects/imports_module_alias`）：

```yux
use math
fn main() {
    println(math.square(7))
}
```

### §10.2.3 通配导入

§10.2.3.1 `use a.b.*` 把 `a.b` 下的全部公开成员"扁平化"导入当前模块：

- 若 `a.b` 是文件模块（`<src>/a/b.yux`）：导入该文件的全部公开顶层声明；
- 若 `a.b` 是包模块（`<src>/a/b/`）：按 `pkg` 文件展开（§10.2.4）。

§10.2.3.1.1 若包目录**不含** `pkg` 文件，语义**等价于** `pkg` 文件中按文件名排序逐行列出所有 `.yux` 子模块（`name` 形式，**不做** `name.*` 扁平再导出）及子目录。即调用方通过 `use pkg.*` 后以 `child.fn()` 访问各子模块成员，不能直接用裸名 `fn()`。

§10.2.3.2 通配导入下，公开成员可直接以裸名使用，无需模块前缀。

### §10.2.4 `pkg` 文件（包再导出）

§10.2.4.1 包目录可含一个**无后缀**的纯文本文件 `pkg`，描述该包的"再导出清单"。

§10.2.4.2 `pkg` 文件每行一条导出项，语法如下：

| 行形态 | 语义 |
|---|---|
| 空行 / 仅空白 | 忽略 |
| `;...` 注释行 | 忽略（与 yux 注释一致） |
| `name` | 把同包下的子模块 `name`（文件 `name.yux` 或子目录 `name/`）作为别名再导出 |
| `name.*` | 把子模块 `name` 的全部公开成员扁平再导出到该包名空间 |
| `name as alias` | 把子模块 `name` 以别名 `alias` 再导出（重命名）；调用方以 `alias.member` 访问 |

§10.2.4.3 `pkg` 文件的存在使其所在目录被视为**包模块**；其内容决定 `use <pkg-path>` 与 `use <pkg-path>.*` 的展开形态。

§10.2.4.4 例（`tests/projects/pkg_wildcard_export/src/mymath/`）：

```
; src/mymath/pkg
add.*    ; 把 add 模块的所有公开成员扁平导出
sub      ; 把 sub 模块作为别名导出
```

调用方：

```yux
use mymath.*
fn main() {
    println(add(10, 5))     ; add 来自 add.yux，扁平
    println(sub.sub(10, 5)) ; sub 作为别名，需 sub.sub
}
```

§10.2.4.4.1 重命名导出例（`tests/projects/pkg_rename_export/src/mymath/`）：

```
; src/mymath/pkg
add as addition    ; 把 add 模块以 addition 别名导出
sub.*              ; 把 sub 模块的所有公开成员扁平导出
```

调用方：

```yux
use mymath.*
fn main() {
    println(sub(10, 3))          ; sub 来自 sub.yux，扁平
    println(addition.add(7, 2))  ; add 模块以 addition 别名访问
}
```

§10.2.4.5 `pkg` 文件**只读**，不参与编译；其语法独立于 `.yux`，仅在模块解析阶段被读取。

§10.2.4.6 一个目录可同时含 `pkg` 文件与 `.yux` 文件 / 子目录；无声明在 `pkg` 中的子模块仍可用全名 `pkg.sub` 形式导入。

### §10.2.5 命名解析

§10.2.5.1 顶层声明的查找顺序：

1. 当前文件内的声明；
2. 通过 `use` 显式导入的模块成员（含 `pkg` 再导出）；
3. SDK 的 `yux.core` / `base.yux` 内的内置类型与函数（§10.4）。

§10.2.5.2 同名冲突：两个被 `use` 导入的模块导出同名成员时编译器**应当**报错；用户**应当**改用更细粒度的 `use a.b.c`，或通过模块前缀访问（如 `mod1.foo` vs `mod2.foo`）。

### §10.2.6 循环依赖

§10.2.6.1 v1 **禁止**模块间循环依赖：`a use b` 且 `b use a`（直接或传递）**应当**编译报错，错误信息**应当**给出环路（`a -> b -> a`）。

§10.2.6.2 该约束允许编译器按拓扑序逐模块编译，简化实现。Open Issue：未来是否引入 forward 声明放宽该限制。

## §10.3 可见性

### §10.3.1 默认可见性

§10.3.1.1 顶层声明（`fn` / `struct` / 全局 `let` / `extern` 块）默认**公开**：可被其它模块通过 `use` 导入。

§10.3.1.2 yux **不**引入 `pub` / `private` 等可见性修饰符（永久决议）；可见性靠命名约定（§10.3.2）决定。

### §10.3.2 `_` 前缀私有

§10.3.2.1 以下划线 `_` 开头的标识符为**私有**：仅在当前模块（同一 `.yux` 文件）可见，跨模块访问**应当**编译报错。

§10.3.2.2 适用范围：

- 顶层 `fn`（如 `fn _internal_helper()`）；
- 顶层 `struct`（如 `struct _State`）；
- 全局 `#Cval let`（如 `#Cval let _MAX_RETRIES i32 = 3`）；
- 结构体方法、字段（同模块外不可见）。

§10.3.2.3 编译器内部使用的 runtime helper（如 `_box_alloc` / `_array_grow` / `_ptr_offset`）也**应当**遵循该前缀约定（§8 / impl log）。

§10.3.2.4 `_` 前缀**不**影响同一模块内的可见性；同模块内可自由调用。

§10.3.2.5 `pkg` 文件的再导出**不得**穿透私有边界：`_foo` 这类私有符号**不**可被 `pkg` 文件以 `name.*` 形态再导出。

## §10.4 SDK 与 `base.yux`

### §10.4.1 `yux.core` 模块

§10.4.1.1 `sdk/yux/` 是 yux 的内置 SDK，作为库项目（`[lib] type="static"`）发布。其源在 `sdk/yux/src/yux/core/*.yux`，逻辑模块名 `yux.core`。

§10.4.1.2 `yux.core` 包含 `base.yux`（约定俗称）：定义内置类型（`i32` / `f64` / `bool` / `String` / `Array<T>` / `Rc<T>` / `Weak<T>` / `Nullable<T>` / `StringBuilder` / `Ptr`）的占位声明、内置方法签名与部分用户态实现。

§10.4.1.3 用户模块**应当**通过 `use yux.core.*` 显式导入内置 print / I/O 等公开成员；纯类型 / 内置 builtin（如 `i32` / `same_ref` / `upgrade`）由编译器隐式注入命名空间。

### §10.4.2 `#Builtin`

§10.4.2.1 `base.yux` 中标 `#Builtin` 的声明由编译器内部合成实现（§11.2）；其余按普通用户代码编译。

§10.4.2.2 SDK 与编译器的版本绑定：任何 ABI / 临时帧 / RC 协议改动**应当**触发 SDK 重 build；CI / 自动构建链路**应当**强制 SDK 与编译器同步重 build（impl log Phase 8d.5）。

### §10.4.3 编译顺序

§10.4.3.1 编译器**应当**在每个用户模块加载前先创建 `yux.core` 的 `FileNode`（隐式占位），使其声明在命名解析中作为兜底空间存在（§10.2.5.1 第 3 步）。

§10.4.3.2 `yux.core` 一旦创建，对一次编译会话**不**重复加载，避免多份 SDK 互相覆盖。

### §10.4.4 用户对内置类型的限制

§10.4.4.1 用户**不得**对内置类型新增方法、重载运算符或修改字段（§7.2.3.5、§9.10）。

§10.4.4.2 用户**不得**重复定义与 `yux.core` 同名的顶层符号（无论是否 `_` 前缀）。
