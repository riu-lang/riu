# §4 表达式

本章规范 yux 表达式（`expr` 产生式）的求值语义、优先级与结合性。语法形态见 §2 / [附录 B §B.6](附录B-语法汇总.md#b6-表达式按-yuxg4-中-expr-的分支顺序决定优先级)；内置类型相关的表达式语义见 §9；与所有权 / 借用 / RC 相关的细节见 §8。

## §4.1 求值顺序

### §4.1.1 子表达式求值

§4.1.1.1 二元运算符与函数调用的实参按**从左到右**严格求值。即在 `f(a, b, c)` 中，`f` 先于 `a`，`a` 先于 `b`，`b` 先于 `c`。

§4.1.1.2 字段链 `a.b.c`、索引链 `a[i][j]`、调用链 `f()()` 沿语法树自左至右求值。

§4.1.1.3 短路运算 `&&` / `||`、`??`、`?.` 的右侧在左侧不能确定结果时**才**求值（§4.4.3 / §4.6）。

### §4.1.2 临时值寿命

§4.1.2.1 表达式求值产生的中间结果（特别是堆句柄类型 `Rc<T>` / `Array<T>` / `String` / `Weak<T>`）称为**临时值**（temporary）。

§4.1.2.2 临时值寿命延伸至其所在**语句 / 顶层表达式 / 代码块**的边界；边界处所有未消费的临时值统一 release（详见 §8.6 临时值清单）。

§4.1.2.3 receiver 与字段访问只是**借用**临时值，不消费它（不夺所有权）。

§4.1.2.4 `T&` **不得**绑定临时值；该约束由 §8.4 的寿命规则保证（临时值的"作用域"是当前语句或表达式，比任何 `var` 声明都小）。

### §4.1.3 副作用点

§4.1.3.1 yux v1 仅以下表达式具有副作用：函数调用、方法调用、`exprSet` 经语句（§5.2）、`a <- b` 移入赋值（§4.13）、`Self { ... }` 字段字面量内的字段写入（§7.3.2 / §7.10.3）。

§4.1.3.2 任何副作用的**可观测**顺序遵循 §4.1.1 的左→右规则。

## §4.2 优先级与结合性

### §4.2.1 优先级表

下表按 `yux.g4` 的 `expr` 产生式自上至下排列，**位置越靠前优先级越高**。同一行视为同一优先级。

| 等级 | 产生式 | 示意 | 结合性 |
|---|---|---|---|
| 1 | `exprParen` | `(e)` | — |
| 2 | `exprGetRef` | `&obj.f.g` | — |
| 3 | `exprGet` | `e[i, j]` | 左结合 |
| 4 | `exprTryCatch` | `try { ... } catch e E { ... }` | — |
| 4 | `exprOneLineIfElse` | `if c { a } else { b }` | — |
| 5 | `exprIfElsePreValue` | `a if c else b` | 右结合 |
| 6 | `exprIfElse` | `if c { ... } elif ... else { ... }` | — |
| 7 | `exprArrayInit` | `[v ... T?]` | — |
| 8 | `exprDot` | `e.f` / `e?.f` | 左结合 |
| 9 | `exprArray` | `[e1, e2, ...]` | — |
| 10 | `exprCall` / `exprCallTrailingOnly` | `f(args)` / `f:<T>(args)` / `f { lambda }` / 任一形态末尾可带 `!`（§4.12.1） | 左结合 |
| 11 | `exprUnary` | `-e` / `~e` / `!e` | 右结合 |
| 12 | `exprShift` | `e << e` / `e >> e` | 左结合 |
| 13 | `exprBinOp` | `e & e \| e ^ e` | 左结合 |
| 14 | `exprMulDivMod` | `e * e` / `e / e` / `e % e` | 左结合 |
| 15 | `exprAddSub` | `e + e` / `e - e` | 左结合 |
| 16 | `exprCompare` | `e < e` / `e <= e` / `e > e` / `e >= e` | 左结合 |
| 17 | `exprEq` | `e == e` / `e != e` | 左结合 |
| 18 | `exprBool` | `e && e` / `e \|\| e` | 左结合 |
| 19 | `exprUnit` | `()` | — |
| 19 | `exprLiteral` | 字面量 / `ID` | — |
| 20 | `exprNullElse` | `e ?? e` | 右结合 |
| 21 | `exprMoveAssign` | `a <- b` | 右结合 |
| 22 | `exprThis` | `$` | — |

> *informative*：移位 `<< >>` 优先级**高于**位运算 `& | ^`（与 C / Rust 同向）。`docs/基础语法.md` 的优先级小节如有不一致，应以本表 / `yux.g4` 为准并同步。

### §4.2.2 圆括号

§4.2.2.1 `(e)` 不改变 `e` 的类型与值，仅改变解析优先级。

§4.2.2.2 圆括号在调用 `f(args)` / 形参列表 `(p T)` 中是分隔符，不构成 `exprParen`。

## §4.3 字面量与原子表达式

### §4.3.1 字面量

§4.3.1.1 `exprLiteral` 直接产出对应类型的值，类型推断规则见 §3.5 / §3.6.4。

§4.3.1.2 `literalObj`（即 `ID`）按 §10 的解析规则查找：
- 局部变量 / 形参 / receiver 字段（通过 `$` 隐式）；
- 当前模块中的 `cval`、`fn` 名；
- 通过 `imports` 引入的外部名。

§4.3.1.3 字符串字面量 `STR_LINE` / `STR_LINE_RAW` 编译为只读段中的 `String`，RC 头哨兵为 `0xFFFFFFFF`（§8.2.5）。

§4.3.1.4 整数 / 浮点字面量的位宽推断按 §3.5；整数字面量在赋给具体类型上下文时按位截断 / 扩展行为是**编译期错误**，需通过显式后缀（`100u8`）或 `to_*` 方法（§3.5.2）。

§4.3.1.5 双引号字符串字面量 `"..."` 同时承载**纯字符串**与**字符串模板**两种形态，语法上由产生式 `stringTemplate` 统一描述（见附录 B）：

```
stringTemplate : '"' templatePart* '"'
templatePart   : STR_TPL_TEXT                       # 纯文本片段
               | STR_TPL_DOLLAR_ID                  # $ident 单标识符插值
               | STR_TPL_INTERP_OPEN expr '}'       # ${expr} 表达式插值
```

构造规则：
- `$ident` 形式中 `ident` 紧跟 `$`，不得有空白；`ident` 须满足 `ID` 的首字符约束（不允许以数字、运算符、空白起始）。
- `${ ... }` 内为完整 `expr`（§4 全部表达式产生式），词法上允许嵌套 `{}`（lexer 用 `interp_brace_depth` 平衡跟踪），结束于配对的 `}`。
- 不允许跨行：`STR_TPL_TEXT` 不接受 `\r` / `\n`；多行字符串属未来扩展。

§4.3.1.6 字符串模板的转义规则在 `STR_TPL_TEXT` 片段内生效（与 §1.x 普通字符串字面量一致），并新增 `\$` 一项：

| 转义 | 含义 |
|------|------|
| `\n` `\r` `\t` `\0` | 控制字符 |
| `\\` `\"` | 反斜杠 / 引号 |
| `\$` | 字面 `$` 字符（**不**触发插值） |
| `\xNN` | 1 字节 |
| `\uNNNN` | 1 个 BMP 码点 |

未列出的 `\X` 形式按 `X` 字面追加（与现行实现一致）。`r"..."`（`STR_LINE_RAW`）仍走旧路径，**不参与模板解析**，`$` 在 raw 字符串内永远是字面字符。

§4.3.1.7 求值与 lowering：
- 不含任何插值（仅 `STR_TPL_TEXT` 片段，或为空字符串）的模板，在 AST 构造期降级为 `LiteralStringNode`，与 §4.3.1.3 完全一致。
- 含插值的模板被构造为 `StringTemplateNode`，其不变量为 `parts.size() == interps.size() + 1`，交替序列 `parts[0], interps[0], parts[1], ..., parts[N]`。
- 含插值模板按以下伪代码 lower（v0.6 Phase 2a 落地）：
  ```
  sb := StringBuilder()
  for i in 0..N: if !parts[i].empty: sb.append(parts[i] as String literal)
                 if i < N:           sb.append(interps[i])
  result := sb.build()
  ```
  `result` 即整个模板表达式的求值结果（类型 `String`）；`sb` 在表达式结束后随即析构（释放 `build()` 后留下的空 `Array<u32>`）。
- **类型规则**（v0.6 Phase 2b）：插值位置的表达式类型必须是 `String` 或实现 `ToString`，否则报 [E3026]。`String` 直接 `append`；其他类型由编译器在插值位置合成 `expr.to_string()` 调用，复用 v0.5 单态化方法分发（含内置类型 `i8/u8/.../i64/u64/f32/f64/bool` 与用户类型的显式 `Type : ToString { ... }` 实现块）。

> 阶段进度：Phase 2a — `String` 插值已落地；Phase 2b — `ToString` 自动分发已落地；Phase 2c — `String` 上的 `+` 链已落地（详见 §4.4.1.4）。详见 `CHANGELOG`。

### §4.3.2 `$`（exprThis）

§4.3.2.1 `$` 表示当前作用域的接收者：

- 在结构体实例方法体内：`$` 类型为 `Self&`（§7.2.2）。
- 在 `#Static fn` 体内：`$` **不得**出现（§7.10.4，报 `E3128`）；通过 `Self` 类型字面量 / `Self { ... }` 访问类型层 / 构造新值。
- 在普通函数体内：`$` **不得**出现。

§4.3.2.2 `$.field` 访问当前对象字段；`$.method(args)` 调用当前类型的方法。

§4.3.2.3 析构函数 `fn ~()` 内 `$` 仍为 `Self&`，对字段的写不触发 `#Val` / `#Frozen` 限定（§7.4.1 / §7.1.4.3）。

## §4.4 算术与位运算

### §4.4.1 算术运算（`exprAddSub` / `exprMulDivMod`）

| 运算 | 操作数类型 | 结果类型 | 语义 |
|---|---|---|---|
| `e1 + e2` | 同种整数 / 浮点 | 同左 | 数值加 |
| `e1 - e2` | 同种整数 / 浮点 | 同左 | 数值减 |
| `e1 * e2` | 同种整数 / 浮点 | 同左 | 数值乘 |
| `e1 / e2` | 同种整数 | 同左 | 整数除（向零截断） |
| `e1 / e2` | 同种浮点 | 同左 | IEEE 754 浮点除 |
| `e1 % e2` | 同种整数 | 同左 | 整数取余（与 `/` 同向截断） |

§4.4.1.1 操作数类型**应当**完全一致（含位宽与符号）；不存在隐式扩展（§3.5）。混合类型需先 `.to_*()`。

§4.4.1.2 整数溢出按 LLVM `add` / `sub` / `mul` / `sdiv` / `udiv` / `srem` / `urem` 的二进制补码语义截断；`-INT_MIN`、整数除零、整数 `% 0` 行为由 LLVM 决定，规范不保证 panic。

§4.4.1.3 浮点除零、`0.0 / 0.0`、`Inf - Inf` 行为遵从 IEEE 754（产生 ±Inf 或 NaN）。

§4.4.1.4 字符串 `+`（v0.6 Phase 2c）：当 `+` 的任一操作数为 `String` 时，整个 `exprAddSub` 表达式的结果类型为 `String`，左结合的整条 `+` 链 lower 为单条 `StringBuilder` 累加：

```
sb := StringBuilder()
for each leaf in flatten(left-spine of `+` chain):
  if leaf : String     -> sb.append(leaf)
  else if leaf : ToString -> sb.append(leaf.to_string())
  else                 -> [E3026]
result := sb.build()
```

扁平化只沿**左脊**进行：`a + b + c + d` 视为单链 `[a, b, c, d]`；`a + (b + c)` 中 `(b + c)` 作为整体单叶子参与外层链（若其结果仍为 `String`，由其自身独立 lower）。叶子类型规则与 §4.3.1.7 模板插值完全一致：`String` 直接 `append`；其他类型由编译器在该位置合成 `leaf.to_string()`，复用 v0.5 单态化方法分发；未实现 `ToString` 报 [E3026]。

`String` 上的 `-` 仍**未定义**；`String` 不实现 `String.plus`（v0.6 起 `+` 在 String 上的语义由编译器直接 lower，不走方法分发）。需要保留中间 `StringBuilder` 句柄、批量追加非 `+` 形式（如循环累积）时仍用 §9.4 的 `StringBuilder` 显式 API。

### §4.4.2 位运算（`exprBinOp` / `exprShift`）

| 运算 | 操作数类型 | 结果类型 | 语义 |
|---|---|---|---|
| `e1 & e2` | 同种整数 / `bool` | 同左 | 按位与 |
| `e1 \| e2` | 同种整数 / `bool` | 同左 | 按位或 |
| `e1 ^ e2` | 同种整数 / `bool` | 同左 | 按位异或 |
| `e1 << e2` | 同种整数 | 同左 | 左移；`e2` 须为无符号或非负 |
| `e1 >> e2` | 整数 | 同左 | 算术 / 逻辑右移：有符号操作数走算术右移（保符号位），无符号走逻辑右移 |

§4.4.2.1 `bool` 上的 `&` / `|` / `^` 是**非短路**布尔运算（与 `&&` / `||` 区别）。

§4.4.2.2 移位次数 `e2` 大于等于操作数位宽时行为遵从 LLVM `shl` / `lshr` / `ashr`（结果未定义而非 panic）。

§4.4.2.3 移位 `<< >>` 优先级**高于**位运算 `& | ^`（同 C / Rust），由 `yux.g4` 中 `exprShift` 早于 `exprBinOp` 保证。

### §4.4.3 一元运算（`exprUnary`）

| 形态 | 操作数类型 | 结果类型 | 语义 |
|---|---|---|---|
| `-e` | 整数 / 浮点 | 同左 | 数值取反 |
| `~e` | 整数 | 同左 | 按位取反 |
| `!e` | `bool` | `bool` | 逻辑取反 |

§4.4.3.1 操作符与操作数之间**不得**有空格（`-1` 是 `exprUnary`，`- 1` 不被该产生式接受；详见 §1.7.3）。

§4.4.3.2 `-e` 中 `e` 为无符号整数（如 `u32`）属类型错误；需先 `to_iN()`。

§4.4.3.3 `~bool` 不合法（`bool` 上请用 `!`）。

## §4.5 比较与逻辑运算

### §4.5.1 比较（`exprCompare`）

§4.5.1.1 `<` `<=` `>` `>=` 接受同种整数或同种浮点操作数，结果类型 `bool`。

§4.5.1.2 浮点比较遵从 IEEE 754：`NaN < x` / `NaN > x` / `NaN == x` 均为 `false`；`NaN != x` 为 `true`。

§4.5.1.3 比较运算**不**支持链式（`a < b < c` 解析为 `(a < b) < c`，类型错误）。

### §4.5.2 等值（`exprEq`）

§4.5.2.1 `==` 在所有类型上为**内容相等**：

- 内置标量：值相等。
- 用户 `struct`：编译器派生**字段递归** `==`（每个字段递归 `==`）。
- `Rc<T>`：自动解引用比 payload 内容（即 `T` 上的 `==`）。
- `Array<T>`：长度相等且各元素递归 `==`。
- `String`：内容逐字节相等。
- `Weak<T>`：v1 **禁用** `==` / `!=`（§3.7、§8.5）；地址比对走 `same_ref`（§4.6.4 / §9）。

§4.5.2.2 `!=` 是 `==` 的逻辑反。

§4.5.2.3 `null` 与 `T?` 的等值通过 `Nullable<T>::has() / get()` 解构后比较；编译器对 `t? == null` 提供编译期常量化为 `!t?.has()` 的等价形式。

### §4.5.3 布尔短路（`exprBool`）

§4.5.3.1 `e1 && e2`：`e1` 求值为 `true` 时再求 `e2`；否则结果 `false`，`e2` 不求值。

§4.5.3.2 `e1 || e2`：`e1` 求值为 `false` 时再求 `e2`；否则结果 `true`，`e2` 不求值。

§4.5.3.3 `&&` 与 `||` 的两侧操作数**应当**为 `bool`。

§4.5.3.4 由于 `&&` / `||` 同属 `exprBool` 一级（无内部分级），混用时**应当**显式加圆括号（`a && (b || c)`）。

## §4.6 Nullable 相关运算

### §4.6.1 `??`（exprNullElse）

§4.6.1.1 形态：`a ?? b`。`a` 类型须为 `T?`；持值返回内层 `T`，空时求 `b` 并返回。

§4.6.1.2 `b` 类型须可赋值给 `T`（§3.4.2）。

§4.6.1.3 `??` 右结合：`a ?? b ?? c` 解析为 `a ?? (b ?? c)`。

### §4.6.2 `?.`（exprDot 中的可选 `?`）

§4.6.2.1 形态：`a?.field`。`a` 类型须为 `T?` 且 `T` 是含 `field` 的结构体；结果类型 `<field 类型>?`。

§4.6.2.2 链式：`a?.b?.c` 解析为 `(a?.b)?.c`，逐级展开。

§4.6.2.3 v1 **不**支持 `a?.method(args)`（语法层不允许）。

### §4.6.3 `null` 字面量

§4.6.3.1 `null` 仅在 `T?` 上下文（赋值、形参、返回值）合法；裸 `null` 在表达式中类型不确定，规范层视为错误。

## §4.7 取址、字段与索引

### §4.7.1 `&expr`（exprGetRef）

§4.7.1.1 形态：`& obj (.subs)*`，其中 `obj` 为 `ID` 或 `$`。即 `&` 仅可作用于：
- `&局部变量` / `&函数参数`；
- `&$.field` / `&$.f.g`；
- `&boxOrId.field.field...`（自动经 Rc 解引用，§9）。

§4.7.1.2 `&` 的结果类型：

| 形态 | 结果类型 | 备注 |
|---|---|---|
| `&v`（`v` 类型 `T`） | `T&` | |
| `&$.f` | 字段类型 `&` | |
| `&box`（`box: Rc<T>`） | `Rc<T>&` | 借用句柄本身，不是 payload（§8.4） |
| `&box.field` | 字段类型 `&` | 自动解引用后取字段，借用绑到 box 句柄存活期 |
| `&arr[i]` | — | **不合法**（`[]` 返回 `T&`，对 `T&` 再取址会形成 `T&&`，由 §2.6.1 / §4.7.1.4 拒绝） |
| `&f()` | — | **不合法**（函数返回值是右值临时） |

§4.7.1.3 `&` 的寿命规则：源对象（追到 `&` 的根对象 / `T&` 形参）的**声明作用域**应当 ⊇ 该 `T&` 变量自身的声明作用域（详见 §8.4）。

§4.7.1.4 `&` **不得**作用于 `T&` 变量本身（结果会是 `T& &`，由产生式 / §2.6.1 拒绝）。

§4.7.1.5 `&obj.f.g` 链中 `.` 之前允许换行（产生式 `'&' (ID|'$') (LineEnd* '.' ID)*`），与 §4.7.2.5 的 `exprDot` 链式换行保持一致。

### §4.7.2 字段访问 `e.f`（exprDot）

§4.7.2.1 `e` 为 `T`：在 `T` 的字段表中查找 `f`，结果类型为该字段类型。

§4.7.2.2 `e` 为 `Rc<T>`：自动解引用到 `T` 的字段表上分发，等价 `(*e).f`（无显式 `*` 语法，§9）。

§4.7.2.3 `e.f` **不**自动 retain：字段读取只是"借用视角"；只有当读出的值被存进新变量 / 作为参数 / 作为 `ret` 表达式时才按复制语义 retain（§8.5）。

§4.7.2.4 `e?.f` 形态见 §4.6.2。

§4.7.2.5 链式 `.` / `?.` 之前允许 `LineEnd*`（产生式 `expr LineEnd* '?'? '.' ID`），便于多行写法：

```yux
val x = builder
    .with_a(1)
    .with_b(2)
    .build()
```

格式化器规则（*informative*）：默认仅在超 120 列时把 `.` 前换行；用户已**手动**把每个 `.` 前都换行时，格式化器**保留**手写换行不合并。

### §4.7.3 索引访问 `e[args]`（exprGet）

§4.7.3.1 `e[args]` 是 `e.get(args)` 的语法糖，两者均返回 `T&`。

§4.7.3.2 `&arr[i]` 不合法（对 `T&` 再取址会形成 `T&&`，由 §2.6.1 / §4.7.1.2 拒绝）；`arr[i] = expr` 写入走 `statementSet`（§5.2.3），等价于 `arr.set(i, expr)`。

§4.7.3.3 `[` 之后、参数间 `,` 之后、`]` 之前允许 `LineEnd*`，末参允许尾随 `,`：单行 `m[i, j]` 与多行写法语法等价。

## §4.8 调用（exprCall）

### §4.8.1 形态

```
exprCall ::= expr (':' genericDef)? '(' LineEnd*
                 (expr (',' LineEnd* expr)* ','? LineEnd*)? ')'
```

§4.8.1.1 调用左侧 `expr` 须为：
- 函数名（`literalObj` 解析到 `fn`）；
- 方法访问 `obj.method`（语法上是 `exprDot` + `exprCall` 的组合）；
- `Type:<T>(args)` —— 内置类型构造（`Rc:<T>(v)` / `Heap:<T>(v)` / `Dyn:<D>(b)` 等编译器内置）/ `Type::factory:<T>(args)` 静态工厂调用的 turbofish 形态。

§4.8.1.2 turbofish `name:<T1, T2>(args)` 用于显式指定泛型实参，避免 `Generic<T>(args)` 解析为比较运算（§2.4 与 `docs/函数.md`）。

### §4.8.2 实参语义

§4.8.2.1 实参按 §4.1.1 从左到右求值。

§4.8.2.2 实参类型须可赋值给形参类型（§3.4.2）。`T&` 形参的实参**应当**显式取址 `f(&x)`，**不**自动加 `&`（详见 §8.6）。

§4.8.2.3 方法调用 `obj.method(args)` 的 receiver 自动以 `Self&` 形式传入；无需写 `&obj`。

§4.8.2.4 调用约定为 callee-clean retain / release（§8.5）：调用方在传堆句柄实参前 retain（计数 +1），被调用方按局部变量析构 release。

§4.8.2.5 `(` 之后、实参间 `,` 之后、`)` 之前允许 `LineEnd*`，末参允许尾随 `,`：

```yux
; 单行
foo(a, b, c)

; 多行
foo(
    a,
    b,
    c,
)
```

`exprArray` （§4.10.1）同此规则。

### §4.8.3 内置函数调用

§4.8.3.1 编译器 baked 的 turbofish 内置函数：

| 名称 | 签名 | 说明 |
|---|---|---|
| `weak:<T>(box Rc<T>?)` | `Weak<T>` | 由 Rc 构造 Weak（§9） |
| `ptr_of:<T>(obj)` | `Ptr` | 显式转 FFI 指针；T 限定见 §9 / DRAFT §9.4 |
| `same_ref:<T>(a, b)` | `bool` | 地址相等比对（§4.5.2 / §9） |
| `Nullable:<T>(v)` / `Nullable:<T>()` | `T?` | 显式构造 Nullable |

§4.8.3.2 `weak` / `ptr_of` / `same_ref` 不进入 SDK 用户代码；编译器在调用点直接展开。

### §4.8.4 尾随 lambda 调用糖

§4.8.4.1 当函数调用的**最后一个位置实参是块形 lambda**（§4.11.1）时，该 lambda 可移出 `(...)`：

```yux
; 等价形态对
f(a, b, { x => body })       ; 标准
f(a, b) { x => body }        ; 尾随移出

f({ x => body })             ; 唯一实参标准
f { x => body }              ; 唯一实参 + 省略 (...)
```

§4.8.4.2 规则：

- 仅**块形** lambda（`{ args => body }` / `{ body }`）可作尾随；表达式形 `(x) => expr` 不可（与表达式后缀链冲突）。
- 当尾随 lambda 是唯一实参时，`()` 可整体省略；多实参时保留 `(...)` 包裹其余实参。
- 与 `?` / `??` / `?.` 等表达式后缀相容；糖只影响 parse，调用语义层无差异。
- 与 turbofish 相容：`f:<i32>(args) { lambda }` / `f:<i32> { lambda }`。
- AST 改写：尾随 lambda 在 ASTBuilder 阶段并入 `exprCall` 的实参列表末尾，语义阶段无差异。

§4.8.4.3 callee 与 `{` 之间空格规则与现有 `exprCall` 通用空格一致，不强制。

## §4.9 条件表达式

### §4.9.1 单行 `if-else`（exprOneLineIfElse）

§4.9.1.1 形态：`if cond { trueExpr } else { falseExpr }`。`cond` 类型须为 `bool`。

§4.9.1.2 `trueExpr` 与 `falseExpr` 类型须**完全一致**（无隐式提升）。

§4.9.1.3 整体类型即两分支的公共类型。

§4.9.1.4 一支以 `ret` / `panic` 等 `#NoReturn` 调用（DRAFT-错误.md §8.3）结尾时，该 arm 视为**流终止**，不参与 §4.9.1.2 的类型一致性检查；整体类型取另一支的类型。同机制覆盖 `match` arm 与 `try`/`catch` arm（§3.10 / DRAFT §5）。

### §4.9.2 三元前置（exprIfElsePreValue）

§4.9.2.1 形态：`trueExpr if cond else falseExpr`。语义同 §4.9.1。

§4.9.2.2 `if` 与 `else` 两侧均须有空格（§1.2.3）。

### §4.9.3 块形 `if-elif-else`（exprIfElse）

§4.9.3.1 形态：

```
if cond
  statementBlock
(elif cond
  statementBlock)*
(else
  statementBlock)?
```

§4.9.3.2 当作为表达式使用时（如 `val x = if c { a } elif d { b } else { c }`），每个 `statementBlock` 的"值"为其末尾 `statementExpr`（不带尾随 `;`）的值；带尾随 `;` 的语句产出空类型。

§4.9.3.3 用作表达式时**应当**有 `else` 分支，否则在某些路径下整体值未定义，属编译期错误。

§4.9.3.4 用作语句时（不取值）`else` 可省；详见 §5.4。

§4.9.3.5 任意 `statementBlock` 末尾以 `ret` 或 `#NoReturn` 调用结尾时，该 arm 视为**流终止**，不参与表达式类型合并，也不要求与其它 arm 类型一致（§4.9.1.4 同条款）。

## §4.10 数组与对象构造

### §4.10.1 数组字面量（exprArray）

§4.10.1.1 形态：`[e1, e2, ..., eN]`，最外层方括号；空数组 `[]` 合法。

§4.10.1.2 元素类型推断：

- 若上下文存在显式靶向类型（如 `var arr [i32 * 3] = [1, 2, 3]` 或 `var a Array<i32> = [1, 2, 3]`），各 `eN` 须可赋值给元素类型。
- 否则按各 `eN` 类型的最具体公共类型，无公共类型属编译期错误。

§4.10.1.3 `[T * N]`（固定大小数组）与 `Array<T>`（堆句柄）由靶向类型决定：前者栈分配按值复制，后者堆分配 RC（§9）。

§4.10.1.4 靶向类型递归下传：当外层靶向类型为 `Array<U>` 且某个 `eN` 自身是数组字面量时，该字面量按 `Array<U>` 编译（堆句柄、§9 RC），不被自身元素类型推断为 `[U * N]` 固定数组。`Array<Array<T>>` 等任意嵌套形态同此规则递归。

### §4.10.2 数组填充字面量（exprArrayInit）

§4.10.2.1 形态：`[v ...]` 或 `[v ... T]`。

§4.10.2.2 `v` 须为 `literal`（不接受任意表达式）。

§4.10.2.3 元素类型由 `T`（如显式标注）或上下文推断决定；填充长度由靶向数组类型决定。

### §4.10.3 用户结构体构造

§4.10.3.1 v1 构造唯一通道（§7.3 / §7.10）：

- **`#Static fn` 工厂调用**：`Point::make(1.0, 2.0)`，匹配 `Point` 类型 struct body 内名为 `make` 的 `#Static fn`。
- **`Self { .field = expr ... }` 字段字面量**：仅在 `#Static fn` 体内合法（§7.10.3.4），用于工厂体内产出本类型值。

构造函数（与结构体同名的实例方法 `fn Point(...)`）形态 spec-unify v1 已删除；调用方一律走 `Type::factory(...)` 静态调用。

## §4.11 Lambda 字面量

lambda 字面量是 `fn(T)R` 类型（§3.11）的值表达式。本节规范其形态、形参 / 返回类型推断与体表达式约束；运行时表示与捕获语义见 §6.5.5 / §8.7.6。

### §4.11.1 形态

```yux
; --- 表达式形（单表达式体；表达式可含 if / match，§4.11.4） ---
x => expr                          ; 裸单参；类型 / 返回类型均上下文推断
(x i32) => expr                    ; 括参 + 无返回标注 → void
(x i32) i32 => expr                ; 括参 + 显式返回类型
(a, b) => expr                     ; 多参裸列；上下文推断
(a, b) i32 => expr                 ; 多参括参 + 显式返回
(a i32, b i32) i32 => expr         ; 全显式

; --- 块形（语句序列体） ---
{ x => body }                      ; 裸单参
{ a, b => body }                   ; 裸多参
{ a i32, b i32 => body }           ; 全显式（参数组糖同 §6.2：{ a, b i32 => body }）
{ (a, b) i32 => body }             ; 块形也可用括参 + 显式返回
{ body }                           ; 0 参；禁写 =>
```

§4.11.1.1 lambda 字面量是**表达式**，与 `fn` 声明（§6.1）不同：声明产出顶层 / `structImpl` 中具名符号；字面量产出值类型 `fn(T)R` 的值。

§4.11.1.2 0 参 lambda **禁写** `=>`；`=>` ⇔ "≥1 参 lambda"。`{ }` 是 0 参空体 lambda（返回类型为 void）。

§4.11.1.3 表达式形与块形互不可省：表达式形仅含单表达式体，块形含 0..N 条语句序列；二者通过 `=>` 后是否带 `{` 区分。

§4.11.1.4 不引入 `it` 隐式参数名。

### §4.11.2 形参类型推断

lambda 形参形态：`name` 或 `name type`。**类型可省时由"期望函数类型"反推**：

```yux
fn op(fun fn(a, b i32)i32) i32 = fun(1, 2)

; 期望类型 fn(a, b i32)i32 → a / b 推断为 i32
op({ a, b =>
    a + b
})
```

§4.11.2.1 类型上下文来源（与 §3.4 / §3.6 既有推断风格一致）：

- 赋值的变量类型：`var f fn(i32)i32 = x => x + 1` ✅
- 形参传入的类型：`op({ a, b => ... })` ✅
- 返回值类型：`fn make() fn(i32)i32 { ret (x i32) i32 => x + 1 }` ✅
- 无上下文：`var f = x => x + 1` ❌ 编译错（与 §3.6.1.3 `null` 字面量同构）

§4.11.2.2 可混写：`{ a, b i32 => ... }` 合法，与 §6.2.1.1 fn 声明的参数组糖正交。

### §4.11.3 返回类型规则

| 形态 | 参数列表形式 | 返回类型 | 行为 |
|---|---|---|---|
| `x => expr` | 裸（无括号） | 上下文推断 | 推断成功即合法，否则 [E40xx] |
| `(x i32) => expr` | 括号（任意 arity） | **默认 void**（不写即 void） | body `expr` 视作语句位置丢弃 |
| `(x i32) i32 => expr` | 括号 | 显式 `i32` | body 求值结果须可赋值给 `i32` |
| `{ a, b => body }` | 裸 | 上下文推断 | 同表达式形 |
| `{ a, b i32 => body }` | 裸 | 上下文推断 | 类型混写允许 |
| `{ (a, b) i32 => body }` | 括号 + 显式返回 | 显式 `i32` | 同表达式形 |
| `{ (a, b) => body }` | 括号 + 无返回 | void | 同表达式形 |
| `{ body }` | 0 参 | 上下文推断 | `=>` 禁写 |

§4.11.3.1 *为何裸 vs 括号差异化*：括号形态是"完整声明形"（自描述）—— 不写返回类型即视作刻意 void；裸形态是"轻量推断形"，留空让上下文驱动。这避免了"括号但缺信息"的歧义。

### §4.11.4 实参 / 字段值位置：参数必须括起来

当 lambda 出现在**调用实参 / 字段赋值 / 别名右侧**等"已有外层 `(...)`"位置且为表达式形时，lambda 自身的多参列表**必须括起来**，否则与 fn 声明 / fn 类型字面量产生歧义：

```yux
; ✅ 合法
op((a, b) i32 => a + b)
op({ (a, b) i32 => a + b })

; ❌ 与 fn 类型字面量歧义
op(a, b => a + b)            ; 看起来像 fn(a, b => a + b)
```

§4.11.4.1 单参裸形 `x => expr` 在实参位置仍合法（单 ID 不与多参 fn 类型字面量歧义），但风格上建议统一括起来。

§4.11.4.2 块形 `{ ... }` 自带定界符，参数列表可裸：`op { a, b => a + b }` 无歧义（§4.8.4 尾随调用糖）。

### §4.11.5 表达式体可含 `if` / `match`

yux 中 `if` / `match` 是表达式（§4.9 / §5.x）。lambda 表达式形的 `expr` 可直接包含：

```yux
val classify = (x i32) String => if x > 0 { "pos" } else if x < 0 { "neg" } else { "zero" }

val tag = (e MyErr) i32 => match e {
    MyErr::Empty   => 0,
    MyErr::Bad(_)  => 1,
}
```

§4.11.5.1 `if` / `match` 自身的分支类型归一与 `else` 兜底由 §4.9 / §5.x 既有条款约束；lambda 不引入新规则。

### §4.11.6 闭包语义

> 本节为闭包捕获模型的规范摘要；完整决议与细则见 `docs/spec/draft/DRAFT-closure-capture.md`（v0.16 已落地）。三档捕获模式（move / retain / borrow）、捕获包 layout、RC 协议、静态检查规则均已定型。

§4.11.6.1 lambda 体引用非形参 / 非全局标识符时，自动构成闭包：捕获语义按外层变量类型推断（§8.7.6.4 / [#18]），不引入显式捕获列表。

§4.11.6.2 lambda 体**不得**对捕获变量赋值（§8.7.6.8 / [#26]）。

§4.11.6.3 含 `T&` 捕获（包括方法体内 lambda 捕获 `$`）的 lambda **不可逃逸**（§8.7.6.5 / §8.7.6.6）。

§4.11.6.4 lambda 返回 `T&` 的允许源集 = 形参为 `T&` 者；捕获来的 `T&` 不进允许源集（§8.7.6.7）。

§4.11.6.5 `Heap<T>` 非空形态在闭包中的捕获行为：stack-scoped `Heap<T>` 按值捕获（B 档 move，§8.7.6.4 表 `Heap<T>` 行）时，outer slot 写 null，env 独占所有权。禁止非空 `Heap<T>` 按值复制捕获（E4024）。

### §4.11.7 不在范围（lambda）

- 泛型 lambda `<T>(x T) => x`（推 v0.x+1，§8.10）。
- `it` 隐式参数名。
- lambda 字面量的方法链 `.compose(g)` 等（走库函数，不进语言核心）。
- `==` / `!=` 比较（§3.11.8）。

## §4.12 错误处理表达式

错误模型（草案）见 [DRAFT-错误.md](draft/DRAFT-错误.md)。本节仅登记表达式形态、类型与优先级；语义细则、诊断码（E7xxx）、调用约束在草案章节。

### §4.12.1 后缀 `!`（exprCall / exprCallTrailingOnly 的 `errPropagate` 槽）

§4.12.1.1 形态：`!` 是 `exprCall` 与 `exprCallTrailingOnly` 末尾的可选 token（产生式中 `errPropagate=SymbolExcl?`），**仅**附在调用末尾，不构成独立产生式。优先级与 `exprCall` 同档（§4.2.1）。非调用位置出现 `!` 由 `exprUnary` 解析为布尔取反（§4.4.3），与错误传播无关。

§4.12.1.2 左侧调用的被调函数**应当**带 `#Fallible(E)`（§6.7）；普通函数后写 `!` 报 [E7001]；外层 `#Fallible(E')` 的 `E' ≠ E` 报 [E7004]。

§4.12.1.3 语义：当前函数体外层不在 `try` 块内时，将左侧调用的失败值原样 `ret` 给上层调用者；要求外层亦为 `#Fallible(E)` 且 `E` 一致。详见 DRAFT §4.2。

§4.12.1.4 在 `try` 块内对 `#Fallible` 调用写 `!` 触发 [E7016]（冗余 `!`），可由 fixit 删去（DRAFT §5）。

§4.12.1.5 与 trailing lambda 协同：`f(a) { x => body }!` 与 `f { x => body }!` 合法（产生式 `exprCall` / `exprCallTrailingOnly` 都带 `errPropagate` 槽）；详见 DRAFT §4.4。

### §4.12.2 `try` 表达式（exprTryCatch）

§4.12.2.1 形态：`'try' statementBlock (catchArm)+`，其中 `catchArm ::= 'catch' ID type statementBlock`（附录 B `catchArm`）。`try` 后**至少**一个 `catchArm`（语法层 `+` 强制；缺 catch 是解析错误，与 [E7009] 同源）。

§4.12.2.2 `try` 块内对 `#Fallible(E)` 函数的**裸调用**自动路由到匹配 `E` 的 `catch` 分支；`catch e Type { ... }` 沿用 yux 后置类型风格（§7.2.2）。

§4.12.2.3 整体类型由 `try` 块尾值与各 `catch` 块尾值取公共类型；某 arm 以 `ret` / `#NoReturn` 调用结尾时按 §4.9.3.5 流终止规则排除该 arm。catch 块尾类型不匹配 try 块类型报 [E7010]。`try` 后无 `catch` 子句报 [E7009]。

§4.12.2.4 `try` 块体内**不**得写 `!`（§4.12.1.4）；catch 子句覆盖范围与穷尽性、`E` 嵌套形态见 DRAFT §5。

## §4.13 移入赋值表达式 `a <- b`（exprMoveAssign）

### §4.13.1 形态与优先级

§4.13.1.1 形态：`a <- b`，其中 `a` 与 `b` 均为 `expr`。产生式标签 `exprMoveAssign`，优先级最低（§4.2.1 等级 21），右结合。

§4.13.1.2 `<-` 是**表达式**（非语句），与 `a = b`（语句级赋值，§5.2）分工：
- `a = b`：原地修改 LHS 槽内容，整体类型 `void`，不产生值；
- `a <- b`：移出旧值、写入新值、**返回旧值**作为表达式结果，整体类型为 LHS 的类型。

### §4.13.2 语义

§4.13.2.1 求值顺序（§4.1.1）：LHS 先于 RHS。

§4.13.2.2 **左值约束**：`a` 必须为合法 lvalue。当前支持：
- 局部变量名；
- `$`（当前实例引用）；
- 结构体字段访问 `expr.ID`（如 `$.field`、`s.field`）；
- 元组成员 `expr.0`、`expr.1` 等。

索引 `a[i]` 暂不在支持范围。

§4.13.2.3 **类型规则**：结果类型为 `a` 的类型（即旧值的类型）；RHS `b` 的类型须可赋值给 `a` 的类型（§3.4.2），否则报 E3001。

§4.13.2.4 **RC 所有权协议**（详见 §8.7.7）：
- 旧值从 LHS 移出时**不**额外 retain：ownership 从 LHS 槽直接移交给表达式结果；
- 新值写入 LHS 前，若为新鲜临时（构造/调用返回值）则直接消费；否则 retain（LHS 成为新 owner）；
- 若 LHS 类型含 RC 字段，结果旧值记入临时帧（recordTemp），作用域末尾正常 release。

§4.13.2.5 **与 `Heap<T>?` B 档 move 的关系**：`<-` 是通用移入机制，适用于**任意类型**（标量、Rc、Heap、struct 等）。`Heap<T>?` 的 B 档 nullable move（§8.3a.4.2）是调用点按值传参时的自动 move-out，不与 `<-` 重叠；两者在 RC 所有权管理上走同一套"ownership 转移、跳 retain"协议。

### §4.13.3 用例

```yux
; 标量 swap
#Mut let a i32 = 10
#Mut let b i32 = 20
let old = a <- b        ; old = 10, a = 20, b = 20

; 堆句柄交换（无 double-free：旧值 ownership 转给 old）
#Mut let x = Rc:<Point>(1, 2)
#Mut let y = Rc:<Point>(3, 4)
let prev = x <- y       ; prev 持有原 x 的 Rc, x 现在指向 y 的 Rc

; 配合方法调用
let prev = $.buf <- Rc:<Buffer>(64)
; prev = 旧 buf（返回值），$.buf = 新 Buffer

; 字段级移入
let old_field = s.f <- Rc:<Data>(...)
```
