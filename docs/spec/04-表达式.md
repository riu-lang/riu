# §4 表达式

本章规范 yux 表达式（`expr` 产生式）的求值语义、优先级与结合性。语法形态见 §2 / [附录 B §B.6](附录B-语法汇总.md#b6-表达式按-yuxg4-中-expr-的分支顺序决定优先级)；内置类型相关的表达式语义见 §9；与所有权 / 借用 / RC 相关的细节见 §8。

## §4.1 求值顺序

### §4.1.1 子表达式求值

§4.1.1.1 二元运算符与函数调用的实参按**从左到右**严格求值。即在 `f(a, b, c)` 中，`f` 先于 `a`，`a` 先于 `b`，`b` 先于 `c`。

§4.1.1.2 字段链 `a.b.c`、索引链 `a[i][j]`、调用链 `f()()` 沿语法树自左至右求值。

§4.1.1.3 短路运算 `&&` / `||`、`??`、`?.` 的右侧在左侧不能确定结果时**才**求值（§4.4.3 / §4.6）。

### §4.1.2 临时值寿命

§4.1.2.1 表达式求值产生的中间结果（特别是堆句柄类型 `Box<T>` / `Array<T>` / `String` / `Weak<T>`）称为**临时值**（temporary）。

§4.1.2.2 临时值寿命延伸至其所在**语句 / 顶层表达式 / 代码块**的边界；边界处所有未消费的临时值统一 release（详见 §8.6 临时值清单）。

§4.1.2.3 receiver 与字段访问只是**借用**临时值，不消费它（不夺所有权）。

§4.1.2.4 `T&` **不得**绑定临时值；该约束由 §8.4 的寿命规则保证（临时值的"作用域"是当前语句或表达式，比任何 `var` 声明都小）。

### §4.1.3 副作用点

§4.1.3.1 yux v1 仅以下表达式具有副作用：函数调用、方法调用、`exprSet` 经语句（§5.2）、构造函数体内的字段写入（§7）。

§4.1.3.2 任何副作用的**可观测**顺序遵循 §4.1.1 的左→右规则。

## §4.2 优先级与结合性

### §4.2.1 优先级表

下表按 `yux.g4` 的 `expr` 产生式自上至下排列，**位置越靠前优先级越高**。同一行视为同一优先级。

| 等级 | 产生式 | 示意 | 结合性 |
|---|---|---|---|
| 1 | `exprParen` | `(e)` | — |
| 2 | `exprGetRef` | `&obj.f.g` | — |
| 3 | `exprGet` | `e[i, j]` | 左结合 |
| 4 | `exprOneLineIfElse` | `if c { a } else { b }` | — |
| 5 | `exprIfElsePreValue` | `a if c else b` | 右结合 |
| 6 | `exprIfElse` | `if c { ... } elif ... else { ... }` | — |
| 7 | `exprArrayInit` | `[v ... T?]` | — |
| 8 | `exprDot` | `e.f` / `e?.f` | 左结合 |
| 9 | `exprArray` | `[e1, e2, ...]` | — |
| 10 | `exprCall` | `f(args)` / `f:<T>(args)` | 左结合 |
| 11 | `exprUnary` | `-e` / `~e` / `!e` | 右结合 |
| 12 | `exprShift` | `e << e` / `e >> e` | 左结合 |
| 13 | `exprBinOp` | `e & e \| e ^ e` | 左结合 |
| 14 | `exprMulDivMod` | `e * e` / `e / e` / `e % e` | 左结合 |
| 15 | `exprAddSub` | `e + e` / `e - e` | 左结合 |
| 16 | `exprCompare` | `e < e` / `e <= e` / `e > e` / `e >= e` | 左结合 |
| 17 | `exprEq` | `e == e` / `e != e` | 左结合 |
| 18 | `exprBool` | `e && e` / `e \|\| e` | 左结合 |
| 19 | `exprLiteral` | 字面量 / `ID` | — |
| 20 | `exprNullElse` | `e ?? e` | 右结合 |
| 21 | `exprThis` | `$` | — |

> *informative*：移位 `<< >>` 优先级**高于**位运算 `& | ^`（与 C / Rust 同向）。`docs/基础语法.md` 的优先级小节如有不一致，应以本表 / `yux.g4` 为准并同步。

### §4.2.2 圆括号

§4.2.2.1 `(e)` 不改变 `e` 的类型与值，仅改变解析优先级。

§4.2.2.2 圆括号在调用 `f(args)` / 形参列表 `(p T)` 中是分隔符，不构成 `exprParen`。

## §4.3 字面量与原子表达式

### §4.3.1 字面量

§4.3.1.1 `exprLiteral` 直接产出对应类型的值，类型推断规则见 §3.5 / §3.6.4。

§4.3.1.2 `literalObj`（即 `ID`）按 §10 的解析规则查找：
- 局部变量 / 形参 / receiver 字段（通过 `$` 隐式）；
- 当前模块中的 `cval`、`fn` 名；
- 通过 `imports` 引入的外部名。

§4.3.1.3 字符串字面量 `STR_LINE` / `STR_LINE_RAW` 编译为只读段中的 `String`，RC 头哨兵为 `0xFFFFFFFF`（§8.2.5）。

§4.3.1.4 整数 / 浮点字面量的位宽推断按 §3.5；整数字面量在赋给具体类型上下文时按位截断 / 扩展行为是**编译期错误**，需通过显式后缀（`100u8`）或 `to_*` 方法（§3.5.2）。

§4.3.1.5 双引号字符串字面量 `"..."` 同时承载**纯字符串**与**字符串模板**两种形态，语法上由产生式 `stringTemplate` 统一描述（见附录 B）：

```
stringTemplate : '"' templatePart* '"'
templatePart   : STR_TPL_TEXT                       # 纯文本片段
               | STR_TPL_DOLLAR_ID                  # $ident 单标识符插值
               | STR_TPL_INTERP_OPEN expr '}'       # ${expr} 表达式插值
```

构造规则：
- `$ident` 形式中 `ident` 紧跟 `$`，不得有空白；`ident` 须满足 `ID` 的首字符约束（不允许以数字、运算符、空白起始）。
- `${ ... }` 内为完整 `expr`（§4 全部表达式产生式），词法上允许嵌套 `{}`（lexer 用 `interp_brace_depth` 平衡跟踪），结束于配对的 `}`。
- 不允许跨行：`STR_TPL_TEXT` 不接受 `\r` / `\n`；多行字符串属未来扩展。

§4.3.1.6 字符串模板的转义规则在 `STR_TPL_TEXT` 片段内生效（与 §1.x 普通字符串字面量一致），并新增 `\$` 一项：

| 转义 | 含义 |
|------|------|
| `\n` `\r` `\t` `\0` | 控制字符 |
| `\\` `\"` | 反斜杠 / 引号 |
| `\$` | 字面 `$` 字符（**不**触发插值） |
| `\xNN` | 1 字节 |
| `\uNNNN` | 1 个 BMP 码点 |

未列出的 `\X` 形式按 `X` 字面追加（与现行实现一致）。`r"..."`（`STR_LINE_RAW`）仍走旧路径，**不参与模板解析**，`$` 在 raw 字符串内永远是字面字符。

§4.3.1.7 求值与 lowering：
- 不含任何插值（仅 `STR_TPL_TEXT` 片段，或为空字符串）的模板，在 AST 构造期降级为 `LiteralStringNode`，与 §4.3.1.3 完全一致。
- 含插值的模板被构造为 `StringTemplateNode`，其不变量为 `parts.size() == interps.size() + 1`，交替序列 `parts[0], interps[0], parts[1], ..., parts[N]`。
- 含插值模板的 codegen 行为在 v0.6 Phase 2 落地（lower 为 `StringBuilder` 链式 `append`，详见 `CHANGELOG`）；在 Phase 1 仅完成 AST / 类型形态。

### §4.3.2 `$`（exprThis）

§4.3.2.1 `$` 表示当前作用域的接收者：

- 在结构体方法体内（含构造函数）：`$` 类型为 `Self&`（§7.3）。
- 在普通函数体内：`$` **不得**出现。

§4.3.2.2 `$.field` 访问当前对象字段；`$.method(args)` 调用当前类型的方法。

§4.3.2.3 构造函数中 `$` 的特殊语义见 §7.4 与 §8.7（DAA、不可逃逸）。

## §4.4 算术与位运算

### §4.4.1 算术运算（`exprAddSub` / `exprMulDivMod`）

| 运算 | 操作数类型 | 结果类型 | 语义 |
|---|---|---|---|
| `e1 + e2` | 同种整数 / 浮点 | 同左 | 数值加 |
| `e1 - e2` | 同种整数 / 浮点 | 同左 | 数值减 |
| `e1 * e2` | 同种整数 / 浮点 | 同左 | 数值乘 |
| `e1 / e2` | 同种整数 | 同左 | 整数除（向零截断） |
| `e1 / e2` | 同种浮点 | 同左 | IEEE 754 浮点除 |
| `e1 % e2` | 同种整数 | 同左 | 整数取余（与 `/` 同向截断） |

§4.4.1.1 操作数类型**应当**完全一致（含位宽与符号）；不存在隐式扩展（§3.5）。混合类型需先 `.to_*()`。

§4.4.1.2 整数溢出按 LLVM `add` / `sub` / `mul` / `sdiv` / `udiv` / `srem` / `urem` 的二进制补码语义截断；`-INT_MIN`、整数除零、整数 `% 0` 行为由 LLVM 决定，规范不保证 panic。

§4.4.1.3 浮点除零、`0.0 / 0.0`、`Inf - Inf` 行为遵从 IEEE 754（产生 ±Inf 或 NaN）。

§4.4.1.4 `String + String` 在 v1 暂未规范化为 `+` 运算符；字符串拼接走 `String` / `StringBuilder` 方法（§9）。`+` **不得**用于字符串（编译期类型不匹配）。

### §4.4.2 位运算（`exprBinOp` / `exprShift`）

| 运算 | 操作数类型 | 结果类型 | 语义 |
|---|---|---|---|
| `e1 & e2` | 同种整数 / `bool` | 同左 | 按位与 |
| `e1 \| e2` | 同种整数 / `bool` | 同左 | 按位或 |
| `e1 ^ e2` | 同种整数 / `bool` | 同左 | 按位异或 |
| `e1 << e2` | 同种整数 | 同左 | 左移；`e2` 须为无符号或非负 |
| `e1 >> e2` | 整数 | 同左 | 算术 / 逻辑右移：有符号操作数走算术右移（保符号位），无符号走逻辑右移 |

§4.4.2.1 `bool` 上的 `&` / `|` / `^` 是**非短路**布尔运算（与 `&&` / `||` 区别）。

§4.4.2.2 移位次数 `e2` 大于等于操作数位宽时行为遵从 LLVM `shl` / `lshr` / `ashr`（结果未定义而非 panic）。

§4.4.2.3 移位 `<< >>` 优先级**高于**位运算 `& | ^`（同 C / Rust），由 `yux.g4` 中 `exprShift` 早于 `exprBinOp` 保证。

### §4.4.3 一元运算（`exprUnary`）

| 形态 | 操作数类型 | 结果类型 | 语义 |
|---|---|---|---|
| `-e` | 整数 / 浮点 | 同左 | 数值取反 |
| `~e` | 整数 | 同左 | 按位取反 |
| `!e` | `bool` | `bool` | 逻辑取反 |

§4.4.3.1 操作符与操作数之间**不得**有空格（`-1` 是 `exprUnary`，`- 1` 不被该产生式接受；详见 §1.7.3）。

§4.4.3.2 `-e` 中 `e` 为无符号整数（如 `u32`）属类型错误；需先 `to_iN()`。

§4.4.3.3 `~bool` 不合法（`bool` 上请用 `!`）。

## §4.5 比较与逻辑运算

### §4.5.1 比较（`exprCompare`）

§4.5.1.1 `<` `<=` `>` `>=` 接受同种整数或同种浮点操作数，结果类型 `bool`。

§4.5.1.2 浮点比较遵从 IEEE 754：`NaN < x` / `NaN > x` / `NaN == x` 均为 `false`；`NaN != x` 为 `true`。

§4.5.1.3 比较运算**不**支持链式（`a < b < c` 解析为 `(a < b) < c`，类型错误）。

### §4.5.2 等值（`exprEq`）

§4.5.2.1 `==` 在所有类型上为**内容相等**：

- 内置标量：值相等。
- 用户 `struct`：编译器派生**字段递归** `==`（每个字段递归 `==`）。
- `Box<T>`：自动解引用比 payload 内容（即 `T` 上的 `==`）。
- `Array<T>`：长度相等且各元素递归 `==`。
- `String`：内容逐字节相等。
- `Weak<T>`：v1 **禁用** `==` / `!=`（§3.7、§8.5）；地址比对走 `same_ref`（§4.6.4 / §9）。

§4.5.2.2 `!=` 是 `==` 的逻辑反。

§4.5.2.3 `null` 与 `T?` 的等值通过 `Nullable<T>::has() / get()` 解构后比较；编译器对 `t? == null` 提供编译期常量化为 `!t?.has()` 的等价形式。

### §4.5.3 布尔短路（`exprBool`）

§4.5.3.1 `e1 && e2`：`e1` 求值为 `true` 时再求 `e2`；否则结果 `false`，`e2` 不求值。

§4.5.3.2 `e1 || e2`：`e1` 求值为 `false` 时再求 `e2`；否则结果 `true`，`e2` 不求值。

§4.5.3.3 `&&` 与 `||` 的两侧操作数**应当**为 `bool`。

§4.5.3.4 由于 `&&` / `||` 同属 `exprBool` 一级（无内部分级），混用时**应当**显式加圆括号（`a && (b || c)`）。

## §4.6 Nullable 相关运算

### §4.6.1 `??`（exprNullElse）

§4.6.1.1 形态：`a ?? b`。`a` 类型须为 `T?`；持值返回内层 `T`，空时求 `b` 并返回。

§4.6.1.2 `b` 类型须可赋值给 `T`（§3.4.2）。

§4.6.1.3 `??` 右结合：`a ?? b ?? c` 解析为 `a ?? (b ?? c)`。

### §4.6.2 `?.`（exprDot 中的可选 `?`）

§4.6.2.1 形态：`a?.field`。`a` 类型须为 `T?` 且 `T` 是含 `field` 的结构体；结果类型 `<field 类型>?`。

§4.6.2.2 链式：`a?.b?.c` 解析为 `(a?.b)?.c`，逐级展开。

§4.6.2.3 v1 **不**支持 `a?.method(args)`（语法层不允许）。

### §4.6.3 `null` 字面量

§4.6.3.1 `null` 仅在 `T?` 上下文（赋值、形参、返回值）合法；裸 `null` 在表达式中类型不确定，规范层视为错误。

## §4.7 取址、字段与索引

### §4.7.1 `&expr`（exprGetRef）

§4.7.1.1 形态：`& obj (.subs)*`，其中 `obj` 为 `ID` 或 `$`。即 `&` 仅可作用于：
- `&局部变量` / `&函数参数`；
- `&$.field` / `&$.f.g`；
- `&boxOrId.field.field...`（自动经 Box 解引用，§9）。

§4.7.1.2 `&` 的结果类型：

| 形态 | 结果类型 | 备注 |
|---|---|---|
| `&v`（`v` 类型 `T`） | `T&` | |
| `&$.f` | 字段类型 `&` | |
| `&box`（`box: Box<T>`） | `Box<T>&` | 借用句柄本身，不是 payload（§8.4） |
| `&box.field` | 字段类型 `&` | 自动解引用后取字段，借用绑到 box 句柄存活期 |
| `&arr[i]` | — | **不合法**（`[]` 调用的是 `get` 方法，结果是右值） |
| `&f()` | — | **不合法**（函数返回值是右值临时） |

§4.7.1.3 `&` 的寿命规则：源对象（追到 `&` 的根对象 / `T&` 形参）的**声明作用域**应当 ⊇ 该 `T&` 变量自身的声明作用域（详见 §8.4）。

§4.7.1.4 `&` **不得**作用于 `T&` 变量本身（结果会是 `T& &`，由产生式 / §2.6.1 拒绝）。

§4.7.1.5 `&obj.f.g` 链中 `.` 之前允许换行（产生式 `'&' (ID|'$') (LineEnd* '.' ID)*`），与 §4.7.2.5 的 `exprDot` 链式换行保持一致。

### §4.7.2 字段访问 `e.f`（exprDot）

§4.7.2.1 `e` 为 `T`：在 `T` 的字段表中查找 `f`，结果类型为该字段类型。

§4.7.2.2 `e` 为 `Box<T>`：自动解引用到 `T` 的字段表上分发，等价 `(*e).f`（无显式 `*` 语法，§9）。

§4.7.2.3 `e.f` **不**自动 retain：字段读取只是"借用视角"；只有当读出的值被存进新变量 / 作为参数 / 作为 `ret` 表达式时才按复制语义 retain（§8.5）。

§4.7.2.4 `e?.f` 形态见 §4.6.2。

§4.7.2.5 链式 `.` / `?.` 之前允许 `LineEnd*`（产生式 `expr LineEnd* '?'? '.' ID`），便于多行写法：

```yux
val x = builder
    .with_a(1)
    .with_b(2)
    .build()
```

格式化器规则（*informative*）：默认仅在超 120 列时把 `.` 前换行；用户已**手动**把每个 `.` 前都换行时，格式化器**保留**手写换行不合并。

### §4.7.3 索引访问 `e[args]`（exprGet）

§4.7.3.1 `e[args]` 是 `e.get(args)` 的语法糖，按 §4.8 的方法调用语义求值。

§4.7.3.2 v1 不支持取索引位置的引用（`&arr[i]` 不合法，见 §4.7.1.2）；写入走 `statementSet`（§5.2.3）。

§4.7.3.3 `[` 之后、参数间 `,` 之后、`]` 之前允许 `LineEnd*`，末参允许尾随 `,`：单行 `m[i, j]` 与多行写法语法等价。

## §4.8 调用（exprCall）

### §4.8.1 形态

```
exprCall ::= expr (':' genericDef)? '(' LineEnd*
                 (expr (',' LineEnd* expr)* ','? LineEnd*)? ')'
```

§4.8.1.1 调用左侧 `expr` 须为：
- 函数名（`literalObj` 解析到 `fn`）；
- 方法访问 `obj.method`（语法上是 `exprDot` + `exprCall` 的组合）；
- `Type:<T>(args)` —— 内置或泛型构造函数调用，turbofish 形态。

§4.8.1.2 turbofish `name:<T1, T2>(args)` 用于显式指定泛型实参，避免 `Generic<T>(args)` 解析为比较运算（§2.4 与 `docs/函数.md`）。

### §4.8.2 实参语义

§4.8.2.1 实参按 §4.1.1 从左到右求值。

§4.8.2.2 实参类型须可赋值给形参类型（§3.4.2）。`T&` 形参的实参**应当**显式取址 `f(&x)`，**不**自动加 `&`（详见 §8.6）。

§4.8.2.3 方法调用 `obj.method(args)` 的 receiver 自动以 `Self&` 形式传入；无需写 `&obj`。

§4.8.2.4 调用约定为 callee-clean retain / release（§8.5）：调用方在传堆句柄实参前 retain（计数 +1），被调用方按局部变量析构 release。

§4.8.2.5 `(` 之后、实参间 `,` 之后、`)` 之前允许 `LineEnd*`，末参允许尾随 `,`：

```yux
; 单行
foo(a, b, c)

; 多行
foo(
    a,
    b,
    c,
)
```

`exprArray` （§4.10.1）同此规则。

### §4.8.3 内置函数调用

§4.8.3.1 编译器 baked 的 turbofish 内置函数：

| 名称 | 签名 | 说明 |
|---|---|---|
| `weak:<T>(box Box<T>?)` | `Weak<T>` | 由 Box 构造 Weak（§9） |
| `ptr_of:<T>(obj)` | `Ptr` | 显式转 FFI 指针；T 限定见 §9 / DRAFT §9.4 |
| `same_ref:<T>(a, b)` | `bool` | 地址相等比对（§4.5.2 / §9） |
| `Nullable:<T>(v)` / `Nullable:<T>()` | `T?` | 显式构造 Nullable |

§4.8.3.2 `weak` / `ptr_of` / `same_ref` 不进入 SDK 用户代码；编译器在调用点直接展开。

## §4.9 条件表达式

### §4.9.1 单行 `if-else`（exprOneLineIfElse）

§4.9.1.1 形态：`if cond { trueExpr } else { falseExpr }`。`cond` 类型须为 `bool`。

§4.9.1.2 `trueExpr` 与 `falseExpr` 类型须**完全一致**（无隐式提升）。

§4.9.1.3 整体类型即两分支的公共类型。

### §4.9.2 三元前置（exprIfElsePreValue）

§4.9.2.1 形态：`trueExpr if cond else falseExpr`。语义同 §4.9.1。

§4.9.2.2 `if` 与 `else` 两侧均须有空格（§1.2.3）。

### §4.9.3 块形 `if-elif-else`（exprIfElse）

§4.9.3.1 形态：

```
if cond
  statementBlock
(elif cond
  statementBlock)*
(else
  statementBlock)?
```

§4.9.3.2 当作为表达式使用时（如 `val x = if c { a } elif d { b } else { c }`），每个 `statementBlock` 的"值"为其末尾 `statementExpr`（不带尾随 `;`）的值；带尾随 `;` 的语句产出空类型。

§4.9.3.3 用作表达式时**应当**有 `else` 分支，否则在某些路径下整体值未定义，属编译期错误。

§4.9.3.4 用作语句时（不取值）`else` 可省；详见 §5.4。

## §4.10 数组与对象构造

### §4.10.1 数组字面量（exprArray）

§4.10.1.1 形态：`[e1, e2, ..., eN]`，最外层方括号；空数组 `[]` 合法。

§4.10.1.2 元素类型推断：

- 若上下文存在显式靶向类型（如 `var arr [i32 * 3] = [1, 2, 3]` 或 `var a Array<i32> = [1, 2, 3]`），各 `eN` 须可赋值给元素类型。
- 否则按各 `eN` 类型的最具体公共类型，无公共类型属编译期错误。

§4.10.1.3 `[T * N]`（固定大小数组）与 `Array<T>`（堆句柄）由靶向类型决定：前者栈分配按值复制，后者堆分配 RC（§9）。

### §4.10.2 数组填充字面量（exprArrayInit）

§4.10.2.1 形态：`[v ...]` 或 `[v ... T]`。

§4.10.2.2 `v` 须为 `literal`（不接受任意表达式）。

§4.10.2.3 元素类型由 `T`（如显式标注）或上下文推断决定；填充长度由靶向数组类型决定。

### §4.10.3 用户结构体构造

§4.10.3.1 v1 提供两条路径，均落在 `exprCall` 表层（不另设字面量产生式）：

- **构造函数调用**：`Point(1.0, 2.0)`，匹配 `Point` 类型 `structImpl` 中名为 `Point` 的方法（§7.4）。
- **结构体字面量**（详见 §7.4）：DRAFT 中规划的 `Point { x: 1.0, y: 2.0 }` 形态在 v1 语法层暂未启用；以构造函数为准。

§4.10.3.2 构造调用受 §7.4 DAA（定性赋值分析）规约。
