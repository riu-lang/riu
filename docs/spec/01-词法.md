# §1 词法

本章规范 yux 源文件的字符级与词法级结构，规定从字节流到 token 流的解析行为。语法结构（产生式）见 §2，权威来源为 [`yux/ast/yuxLexer.g4`](../../yux/ast/yuxLexer.g4)。

## §1.1 字符集与编码

- §1.1.1 源文件**应当**采用 UTF-8 编码，**不得**使用 BOM。
- §1.1.2 行结束符识别 `\n`、`\r\n`、`\r`、以及文件末尾（`EOF`）；产生式中以 `LineEnd` 表示，参见 §1.2。
- §1.1.3 标识符与字符串字面量允许任意 Unicode 字符，受 §1.4 / §1.6.4 各自限制。

## §1.2 空白与换行

- §1.2.1 空白字符仅指空格 `U+0020`（`Space`）；制表符 `\t` 不是合法的源文件空白字符，**不得**作为缩进或对齐使用（*informative*：编辑器替换为空格即可）。
- §1.2.2 换行（`LineEnd`）是**有意义**的语法符号：
  - 顶层声明、语句、`codeLineEnd` 由 `LineEnd` 终结（§2）。
  - 整行空白行（`EmptyLine`）被丢弃到 HIDDEN 通道，不影响语法。
- §1.2.3 关键字与其后跟随的标识符 / 表达式之间**应当**至少有一个空格；二元运算符两侧**应当**各有至少一个空格；`(` `[` 内紧贴第一个 token、`)` `]` 紧跟最后一个 token；`,` 后**应当**有一个空格。
- §1.2.4 不满足 §1.2.3 但能被词法器拆分的输入（例如 `1+2`），是否被语法接受由 §2 各产生式的实际匹配决定；规范层不对此放宽要求。

> *informative*：§1.2.3 的"应当"由风格审校保证，词法器不对所有违反场景都报错；但"关键字后无空格"会因关键字与标识符黏连而被识别为不同的 token。

## §1.3 注释

yux 的注释一律以 `;` 起始，分两类，由所在列位置区分：

- §1.3.1 **顶行注释（`LineComment`）**：行首（允许任意空格缩进，但行首列应当是 `;` 或空格）后第一个非空白字符为 `;`，注释延伸至行尾，包括尾随的 `LineEnd`。
- §1.3.2 **尾随注释（`LineEndComment`）**：在代码行内、与前驱 token 之间至少有一个空格后出现 `;`，注释延伸至行尾但**不**消费 `LineEnd`。
- §1.3.3 注释体内的所有字节均不参与后续词法分析；不支持块注释 / 嵌套注释。

```yux
; 顶行注释（informative）
fn some() {
    ; 缩进的顶行注释也是 LineComment
    println(1) ; 尾随注释
}
```

## §1.4 标识符

- §1.4.1 标识符（token `ID`）由两部分组成：
  - **首字符**：任意非以下字符的 Unicode 字符——
    `U+0021..U+0040`（即 `!"#$%&'()*+,-./` 与 `0..9 :;<=>?@`）、
    `U+005B..U+005E`（`[\]^`）、
    `` U+0060 ``（`` ` ``）、
    `U+007B..U+007F`（`{|}~` 与 DEL）、
    Unicode `White_Space`。
  - **后续字符**：在首字符限制基础上**额外**排除 `U+002F..U+0039` 等数字与符号区，使得 `_` 等 ASCII 下划线允许出现于后续位置。
- §1.4.2 标识符大小写敏感。
- §1.4.3 以下划线 `_` 起始的标识符具有**模块私有**可见性（§10）；规范层不对其余命名风格作硬性要求。
- §1.4.4 关键字（§1.5）保留，**不得**用作标识符。

> *informative*：实际 ANTLR 产生式见 `yux.g4` 中 `ID` lexer 规则；上文按其字符区间复述。允许中文、希腊字母等识别符，例如 `结构体名`、`λ` 合法。

## §1.5 关键字与保留字

- §1.5.1 yux 的关键字集合（与 [附录 A](附录A-保留字.md) 同步、与 `yux.g4` 一致）：

  `break`、`catch`、`elif`、`else`、`enum`、`extern`、`false`、`fn`、`if`、`let`、`loop`、`match`、`null`、`ret`、`Self`、`struct`、`true`、`try`、`use`。

- §1.5.2 关键字**不得**作为标识符出现（§1.4.4）。
- §1.5.3 旧 `var` / `val` / `cval` 关键字已在 let-unify 落地时从 lexer 移除（附录 A §A.1.1）；局部 / 全局变量声明统一由 `let` + inline 注解 `#Mut` / `#Cval` / `#Frozen` 引入（§5.1），字段段由 `#注解 + name T` 形态声明（§7.1）。
- §1.5.4 当前未保留 `continue`、`return`、`type` 等其它常见关键字；将来引入新关键字时**应当**在本节及附录 A 中同步声明。

## §1.6 字面量

字面量产生式见 `yux.g4` 的 `literal` 规则。

### §1.6.1 整数字面量

- §1.6.1.1 形态：`INT ::= NUN_SIGN? base INT_SUFFIX?`，其中：
  - `NUN_SIGN`：可选 `+` / `-`。
  - `base` 之一：
    - `INT_10`：十进制，首字符 `0..9`，可用 `_` 分组（`1_000`）。
    - `INT_2`：`0b` 前缀 + `[01]`，可用 `_` 分组。
    - `INT_8`：`0o` 前缀 + `[0-7]`，可用 `_` 分组。
    - `INT_16`：`0x` 前缀 + `[0-9a-fA-F]`，可用 `_` 分组。
  - `INT_SUFFIX`：`[iu]('8'|'16'|'32'|'64'|'size')`，例如 `i32`、`u8`、`usize`、`isize`。
- §1.6.1.2 字面量的类型由后缀决定；无后缀的整数字面量类型在表达式上下文中由类型推断（§3）确定，默认靶向类型为 `i32`（与编译器实现一致）。
- §1.6.1.3 字面量值溢出其声明类型（如 `300i8`）的行为属编译期错误。

### §1.6.2 浮点字面量

- §1.6.2.1 形态：`FLOAT ::= NUN_SIGN? (INT_10 | FLOAT_DOT | FLOAT_EXP) FLOAT_SUFFIX?`，其中：
  - `FLOAT_DOT ::= INT_10 '.' INT_10`（要求小数点两侧均存在数字）。
  - `FLOAT_EXP ::= FLOAT_DOT 'e' '-'? INT_10`。
  - `FLOAT_SUFFIX ::= 'f' ('32' | '64')`，例如 `1.5f32`、`2.0f64`。
- §1.6.2.2 仅 `INT_10` 主体的浮点字面量应当带 `FLOAT_SUFFIX`，否则将被识别为整数字面量。
- §1.6.2.3 类型推断默认靶向 `f64`。

### §1.6.3 布尔字面量

- §1.6.3.1 关键字 `true`、`false`，类型 `bool`。

### §1.6.4 字符串字面量

- §1.6.4.1 **普通字符串 `STR_LINE`**：`"..."`，单行；允许的转义序列为：
  - `\n` 换行、`\t` 制表、`\r` 回车、`\0` 空字符、`\\` 反斜杠、`\"` 双引号、`\'` 单引号、`\v` 垂直制表、`\b` 退格。
  - 词法器接受任何 `\<char>`（`'\\'.`），但语义层仅承认上述转义；其它序列视为错误。
- §1.6.4.2 **原始字符串 `STR_LINE_RAW`**：`r"..."`，单行，**不**处理转义；体内所有字符按字面采纳，但仍**不得**包含换行 `\r` / `\n`。
- §1.6.4.3 字符串字面量的类型为 `String`（§9），存储于只读段并以哨兵 RC 头标记（§8）。
- §1.6.4.4 跨行字符串、模板字符串、字符串拼接 `"a" "b"` 自动拼接均不在 v1 范围内。

### §1.6.5 代码点字面量

- §1.6.5.1 形态 `CODE_POINT ::= 'c' '\'' ( '\\' [bnrtv0\\'] | <single non-CR/LF/\\/'> ) '\''`，例如 `c'A'`、`c'\n'`、`c'中'`。
- §1.6.5.2 类型为 `u32`，值为该代码点的 Unicode 标量值。
- §1.6.5.3 字符字面量内部仅允许单个码点；多字节 Unicode 字符按整数代码点收纳。

### §1.6.6 数组字面量

数组字面量的语法形态属于表达式（`exprArray` / `exprArrayInit`，见 §4），不在 `literal` 产生式之内；本节仅出于完整性提示其形态：

```
[e1, e2, e3]                ; exprArray
[0u8 ...]                   ; exprArrayInit，元素类型由变量类型决定
[0 ... i32]                 ; 显式标注元素类型
```

详细语义见 §4 与 §9。

### §1.6.7 `null` 字面量

- §1.6.7.1 关键字 `null` 是 `Nullable<T>` 的空值字面量；它本身没有独立类型，应当在 `T?` 上下文中使用（§3.6）。

## §1.7 运算符与标点

§1.7.1 运算符与标点是独立 token，词法形态如下（按 `yux.g4` 的 `Symbol*` 与括号 token 列出）：

| 类别 | 词法 |
|---|---|
| 算术 | `+` `-` `*` `/` `%` |
| 复合赋值 | `+=` `-=` `*=` `/=` `%=` `^=` `\|=` `&=` |
| 比较 | `==` `!=` `<` `<=` `>` `>=` |
| 移位 | `<<` `>>` |
| 移位赋值 | `<<=` `>>=` |
| 位运算 | `&` `\|` `^` |
| 逻辑 | `&&` `\|\|` `!` |
| 引用 / 取址 | `&`（与位与同形，依上下文区分） |
| Nullable | `?` `??` `?.` |
| 解构 | `~`（一元按位取反 / 析构函数 `fn ~()`） |
| 赋值 | `=` |
| 移入赋值 | `<-` |
| 成员 / 调用 | `.` `:` `,` `;` |
| 注解 | `#` |
| 分隔符 | `(` `)` `[` `]` `{` `}` |
| 当前作用域 | `$` |

§1.7.2 多字符运算符（如 `==`、`<<=`）按最长匹配规则识别。`<<=` 由产生式 `opAssign: SymbolMt SymbolMt SymbolEq` 拼接而成（同理 `>>=`、`<<`、`>>`），即词法层并不预合成 `<<` / `<<=`；语法层据此组合（见 §2.4）。

§1.7.3 一元运算符 `-` / `~` / `!` 与其操作数之间**不得**有空格（参见 §4 `exprUnary`），否则会被解析为二元 `-` 或语法错误。
