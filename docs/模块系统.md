# 模块系统

本文档介绍 yux 的项目布局、模块导入、可见性约定与 SDK 协作。规范层条款见 `docs/spec/10-模块系统.md`。

## 项目结构

### `yux.toml`

项目根由 `yux.toml` 标记：

```toml
name = "myproject"
version = "1.0.0"
entry = "main.yux"
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 项目 / 产物名 |
| `version` | ✅ | 版本号 |
| `entry` | 可执行项目必填 | 入口源文件，**相对源根** |
| `[lib].type` | 库项目用 | 如 `"static"`（见 SDK 自举示例） |
| `[link].libs` | 否 | 链接时追加的系统库名数组（不含 `.lib` 后缀），如 `["user32", "shell32"]` |

库项目（如 SDK 自举）：

```toml
name = "yux"
version = "1.0.0"

[lib]
type = "static"
```

需要链接系统库时，使用 `[link]` 段：

```toml
name = "myproject"
version = "1.0.0"
entry = "main.yux"

[link]
libs = ["user32", "shell32"]
```

### 源根 `src/`

模块解析的起点称为**源根**：

- 若 `<projectRoot>/src/` 存在且为目录，源根 = `<projectRoot>/src/`；
- 否则源根回退为 `<projectRoot>/`。

`entry` 字段相对源根：典型 `entry="main.yux"` 表示 `<src>/main.yux`。

> ⚠️ 当前编译器对 `entry` 不做严格校验（绝对路径 / 逃出 `src/` 都静默通过，见 BUGS.md）。约定上 **`entry` 只写纯文件名**（如 `main.yux`），不要带 `../` 或绝对路径。

### 项目结构示例

```
myproject/
├── yux.toml
├── src/                       ; 源根
│   ├── main.yux               ; 由 entry 指向
│   ├── math.yux
│   └── ops/
│       ├── pkg                ; 包再导出清单（无后缀文本文件）
│       ├── add.yux
│       └── sub/
│           └── inner.yux
└── build/                     ; 构建产物
    ├── myproject.exe          ; 最终产物（可执行）或 myproject.lib（静态库）
    └── src/                   ; 中间产物：镜像 src/ 目录树
        ├── main.obj
        ├── math.obj
        ├── src.cache
        └── ops/
            ├── add.obj
            ├── ops.cache
            └── sub/
                ├── inner.obj
                └── sub.cache
```

## 构建命令

项目模式必须在 `yux.toml` 所在目录执行：

```powershell
yux build            ; 等价于 yux build <toml-name>
yux build <name>     ; 显式给出时必须与 toml 的 name 一致（防误编译校验）
```

最终产物：`<projectRoot>/build/<name>.exe`（可执行项目）或 `<projectRoot>/build/<name>.lib`（静态库）。

中间产物 (obj / IR) 按源文件相对项目根的路径镜像到 `build/`，如 `src/main.yux` → `build/src/main.obj`、`src/utils/math.yux` → `build/src/utils/math.obj`。每个目录视为一个包，目录内 `.yux` 的元信息聚合到该目录下的 `<dirname>.cache` 增量缓存：首行为编译器指纹（重 build `yux` 后自动失效），后续每行 `<filename>\t<src-mtime-ns>\t<src-size>`。删除某个 `build/src/<dir>/` 子目录会清掉该包的 obj 与缓存，下次构建该包全量重编。

> 单文件模式（`yux input.yux`，忽略 `yux.toml`）v1 已弃用，新增代码、示例、文档一律走项目模式。

## 模块导入

### 形态

```yux
use a.b.c           ; 导入文件模块或包模块（末段别名）
use a.b.*           ; 通配：扁平公开成员 + 末段别名
use a.b.MyType      ; 具名类型：把 MyType 注入裸名
use yux.core.*      ; 典型：导入 SDK 内置 println 等（亦可省略：隐式 parent scope）
use yux.io          ; 可选 IO 包；此后才有 io.xxx / yux.io.xxx
use yux.time        ; 可选时间包；此后才有 time.xxx / yux.time.xxx
```

`use` 语句应集中在源文件顶部 `; 注释` 之后，不与其它顶层声明混排。

### 名字解析

`use a.b.c` 解析顺序（按存在性）：

1. `<src>/a/b/c.yux`（**文件模块**）
2. `<src>/a/b/c/`（**包模块**，配合 `pkg` 文件，见下）

同名 `.yux` 与同名子目录并存属冲突，编译器报错。

### `pkg` 文件（包再导出与可见性边界）

包目录可含一个**无后缀**的纯文本文件 `pkg`。有 `pkg` 时清单同时是包外可见性边界：未列出的子模块不能 `use a.c` / `a.c.xxx`。无 `pkg` 时仍可按模块路径访问。同目录兄弟 `.yux` 是包内，不受清单挡。语法要点：

| 行形态 | 语义 |
|---|---|
| 空行 / 仅空白 | 忽略 |
| `;...` 注释行 | 忽略（行首 `;`） |
| `name` / `name as alias` | 公开再导出（有 `as` 则只用别名） |
| `name.*` | 公开扁平再导出；不能写 `name.* as` / `name.* to` |
| `name to t1; t2` / `name as alias to …` | 只对名单内的包 / 模块开放 |

示例 `src/mymath/pkg`：

```
; src/mymath/pkg
add.*      ; 把 add 模块的所有公开成员扁平导出
sub        ; 把 sub 模块作为别名导出
```

调用方：

```yux
use mymath.*
fn main() {
    println(add(10, 5))     ; add 来自 add.yux，扁平
    println(sub.sub(10, 5)) ; sub 作为别名，需 sub.sub
}
```

`pkg` 文件只读，不参与编译；其语法独立于 `.yux`。条款见 `docs/spec/10-模块系统.md` §10.2.4。

### 命名查找顺序

裸名按层：本文件顶层 → `use path.Name` 具名类型 → 通配（含默认 `yux.core.*`）。同层多个不同声明 → 编译报错；上层盖住下层，被盖住的仍可用 `a.Ty` / `yux.core.map.Map` 这类路径。

两个被 `use` 导入的模块导出同名类型时，改用 `use b.Ty` 选定裸名，或始终写 `a.Ty` / `b.Ty`。

### 循环依赖

v1 禁止模块间循环依赖：`a use b` 且 `b use a`（直接或传递）编译报错，错误信息会给出环路（`a -> b -> a`）。

## 可见性

### 默认公开

顶层声明（`fn` / `struct` / `#Cval let` / `extern` 块）默认**公开**，可被其它模块通过 `use` 导入。yux v1 不引入 `pub` / `private` 等修饰符；声明可见性靠 `_` 前缀，子模块对包外的可见性靠 `pkg` 清单。

### `_` 前缀私有

以下划线 `_` 开头的标识符为**私有**，仅在当前模块（同一 `.yux` 文件）可见，跨模块访问编译报错。

```yux
; 私有函数
fn _internal_helper() {
}

; 私有全局常量
#Cval
let _MAX_RETRIES i32 = 3

; 私有结构体
struct _State {
  v i32
}
```

适用范围包括顶层 `fn` / `struct` / 全局常量、结构体方法 / 字段（同模块外不可见）。编译器内部的 runtime helper（`_box_alloc` / `_array_grow` / `_ptr_offset`）也遵循该前缀约定。

`_` 前缀**不**影响同一模块内的可见性，同模块内可自由调用。

`pkg` 文件的再导出**不**穿透私有边界：`_foo` 这类私有符号不可被 `pkg` 文件以 `name.*` 形态再导出。

## SDK 与 `yux.core` / `yux.io` / `yux.time`

`sdk/yux/` 是 yux 的内置 SDK，作为库项目（`[lib] type="static"`）发布。

- **`yux.core`**（`sdk/yux/src/yux/core/*.yux`）：默认隐式 `use yux.core.*`。扁平 `println` / `Map` / `String` 等；路径 `math.abs`、`map.Map`、`yux.core.map.Map`。
- **`yux.io`**（文件模块 `sdk/yux/src/yux/io.yux`）：**必须** `use yux.io` 或 `use yux.io.*`。此后 `io.read_file` / `yux.io.read_file` / `io.IoErr` / `io_err_text`。未 use 时用户可有自己的 `src/io.yux`。
- **`yux.time`**（文件模块 `sdk/yux/src/yux/time.yux`）：**必须** `use yux.time` 或 `use yux.time.*`。此后 `time.sleep` / `yux.time.Duration` / 裸名 `Instant`（仅 `.*`）。未 use 时用户可有自己的 `src/time.yux`。`tick_ms()` 仍在 core。
- 纯类型 / 内置 builtin（`i32` / `String` / `Array<T>` / `same_ref` / `upgrade` 等）由编译器隐式注入命名空间，无需 `use`；
- SDK 中标 `#Builtin` 的声明由编译器内部合成实现，其余按普通用户代码编译。

任何 ABI / RC 协议改动都会触发 SDK 重 build；CI 链路强制 SDK 与编译器同步重 build。

### 用户对内置类型的限制

- 用户**不得**对内置类型新增方法、重载运算符或修改字段；
- 用户**可以**定义与 `yux.core` 扁平符号同名的本文件声明（裸名用自己的；SDK 走 `yux.core.map.Map` 等路径）。
