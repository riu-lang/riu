# pkg 导出与定向开放实施记录

规范：§10.2.4；本轮实现 v0.22 的解析、加载与包边界检查，未改动 g4。

## 解析与加载

- `parsePkgFileAt` 共用解析 `as` / `to`，非法行报 E5020；导出项保留源行号。
- `Yux::visiblePkgItems` 统一计算调用方可见清单。包内按源文件所在目录判断；子目录不属于同包。包外仅公开项及匹配 `to` 的项可见。
- `Yux::resolvePkgPath` 按段将导出名转换为源模块名，逐层检查包边界。源模块身份保留给加载、类型归属和代码生成，调用方别名保持源码书写形式。
- `use`、包通配展开、包孩子预加载、函数点链、类型限定路径共用上述规则。未导出项和改名后的源名报 E5018。
- `to` 目标检查项目源树及已加载依赖；不存在报 E5019，定位到对应 `pkg` 行。此检查不主动加载目标，避免制造循环依赖。
- 同包通过包别名访问自身时复用当前 FileNode；通配展开跳过自身，避免重复注入和伪循环依赖。

## SDK 公开面

- `readSdkPkg` 保留导出名、`name.*` 形态与公开／定向属性；`parseSdkDir` 仍加载 core 下全部非测试模块，但只把公开 `name.*` 加入 `yux.core` parent scope。
- SDK 壳只为公开清单项登记末段别名和 `yux.core.<导出名>` 路径；公开 `name`（如 `math`）可限定访问但不扁平，未列出和仅 `to` 的模块不登记给用户。
- Win32 声明集中到 `helper.yux`，清单写 `helper to yux.io`。core 同包模块和 `yux.io` 显式导入；用户访问 `helper` 报 E5018，裸名／`yux.core.GetStdHandle` 均不可见。
- SDK 自举在解析 core 前登记 `yux.io` 的真实依赖路径，使 E5019 仍按已知依赖严格校验，不为加载顺序放宽规则。

## 增量缓存

- 包级缓存以保留键记录同目录 `pkg` 的修改时间与大小，包含文件不存在的状态；记录变化时，该目录下所有源文件的对象缓存均失效，无需手动清理项目构建目录。
- `pkg_cache_manifest` 在保留首次构建产物的情况下修改 `src/pkg` 并再次构建，断言第二次构建重新发射 IR，覆盖清单变更触发增量失效。
