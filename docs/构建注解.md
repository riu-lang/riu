# 构建注解

构建注解（build annotation）是写在声明前的 `#Name` 标记，用于在**编译期**把额外语义附加到声明上。目前仅供编译器内部使用，没有对外的注解入口（不支持用户自定义注解）。

## 语法

```
#AnnotationName
<声明>
```

- 每条注解单独一行，以 `#` 开头，后跟标识符，再跟换行
- 注解只能附加到以下位置：
  - 顶层函数（`fn`）
  - 结构体方法（`struct` 实现块内的 `fn`）
  - 结构体声明（`struct`）
  - 结构体实现块（`StructName { ... }`）
  - `extern { ... }` 块及其内部函数头（预留）
  - 全局常量 `cval`（预留）
- 未知的注解名会在编译期报错

## 注解列表

### `#CompilerInner`

表示该声明由编译器**内部实现**。

**用在结构体上**：表示该 `struct` 是编译器认识的内置类型，不生成字段/LLVM 结构体。通常用于 `i8..f64`、`bool` 等原始类型的占位声明。

**用在函数/方法上**：表示该函数**没有函数体**，由编译器直接合成实现。最常见的例子是基础类型之间的转换方法 `to_<类型>`。

示例：

```yux
#CompilerInner
struct i32 {
  ; 内部处理
}

i32 {
  #CompilerInner
  fn to_i64() i64

  #CompilerInner
  fn to_bool() bool

  fn to_string() String {
    ; 普通方法有完整函数体
    $.to_i64().to_string()
  }
}
```

带 `#CompilerInner` 的函数**必须**省略函数体。反过来，函数头如果没有函数体，也**必须**带 `#CompilerInner`——否则编译器会报错。

### `#Test`

把一个函数标记为**单元测试**。仅 `yux test` 子命令收集并执行；普通 `yux build` 跳过其编译，不会进入产物。

约束：

- 仅可挂在函数上（顶层 `fn` 或 `struct` 方法）
- 函数签名必须等价 `fn name(): void`：无参数、无返回类型标注
- 必须有函数体；不能与 `#CompilerInner` 同时出现
- **只能写在 `*.test.yux` 文件里**；普通 `.yux` 出现 `#Test` 编译报错

示例（`src/yux/core/arithmetic.test.yux`）：

```yux
#Test
fn add_basic() {
  ; 测试体
}
```

测试文件的模块名 = 在 `src/` 下的相对路径转成点分形式，并保留 `.test` 段。
例：`src/yux/core/arithmetic.test.yux` → 模块名 `yux.core.arithmetic.test`。

`yux test` 命令：

- `yux test` ：跑当前项目下全部测试
- `yux test <prefix>` ：模块名前缀匹配（`yux test yux.core` 命中 `yux.core.*.test`）
- `yux test <module>#<fnName>` ：精确定位某个测试函数

`yux test` 仅在项目模式可用（cwd 须有 `yux.toml`）；当前 v1 同进程顺序执行，无隔离 —— 任一测试崩溃整体退出非零。

## 与 SDK 的关系

`sdk/yux/core.yux` 中 `i8`、`u8`、`i16`、`u16`、`i32`、`u32`、`i64`、`u64`、`f32`、`f64`、`bool` 的占位 struct 以及 `to_<原始类型>` 方法都使用 `#CompilerInner` 标注。编译器据此跳过这些方法的源码编译并合成 LLVM IR 指令（整数扩展/截断、浮点转换、比零等）。
