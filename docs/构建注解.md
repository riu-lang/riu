# 构建注解

构建注解（build annotation）是写在声明前的 `#Name` 标记，用于在**编译期**把额外语义附加到声明上。目前仅供编译器内部使用，没有对外的注解入口（不支持用户自定义注解）。

## 语法

```
#AnnotationName
<声明>
```

- 每条注解单独一行，以 `#` 开头，后跟标识符，再跟换行
- 注解只能附加到以下位置：
  - 顶层函数（`fn`）
  - 结构体方法（`struct` 实现块内的 `fn`）
  - 结构体声明（`struct`）
  - 结构体实现块（`StructName { ... }`）
  - `extern { ... }` 块及其内部函数头（预留）
  - 全局常量（预留）
- 未知的注解名会在编译期报错

## 注解列表

### `#Builtin`

表示该声明由编译器**内部实现**。

**用在结构体上**：表示该 `struct` 是编译器认识的内置类型，不生成字段/LLVM 结构体。通常用于 `i8..f64`、`bool` 等原始类型的占位声明。

**用在函数/方法上**：表示该函数**没有函数体**，由编译器直接合成实现。最常见的例子是基础类型之间的转换方法 `to_<类型>`。

示例：

```yux
#Builtin
struct i32 {
  ; 内部处理
}

i32 {
  #Builtin
  fn to_i64() i64

  #Builtin
  fn to_bool() bool

  fn to_string() String {
    ; 普通方法有完整函数体
    $.to_i64().to_string()
  }
}
```

带 `#Builtin` 的函数**必须**省略函数体。反过来，函数头如果没有函数体，也**必须**带 `#Builtin`——否则编译器会报错。

### `#Test`

把一个函数标记为**单元测试**。仅 `yux test` 子命令收集并执行；普通 `yux build` 跳过其编译，不会进入产物。

约束：

- 仅可挂在函数上（顶层 `fn` 或 `struct` 方法）
- 函数签名必须等价 `fn name(): void`：无参数、无返回类型标注
- 必须有函数体；不能与 `#Builtin` 同时出现
- **只能写在 `*.test.yux` 文件里**；普通 `.yux` 出现 `#Test` 编译报错

示例（`src/yux/core/arithmetic.test.yux`）：

```yux
#Test
fn add_basic() {
  ; 测试体
}
```

测试文件的模块名 = 在 `src/` 下的相对路径转成点分形式，并保留 `.test` 段。
例：`src/yux/core/arithmetic.test.yux` → 模块名 `yux.core.arithmetic.test`。

`yux test` 命令：

- `yux test` ：跑当前项目下全部测试
- `yux test --test-mod <模块名>` ：只编译/运行指定模块的测试（如 `yux test --test-mod yux.core.array`）
- `yux test --threads N` ：指定并行子进程数（默认 CPU 核数）
- `yux test --verbose` ：打印每个测试的 stdout/stderr

`yux test` 流程：`yux build --test` 编译所有测试 DLL → 并行 spawn `yux-test-runner` 子进程（每 DLL 一个独立进程）→ 子进程内顺序执行该 DLL 的全部测试（SEH 包裹异常）→ 汇总 DLL 级 pass/fail。仅在项目模式可用（cwd 须有 `yux.toml`）。
`yux build --test --test-mod <模块名>` 可只编译指定模块的测试 DLL。`yux test --test-mod <模块名>` 同时限制编译和运行范围。

### `#Const`

标记函数为**编译期常量函数**：

- **成员位**：函数体内不得修改 `$` / 参数 / 全局变量，不得调用非 `#Const` fn
- **自由函数 / `#Static fn` 位**：额外承载 **const-eval 通路**——编译期在 sema 阶段对调用点递归求值整个 body，产出编译期常量。要求 body 形态在白名单内（`= expr` / 顺序 const let / if-expr / if-ret），形参/返回类型为值类型（标量 / const struct / `#Builtin` rodata，不接受 `String` / `Rc` / `T&` 等）

```yux
#Const
fn add(a i32, b i32) i32 = a + b

#Const
fn make_point(x i32, y i32) Point {
  ret Point {
    .x = x
    .y = y
  }
}

; 全局 #Cval 可调 #Const fn
#Cval
let TEN i32 = add(4, 6)

#Cval
let ORIGIN Point = make_point(0, 0)
```

> 成员位 `#Const` 语义不变；const-eval 通路仅对自由/静态成员位生效。违反 body 白名单 → `E3141`，形参/返回类型不在白名单 → `E3144`。

### `#Cval`

标记 `let` 声明为**编译期常量**（局部 inline / 全局顶行）：

- 局部 `#Cval let`：初值须为常量表达式（字面量、`#Cval` 引用、算术/位/比较/逻辑运算、`#Const fn` 调用、struct 字面量）
- 全局 `#Cval let`：同上；全局 `let` 必须带 `#Cval`，缺则报 `E3116`

```yux
; 全局（顶行 + 换行）
#Cval
let MAX i32 = 100

; 局部（inline）
fn foo() {
  #Cval let SIZE i32 = MAX * 2
}
```

### `#Mut` / `#Frozen` / `#Val` / `#Static`

- `#Mut`：可变档位。用于局部 `let`（inline）、全局 `let`（顶行）、struct 静态字段（与 `#Static` 组合，顶行）。允许重赋；局部 `let` 还允许延后赋值（无初值）。与 `#Cval` / `#Frozen` 互斥
- `#Frozen`：深不可变，用于参数 / 字段 / 局部 `let`
- `#Val`：字段浅不可变（仅字段位）
- `#Static`：struct body 内方法标记为静态函数（无 `$`）+ 字段标记为静态字段（关联于类型）。调用/读写语法均为 `Type::name(...)` / `Type::FIELD`

## 与 SDK 的关系

`sdk/yux/core.yux` 中 `i8`、`u8`、`i16`、`u16`、`i32`、`u32`、`i64`、`u64`、`f32`、`f64`、`bool` 的占位 struct 以及 `to_<原始类型>` 方法都使用 `#Builtin` 标注。编译器据此跳过这些方法的源码编译并合成 LLVM IR 指令（整数扩展/截断、浮点转换、比零等）。
